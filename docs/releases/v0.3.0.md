Talaria is an experimental, Hermes-native terminal UI. This release comes out of driving v0.2 by hand and finding that four defects which looked unrelated were all the same problem: **Talaria did not confirm what it had just done.** It now does. Alongside that, the composer gains the two conventions every comparable interface already has — history on `Up`, and a slash-command palette.

Nine units, planned one at a time against the hands-on notes that produced them. Two shipped clean, three needed one repair round, and four needed a further round after an independent check found the first report had claimed more than the work delivered. Seven of the nine went to independent code review before merge. The session-by-session record, including every rejected claim, is in [the v0.3 decision register](https://github.com/infiquetra/talaria/blob/v0.3.0/docs/plans/2026-08-11-v0-3-decision-log.md).

## Read this part first

Carried forward from v0.1 and v0.2, unchanged and not superseded by anything in this release:

- **No person has driven the interface on Linux.** The suite runs there in continuous integration; nobody has used it there.
- **Every measurement behind these releases was taken against a bare pseudo-terminal**, not a real terminal emulator. The hands-on drives that produced this release's scope did use a real terminal, on macOS, and were observations rather than measurements.
- **A credential your shell exported before Talaria started is still visible** in the process environment for the life of the process. Use the credential file.

New to this release, and the limit to weigh hardest:

- **No unit in this release was gated on a live drive against a Hermes gateway.** Every one was merged on its own tests, and seven of the nine on an independent code review as well. A live acceptance pass is not part of this release's record. The units most exposed by that gap are the two that touch the composer's key handling, because their tests drive a headless application rather than a terminal.

## What is new to use

- **`Up` recalls what you sent.** The composer keeps an in-memory history of every line you dispatched, bounded at 100 entries. `Down` walks back toward the newest and then restores the draft you were part-way through typing, caret at the end. A multi-line draft only recalls when the caret is already at the boundary you are moving through, so editing a paragraph still works. History holds slash commands and lines the gateway failed to deliver; it excludes empty lines and submissions Talaria refused. **It is never written to disk.**
- **`/` opens a filterable command palette** over every command available to you — Talaria's own eight first, then the gateway's. Filtering is by prefix, case-insensitively, so `/mod` reaches `/models` and a command that merely contains those letters does not. `Up` and `Down` move the selection and scroll it into view, `Enter` inserts the canonical name with a trailing space and sends nothing, and `Escape` closes the palette while keeping what you typed. Moving the caret closes it too. `F3` still browses the whole list where the desktop delivers that key.
- **An outstanding prompt card takes the caret by itself** when the composer is empty, so the answerable thing is where your hands already are. The first card of a batch takes focus; a later card in the same batch does not steal it from the one you are answering.
- **A resumed session names itself on arrival**, by its durable id, as the first thing in the transcript — placed so it survives the transcript clear and introduces the history it precedes. A reply that carries no durable id names the runtime id and says that is what it is doing.
- **A keypress that did something is distinguishable from one that did not.** Four keypresses that used to be silent now confirm themselves on the composer notice, each at the site of its silence — including re-following when you are already at the bottom, and toggling sub-agent rows when there are none to show.
- **Typing where text cannot go says so.** A printable key or a paste that lands in the transcript, the prompts container or the sub-agent list is still discarded, but the notice now names that typing is paused, names the region, and leads with the way back so the sentence survives an eighty-column terminal. It clears when the caret leaves that region.

## What changed that you may have been relying on

- **`F1` no longer jumps to the newest unanswered prompt, and the binding is gone.** The card owns focus now, so the jump has no job. On macOS the key never reached Talaria in the first place: the desktop ate it, and an eaten key sends no bytes, so the program could not even report the loss.
- **The caret status row is gone.** It named where the caret was, and it was unreadable in the one case where that mattered and redundant everywhere else. What replaces it speaks only when a keystroke is about to be discarded, which is the case the row existed for.
- **Every action the desktop can eat now has a non-function-key primary.** `ctrl+g` toggles sub-agent rows, `ctrl+c` interrupts, `end` re-follows the newest line. `F2`, `F4` and `F5` remain as aliases where your desktop delivers them; `F3`, `F6` and `F7` remain as aliases beside their slash primaries; `F8`, `F9` and `F10` stay primary for replay pacing. The footer now advertises only the bindings the current mode actually has, so a live session no longer offers you replay keys.
- **The fallback banner reports what is hidden rather than what is retained.** It used to print a retained line count under the word "clipped", which reads as a loss and was visibly falling as more was hidden. It now says how much of the entry is hidden out of how much there is, at a named scope.
- **An unknown gateway event announces once per type, per connection**, with repeats counted rather than reprinted, and an unknown event belonging to a background session no longer writes into the session you are looking at.

## One correction to the v0.2.0 notes

`F4` was published as sweeping the answerable set, and that description was missing its destructive half. `F4` is bound to `interrupt`: it **cancels the in-flight turn**, and only then, and only when the gateway confirms the cancellation, does it decline that turn's outstanding prompts. An interrupt whose outcome is unknown declines nothing, deliberately, because the turn may still be alive.

The shipped v0.2.0 notes are left exactly as they were published — a released artifact says what it said — and this is the correction of record.
