# Talaria v0.6.5

Talaria v0.6.5 ships typed schema and env load outcomes after v0.6.4.
A failed `/config` load names the phase and failure class instead of
collapsing every error into a silent unlabeled placeholder.
`summarize_schema_shape` reports field and category counts plus sorted
top-level keys, with no descriptions, options, or values.

Read the limits first. This file is the candidate release note for the
v0.6.5 line.

## Read this part first

Carried forward from earlier releases and still true:

- **No person has driven the interface on Linux.** The suite runs there in continuous
  integration; nobody has used it there. macOS remains the supported platform.
- **A credential your shell exported before Talaria started stays visible** in the process
  environment for the life of that process. Use the credential file.
- **Host administration is read-only status.** Update checks and receipts, local-model
  status/catalog/hardware/jobs/search, and gateway-migration plans may be shown. The
  workspace offers no Hermes-update, local-model mutation, or gateway-migration action.
- **Revealed plaintext is presentation-ephemeral.** It may exist only in the
  in-flight response and the active reveal overlay. It is never added to
  domain state, notices, logs, recordings, or reprs, and is wiped on close or
  timeout.

New to this line:

- **Load failure is typed product state.** Schema and env catches are
  named transport or decode outcomes. Unknown exceptions do not become
  `schema=None`.
- **Live T3R found no-failure-class.** The accepted v0.6.4 remount was
  not rewritten. This release does not claim installed J3 or J4.

## What this release adds

- Actionable placeholder notices that name the schema or env phase and
  the failure class (`unreachable`, `timeout`, `decode`, and the other
  named transport reasons).
- `summarize_schema_shape` for metadata-only diagnosis: object bodies
  yield counts and sorted keys; non-objects raise `SettingsDecodeError`
  with no body content.
