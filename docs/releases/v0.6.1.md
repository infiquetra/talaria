# Talaria v0.6.1

**Talaria v0.6.1 is the first published release since v0.5.0 on 1 September.** The
v0.6.0 line landed on `main` but was never tagged, built, or published, so
upgrading from v0.5.0 delivers two releases' worth of change in one artifact: the
whole v0.6.0 line — honest gateway compatibility reporting, Herdr-safe keyboard
defaults, single-Enter picker dispatch, inspector-housed diagnostics, the
script-driven bottom bar, marketplace theme import with explicit Reload,
configurable appearance, and status-script credential hardening — plus this
release's own work. The v0.6.0 headline is the [v0.6.0 release
notes](v0.6.0.md) and the `[0.6.0]` section of the
[changelog](../../CHANGELOG.md); read them alongside this file, because their
limits still apply to the shipped build.

v0.6.1 is an interface-focused release. It answers the operator's 2026-09-04
interface feedback and shapes five capability areas: a discoverable
slash-command palette with wire-backed provenance, composer file and image
attachments, a richer Mixture of Agents presentation with an honest fallback,
desktop-like configuration views inside the client boundary, and a
session-scoped launch directory with an honest adoption status. Read the limits
first, then the reasons to upgrade, then the findings-to-evidence map — the
limits below apply to the shipped build.

## Read this part first

Carried forward from earlier releases and still true:

- **No person has driven the interface on Linux.** The suite runs there in continuous
  integration; nobody has used it there. macOS remains the supported platform.
- **A credential your shell exported before Talaria started stays visible** in the process
  environment for the life of that process. Use the credential file.
- **A fresh launch with no stored credential shows a password prompt you cannot cancel.**
  `talaria/transport/credentials.py` is untouched by this release.

New to this release, and the limits to weigh hardest:

- **Plugin-command provenance is proven at class granularity only, and that is a limit of
  the gateway, not of the acceptance run.** The gateway's command catalogue drops the
  owning-plugin field and keeps a single plugin-commands bucket, so no interface can attest
  which specific plugin owns a command. What is wire-backed, and what the palette shows, is
  the catalogue's category assignment — a command is a plugin command, a quick command, a
  bundle command, or a skill command. It is not the named plugin behind it.
- **Image attachments have no image-incapable route to exercise on this transport.** A
  text-only acting model still routes an attached image to the gateway's auxiliary vision
  model, and Talaria has no flag to read or flip that would keep an image from a model that
  cannot see it. The "the model cannot see this image" path is inapplicable on this gateway,
  not verified against it. Talaria's own client-side refusals — an unsupported type before a
  socket is opened, and an oversize file — are the refusals that do fire.
- **A model switch that carries an argument can time out before the gateway answers.** A
  `/model <name>` switch cold-spawns a first-use worker whose ceiling on the gateway is
  forty-five seconds, and Talaria gives up at thirty (`call_timeout`, `talaria/ui/app.py`).
  A user who switches models and sees nothing come back is inside that gap, which is real
  and queued for repair, not a silent hang with no cause.

## Reasons to upgrade

### A discoverable slash-command palette with verified provenance

A large slash-command inventory is discoverable, sectioned, and paged, and every entry's
provenance is the category the gateway's catalogue actually carries rather than an invented
owner — see the limit above for exactly how far that proof reaches. See
[Slash commands](https://github.com/infiquetra/talaria/blob/main/talaria/domain/commands.py)
and the palette surface in
[`talaria/ui/palette.py`](https://github.com/infiquetra/talaria/blob/main/talaria/ui/palette.py).

### Composer file and image attachments

Drop or paste a path into the composer and Talaria classifies the route — a file attachment
or an image attachment — cleans the path text, refuses an unsupported type before opening a
socket, and surfaces the gateway's honest oversize refusal instead of pretending an
over-limit file was sent. See
[`talaria/ui/attach.py`](https://github.com/infiquetra/talaria/blob/main/talaria/ui/attach.py)
and the transport in
[`talaria/transport/attachments.py`](https://github.com/infiquetra/talaria/blob/main/talaria/transport/attachments.py).

### Mixture of Agents presentation with an honest fallback

Multi-agent progress renders richly when the gateway reports sub-agent activity, and falls
back to an honest single-line presentation when it does not, rather than drawing a structure
the wire never described. See
[`talaria/ui/app.py`](https://github.com/infiquetra/talaria/blob/main/talaria/ui/app.py).

### Configuration views inside the client boundary

Desktop-like configuration views live inside Talaria's own client responsibilities — the
surfaces Talaria owns, not gateway or server settings it does not. See
[`talaria/ui/config_view.py`](https://github.com/infiquetra/talaria/blob/main/talaria/ui/config_view.py).

### Session-scoped launch directory with honest adoption status

Talaria offers its launch directory to the gateway on `session.create` and reports the
outcome honestly: unreported, reported, adopted, not-adopted, or moved. The inspector's
Context section shows the launch directory and the agent's reported working directory as
distinct rows, so a directory that was offered but not adopted reads as exactly that. See
[`talaria/domain/workdir.py`](https://github.com/infiquetra/talaria/blob/main/talaria/domain/workdir.py).

### Interface feedback answered

- **The custom-theme lifecycle reloads, persists, and explains itself.** A selected theme
  persists automatically, a source-less custom theme reloads without a phantom source, and
  the lifecycle states its own behavior instead of leaving it to be inferred (#140).
- **Transcript text renders on the canvas.** Category colors are themeable, there are no
  fixed category boxes around transcript text, left-bar visibility is theme-controlled, and
  the fixed `A Talaria` assistant label is gone (#141).
- **Theme sources are explained and import reports lead with their fallbacks.** An import
  report names what it could not honor first, and Homebrew's provenance is stated rather
  than assumed (#142).
- **The status bar has a setup path with honest data availability.** Activation feedback and
  honest "no data yet" states replace a silent bar (#143).
- **Diagnostics stay inspector-only.** Roster, approval, and HTTP-runner rows live in the
  inspector, and the caret label moved off the composer row (#144).
- **`session.usage` is handled.** The gateway's `session.usage` event is decoded instead of
  reported as an unknown event type (#145).

## Defects fixed this run

Two of these are conditions a v0.6.0 user has been living with on `main`.

- **The slash palette drew duplicate headings when two rebuilds raced.** The rebuild is now
  serialized and headings are drawn by grouping rather than by adjacency, so two callers
  rebuilding at once can no longer double a section heading (#161, commits `da618eb`,
  `6d8ea65`).
- **An attachment failure notice was erased milliseconds after it appeared** by the
  reconnect that followed. A reconnect now clears only its own notice, not a dropped
  attachment's explanation, so the reason a file did not attach stays on screen (#161,
  commit `f4740c4`).
- **A mid-stream credential failure could silently discard assistant text you had already
  received.** A non-terminal dial no longer publishes `auth_failed` without its cause, and
  `close()` re-delivers that cause, so a credential drop in the middle of a turn surfaces its
  reason instead of throwing away text already on your screen (#166, #146 lineage, commit
  `fcfd7e5`).

## Acceptance

**No acceptance result is recorded in this file.** The v0.6.1 integrated regression has not
been captured against the final candidate yet, and a notes file that claimed a pass before
the gate flipped would be the most damaging kind of untruth in this repository.

What will fill this section when the gate flips: the twenty-one required live cases plus the
two added this run — Live 22 for Herdr-safe keyboard defaults under nested capture, Live 23
for honest gateway compatibility drift and refusal — run against the final candidate with
recorded evidence and reviewer inspection, consolidated on issue #150. The status-script
credential-hardening surface is carried by the consolidated record's unchanged-area
statement, which cites v0.6.0's credential-deny observation and the byte-identity of
`talaria/status/contract.py` and `talaria/status/local.py` between the two candidates, since
no live case witnesses that boundary firing.

## What changes when upgrading from v0.5.0

A v0.5.0 user receives both the v0.6.0 line and the v0.6.1 changes in this one artifact. From
the v0.6.0 line, configuration gains `[keys]` and the versioned status-script document, the
status allowlist falls back to empty for any non-list shape, and marketplace theme import with
explicit `/theme reload` arrives; the full list is in the [v0.6.0 release
notes](v0.6.0.md). From v0.6.1, a selected theme now persists automatically, the composer
accepts dropped file and image paths, a large slash inventory is discoverable with wire-backed
provenance, configuration views open inside the client, and the launch directory is offered to
the gateway with an honest adoption status. The credential boundary and the read-only posture
are unchanged; nothing here promotes, publishes, or deploys.
