# Talaria v0.5.0

Talaria v0.5.0 is a visual and operational upgrade for people moving from v0.4.0. It makes the
terminal interface consistently themeable, keeps current session context visible at the bottom of
the screen, adds a responsive inspector and a strictly read-only view of reported changes, and makes
focus and scrolling more predictable. The changelog entry for this version is
[`[0.5.0]`](https://github.com/infiquetra/talaria/blob/v0.5.0/CHANGELOG.md).

## Read this part first

Carried forward from earlier releases and still true:

- **No person has driven the interface on Linux.** The suite runs there in continuous integration;
  nobody has used it there. macOS remains the supported platform.
- **A credential your shell exported before Talaria started stays visible** in the process
  environment for the life of that process. Use the credential file.
- **A fresh launch with no stored credential shows a password prompt you cannot cancel.**
  `talaria/transport/credentials.py` is untouched by this release.
- **Talaria never calls Hermes's model-picker methods**, which refuse with code 4018. Present since
  2026-08-06.

New to this release, and the limits to weigh hardest:

- **One live acceptance check is blocked, and not by a defect in Talaria.** Checklist item 24 covers
  a keyless, possibly-duplicate approval shape. Hermes 0.21.0 assigns request identifiers to live
  approvals, so that state cannot be reached without simulating acceptance — which is exactly the
  simulated acceptance this release's testing contract forbids. It was re-tested against the shipping
  build three times rather than inherited, and every other check passed: 42 of 43.
- **The last scored code-review verdict does not describe this tag.** One review ran seven lenses at
  an exact frozen revision, three times, ending with every applicable dimension above its floor and
  no highest-severity findings outstanding. After that freeze the release took sixteen repairs, two
  further complete two-tester live acceptance runs, a privacy-gate widening and the restoration of an
  evidence-provenance guard — none of it scored, because the review's cycle cap was spent and the
  decision to run one further unscored repair round was taken deliberately. Read the published review
  artifacts as the record of how the release got here, not as a verdict on what you are installing.
- **Six review findings are carried rather than fixed.** Five are minor. The one worth naming: the
  credential-name deny list in `talaria/domain/redaction.py` anchors its API-key pattern to the whole
  name, so `OPENAI_API_KEY` and its siblings pass a boundary this release newly leans on. It is
  pre-existing and present on the previous tag; repairing it would have touched product code and
  invalidated the entire live acceptance run, so it is disclosed here rather than fixed quietly at
  the end of a release.
- **`talaria gate` fails one steady-state latency check of thirty-two.** Pre-existing — v0.4.0 fails
  it too, and the run-to-run spread is wider than the difference between the two versions, so no
  ordering between releases can be drawn from it.

## Reasons to upgrade

### A complete theme token layer

Every application surface now resolves colors through one semantic token model. The four built-in
themes are Refined Default, Dark Green Terminal, Neutral Dark, and Accessible High Contrast. They
cover the application canvas, transcript roles, bottom bar, inspector, diff viewer, syntax classes,
focus, selections, and connection states without making color the only signal.

Use `/theme` to preview and select a theme in the running process. Preview and session selection do
not write a file. `/theme save`, `/theme save user`, and `/theme save repository` are the explicit
persistence routes. See [Themes](https://github.com/infiquetra/talaria/blob/v0.5.0/docs/themes.md) for precedence and save behavior.

### Bounded Visual Studio Code theme import

Talaria can import the supported parts of a Visual Studio Code color-theme JSON file:

```text
talaria theme import FILE [--name NAME] [--json]
```

`--json` writes one versioned machine-readable report to standard output. Its success and error
fields are defined in the
[Visual Studio Code theme import format](https://github.com/infiquetra/talaria/blob/v0.5.0/docs/formats/vscode-theme-import.md).

The importer maps a documented allowlist of workbench colors and syntax scopes, reports unsupported
input, fills unmapped Talaria tokens from Refined Default, and atomically stores a canonical user
theme. Re-importing the same name is deterministic. Malformed or empty input writes nothing. The
source format and exact mapping are in the
[Visual Studio Code theme import format](https://github.com/infiquetra/talaria/blob/v0.5.0/docs/formats/vscode-theme-import.md).

### A responsive bottom status bar

The final terminal row is now a configurable bottom status bar. Its default segments show the launch
directory and Git branch, the focused agent and model, held context usage, task and queue progress,
connection state, and the Talaria version. It shortens and then drops lower-priority segments at
fixed width bands instead of wrapping or presenting a clipped wide row; the connection indicator is
the minimum retained signal.

`/bar` reports the enabled segments, and `/bar SEGMENT` toggles one for the current process without
writing configuration. Persistent order, visibility, and value caps come from the `[status]` table.
The literal connection and attention markers remain present when color is unavailable. The complete
breakpoint table is in [Terminal UI](https://github.com/infiquetra/talaria/blob/v0.5.0/docs/terminal-ui.md#responsive-status-bar).

### A right inspector from held session state

`Ctrl+B` or `/inspector` opens the right inspector. It projects four sections already held by the
client: Tasks, Context, Changed files, and Operation details. At wide terminal sizes it docks beside
the transcript; at narrow sizes it becomes an overlay without reflowing the transcript. Empty
sections say that no state is available instead of disappearing or initiating a scan.

The inspector adds no gateway request, Git process, filesystem scan, or polling loop. Its width,
open state, current row, and selection belong only to the running process.

### A bounded read-only diff viewer

`/diffs` or `Enter` on an inspector changed-file row opens the read-only diff viewer. It renders only
unified diff text already reported by the current session. Side-by-side mode is available at 112
columns and wider; narrower terminals use unified mode without overwriting the preferred mode.
Navigation covers files and hunks, and syntax and intraline work remain bounded to visible content.

The viewer does not open working-tree files, invoke Git, call the gateway, or expose edit, stage,
apply, revert, discard, or checkout actions. It is a projection, not a repository mutation surface.

### Interaction and readability polish

Focus now changes reserved gutters and existing borders without changing layout height. Transcript
kinds, connections, queued attention, approvals, agent states, selections, and diffs retain literal
labels or glyphs as well as color. Scroll anchoring preserves the reader's held entry when content or
layout changes; `End` or `F5` returns to following the newest line.

Set `ui.reduced_motion = true` to make nonessential progress static and routed scrolling immediate.
Content, protocol progress, and elapsed-time updates continue because they communicate state rather
than decoration.

## What changes when upgrading from v0.4.0

Existing configuration remains valid. The new theme, user-interface, and status settings are
additive and use documented defaults when omitted. Inspector geometry and diff-viewer state are
session-only and are not added to the configuration file.

Configuration is restart-to-apply. Editing `config.toml` or a stored imported theme while Talaria is
running does not alter that process, because Talaria provides no external-file live reload.
`/theme` and `/bar` can change their current-session projections immediately, but only the explicit
theme save commands persist a theme and `/bar` never writes configuration. A newly imported theme is
available after a fresh Talaria process loads the stored theme library.

The supported installation platform remains macOS. Linux interactive support and Windows support
are not claimed for this release. Read [Install Talaria](https://github.com/infiquetra/talaria/blob/v0.5.0/docs/install.md) for prerequisites, the
tagged-release and source-checkout commands, and the two known credential and command-path traps.
