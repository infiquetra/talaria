# Talaria v0.6.2

Talaria v0.6.2 is the comprehensive configuration release. It expands
Talaria-owned settings to the finite D12 set, adds a `[connections.<id>]`
inventory that is not keyed by profile, generalizes the byte-preserving
writer to every DEFAULTS table, and redacts secret-bearing admin HTTP
exchanges by route before they can be recorded. Hermes configuration
surfaces stay on existing network APIs; Talaria does not write Hermes
files, spawn the dashboard, or add routes.

Read the limits first. This file is the candidate release note for the
v0.6.2 line; final installed-release evidence is recorded against the
published tag.

## Read this part first

Carried forward from earlier releases and still true:

- **No person has driven the interface on Linux.** The suite runs there in continuous
  integration; nobody has used it there. macOS remains the supported platform.
- **A credential your shell exported before Talaria started stays visible** in the process
  environment for the life of that process. Use the credential file.
- **Host administration is read-only status.** Update checks and receipts, local-model
  status/catalog/hardware/jobs/search, and gateway-migration plans may be shown. The
  workspace offers no Hermes-update, local-model mutation, or gateway-migration action.

New to this release, and the limits to weigh hardest:

- **`profiles.endpoints` is a compatibility alias, not a UI write target.** The
  workspace manages `[connections.<id>]`. Operators who still keep a profile-to-URL
  map edit that table by hand; Talaria will not rewrite the whole map.
- **Connection secrets never land in `config.toml`.** A URL carrying `user:pass@`
  is dropped on load and refused on write. Tokens stay in `~/.talaria/credentials`
  at mode `0600`.
- **Reveal and token HTTP responses are not persisted**, even as redacted markers.
  Env write, provider, vault, and OAuth request bodies persist only as a
  route-denied marker. Harmless token-count fields remain visible.
- **Keybindings and connection inventory take effect on the next session.**
  Theme, inspector geometry, timestamps, composer thresholds, attachment cap,
  status segments, and notification transcript-line control are live when the
  running process can apply them. The Save summary says so.

## Reasons to upgrade

### Talaria-owned settings that match today's behavior

Inspector width (28–48), inspector open-at-start, dock and diff side-by-side
thresholds, transcript timestamps, the remaining named app bindings, the
composer attachment cap, and notification transcript-line control become
preferences. Defaults are the values the interface already used, so an older
file changes nothing until the operator writes a new key.

### A connections inventory that is not a profile map

`[connections.<id>]` stores `url`, `auth` (`loopback` or `gated`), and an
optional `label`. Profiles remain selectable server-side scopes on a
connection. `profiles.endpoints` continues to resolve as a compatibility
alias with no automatic migration.

### Byte-preserving writes, generalized

`save_settings` extends the surgical rewrite already used for `theme.name`
and `[status]` to every DEFAULTS table and to one connection entry at a
time. Comments, CRLF, and dotted keys survive. Unsupported shapes refuse
without changing bytes.

### Secret-boundary recording

HTTP config/env/provider/vault/OAuth/token exchanges are redacted by route
before any recorder or evidence sink. Summaries name keys and actions, never
values. Existing JSON-RPC frame redaction remains the defense-in-depth layer
underneath, and the TypeScript-equivalence harness stays the pin for that
layer.

## What does not change

Hermes host administration stays visible and non-mutating. Talaria does not
install Hermes updates, mutate local models, or migrate gateways. Dashboard
restart remains "required; not available over the API." No Hermes source
change, direct file write, SSH call, or new route is part of this release.
