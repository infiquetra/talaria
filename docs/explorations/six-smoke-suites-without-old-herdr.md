# Six smoke suites without old Herdr

The source inventory uses the documented hc 0.1.20 key measurement. The live attempt used hc 0.1.21 and a running fixture gateway; it did not repeat a separate key survey. The six attempts stopped at their first failure, so later checks remain unobserved.

## 1. Input inventory

`HcCli::send_text` converts each character to a key before sending any of them. A space becomes `space`, uppercase becomes `shift+` and a lowercase letter, and the accepted punctuation is `'`, `,`, `-`, `.`, `/`, `;`, `=`, `[`, `\`, `]`, and backtick. A refused character rejects the entire call. In contrast, `Terminal::run` uses `hc send`: it pastes its argument and presses Enter. A `submit` helper is not necessarily `Terminal::run`; the phase 4 and 5 helpers type first and press Enter separately.

## 4. Route and costs

**Recommendation: ask herdr core for text input without Enter.** This addresses the observed `@`, `_`, and token-prompt colon failures, as well as the source-identified `!` and `?` gaps, without replacing the harness terminal integration. It is insufficient on its own: phase3 also needs Talaria's old-Herdr pane guard addressed, and checks not reached in the live attempts still need read and foreground validation.

- **Herdr core text input without Enter:** herdr core must provide and maintain that operation, and the smoke adapter must use it. The run must also resolve any observed read, foreground or pane-identity gaps. No downstream issue is filed by this exploration.
- **Harness-owned terminal:** build and maintain terminal process lifecycle, input without Enter and Enter-submitting paste, key delivery, screen and scrollback capture, foreground/process status, pane creation and cleanup, plus any Herdr-specific integration needed by the suites. The existing tmux helper already provides private-file buffer loading, bracket-aware paste, session checks and cleanup for phase2a; it is not a complete replacement terminal and is not a fourth route.
- **Keep old Herdr for these suites:** retain and operate the old terminal path and its pane/process interfaces, and defer removing that dependency for these suites. This avoids building a replacement input path but retains the old program and its maintenance burden.
