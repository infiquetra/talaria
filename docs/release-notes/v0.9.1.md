# Talaria v0.9.1

Talaria is a terminal client for the Hermes agent backend. Before upgrading
from 0.6.5, read the
[migration guide](https://github.com/infiquetra/talaria/blob/v0.9.1/docs/migrating-from-0.6.5.md).

Talaria v0.9.1 delivers the prebuilt release archives and Homebrew formula for
v0.9.0 after [PR #757](https://github.com/infiquetra/talaria/pull/757) fixed
packaging `--version` validation and the Homebrew formula audit. There are no
Rust runtime behavior changes from v0.9.0. The v0.9.0 tag remains unchanged.

## Read this part first

- **The workspace is optional.** The default inline view keeps finished output
  in native terminal scrollback. The workspace uses the whole screen; while it
  is open, native scrollback and terminal search do not cover the conversation.
  Finished output waits in memory until you return to inline view, so a process
  crash can lose it.
- **Client voice is opt-in.** Capture and playback helpers run on your machine
  and must be installed and configured separately. Sending audio to a remote
  gateway requires explicit `remote_audio = true`; attaching remotely alone
  does not grant that permission.
- **Check your gateway.** The pinned Hermes contract is v0.23.1; Talaria
  accepts a gateway at Hermes v0.23.0 or later. Run `talaria doctor` to check
  the gateway you use.

## What is new

- Packaging accepts the Hermes compatibility line in `talaria --version`
  while still checking the version and rejecting extra output (#757).
- The Homebrew formula test checks the first version line, and final releases
  omit the redundant `version` declaration rejected by `brew audit --strict` (#757).

The feature set from [v0.9.0](https://github.com/infiquetra/talaria/blob/v0.9.0/docs/release-notes/v0.9.0.md)
is unchanged. Its highlights include:

- Hermes v0.23.1 bindings, a compatibility table, and notices for gateways
  outside the supported or tested range.
- Connection and skin fixes, clearer help and workspace hints, and theme colours
  in the default inline view.
- Clipboard copying, a fresh local `/clear`, and approval notes retained when
  Hermes refuses a follow-up prompt.
- Workflow concurrency defaults and an offer to install the Ultracode skill.
- Visible Hermes notices, readable sign-in details, recovered waiting prompts,
  connection requests, agent messages, and review summaries.

## What changed from 0.6.5

Talaria is now a Rust client that attaches to the Hermes session authority.
Configuration still lives at `~/.talaria/config.toml`, but some older keys
are retired and produce notices. Read the
[migration guide](https://github.com/infiquetra/talaria/blob/v0.9.1/docs/migrating-from-0.6.5.md)
for upgrade and coexistence steps.

## Install

Install the prebuilt release through Homebrew:

```bash
brew install infiquetra/talaria/talaria
talaria --version
```

Or build the tagged source using the Rust toolchain in `rust-toolchain.toml`:

```bash
git clone --branch v0.9.1 https://github.com/infiquetra/talaria
cd talaria
cargo build --release
target/release/talaria --version
```

See the [installation guide](https://github.com/infiquetra/talaria/blob/v0.9.1/docs/install.md)
for distribution options. Talaria is not published under this name on crates.io,
npm, or the Python Package Index; similarly named packages there are not this
release.

configured speech services depend on the connected Hermes installation;
`talaria doctor` reports available capabilities.

## Staying on 0.6.5

You can continue using 0.6.5 or Hermes's native terminal interface while
reviewing the [migration guide](https://github.com/infiquetra/talaria/blob/v0.9.1/docs/migrating-from-0.6.5.md).

## Known limits

- The workspace does not put its live conversation in native terminal
  scrollback until returning to the inline view.
- Local voice requires separately installed helpers and configured Hermes
  speech services. Remote audio is disabled until explicitly allowed.
- Hub fetched counts include duplicates from different sources and are not a
  complete match total.
- macOS release archives are not Apple Developer ID notarized.

## What was checked

The release candidate's verification and any live-device checks are recorded
with its review and release evidence. A prepared version and these notes do
not by themselves establish a completed release gate or a published tag.
