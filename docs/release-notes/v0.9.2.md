# Talaria v0.9.2

Talaria 0.9.2 is the stable follow-up to 0.9.1 and the two 0.9.2 prereleases.
It improves workflow recovery and makes terminal controls and feedback easier
to read.

## Read this part first

- A workflow can report failed agents even when the script itself completed.
  Check the agents and any leftover work shown in the final result.
- `talaria workflow result <run>` reads the saved result. `talaria workflow
  resume <run>` continues work, including an agent marked for restart.
- Use `/theme` to preview and select a theme for the current profile. Use
  `/theme report` for the detailed report.

## What is new

- Stopped agents can wait for a decision. You can fail or rerun the agent,
  abort the run, or use the agent's next reply. A run can resume agents that
  its own stop interrupted and keep results from agents that finished.
- Workflow results show failed and cut-short agents, which phases never
  started, and which worktrees still hold changes. Talaria can save an isolated
  agent's remaining changes to a branch after a stop or failure.
- Talaria ships 15 built-in themes, clearer keyboard help, better navigation
  in the slash menu, and more readable overlays in narrow terminals.
- Talaria keeps credential paths out of attachments, checks what it reads
  from local workflow files, and prevents Git hooks and filters from running
  during worktree recovery.

## What changed from 0.6.5

Talaria now attaches to the Hermes session gateway as a Rust terminal client.
Check the [migration guide](https://github.com/infiquetra/talaria/blob/v0.9.2/docs/migrating-from-0.6.5.md)
before carrying forward an older configuration.

## Install

Use the prebuilt archives from the release page or install through Homebrew
once the tap update is merged:

```bash
brew install infiquetra/talaria/talaria
talaria --version
```

To build from source with the toolchain in `rust-toolchain.toml`:

```bash
git clone --branch v0.9.2 https://github.com/infiquetra/talaria
cd talaria
cargo build --release --locked
target/release/talaria --version
```

Talaria is not published under this name on crates.io, npm, or the Python Package Index.

## Works with Hermes

The bundled Hermes contract is v0.23.1 (commit `3b421578`). The compatibility
floor is v0.23.0. `talaria doctor` reports the gateway version and the contract
Talaria was tested against.

## Staying on 0.6.5

You can keep using 0.6.5 or Hermes's native terminal interface while you
review the migration guide.

## Known limits

- The optional full-screen workspace keeps finished output in memory until you
  return to the inline conversation, where the terminal owns scrollback.
- Voice is opt-in. It uses separate capture and playback helpers, and
  sending audio to a remote gateway requires explicit permission.
- macOS release archives are not Apple Developer ID notarized.

## What was checked

The tagged release workflow runs the workspace tests, builds the platform
archives, checks the packaged binaries and publishes their checksums.

In a live terminal inside tmux, Talaria connected to Hermes v0.23.4,
received a reply, opened and closed the appearance picker, and exited
cleanly. Earlier interactive checks of the terminal fixes are described in the
[November terminal verification notes](../handoff/2026-11-25-tui-recommendations-accepted/README.md).
