# Talaria v0.7.1

Talaria is a terminal client for the Hermes agent backend. Version 0.7.1 is a patch release on 0.7.0 that fixes the three known issues listed in the v0.7.0 release notes and sharpens status feedback for goals, model reasoning, `/skin` selection, toolset toggles, Ultracode workflow prerequisites, remote voice safety, and queued messages. Before upgrading from 0.6.5, read the limits below and the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.1/docs/migrating-from-0.6.5.md).

## Read this part first

- **Fixes the v0.7.0 known issues.** The hidden goal completion verdict ([#463](https://github.com/infiquetra/talaria/issues/463)), unchecked `/skin` names ([#466](https://github.com/infiquetra/talaria/issues/466)), and unblocked remote-gateway voice commands ([#476](https://github.com/infiquetra/talaria/issues/476)) reported in the v0.7.0 release notes are all fixed in v0.7.1.
- **Interactive terminal verification ran on macOS.** Automated release-candidate gates and Linux continuous-integration checks ran on both macOS and Ubuntu Linux, while live interactive operator driving and physical microphone/speaker voice checks ran on macOS (Apple silicon).
- **Requires Hermes v0.22.3 or newer.** Talaria attaches to the Hermes session authority (`gateway/session_authority.py`), which first shipped in stable Hermes v0.22.3. Run `talaria doctor` after installing to verify your gateway version and capabilities.
- **Configuration keys from 0.6.5 have changed.** Talaria reads `~/.talaria/config.toml` and prints explicit startup notices for retired 0.6.5 keys rather than silently ignoring them. Review the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.1/docs/migrating-from-0.6.5.md) before removing old settings.
- **macOS browser downloads are not notarized.** Release archives are signed with GitHub artifact attestations and SHA-256 checksums, not Apple Developer ID notarization. Install via Homebrew or `gh release download` to avoid macOS Gatekeeper quarantine prompts.

## What is new

- **Goal completion verdict and reason shown on screen ([#463](https://github.com/infiquetra/talaria/issues/463)).** The v0.7.0 release notes listed the hidden goal verdict as a known issue; it is fixed in v0.7.1. When a goal finishes on the Hermes gateway, Talaria now displays a completion notice in the session transcript with the goal's verdict, reason, and summary even when the gateway's final snapshot arrives without a separate status note.
- **Running goal turn shown while a goal works ([#464](https://github.com/infiquetra/talaria/issues/464)).** While a goal is actively working on its first or next turn, the goal status row now shows the running turn (`turn 1 of 20`, advancing as turns complete) instead of staying at `0/20 turns`.
- **Labeled model reasoning blocks ([#465](https://github.com/infiquetra/talaria/issues/465)).** Model reasoning cells now begin with a muted `∴ thinking` header label so you can tell reasoning apart from regular assistant output without relying on text color alone.
- **Checked `/skin` names and available skin list ([#466](https://github.com/infiquetra/talaria/issues/466)).** Fixes the v0.7.0 known issue where `/skin <name>` saved any name without checking it. Running `/skin` or `/theme` with no name now lists the skins available on the connected Hermes gateway, and passing a skin name checks it against the gateway's skin list before saving it.
- **Toolsets toggle confirmation and timing notice ([#467](https://github.com/infiquetra/talaria/issues/467)).** Toggling a toolset on the Capabilities screen's Toolsets tab now displays a confirmation notice (`<label> on/off · new sessions; some on resume or next turn`) stating whether the toolset was enabled or disabled and when the change takes effect, while the footer reminds you that `Enter` opens the detail view.
- **Ultracode workflow skill explanation ([#468](https://github.com/infiquetra/talaria/issues/468)).** The Ultracode screen now explains why the `talaria-workflows` skill is required before compiling or running a workflow.
- **Remote gateway voice refusal ([#476](https://github.com/infiquetra/talaria/issues/476)).** Fixes the v0.7.0 known issue for remote voice commands. `/voice` and `Alt+R` are now refused when Talaria is connected to a remote gateway, with a clear message explaining that gateway voice uses the gateway machine's microphone and speaker and requires a local gateway connection.
- **Queued-message waiting time ([#483](https://github.com/infiquetra/talaria/issues/483)).** After a queued item has waited at least one whole minute, the queued-message strip above the composer shows its waiting age in whole minutes (`waiting 27m`) or hours and minutes (`waiting 1h02m`), with a `+` suffix (`waiting 27m+`) when the row was discovered from a session snapshot, preserving observed wait times across snapshot refreshes.

## What changed from 0.6.5

- The executable name is still `talaria`, and configuration still lives in `~/.talaria/config.toml`.
- Retired 0.6.5 settings in `~/.talaria/config.toml` produce explicit startup notices instead of failing silently; `composer.paste_collapse_lines`, `environment.allowlist`, `status.command`, `status.interval_seconds`, and `ui.reduced_motion` continue to work.
- Status-line commands (`status.command`) are split without a shell, run with a two-second timeout and a default-deny environment, and accept plain text or version-2 JSON rows (see [status-line.md](https://github.com/infiquetra/talaria/blob/v0.7.1/docs/formats/status-line.md)).
- Theme selection now follows the active Hermes skin (`/skin` and `/theme`), with local `theme.mode` (`auto`, `dark`, `light`) and `ui.reduced_motion` settings in `~/.talaria/config.toml`.
- Step-by-step upgrade and coexistence instructions are in the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.1/docs/migrating-from-0.6.5.md).

## Install

Install prebuilt binaries with Homebrew on macOS and Linux, download a verified release archive (`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`) with `SHA256SUMS` and GitHub artifact attestation, or build from source. Full instructions are in [Installing Talaria](https://github.com/infiquetra/talaria/blob/v0.7.1/docs/install.md).

```bash
brew install infiquetra/talaria/talaria
```

To build from source, install the Rust toolchain named in `rust-toolchain.toml` (rustup reads it automatically), then run:

```bash
git clone --branch v0.7.1 https://github.com/infiquetra/talaria
cd talaria
cargo build --release
target/release/talaria --version
```

Nothing is published to crates.io, npm or the Python Package Index under the name `talaria`; a package with that name there is someone else's software.

## Works with Hermes

Talaria 0.7.1 was tested against Hermes v0.22.4. It needs Hermes v0.22.3 or newer. The contract check passes against Hermes v0.22.4 and v0.22.5; upstream Hermes v0.22.6 (released 2026-11-02) removes unused browser-controller notification schemas from its OpenRPC contract and is tracked for the next contract refresh.

## Staying on 0.6.5

If you are not moving to 0.7.1 yet, use Hermes's own terminal interface with `hermes --tui --native`. If you keep Talaria 0.6.5 installed, reinstall it with bytecode compilation so it starts faster: `uv tool install --compile-bytecode git+https://github.com/infiquetra/talaria@v0.6.5` (or set `UV_COMPILE_BYTECODE=1`). The migration page has the rest: https://github.com/infiquetra/talaria/blob/v0.7.1/docs/migrating-from-0.6.5.md.

## Known limits

- The three known issues from v0.7.0 — hidden goal completion verdicts ([#463](https://github.com/infiquetra/talaria/issues/463)), unchecked `/skin` names ([#466](https://github.com/infiquetra/talaria/issues/466)), and unblocked remote-gateway voice commands ([#476](https://github.com/infiquetra/talaria/issues/476)) — are fixed in v0.7.1.
- Interactive human driving and physical audio hardware verification for v0.7.0 and v0.7.1 were performed on macOS; Linux verification ran via the automated release-candidate and continuous-integration suites.
- Prebuilt macOS release archives are verified by SHA-256 checksums and GitHub build provenance attestations (`gh attestation verify`), not Apple Developer ID notarization.
