# Talaria v0.7.0

Talaria is a terminal client for the Hermes agent backend. Version 0.7.0 is a complete rewrite in Rust that attaches to the Hermes session authority, keeps finished output in native terminal scrollback, and brings multi-session fleet management, full Hermes configuration, and multi-model workflows into one terminal interface. Before upgrading from 0.6.5, read the limits below and the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/migrating-from-0.6.5.md).

## Read this part first

- **Interactive terminal verification ran on macOS.** Automated release-candidate gates and Linux continuous-integration checks ran on both macOS and Ubuntu Linux, while live interactive operator driving and physical microphone/speaker voice checks ran on macOS (Apple silicon).
- **Requires Hermes v0.22.3 or newer.** Talaria attaches to the Hermes session authority (`gateway/session_authority.py`), which first shipped in stable Hermes v0.22.3. Run `talaria doctor` after installing to verify your gateway version and capabilities.
- **Configuration keys from 0.6.5 have changed.** Talaria reads `~/.talaria/config.toml` and prints explicit startup notices for retired 0.6.5 keys rather than silently ignoring them. Review the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/migrating-from-0.6.5.md) before removing old settings.
- **macOS browser downloads are not notarized.** Release archives are signed with GitHub artifact attestations and SHA-256 checksums, not Apple Developer ID notarization. Install via Homebrew or `gh release download` to avoid macOS Gatekeeper quarantine prompts.

## What is new

- **Native terminal scrollback and low-latency viewport.** Finished transcript cells flush directly into native terminal scrollback so terminal search, selection, and copy work naturally, with one status line and on-demand overlays. See [Working in a session](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#working-in-a-session).
- **Always-running Hermes sessions and full coding parity.** Attach to active sessions, resume or branch conversations, review diffs and git changes, answer approval prompts, queue or steer mid-turn messages, attach files and clipboard images, use Vim composer mode, and switch models per session without changing the gateway's global default. See [Your first session](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#your-first-session) and [Keybindings](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/keybindings.md).
- **Multi-session fleet view, Kanban board, remote gateways, and external agents.** Monitor sessions across local and SSH-tunneled remote Hermes gateways, inspect subagent trees, answer every pending approval from one attention queue, manage cards on the `/kanban` board, and launch external Agent Client Protocol (`acp`) coding agents. See [Many sessions at once](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#many-sessions-at-once) and [External ACP agents](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/configuration.md#external-acp-agents).
- **Schema-driven Hermes configuration and voice.** Configure providers, profiles, Model Context Protocol servers, skills, plugins, cron jobs, memory, and local/gateway voice settings from `/config`, `/providers`, `/mcp`, and `/profiles`, or describe changes in plain English with `/configure`. See [Settings](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#settings) and [Configuration](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/configuration.md).
- **Deterministic multi-agent workflows and headless automation.** Run multi-model workflows (`talaria workflow run`), compile workflows from natural language (`talaria workflow compile`), and drive one-shot (`talaria -p`), background (`talaria --bg --worktree`), or bidirectional `stream-json` sessions from scripts. See [Workflows](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#workflows) and [Scripts and automation](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/guide.md#scripts-and-automation).

## What changed from 0.6.5

- The executable name is still `talaria`, and configuration still lives in `~/.talaria/config.toml`.
- Retired 0.6.5 settings in `~/.talaria/config.toml` produce explicit startup notices instead of failing silently; `composer.paste_collapse_lines`, `environment.allowlist`, `status.command`, `status.interval_seconds`, and `ui.reduced_motion` continue to work.
- Status-line commands (`status.command`) are split without a shell, run with a two-second timeout and a default-deny environment, and accept plain text or version-2 JSON rows (see [status-line.md](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/formats/status-line.md)).
- Theme selection now follows the active Hermes skin (`/skin` and `/theme`), with local `theme.mode` (`auto`, `dark`, `light`) and `ui.reduced_motion` settings in `~/.talaria/config.toml`.
- Step-by-step upgrade and coexistence instructions are in the [migration guide](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/migrating-from-0.6.5.md).

## Install

Install prebuilt binaries with Homebrew on macOS and Linux, download a verified release archive (`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`) with `SHA256SUMS` and GitHub artifact attestation, or build from source. Full instructions are in [Installing Talaria](https://github.com/infiquetra/talaria/blob/v0.7.0/docs/install.md).

```bash
brew install infiquetra/talaria/talaria
```

To build from source, install the Rust toolchain named in `rust-toolchain.toml` (rustup reads it automatically), then run:

```bash
git clone --branch v0.7.0 https://github.com/infiquetra/talaria
cd talaria
cargo build --release
target/release/talaria --version
```

Nothing is published to crates.io, npm or the Python Package Index under the name `talaria`; a package with that name there is someone else's software.

## Works with Hermes

Talaria 0.7.0 was tested against Hermes v0.22.4. It needs Hermes v0.22.3 or newer. On 2026-11-01 the newest stable Hermes release was v0.22.5; the contract check against it passed.

## Staying on 0.6.5

If you are not moving to 0.7.0 yet, use Hermes's own terminal interface with `hermes --tui --native`. If you keep Talaria 0.6.5 installed, reinstall it with bytecode compilation so it starts faster: `uv tool install --compile-bytecode git+https://github.com/infiquetra/talaria@v0.6.5` (or set `UV_COMPILE_BYTECODE=1`). The migration page has the rest: https://github.com/infiquetra/talaria/blob/v0.7.0/docs/migrating-from-0.6.5.md.

## Known limits

- When a goal finishes on the shared gateway, its outcome is saved, but the completion verdict is not shown on screen ([#463](https://github.com/infiquetra/talaria/issues/463)).
- `/skin <name>` saves the requested skin name without first checking it against the gateway's available skin list or listing the valid skin names ([#466](https://github.com/infiquetra/talaria/issues/466)).
- Voice commands are not yet blocked on a remote gateway connection, where they would act on the gateway machine's microphone and speaker. Use voice only with a local gateway until v0.7.1 ([#476](https://github.com/infiquetra/talaria/issues/476)).
- Interactive human driving and physical audio hardware verification for v0.7.0 were performed on macOS; Linux verification ran via the automated release-candidate and continuous-integration suites.
- Prebuilt macOS release archives are verified by SHA-256 checksums and GitHub build provenance attestations (`gh attestation verify`), not Apple Developer ID notarization.
