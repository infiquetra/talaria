# TRU-ACC: Live proof: Talaria connects with any skin and /clear starts a fresh session

Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

How to use this document: read it for the strings already in the tree, for the empty acceptance file this record fills, and for why the resume command on `fixture` carries a profile flag. The requirements, the scenarios, and the acceptance checks are only in the issue. This page points at them by id.

## What exists today

`docs/acceptance/v0.9.0/truth.md` is absent from this checkout. [#557](https://github.com/infiquetra/talaria/issues/557) (`PROOF-4`) creates it and is on `main` before this issue starts. The first line is `# truth acceptance record`. The header lines [#557](https://github.com/infiquetra/talaria/issues/557) (`PROOF-4`) writes are `Candidate:`, `Hermes:`, `Herdr:`, `OS:`, and `Date:`, each with nothing after the colon. There is no `hc:` header. The preconditions copy the release binary to `/tmp/talaria-<short>/talaria` and start it in the `run` folder beside that binary. The record shows that path as typed. The `talaria` found on `PATH` is not used. `Hermes:` comes from that binary's `doctor --profile fixture`, with no `--model`, no `--provider`, no `--restart`, and no `--yes`. Do not follow a line that says to run `hermes update`. The table columns are `id`, `persona`, `result`, `evidence`, `commit`. REQ-1 keeps that title and those columns, and fills the rows. The v0.7.0 record with the same columns is `docs/acceptance/v0.7.0/phase-1.md`.

`docs/themes.md` under `## Known limit` says an unquoted `#` in a skin file is read by YAML as a comment, so Hermes sends that colour as `null`. [#559](https://github.com/infiquetra/talaria/issues/559) (`TRU-1`) is what lets launch continue, and its operator setup is `skins/nullcolour.yaml` with `display.skin` set to `nullcolour`. [#559](https://github.com/infiquetra/talaria/issues/559) (`TRU-1`) also says the handshake does not list the dropped key under `Ignored skin values`. This issue does not edit `docs/themes.md`.

A failed ready frame is the sentence `the gateway sent a gateway.ready frame Talaria could not use.` (`crates/hermes-client/src/connect.rs:288-289`). A failed describe is `the gateway sent a runtime.describe reply Talaria could not use.` (`connect.rs:298-299`). `LaunchFailure::render` (`crates/talaria-app/src/failure.rs:20-22`) prints those as `talaria: <what>`. REQ-3 treats either sentence as a failed connect.

The empty composer placeholder begins `Type a message.` (`crates/talaria-tui/src/composer/mod.rs:943-944`). REQ-3 uses that as the sign that the seat is up.

`notice_lines` (`crates/talaria-app/src/app.rs:2345-2346`) prefixes each notice line with a middle dot and a space. The success sentence and the turn refusal both go through it. A search for the sentence still matches. The success sentence REQ-4 searches for is the notice the issue quotes. The resume command inside it follows the profile rule in `exit_hint` (`crates/talaria-app/src/launch.rs:213-217`): add ` --profile <name>` when the profile is not `default`. Profile `fixture` therefore ends that command with ` --profile fixture`. `exit_hint` itself prints `Resume this session with:`, which REQ-4 does not search for.

A command Hermes still owns is refused as `/{name} is not available on the shared Hermes gateway.` (`crates/talaria-core/src/commands/outcome.rs:221`). REQ-4 fails the row when that sentence is present. The turn refusal REQ-5 searches for is `Finish or interrupt the current turn before /clear.`, which [#561](https://github.com/infiquetra/talaria/issues/561) (`TRU-3`) prints and which does not detach or create a session. The screen has no fixed sentence for a running turn. REQ-5 reads `hc get <hc-address> --json`. `status.state` is `working` while the turn runs. That reported state is provided by [#535](https://github.com/infiquetra/talaria/issues/535) (`SEAT-3`), shipped in Talaria v0.8.1, and is on `main` before this issue starts. The tester sends `/clear` only after reading `working`, and reads the state once more straight after.

`cargo test -p talaria-cli --test docs` is the documentation suite [#564](https://github.com/infiquetra/talaria/issues/564) (`TRU-6`) names. REQ-6 pastes that command and a `test result: ok` line. It does not launch Talaria, does not start a turn, and does not use the gateway. A gateway that is already running is left alone.

`case_proof_gates_and_acceptance` in `tools/release/tests/rc.test.sh` is what [#557](https://github.com/infiquetra/talaria/issues/557) (`PROOF-4`) adds. It checks the title, the column header, and the absence of `v0.22.4`. It does not look for `PASS`. REQ-1 records `PASS`, and that cell does not fail the test.
