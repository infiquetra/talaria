## Launch and the two commands

`crates/talaria-cli/Cargo.toml` names the bin `talaria`. The agent builds once. `CARGO_TARGET_DIR` is only the prefix on that cargo line. The binary is copied to `/tmp/talaria-<commit>/talaria`, and every terminal types that path. `<commit>` is `git rev-parse --short HEAD`. Worktrees share one `target` folder, so the build uses that private directory and does not use the shared folder. A bare `talaria` resolves through `PATH` and can be an older install. Live processes start in `/tmp/talaria-<commit>/run`.

`/tmp/talaria-<commit>/talaria doctor --profile fixture` is `crates/talaria-cli/src/doctor_cmd.rs:20` and `:66`. It does not take `--restart` for this row. `CheckId::HermesVersion` is the variant at `crates/talaria-core/src/doctor.rs:28`. `version_check` builds the row at lines 378-447, and the summary uses `code_version` at line 387. `check_name` maps that variant to `Hermes version` at line 880. `render_text` prints the summary at lines 907-911 and prints a detail only when it starts with `also:` (lines 918-921), so the `running:` detail is not printed. The issue copies the reported version from the summary, not `crates/hermes-contract/PINNED`. There is no `crates/talaria-cli/src/doctor.rs`. `MIN_HERMES` is `(0, 22, 3)` at `crates/talaria-core/src/doctor.rs:8`, and line 213 returns `TooOld` only when the running version is below it. This record's floor is `OLDEST_SUPPORTED` `(0, 23, 0)` from [#554](https://github.com/infiquetra/talaria/issues/554) (`PROOF-1`). `MIN_HERMES` is not this floor. A gateway at or above the floor is expected, and its reported version is the `Hermes:` line.

`crates/talaria-cli/src/args.rs:45` is `--model`, `:47` is `--provider`, `:51` is `--profile` with default `default`, `:65` is `--bg`, and `:73` is the positional `PROMPT`. The `--bg` help text says the prompt is an argument or standard input. REQ-2 uses the argument, and the words are the prompt the operator names. The guide's first session (`docs/guide.md:37-39`) shows `talaria` with no flags. `/fleet` is the local command at `crates/talaria-core/src/commands/local.rs:509-515`, action `LocalAction::Fleet`. `crates/talaria-app/src/app.rs:5916-5918` calls `open_fleet_view`. The guide names the command at `docs/guide.md:65`.

The fleet peek binding stored in code is `space` (`crates/talaria-tui/src/keys.rs:1783`). The answer binding is `a` (`keys.rs:1786`). `docs/keybindings.md:177` and `:180` print those letters in upper case. There is no default key for opening the fleet view (`keys.rs:1774` is an empty list). Enter is open (`keys.rs:1781`), not peek.

`/copy` is not in this tree. [#571](https://github.com/infiquetra/talaria/issues/571) (`ACT-3`) adds it and is on `main` before this issue starts. A slash command that did reach the gateway can show `Hermes refused /{name}: it is not a command this gateway runs.` (`crates/talaria-core/src/commands/outcome.rs:198`), `Hermes does not know /{name}.` (`outcome.rs:209` in that file), `/{name} is not available on the shared Hermes gateway.` (`outcome.rs:221`), or `/{name} was refused:` (`outcome.rs:252`). `crates/talaria-app/src/bg/outcome.rs` is a different file and has none of those lines. REQ-3 names the four phrases for `/copy`. The command is local, so the read has none of them.

The clipboard writer that already exists is `InlineTerminal::copy_to_clipboard` (`crates/talaria-tui/src/terminal.rs:724-727`). It writes `osc52` (`crates/talaria-tui/src/providers/clipboard.rs:3-8`), which begins with escape, `]52;c;`. The issue's paste is the operator reading that clipboard outside Talaria. The UAT-1 paste is taken before any later `/copy`, because a second write replaces the clipboard. The issue does not assert that a Herdr pane passes the sequence through. UAT-4 passes when each paste's character count equals the count in `Copy requested: reply <N>, <count> characters.` and the first line pasted is the first line of the reply on screen. [#571](https://github.com/infiquetra/talaria/issues/571) (`ACT-3`) REQ-5 applies `strip_terminal_escapes` and the app counts `chars()`. That source is not on screen. A paste that fails either check is `FAIL`.

`hc send <id> "text"` pastes and presses Enter. `hc wait <id>` waits until that terminal stops working. An idle terminal counts as stopped, so a bare wait returns at once. `hc read <id>` prints its screen and history, including earlier notices. `herdr-app --version` prints the Herdr app. `hc --version` prints herdr core. They are different programs. The UAT-1 hc terminal is started with `--cwd /tmp/talaria-<commit>/run`. `hc --version` is evidence on the UAT-1 row, not a header line. `<id>` is positional. With no identifier, `hc read` prints the caller and `hc wait` waits on the caller. UAT-1 passes the identifier the operator named for that seat. The UAT-4 paste from that seat happens after the successful `/copy` read and before `/copy 9`. The operator starts three seats: that hc terminal, the operator's own terminal outside Herdr, and a second Herdr terminal for UAT-3.

## The card the rows read

The shared approval hint is still built at `crates/talaria-tui/src/prompts/stack.rs:607-609`: `1-{} choose · Enter confirm · Esc deny · Tab note · Ctrl+C deny and stop`. `add` (`stack.rs:696-702`) runs that hint through `wrap_lines`. A terminal under 80 columns can split the suffix onto the next row. The issue requires 80 columns so the whole clause is on the last line.

[#569](https://github.com/infiquetra/talaria/issues/569) (`ACT-1`) rewrites the painted fleet card before this issue starts. List focus with the card visible ends in `ctrl+c close`. Answer focus ends in `ctrl+c back to list`. This proof reads the screen. It does not edit `crates/talaria-tui/src/fleet_view/peek.rs`. `card_hint` is at `peek.rs:65`.

Space opens a peek and leaves focus on the list. `open_peek` (`crates/talaria-core/src/fleet_view/state.rs:577-586`) sets `PeekStatus::Opening` and emits `OpenPeek`. List-focus Ctrl+C calls `close_all` (`state.rs:910`, function at `:980-986`), which closes the peek and the fleet view. `a` calls `answer_start` (`state.rs:1247`). On a background Hermes row with an open prompt it sets `Focus::Answer` (`state.rs:1273-1274`). On a Herdr backend row it calls `reply_start` instead (`state.rs:1262-1267`). On the foreground row it emits `Close` (`state.rs:1269-1271`). Answer-focus Ctrl+C sets focus back to the list and emits nothing (`state.rs:1279-1281`). The issue's reopen step is how the operator sees that the approval was not denied.
