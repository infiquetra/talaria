# FLW-2: A usage-limit card on a refused turn

Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

How to use this document: read it for the failed-turn notice and the model switch that exist today. The requirements, the tests and the acceptance checks are only in the issue. This page points at them by id.

## What exists today

A `message.complete` with status `error`, and any status string other than `complete`, `interrupted`, and `error`, takes `TurnOutcome::Failed` (`state.rs:30`, `reducer.rs:604`). The notice text is `error`, else `text`, else `failure_reason`. The raw `error_surface` object is stored on `NoticeCell.detail` (`reducer.rs:613-618`, `crates/talaria-core/src/session/cell.rs:170`). A completed turn does not take that arm. `ErrorSurface` at this checkout has no `usage_limit` field (`crates/hermes-contract/src/generated/schemas.rs:7381-7390`). `PIN-3` adds that field. REQ-1 reads the object from the stored detail and does not edit the schema.

`PromptKind` is `Approval` or `Clarify` (`cell.rs:176-180`). The prompt stack's private `Identity` is `Prompt` or `Masked` (`crates/talaria-tui/src/prompts/stack.rs:19-22`) and its `Content` is the same pair (`stack.rs:24-27`). `sync` (`stack.rs:161-207`) rebuilds `cards` from the prompts and masked views it is given and drops any other identity. `PromptIntent` (`crates/talaria-tui/src/prompts/mod.rs:18-33`) is `Approve`, `Clarify`, or `Masked`. `KeyOutcome` (`mod.rs:56`) carries `Option<PromptIntent>`. `run.rs` maps that intent to a `UserAction` near line 1994, and `card_answer` (`run.rs:707`) maps it to a peek answer. `AttentionSnapshot::from` (`crates/talaria-app/src/comforts/mod.rs:26-50`) builds needs only from `open_prompts` and masked requests. REQ-5 does not add a third prompt kind.

`ModelsService` builds the `model` payload at `pick.rs:269-276` (`model`, then `provider` when present, then `reasoning` when an effort is set) and passes it to private `Pick` (`pick.rs:13`). `save` is a field of that struct (`pick.rs:17`, set at `pick.rs:283`), not a payload key. `submit` (`pick.rs:956`) calls `ledger.build(sid, operation, payload, true)` at `pick.rs:977`. The `true` is `with_generation` (`crates/talaria-core/src/mutation.rs:238-243`). `AppEffect::Mutate` (`crates/talaria-app/src/app.rs:2311`) is sent at `app.rs:13029` and comes back as `AppMessage::Mutated`. `mutated` (`app.rs:7954`) settles the ledger and today treats the receipt as a rename. A `message.complete` is recognized at `app.rs:9030`, and `apply_inbound` runs at `app.rs:9047-9049`. `crates/talaria-core/src/models/mod.rs` is a private `mod pick` and re-exports `ModelsState` only (`mod.rs:6`, `mod.rs:14`). `MutationOutcome` (`crates/talaria-core/src/mutation.rs:86`) includes `Committed`, `Refused`, and `FenceRefused` among other variants. `MutationOutcome::Committed` for operation `model` is handled at `pick.rs:1023`. A fence refusal retries the mutate once (`pick.rs:1013-1019`). `/retry` is `LocalAction::Retry` (`crates/talaria-core/src/commands/local.rs:487`) and becomes `RewindInput::Retry { turn_running }` (`crates/talaria-app/src/app.rs:2908`). `turn_running` is computed at `app.rs:2901`. `RewindInput` is public (`crates/talaria-core/src/rewind/state.rs:126`). `SessionState::notice` (`state.rs:362`) is `pub(crate)`. `SessionState::cells` (`state.rs:198`) is public.

`crates/talaria-core/tests/model_pick.rs` drives that service with `session`, `switch`, and `command`. `crates/talaria-core/tests/session_rules.rs` drives the reducer with `ev` (`tests/support/events.rs:61`) and `drive::reduce` (`tests/support/drive.rs:11`). `View` is built only in `app.rs:1296`. `sync_prompts` is `run.rs:1934`. `limit_text` is `crates/talaria-core/src/models/catalog.rs:278`. `complete` in the reducer returns at once when the turn is already `Finished` (`reducer.rs:573-575`), so a second `message.complete` appends no cell. When the interrupt latch is set it appends the interrupted notice, which has no detail (`reducer.rs:576-581`). A new turn starts only from an inbound event: `message.start` calls `begin_turn` (`reducer.rs:362-363`), and a `message.delta` does the same when the turn is `Finished` (`reducer.rs:382`). `begin_turn` (`state.rs:420`) sets `TurnState::Running`.
