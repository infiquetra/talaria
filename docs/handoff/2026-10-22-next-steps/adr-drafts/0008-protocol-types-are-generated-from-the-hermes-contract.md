# ADR-0008 (draft): Protocol types are generated from the contract Hermes publishes

Status: `proposed`
Date: 2026-10-22
Deciders: operator
Affected components: the contract crate (or package), the client, continuous integration
Evidence revision: Hermes Agent `22063fc09`

## Context

ADR-0003 told Talaria to re-encode Hermes's terminal-UI behaviour rather than port its code. The
behaviour half of that decision was right. The protocol half — reading Hermes source and transcribing
method shapes by hand, then probing for them at startup — did not survive contact with a backend that
merges thousands of changes per release. Talaria's baseline is pinned to a revision 36,115 commits old.

Since 2026-09-14 Hermes declares every method, server-to-client request and event as a Pydantic model
and generates `apps/shared/src/gateway-contract.openrpc.json` and a TypeScript type file from them; its
own tests fail when either is stale. Code generation was tried on 2026-10-22: `cargo typify` produced
925 Rust types after a small preprocessing step; Hermes's own TypeScript client files type-check and
run unmodified outside the Hermes repository.

## Decision

1. Talaria pins a Hermes release (the stable channel) and vendors that release's contract file. The
   pin is v0.22.3 or later: v0.22.3 (2026-10-21) is the first stable release with the session
   authority, the control-socket ticket and the canonical `hermes-gateway-v1` methods.
2. Types are generated by a checked-in script. Preprocessing strips `additionalProperties: false`
   (so new fields never break decoding), handles the known schema defaults the generator rejects, and
   namespaces methods by transport (`methods` versus `x-canonical-methods`).
3. Canonical events missing from the contract (`approval.request`, `approval.settled`,
   `clarify.request`, `clarify.settled`, `session.replay_gap`) are hand-typed in one small module that
   cites `apps/shared/src/gateway-events.ts` at the pinned revision, until upstream declares them.
4. A scheduled CI job regenerates against the newest Hermes stable release and fails on breaking
   changes; bumping the pin is an ordinary pull request.
5. Features are gated on `runtime.describe` capabilities, not on probing methods.

## Consequences

- Hermes drift becomes a compile error in continuous integration instead of a bug in the operator's
  terminal.
- The startup compatibility probe and its hand-written baseline are deleted.
- The behaviour rules (reconciliation, interrupt latch, request-id keying) still have to be written by
  hand; they live next to the reducer with tests driven by recorded frames.

## Revisit when

- Hermes publishes a versioned client package or a stability promise for third-party clients.
- The generator cannot keep up with contract churn (repeated new failure classes after preprocessing).
