## 1. What this unit is, in one paragraph

Eleven earlier units built the parts of a Talaria session: finding and joining the Hermes gateway, a typed request channel, reconnect and replay, a recorder, a session state machine, an inline renderer, Markdown, a composer, prompt cards, a status line and a performance harness. None of them can be run alone. This unit is the join: the `talaria` program. It decides what the command line means, opens a session in one of three ways (new, continue, resume), keeps one application event channel, runs the loop that turns keys and gateway events into screen updates and gateway calls, and ends cleanly by detaching. It adds almost no technology. Its value is that the joins are correct: a quit that does not end the session, a `-c` that never opens the wrong folder, a first frame that does not wait for the network, and a terminal that is always restored.

## 3. Command line, exit codes and messages

### 3.1 Grammar

```text
talaria [--profile NAME] [--model NAME] [--provider NAME] [--effort LEVEL]      new session
talaria -c | --continue [--profile NAME]                                        continue
talaria --resume [ID] [--profile NAME]                                          resume (list when ID is absent)
talaria ... [--record PATH] [--no-ensure]                                       allowed with every form above
talaria --bench-replay FIXTURE [--bench-speed V] [--bench-report PATH]           P1-11's entry; needs a terminal, no gateway
talaria --help | --version
```

Use `clap` 4 with derive. `--resume` takes an optional value (`num_args = 0..=1`); an empty or blank value is a usage error (exit 2), not the list. An empty or blank `--model`, `--provider`, `--profile` or `--record` value is a usage error too (exit 2), so it never reaches Hermes as an `invalid_params` refusal. A relative `--record` path is relative to the launch folder. `-c`/`--continue` and `--resume` conflict. `--model`, `--provider` and `--effort` conflict with both. `--effort` values are case sensitive and lower case (`HIGH` is refused), and exactly eight: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra` (H23). `false` and `disabled`, which Hermes also reads as "off", are refused here: one spelling for off. `--help` and `--version` are clap's; `--version` prints `talaria <version>` (the placeholder's `tests/cli.rs` stays and must keep passing).

`--bench-replay` is not parsed by clap in practice: `main.rs` first calls `{{P1-11}}`'s `bench_replay::parse_args` on the raw arguments and, when it returns `Some`, runs `bench_replay::run` and exits with its code, so `--bench-speed` and `--bench-report` keep working exactly as `{{P1-11}}` and its `bench` job use them. The clap struct declares the three bench options (visible, so `--help` lists them) only for the help text; if clap ever sees one, it is a usage error that points to `--help`. Usage errors exit 2 (clap's default). Whatever clap prints is passed through `{{P0-02}}`'s neutralising rule (T9) before it reaches standard error, because clap echoes an unknown argument verbatim. `{{P0-02}}`'s placeholder `respond` and its three `main.rs` unit tests are deleted by the test author in the first commit, with that reason in the message; `tests/cli.rs` and `tests/repository.rs` stay.

| Code | Meaning |
|---|---|
| 0 | Normal quit; `--resume` list cancelled or empty |
| 1 | also: a quit that follows `SessionGone` or a `Failed` link (a runtime failure the screen already showed; REQ-18, 6.11) |
| 1 | Start-up or runtime failure (no gateway, unknown profile, nothing to continue, unknown id, a refusal) |

The failure format is `talaria: <what>` then `Next step: <next>`, both on standard error, nothing else. Texts are plain English, start with a lower-case letter after `talaria: ` (unless the first word is a proper noun such as Hermes) and end with a full stop. Tests assert these exactly.

| Situation | what | next step |

## 5. Request and result shapes

All requests are JSON-RPC 2.0 over the WebSocket: `{"jsonrpc":"2.0","id":<n>,"method":"<name>","params":{...}}`. `<n>` comes from `{{P1-02}}`. Examples use placeholders; real ids are opaque strings.

### 5.1 Create

```json
{"method":"session.create","params":{"request_id":"3f9c...32 hex...","source":"tui","cwd":"<absolute launch folder>","model":"minimax-m3.1-flash","provider":"ollama-cloud","reasoning":"high"}}
```

`model`, `provider` and `reasoning` appear only when the matching flag was given. Result: a `CanonicalSnapshot`, for example (fields abbreviated; take a real one from `fixtures/frames/`):

### 5.2 Resume

## 6. Behaviour step by step

### 6.1 Start-up sequence

```text
parse args ──► usage error? ─► exit 2
   │   (also before any terminal work: resolve and canonicalise the launch folder, failure = 3.3 row, exit 1;
   │    --record: the path must not exist and its folder must, else 3.3 row, exit 1, nothing drawn)
   ▼
   ▼
stdin and stdout are terminals? ──no──► exit 2 (REQ-3)
   │
   ▼
bench_replay? ──yes──► hand over to P1-11's entry (needs a terminal, no gateway; main.rs asks P1-11's parse_args first)
   │
   ▼
TerminalGuard::acquire + startup probe (P1-06) ──► first frame (composer + "Connecting to Hermes")   [t1]
   │                                     key reader and app loop start; typing is accepted
   ▼                                     background task A (all slow work below)
A1  --resume with no id first runs the list of 6.5 (it connects and prints before any frame is drawn: the one
    exception to "no network before the first frame"); this diagram then applies to the id the user chose
A2  home = default_home(); folder = canonical cwd
A3  ConnectionService::open: discover_with (ensure once unless --no-ensure) -> resolve_profile
    -> Link::start (ticket, WebSocket, handshake) -> runtime.describe
A4  for -c and for --resume ID: git toplevel (5 s limit), started at the same time as A3 and not after it,
    so the result is ready when the session reply arrives (a late answer waits for the rest of its 5 s) -> workspace_key
A5  plan(): checks flags against describe -> SessionRequest
A6  SessionService::open -> create or resume -> OpenedSession
A7  Link::track(session_id, cursor); send AppMessage::Opened
A8  loop: held prompts sent in order; resume history committed (6.6)
failure in A* ──► restore terminal ──► print LaunchFailure ──► exit code
```

"Launch" in the budgets means the moment the test harness spawns the process (not entry to `main`). The first frame (`t1`) must not depend on anything in task A. The 100 ms first frame is measured by `{{P1-11}}`'s `bench` job on the replay path (no gateway); the 200 ms usable composer with the gateway running is measured by live test 44 of this unit (15 launches of the release binary, median at most 200 ms), because `{{P1-11}}` cannot measure it and prints that row as SKIPPED. Test 37 only proves the ordering (first frame before any network or `git` call) and records the time against a loose 500 ms bound. Do the terminal probe (P1-06) and drawing on the main task and spawn A immediately after. The reference slice did this in the reverse order, which is why its first frame waited for the attach.

### 6.2 New session

1. `plan` builds `NewSession`: `request_id` = `new_request_id()` (32 lower-case hex from `getrandom`), made once per launch by the caller and passed in; `source` = `tui` if the descriptor lists it, else `UsageError::NoSessionSource` (no fallback to `cli`: a session stored as `cli` would never be found by `-c`, which asks for `tui`); `cwd` = launch folder; `reasoning` = `parse_effort(--effort)`.
2. Reject an option key the descriptor's `parameters` lacks: `model`, `provider`, `reasoning` when given (`OptionNotOffered`), and `cwd` always (`CwdNotOffered`). Only option keys are checked: `source` and `request_id` are not, as in Hermes's own client (H29). Texts: section 3.3.
3. Call `session.create` with the default call timeout of `{{P1-02}}` (120 seconds). On `CallError::Unknown`, wait for the link to reconnect (the link reports `State(Connected)`), then call once more with the same `NewSession` (same `request_id`, an identical parameter set, which H6 accepts). A second `Unknown` fails the launch with the `Create reply lost twice` text of 3.3, which says Hermes may have created an empty session. That orphan row is accepted: `-c` ignores launch stubs (H9) and the live tests use `fixture`.

Timeouts of the other calls: `session.resume`, `session.list`, `prompt.submit` and `session.interrupt` use the same default; `session.detach` uses 2 seconds. This unit sets no limit on the approval deny of 6.9.
4. On success build `OpenedSession` and call `Link::track`.

### 6.3 Continue (`-c`)

1. Compute the workspace key in task A: `find_git_toplevel(folder)` (spawn `git rev-parse --show-toplevel` with the folder as working directory, kill after 5 seconds, trim, require an absolute path) then `workspace_key`.
2. Call `session.resume {latest:"tui", workspace, display_projection:true}`.
3. `not_found` -> failure `-c` text.
4. Otherwise `belongs(info.cwd, workspace)`:
   - `Yes`: continue.
   - `Unknown` (no `info.cwd`): fail closed, exactly like `No` but with the `-c`, folder unknown text of 3.3 (the user is not told "no session", because one exists). The folder cannot be checked, and decision 3 says a session must never open silently in another folder.
   - `No`: call `session.detach` for the returned `session_id` and `subscription_id` (no `end_reason`), `Link::untrack` if tracked, then fail with the `-c` text. Do not print the other session's folder or id.
5. `belongs` canonicalises both sides when the paths exist (falling back to the text), then tests `session_cwd == workspace` or `session_cwd.starts_with(workspace)` by path components, so `/a/proj2` is not inside `/a/proj`. The workspace is the git top level (or the folder), so a session created in a subfolder of the same repository is inside. A different worktree of the same repository has a different top level and is outside, which matches how Hermes keys workspaces (H10).

Side effects to know (H28, H15): attaching to the other folder's session (step 2, cases `No` and `Unknown`) re-reads that session's config-derived settings, refreshes its profile hooks, starts its notice task and cancels a stored pending close. A session its last viewer closed on purpose was already ended, so the last is harmless. The others change nothing the user sees; they are accepted and listed so nobody is surprised.

An ended session opens as a read-only mount until its first admitted prompt reopens it (H28). Talaria shows it like any other session and allows the prompt; Hermes reopens it then. This unit adds no special state.

Difference from Hermes's own `-c` (H29): it first tries a terminal breadcrumb, the session this terminal used last. Talaria does not, on purpose: the promise is "the most recent session of this folder". Live test 40 also checks the workspace string: the folder is canonical on both sides (U9).

If no earlier session exists, or the found one is for another folder, the user sees the same `-c` text; only the unknown-folder case differs.

### 6.4 Resume by id

1. Trim the id; empty is a usage error.
2. Call `session.resume {session_id, display_projection:true}`.
3. `not_found` -> failure with the profile name. Other reasons -> section 3.3.
4. `belongs(info.cwd, workspace_key(launch.folder, git))` is evaluated with the git result of step A4, which runs for `--resume ID` as well as for `-c`, concurrently with the connection, so it adds no wait of its own. The rule is the workspace key everywhere (the git top level when the folder is in a repository, else the folder), the same as `-c`: a session made in a sibling subfolder of the same repository is inside and gets no notice. `No` -> carry on and queue the "works in another folder" notice cell (test 18). `Unknown` -> carry on without a notice: the user named the id on purpose.

### 6.5 Resume with no id: the list

This is the one path that talks to the gateway before drawing anything, because it needs a plain prompt on the normal screen.

1. Connect as in 6.1 (A2, A3) without drawing a frame.
2. Call `session.list` twice (`live` then `stored`, 20 rows each; if the `stored` call fails or is refused, use the `live` rows only).
3. Merge by `session_id`; when a session is in both scopes the `live` row wins (its `running` and `title` are current); sort by `started_at` descending (missing sorts last); keep 20.
4. Print to standard output one line per row: `{n:>3}  {title or "(untitled)"}  {age}  {model or "-"}  {message_count} messages{"  working" if running}  {id}`. Title and model go through `history::sanitize` of `{{P1-06}}`. `age` is a coarse phrase from `started_at` (seconds since the epoch, a float): under 60 seconds or a future value `just now`, under an hour `<n>m ago`, under a day `<n>h ago`, else `<n>d ago`; a missing `started_at` shows `-`. If the `live` call fails, the launch fails with that call's text; if only the `stored` call fails or is refused, use the live rows.
5. Print `Number or id (Enter to cancel): `, flush, read one line from standard input (the terminal is still in normal mode). The reading and printing are `picker::pick` in `talaria-cli`; the rest is pure (`merge_rows`, `format_rows`, `parse_choice`).
6. A line of digits is a row number: in range (1 to the row count) it picks that row's `session_id`; out of range (0 or too large) prints `No row <n>. Enter a number from 1 to <rows>, an id, or press Enter to cancel.` and asks again, with no limit (Enter or Ctrl+C leaves). Any other text is an id. An empty line prints `Cancelled.` and exits 0; an empty merged list prints `No sessions found for profile <name>.` and exits 0.
7. Output streams: the rows, the prompt, the out-of-range hint, `Cancelled.` and `No sessions found ...` go to standard output; a launch failure goes to standard error as usual. The normal start-up then runs with `Resume(Some(id))`. Reuse the open connection: move the `OpenConnection` (it owns the `Link`; nothing is dialled twice). Only if the merged `Link` cannot be handed on, close it and connect again with `EnsurePolicy::Never`, so `ensure` still runs at most once per launch (REQ-6, test 34), and say so in the pull request. The second connection costs about 40 ms on a warm gateway (identify 1 to 3 ms, ticket about 1 ms, upgrade 17 to 20 ms, ready about 5 ms, describe 5 to 9 ms, from `03-hermes-today.md` section 2), acceptable for a rare path.

### 6.6 Showing an opened session

After the first frame and once `Opened` arrives:

1. If the cell list has final cells: commit the separator line, then, if more than 50 final cells exist, the marker `(<n> earlier messages not shown)` where `n` is the number of final cells not shown (a tool call or a notice counts as one, so the word "messages" is a plain-language label, not a message count), then the last 50 final cells. For a new session with no cells commit nothing.
2. Separator text: `── Resumed: <title or "untitled session"> ──`. Title: the snapshot's `info.title` when present, else the session list row's title when the session came from the `--resume` list, else the first user cell's first line truncated to 60 characters, else `untitled session`. Cut at 60 characters with no ellipsis, then pass it through `sanitize`. The order of the commits is: separator, marker (when more than 50 final cells exist), the last 50 cells (test 21).
3. Call `ledger.take_ready(state.cells())` once on the snapshot's cells so the ledger counts all of them as handed out, but pass only the last 50 final cells to `InlineTerminal::commit`; the normal commit path then never prints the earlier ones again. (The ledger has no way to set a count.)
4. If the snapshot's `prompts` hold open approvals or questions, `{{P1-05}}`'s `open_prompts()` yields them and `{{P1-09}}` draws the cards. `pending` (queued admissions) is ignored (H30).

Why 50: the terminal's own scrollback may still hold the earlier run, a full replay of a 2,000 message session would break the 100 ms and memory budgets, and the pager of `{{P2-02}}` will show everything. The constant lives in one place so the operator can change it.

### 6.7 Event gate and tracking

`accept_event(cursor, replay_epoch, seq)` returns false only when the event's `replay_epoch` equals `cursor.replay_epoch` and `seq <= cursor.last_sequence`. Events without `seq` or `replay_epoch` pass. Apply it to every `LinkEvent::Inbound` of the session before the reducer, for as long as the session lives (it is cheap, and after `Link::track` the link applies the same rule, so the second check never fires in normal running). The gate matters in the window between receiving the snapshot and calling `Link::track`.

### 6.8 Sending a prompt

1. Composer `Submit(t)`. A line that is empty or only whitespace does nothing (REQ-14 says "non-blank": the same rule). The text is sent as typed, never trimmed. The slash check uses the first character of the raw line: if it is `/` and the second character is a letter, then `t.trim_end() == "/quit"` quits (so `/quit ` quits) and any other slash line shows the notice; ` /help` (leading space) is not a slash line and is sent as typed. Otherwise continue.
2. No `OpenedSession` yet -> push to `held` (cap `MAX_HELD_PROMPTS`; refuse the 11th with the notice and leave the text in the composer).
3. Otherwise `update(state, Event::Submit { text, submission_id })` with `submission_id = format!("talaria-{launch_id}-{n}")`, `n` starting at 1 and incremented per prompt (held prompts take their number when sent, in order). `launch_id` is 16 hex characters from `getrandom` made once per launch.
4. Execute `Effect::SendPrompt` with `prompt.submit` (section 5.3). Enter works while a turn runs: Hermes queues the prompt (test 28). `Rpc` error: feed `Event::SubmitFailed { submission_id, reason }` to `update` (the reducer drops the waiting user cell and adds the error notice) and show `Hermes refused the prompt (<reason>).`, with the second sentence for `permission_denied` (3.3). Three cases, three notices, never merged (3.3): an `Rpc` error gives `Hermes refused the prompt (<reason>).`; `CallError::Unknown` gives the unknown-outcome text; a `{voice_stopped: true}` reply gives the voice-stop text. Each feeds `Event::SubmitFailed { submission_id, reason }` with a short plain `reason` (`refused`, `connection dropped`, `voice stop`) for the reducer's own line; no resend. Send `prompt.submit` with `Client::call_raw` and read the reply as a JSON value: if it is an object whose `voice_stopped` is `true`, that is the third case; otherwise ignore the receipt beyond logging its `status`. The typed `AdmissionStatus` decode would refuse the voice-stop reply (H32), which is why this call is loose. If `call_raw` is not available in the merged `{{P1-02}}`, stop and report.

When `Opened` arrives, drain `held` through the same path before accepting new Enters, so order is preserved.

### 6.9 Interrupt

Keys, from `{{P1-08}}` REQ-9 and `{{P1-09}}` REQ-3 and REQ-15 (this unit adds none): with no card focused, Esc interrupts a running turn and keeps the draft; Ctrl+C clears a draft, else interrupts a running turn, else arms exit. With an approval card focused (and the draft empty), Esc denies the card and Enter sends the highlighted choice, which starts on `once`; Ctrl+C returns `interrupt_requested`, which this unit turns into `Event::Interrupt`. So UAT-6 denies with Esc and approves with Enter, UAT-7 and test 45 interrupt with Esc on a plain turn, and test 43 interrupts with Ctrl+C on an open card.

Where the generation comes from: this unit keeps none. `{{P1-05}}`'s reducer records `execution_generation` from each `message.start` and from the snapshot, and its `Effect::Interrupt` carries it; the effect is never built without one (a reducer with no known generation emits nothing). This unit sends the value as given. Hermes refuses a different value with `stale_generation` (H31). Then (and for any other refusal or `Unknown`) feed `Event::InterruptFailed`, which clears the latch, and show the `session.interrupt refused` notice of 3.3; the next press uses the reducer's current value. Whether the live number advances at each turn start is U10.

One interrupt sequence runs at a time: while a deny or an interrupt is in flight, further `Effect::Interrupt` values are dropped and the key reader keeps running (the screen stays live, and typed keys reach the composer). Repeated presses therefore send no second deny or interrupt.

`Effect::Interrupt { session_id, execution_generation }` from `{{P1-05}}`. Before executing: if `open_prompts()` has an open approval, call `{{P1-09}}`'s `deny_before_interrupt` (it sends `approval.respond` with the choice `deny` and echoes `session_id`, `prompt_id`, `execution_generation`). Await it with no timer of this unit's own: `{{P1-09}}` REQ-14 bounds the call at 2 seconds in its own code (it returns when every reply or failure has arrived, or after 2 s), and a deny that did not settle only produces its own notice. The architecture's 300 seconds is how long Hermes lets a person answer an approval; it is not this wait. If the merged `{{P1-09}}` has no bound, still add none here: report it on `{{P1-09}}`. If the deny fails or times out, send `session.interrupt` anyway: the user asked to stop, and at v0.22.4 the interrupt also ends the wait (H27). On a failed interrupt feed `Event::InterruptFailed` to `update`. If `{{P1-09}}` offers no such call, that is a stop condition.

Why deny first when the interrupt would end the wait anyway (H27): the handoff's notes record that Hermes waited out the approval's timeout in an earlier revision, and an explicit deny settles the card as the user's choice and not as a withdrawn prompt. Open clarification questions need no step of their own, because the interrupt withdraws the question (H27). Live test 43 records, with a card open, whether the turn ends within 10 seconds of the Ctrl+C and in which order the frames went; that is an observation, not an assertion.

### 6.10 Gap recovery

On `LinkEvent::Gap(gap)`:

1. `session.resume {session_id: gap.session_id, display_projection:true}` (a `not_found` reason becomes the session-gone notice).
2. Build `new = SessionState::from_snapshot(snapshot)`.
3. Let `shown` = the cells already committed (count `c` and their identities, kept in `AppState`). If `new.cells()[..c]` is equal to those cells (compare with the cells' `PartialEq`), commit the final ones of `new.cells()[c..]` through `ledger.take_ready` after one `take_ready` call over the first `c` cells has marked them. Otherwise call `ledger.reset()`, commit `── Transcript refreshed ──` and the last 50 final cells (a `take_ready` over all cells, committing only the last 50).
4. Replace the stored state, keep the new `subscription_id`, call `Link::resync(session_id, Cursor { replay_epoch: snapshot.replay_epoch, last_sequence: snapshot.last_sequence })`.
5. Show the `Reconnected. The transcript was refreshed.` notice.

Live (non-final) cells at the time of the gap are discarded and replaced by the snapshot's; do not try to merge them.

### 6.11 Quit

```text
quit requested (/quit, composer exit request, end of input)
  1  stop the key reader; set quitting
  2  Link::untrack(session_id)
  3  session.detach {session_id, subscription_id}   timeout 2 s; no end_reason
  4  Link::close
  5  InlineTerminal::restore / TerminalGuard drop
  6  print hint (stdout) and unsent held prompts (stderr)
  7  exit 0
```

If steps 2 to 4 fail or time out, continue to step 5: the user must get the terminal back. The hint is printed only when the session has at least one user message (a user cell: the word "prompt" in this document means a user message, and open approval and question cards are called cards), from an earlier run or sent now; a session that was only opened and left is not worth resuming and `-c` ignores empty launch stubs (H9). After a `SessionGone` or a `Failed` link, skip steps 2 and 3 and exit 1 (3.2). After `SessionGone` print no hint: the gateway says the session no longer exists, so resuming it would only fail. After a `Failed` link the session is still on the gateway: print the hint under the usual condition.

**Quit before the session exists** (while `session.create` or a resume is in flight, test 25): stop reading keys, wait up to 5 seconds for the reply, and if it arrives call `session.detach` for it and close the link. Print no hint (no prompt was sent, because held prompts are never sent after a quit). If nothing arrives in 5 seconds close the link and restore the terminal; an empty session row may remain, and `-c` ignores it. Held prompts are printed as below.

Hint text, exactly (profile `default` has no flag):

```text
The agent is still working on it in the background.      <- only when a turn was running at quit
Resume this session with:
  talaria --resume <session_id> --profile fixture
```

Use `stored_session_id` from the snapshot as `<session_id>` in the hint (it equals `session_id` for local sessions in the contract's shape); `session_id` is what `session.detach` carries. Never abbreviate it.

Unsent held prompts go to standard error after the hint, in this form (plural: `<n> typed prompts were never sent:`; one: `1 typed prompt was never sent:`), then each prompt on its own line, indented two spaces, passed through `sanitize` and cut at 80 characters.

### 6.12 Signals

Install handlers for `SIGTERM` and `SIGHUP` (tokio's `signal` module). On either: set quitting, skip steps 2 to 3 (the process may be about to lose its terminal), close the link, restore the terminal, exit 143 or 129. `SIGINT` in raw mode arrives as a key event and is handled by the composer (`{{P1-08}}`); outside raw mode (during a `--resume` list prompt) it ends the process by the signal (the shell reports 130) and nothing needs restoring (listed in 3.2). A panic restores the terminal through `{{P1-06}}`'s guard and its own test (its test 9); this unit adds no panic test and says so. Test 39 measures "raw mode off" by reading the pseudo-terminal's terminal flags after exit (`ICANON` and `ECHO` set again, through `portable-pty`'s `get_termios` where the pinned version offers it, else by running `stty -a` in the same pseudo-terminal), together with the `vt100` screen being free of leftover composer rows.

## 9. Design reasoning

**Why `/quit` sends no `end_reason`.** The roadmap says "`/quit` detaches and leaves the session running". H17 shows that an `end_reason` interrupts the session's own background delegations and ends the row. Hermes's terminal UI wants that because it owns the conversation's lifetime. Talaria's promise (requirement R5, the always-running backend: closing Talaria never stops a turn) is the opposite. Cost: the owner never runs its session-end work (memory extraction, plugin finalisation) for sessions Talaria leaves. If the operator wants a deliberate "end this session" command, a later unit sends `end_reason` from that command only. Rejected alternative: send `tui_shutdown` only when the session is idle at quit. It would make the same user action behave differently depending on timing, and an idle session left open costs nothing.

**Why `-c` refuses another folder, and an unknown one.** H8 and H11 show the fallback is deliberate in Hermes (a fresh directory should still continue the last session). For a coding agent that is dangerous because the session's `cwd` is fixed at creation (H14), so the next prompt would act in the old folder. The roadmap's own wording is "the most recent session in this folder". When `info.cwd` is missing the check cannot be made, and a check that can silently switch itself off is not a guard, so the launch fails closed (H14: the field is set only for sessions with a launch policy). Rejected alternatives: ask the user to confirm (a prompt before the screen starts adds a second interactive path to test); continue when the folder is unknown (the very case the guard exists for); copy Hermes (silent wrong-folder edits). Open question for the operator: whether to follow Hermes instead.

**Why check `info.cwd` after the fact rather than before.** The owner resolves `latest`; there is no call that resolves without attaching, and `session.list` rows carry no folder (H22). So Talaria attaches, checks, and detaches on mismatch. The side effect (H15) is minor.

**Why a first frame before the network.** The budget is 100 ms to a first frame and 200 ms to a usable composer. A warm attach alone is about 40 ms but the first connection after the gateway was idle took 771 ms to upgrade (`03-hermes-today.md` section 2), and Hermes's own terminal UI took 3 to 3.7 s to a usable prompt. The user must be able to type while that happens. Held prompts exist for the same reason.

**Why no automatic resend of an unknown submit.** `prompt.submit` outcome unknown means the gateway may have admitted it. The idempotency key probably makes a resend safe (U8) but the roadmap's protocol rules say an unknown outcome is never success, and the bake-off report records no proof. A duplicate agent turn can edit files twice. The notice is cheap.

**Why `source: "tui"` and no fallback.** Hermes's `latest` lookup works by family (H8). A Talaria session stored as `cli` would be found by `hermes -c` in the classic CLI; as `tui` it is found by `hermes --tui -c` (which falls back to the CLI family, H11). `-c` always asks for `tui`, so a session created as `cli` after a fallback would never be found by it and the user would be told "no earlier session" just after creating one. The launch therefore fails when `tui` is not offered. The operator may prefer `cli` for both; that is a one-constant change in two places and an operator question.

**Why no `client_env` and no environment launch flags.** Hermes's own client adds both (H29). Talaria's session behaviour must not depend on the terminal that started it, and the roadmap lists no use for them. Whether Hermes changes anything for a `tui` session without them is not verified (U6); the first live run records the tool list.

**Why 50 cells on resume, 10 held prompts, 20 list rows.** Small named constants chosen to bound cost and memory; each is a single `const`.

**Why this unit adds no timer around the deny.** `{{P1-09}}` owns that wait and, in its REQ-14, bounds it at 2 seconds in its own code, so the screen cannot stay stuck on it; a failed or expired deny never blocks the interrupt. The architecture's rule that approval responses may take up to 300 seconds and that a client timeout must not be shorter is about answering an approval (`approval.respond` keeps `{{P1-02}}`'s 300 second default); a deny that is sent only to be followed by an interrupt is a different case, and the interrupt itself ends the wait (H27). A second timer here would only disagree with `{{P1-09}}`.

**Why not blocking Enter during a turn.** The reference slice blocked it. Hermes queues durably (`prompt.submit` on a busy session), the operator check says typing must not stall, and `{{P2-08}}` adds the queue view. Blocking would hide a Hermes feature; allowing it needs no extra code here.

**Why `talaria-cli` has a `run.rs`.** `main.rs` stays trivial so the process tests exercise real code, and `run.rs` contains only construction and calls.

## 12. Decisions that belong to the operator

1. `-c` strictness: folder-strict and fail closed (this unit) or Hermes's fallback to any folder.
2. Whether a separate command should end a session for good (send an `end_reason`), given that `/quit` never does.
3. The look of `--resume` with no id: a plain numbered list before the screen (this unit) or waiting for the full picker of `{{P2-07}}`.
4. The session source: `tui` only (this unit; the launch fails if it is not offered) or `cli`.
5. The three constants: 50 resume cells, 10 held prompts, 20 list rows.
6. Lines that start with `/` other than `/quit` are refused in this version (this unit) or sent to Hermes as ordinary text.
7. The new `--no-ensure` flag, which the roadmap does not list.
8. The operator preconditions for done: the `fixture` profile with `approvals.mode: manual` (the roadmap says phase 1's approval precondition comes from `{{P1-04}}`; this issue is the more specific reference and treats a missing precondition as "not done", never as a pass).
9. The statistic for the 200 ms budget: the median of 15 launches (this unit) or something stricter, such as no launch above a ceiling.
10. `-c` and Hermes's own terminal UI: both create `tui` family sessions (H33), so `-c` may continue a session started by Hermes's terminal UI in the same folder. This unit accepts that (the folder check still holds); the alternative is a Talaria-only marker, which needs a Hermes change.
11. After `SessionGone` or a `Failed` link, `/quit` exits 1, and prints the hint only after `Failed` (6.11); the alternative is exit 0 in both.
12. The idle-session gap of U2: a detached idle session may appear in neither list scope. UAT-8 therefore lists a session that is still working; what to do about idle ones is the operator's.
