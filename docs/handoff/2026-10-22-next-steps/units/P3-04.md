## 1. What this unit is

A Hermes agent delegates work with its `delegate_task` tool. Each delegated task runs as a child agent ("subagent") inside the same gateway process. Hermes streams the children's lifecycle as `subagent.*` events on the parent session's event stream and offers four methods to list, read, steer and stop them, plus a gateway-wide pause for new spawns. Talaria today ignores all of it: the phase 1 session reducer treats the six event names as known and silent (P1-05 unit specification, ownership table, row "Subagent rows").

This unit adds:

- a pure tree model in `talaria-core` (`talaria_core::subagents`);
- an application hub in `talaria-app` that feeds the tree from events and `subagent.list`, polls the transcript tail, and sends steer, stop and pause;
- a dock above the composer, a full-screen agents panel, and a batch block in scrollback in `talaria-tui`;
- the `/agents` local command, key bindings, `[subagents]` settings, and the status line's subagent counts.

Where it sits in the roadmap: [07-roadmap-and-work-units.md, phase 3](../07-roadmap-and-work-units.md#phase-3--the-fleet-many-agents-in-the-background). The protocol rule it implements: [05-architecture.md, protocol rules](../05-architecture.md#protocol-rules-every-client-layer-must-keep) ("Subagent rows are keyed by the server's `subagent_id`; a terminal state is never overwritten by a late start; late events never create rows"). The screen element it adds: "a subagent batch" cell in [05-architecture.md, the screen](../05-architecture.md#the-screen).

## 5. The tree model

### 5.1 Event application (`apply`)

| Event | Row exists, live | Row exists, terminal | Row absent, not retired | Row retired |
|---|---|---|---|---|
| `spawn_requested` | merge fields; state unchanged (never back to `Queued` from `Running`) | ignore | create `Queued`, `seen_live` | ignore |
| `start` | merge; `Queued` becomes `Running` | ignore | create `Running`, `seen_live` | ignore |
| `progress`, `thinking`, `tool` | merge; add activity; `Queued` becomes `Running` (a child that acts has started); the status word is ignored | ignore | ignore | ignore |
| `complete` | merge; state from status (5.2); add the summary activity; `stop_requested` cleared | ignore | ignore | ignore |

An event whose payload has no `subagent_id` (or an empty one) returns `Applied { changed: false, missing_id: true }`; the hub raises one diagnostic notice per connection generation: `Hermes sent a subagent event without an id; it was ignored.`

Every applied event for an existing row sets `last_event_ms`. After `apply`, the hub calls `expire(now)`.

### 5.2 Status mapping

| Wire `status` | On `complete` | On `spawn_requested`, `start`, `progress`, `thinking`, `tool` | On a list entry (5.5) |
|---|---|---|---|
| `completed` | `Completed` | ignored | unseen id: skipped; existing row: ignored |
| `failed` | `Failed(Failed)` | ignored | as above |
| `error` | `Failed(Error)` | ignored | as above |
| `timeout` | `Failed(Timeout)` | ignored | as above |
| `interrupted` | `Interrupted` | ignored | as above |
| `queued` | `Failed(Failed)` (fail closed) | ignored (the event kind decides, 5.1) | treated as live: unseen id created `Running` |
| `running`, absent, unknown | `Failed(Failed)` (fail closed) | ignored (the event kind decides, 5.1) | treated as live: unseen id created `Running` |

A list entry or a live event never makes a row terminal. At v0.22.4 a list entry is always `running` (H32), so the "skipped" rows are a guard against a future Hermes, not a current case.

### 5.3 Field merge

- Strings and numbers: a present, non-empty payload value replaces; absent or null keeps. `goal`: replaced only by a non-empty string.
- `tool_count`: `max(old, new)`.
- `delegation_id`, `parent_id`, `child_session_id`, `model`, `depth`: once set, a later absent value keeps; a later different value replaces (Hermes never changes them; replacing keeps the tree honest if it does). A `Queued` row created from `spawn_requested` has no `delegation_id` (H33); `start` sets it.
- `files_read`, `files_written`, `toolsets`, token counts, `api_calls`, `duration_seconds`, `summary`: replaced when present.
- `started_at`: from a list entry only (events do not carry it). At creation the row records `first_seen_ms = now.mono_ms` and `first_seen_s = now.wall_s`.
- `last_event_ms`: set on every event for the row.

### 5.4 Activity lines

Built in this order from one payload, each appended unless equal (kind, text, error flag) to the newest line already in the row; at most 24 kept (oldest dropped). "Collapsed" means runs of whitespace (spaces, tabs, `\r`, `\n`) become one space and the result is trimmed; "cut to n" means at most n characters, with `…` as the last character when cut.

1. each `output_tail` item: `Tool` kind, `<tool>("<preview collapsed, cut to 96>")` when the collapsed preview is non-empty, else `<tool>`; `is_error` copied;
2. `tool` event: `Tool` kind, `<tool_name>("<tool_preview or text, collapsed, cut to 96>")`, or `<tool_name>` when both are empty;
3. `progress` event with non-empty collapsed `text`: `Progress` kind, cut to 220;
4. `thinking` event with non-empty collapsed `text`: `Thinking` kind, cut to 220;
5. `complete`: `Summary` kind with `summary` (else `text`, else for `timeout` `Timed out after <duration_seconds>s`), collapsed and cut to 220, `is_error` for failed kinds.

`last activity` (dock and panel) is the newest line's text; for a row with none: `queued` for `Queued`, `starting` for `Running`.

### 5.5 Reconcile with `subagent.list`

An answer without a `subagents` key is a failed list: nothing changes and it is not a miss. Otherwise, for each snapshot (ignore entries with an empty `subagent_id`):

- retired id: skip;
- row absent, status terminal (5.2): skip;
- row absent, status live or absent: create `Running` from the snapshot fields; if `last_tool` is non-empty, seed one `Tool` activity `<last_tool>`; `seen_live` false;
- row terminal: skip;
- row `Queued`: becomes `Running`; merge;
- row `Running`: merge (`accepting_steer` always replaced, including by `null`, which means unknown); seed `last_tool` only when the row has no activity.

Then for each `Running` row not in the snapshot set: increment its miss counter; at 2 it becomes `Gone` (terminal). A row in the snapshot resets its counter to 0. `Queued` rows are never counted (H32: queued children are not listed). A failed list call changes nothing and does not count as a miss. `delegations` is ignored (always `[]` on the gateway socket, H7). After `reconcile`, `hydrated()` is true.

### 5.6 Expiry

`expire(now)`: a `Queued` row whose `last_event_ms` is at least 600,000 ms before `now.mono_ms` is removed from the tree. Its id is not retired, so a later `start` creates the row again (as `Running`), and a later `progress`, `thinking`, `tool` or `complete` for it is ignored as for any absent row. The hub calls `expire` on every poll tick and after every event. At v0.22.4 a queued child starts within seconds (H33), so expiry only cleans up children whose start never came (for example a parent interrupted while children were being built).

### 5.7 Order

`rows_in_order()`: build children lists by `parent_id`; a row whose `parent_id` is absent or names no row is a root. Sort roots and each sibling list by `(start_s, task_index, goal)`, where `start_s` is `started_at` when known, else `first_seen_s` (both are wall-clock seconds since 1970, so rows learnt from a list and rows created by events compare correctly). Walk depth first; keep a visited set so a cycle (Hermes never makes one; a corrupt payload could) ends the walk; rows not reached from any root follow at depth 0 in insertion order. `depth` in `TreeRow` is the walk depth, capped at 8 for drawing.

### 5.8 Batches and pruning

- Batch key: the root row's `delegation_id`, else `"row:" + root id`. All roots with the same `delegation_id` belong to one batch (the children of one `delegate_task` call are siblings at the root, H33); rows join their root's batch through `parent_id` links.
- `take_finished_batches()` returns each batch whose rows are all terminal and of which at least one row has `seen_live`, once (the key is remembered, newest 512). While any live root row has no `delegation_id` (a child still queued, U1), no batch is returned, because that row may belong to any of them; the hold ends when it starts (and gets its id) or expires.
- A batch learnt only from a list after a resume, all terminal, is never returned (it was printed by whoever saw it run, or not at all).
- `prune_finished()` removes every row of each batch whose rows are all terminal and which was returned, or can never be returned because none of its rows has `seen_live` (rows learnt from a list after a resume or a foreground switch, and `Gone` rows of such batches). Each removed id joins the retired set (newest 512 ids kept; the oldest forgotten). It returns `true` when it removed something. Without the second case such rows would stay for the whole session and inflate `counts().terminal`.
- Order for the block: the batch's rows in `rows_in_order` order.

### 5.9 Counts and version

`live` = `Queued` + `Running`; `queued` = `Queued`; `terminal` = all terminal rows present; `failed` = `Failed(_)` + `Gone`; `stopped` = `Interrupted`. `version()` increases by one per call of `apply`, `reconcile`, `mark_stop_requested`, `prune_finished` or `expire` that changed the set of rows, their order, or any row field other than `last_event_ms` (bookkeeping for expiry, never drawn). An identical list or a repeated event leaves it unchanged, so an idle tree draws nothing (test 40). `SubagentHub::on_notification` and `on_message` return `true` exactly when the version rose or a hub-level visible value changed (spawning state, flash text, tail text).

## 6. Application hub

### 6.1 Attach and routing

- `app.rs` attaches the foreground session after its `session.create` or `session.resume` snapshot is applied, with the foreground `Client`. On a foreground switch it detaches the old key (the tree, its `seen_live` flags and its returned-batch keys are dropped) and attaches the new one. Consequence, accepted: on switching back, the rows are relearnt from the list with `seen_live` false, so a batch whose children all started before the switch prints no scrollback block (section 12, row "Foreground switch away and back").
- Owners of other attached sessions (P3-02, P3-03) call `attach` with the session's own client and `detach` when they let go.
- `app.rs` passes every notification of an attached session whose name starts with `subagent.` to `on_notification`, and `message.start` too (prune). It does this before, and independently of, the session reducer, so the reducer's interrupt latch cannot hide them (issue decision 4).
- After P1-03 reports a reconnect for the session's link, and after a replay gap is resolved with `session.resume`, `app.rs` calls `on_reconnected`.
- Batches: after every applied event and every list answer, the hub calls `take_finished_batches()` on that tracker. For the foreground key it sends one commit of `batch_block_lines` per batch through P1-06's `commit_lines` at once; for any other key it drops the batches unprinted (they are still pruned at that session's next `message.start`). The block is committed when the children finish, which can be before the parent's reply has finished streaming; P1-06 puts committed lines above the live region, so the block lands above the still-streaming reply. Nothing waits for `message.complete`.
- Status line (issue REQ-36): `StatusInputs` takes the foreground tree's counts once `hydrated()` is true or listing is disabled on that connection by -32601 (then the tree is fed by events only); before that, `usage.active_subagents` and 0.

### 6.2 Listing

| Trigger | Action |
|---|---|
| attach, `on_reconnected`, panel opened for the key | one `subagent.list {session_id}` now (if none in flight) |
| poll tick | a list call, if (the tree has a live row or the panel shows this key) and failures < 3 and listing is enabled |
| list answered OK | `reconcile`; failures = 0; schedule the next tick in `poll_s` if the condition still holds |
| list failed (timeout, refusal, connection lost, or an answer without a `subagents` key) | failures += 1; tree unchanged; at 3, stop ticking until the next attach, reconnect or panel open (which resets failures) |
| -32601 | listing disabled for this connection generation; one notice `This Hermes does not list subagents; showing events only.` |
| reply from an older connection generation | dropped |

At most one list call per tracker is in flight. Timeout 5 s.

### 6.3 Tail

`OpenTail(id)` sends `subagent.tail {session_id, subagent_id}` at once and every `tail_poll_ms` while the tail view is open for that id; `CloseTail` stops it; one call in flight; timeout 5 s. A failure keeps the last text and shows `Live transcript unavailable.` only if no text was ever received. When `truncated` is true the text up to and including the first `\n` is dropped. The text is split into lines, each sanitized (section 7.6).

### 6.4 Controls

- Steer: `text.trim()`; empty: nothing sent, flash `Type an instruction first.`; else `subagent.steer {session_id, subagent_id, text}`, timeout 10 s. `queued` gives `SteerQueued`, `rejected` gives `SteerRejected`.
- Stop: on a `Running` row, `subagent.interrupt {session_id, subagent_id}`, timeout 10 s; `found: true` calls `mark_stop_requested` and gives `StopRequested`; `found: false` gives `AlreadyFinished` (the child most likely ended between the last event and the call). On a `Queued` row nothing is sent and the outcome is `NotStarted` (a queued child is not registered, H22, H32, so Hermes would answer `found: false`). On a terminal row nothing is sent and the outcome is `AlreadyFinished`. On a `Running` row whose `stop_requested` is already set nothing is sent and the outcome is `AlreadyStopping` (one interrupt per child is enough; Hermes's hard interrupt is already pending).
- Stop all: counts `Running` rows only. The first `StopAll` arms a 3,000 ms window and flashes the confirmation; a second within the window (`now.mono_ms - armed <= 3000`) sends one interrupt per `Running` row (up to 10 in flight) and flashes `StopAllSent`; after the window a press arms again. With no `Running` row: flash `No running subagents to stop.` Queued children are not stopped; they start and can then be stopped.
- Pause: when `spawning()` is `On` or `Unknown`, `RequestPause` switches the panel to `ConfirmPause`; `y` sends `delegation.pause {paused: true}`; `n` or Esc sends nothing. When it is `Paused`, `p` sends `Resume` at once. `Resume` sends `{paused: false}` without asking. After either answer, one `delegation.status {}`, and `Spawning` is set from the pause answer even if the status call fails.
- `/agents` forms (issue REQ-35): `Open` calls `open_panel` for the foreground key. `Pause` opens the panel for the foreground key and then acts as `p` does: with `On` or `Unknown` the panel enters `ConfirmPause` (the 6.6 confirmation on the flash line); with `Paused` it stays in List and flashes the `Paused(true)` text, sending nothing. `Resume` sends `{paused: false}` at once without opening the panel; the outcome text prints under the typed command as P2-03's local command output. `Unknown(arg)` prints `unknown_text()` and sends nothing.
- Status: `delegation.status {}` on panel open, after a pause answer, and on poll ticks while the panel is open if 5 s have passed since the last one. Its `paused`, `max_spawn_depth`, `max_concurrent_children` set `Spawning::On(Some(caps))` or `Paused(Some(caps))`; `active.len()` is used only in the pause confirmation. A -32601 answer sets `Spawning::Unknown` (or keeps a known pause state from a pause answer, without caps) and stops status calls on that connection until the panel is opened again; it raises no notice beyond the header text.

### 6.5 Allowed methods

`subagent.list`, `subagent.tail`, `subagent.steer`, `subagent.interrupt`, `delegation.status`, `delegation.pause`. Never a `profile` key, never `session.interrupt`, `spawn_tree.*`, or `unattended`.

  - width under 100: the goal cut to `width - prefix_w - 9`, two spaces, the elapsed text right-aligned in 7;
  - no line has trailing spaces (the last field is never padded).
- Elapsed (`format_elapsed`): terminal rows use `duration_s`; live rows `now.wall_s - started_at` when known, else `(now.mono_ms - first_seen_ms) / 1000`; unknown is empty. Format: `0s` to `59s`, `1m 05s` to `59m 59s`, `1h 02m` and above.
- Selected row reversed. The list scrolls to keep the selection visible.
- Flash line: the line above the footer shows the latest outcome text (6.6) until the next key; the steer box and the pause confirmation also use it.
- Footer: as in the sample; with `X` armed the `X` hint reads `X again to stop all`; when spawning is paused the `p` hint reads `p resume spawns`. Each hint uses `KeyMap::label` of the bound key; an unbound action's hint is left out.
- Empty tree: `No subagents in this session yet. They appear when the agent uses delegate_task.`
- `tab` (`agents_next_session`) moves to the next attached key with a tree that has rows, foreground first; with one key it does nothing.
- Elapsed text redraws once a second only while the panel is open and a row is live (an `ElapsedTick` timer that stops otherwise).

### 7.3 Detail view

Lines, each present field only: `Goal` (wrapped, not cut), `Status` (`running`, `queued`, `completed`, `failed`, `error`, `timed out`, `stopped`, `ended; result not seen`, plus ` (stopping)`), `Id`, `Parent`, `Depth`, `Model`, `Toolsets`, `Started` (`<elapsed> ago`), `Duration`, `Tools` (`<n>`, last `<last_tool>`), `Tokens` (`in <n> · out <n> · reasoning <n>`; a missing count is left out, never written 0), `API calls`, `Files read` (first 10, `… +<n> more`), `Files written` (same), `Summary` (wrapped), `Activity` (the activity lines, newest last), `Steering` (`accepted` / `closed` / `unknown`). Scrolling as the tail view.

### 7.4 Tail view

Header `Live transcript · "<goal>"` plus ` (latest 16 KB; older lines cut)` when truncated. Body: the lines; follows the end until the operator scrolls up (`agents_up`, `agents_page_up`, `agents_top`); `agents_bottom` resumes following. No text yet: `No live transcript yet.`; failures with no text ever: `Live transcript unavailable.`

### 7.5 Steer box and pause confirmation

Steer: the flash line becomes `Steer "<goal>": <draft>` with a reversed caret; printable characters append (up to 4,000 characters), Backspace deletes, Enter sends, Esc cancels. Offered only when `accepting_steer` is not `Some(false)`; otherwise `e` flashes `"<goal>" is no longer accepting steering.` For a terminal row `e` flashes `"<goal>" had already finished.`; for a `Queued` row it flashes the `NotStarted` text, since a queued child cannot be steered (H32). Pause: the flash line shows the 6.6 confirmation; `y` or `n` (case-insensitive) or Esc.

### 7.6 Text safety

Every Hermes string goes through P1-06's `sanitize` (ESC as `␛`, BEL as `␇`, bidirectional overrides as `‹U+202E›`), after `\r`, `\n` and `\t` runs are collapsed to one space for one-line fields. Tail lines keep their line breaks; each line is sanitized; tabs become four spaces. Cutting uses P2-11's `cut_to_width`.

### 7.7 Batch block (scrollback)

```text
⎇ Subagents · 2 finished · 1 failed · 14s
  ✓ list the files in the current directory · 6s · 3 tools · Found 4 files
  ✗ read notes.txt · 8s · 1 tool · failed: notes.txt not found
```

- Header: `⎇ Subagents · <n> finished`, then ` · <f> failed` (failed and gone), ` · <s> stopped`, ` · <longest duration_s>` (left out when no row has one).
- Rows: two spaces plus two per depth level beyond 1, glyph, goal, ` · <duration>` when known, ` · <n> tools` when known, then ` · <summary first line>` for completed, ` · failed: <summary>`, ` · error: <summary>`, ` · timed out: <summary>`, ` · stopped`, ` · ended; result not seen`. Cut to the width.
- At most 20 rows, then `  … +<n> more`. No blank line before or after. Committed with P1-06's `commit_lines` when `take_finished_batches()` returns it; under an overlay the commit is still issued (P1-06 queues it).
- `plain()` style keeps bold and dim, drops colour; used when the app passes `color: false` to P1-07's renderer (the same rule as P2-11).

### 7.8 Style

Running glyph cyan, queued dim, completed green, failed red, interrupted yellow, gone dim; goal bold for the selected row; hints and activity dim.

### 7.9 Keys by panel mode

No other action may hold `alt+s` (P3-06 holds `alt+a`, P2-11 holds Ctrl+T); test 43 asserts it against the merged key map.

## 12. Edge cases

| Case | Behaviour |
|---|---|
| Parent interrupted with Esc while children run | Children's `complete {interrupted}` still land (issue decision 4); if none arrives, the list rule makes them `Gone` after two polls. |
| `/quit` while children run | The tree is dropped with the process; Hermes keeps the children running (P1-12 detaches without `end_reason`). Next launch's resume hydrates them from the list. |
| Resume of a session whose children finished while Talaria was closed | The list does not show finished children; nothing is printed; the batch block never appears for them (5.8). |
| Replay gap | `session.resume` then `on_reconnected` lists; rows missed meanwhile come from the list. |
| Nested children (`max_spawn_depth` > 1) | Tree by `parent_id`; batches by root; stop-all covers every live row, nested included. |
| A child listed but unreachable (H8) | Steer gives `rejected`, stop gives `had already finished`, tail `No live transcript yet.`; the row stays until a terminal event or the absence rule. |
| Managed worker session | Every call refused `unsupported_projection`; the panel shows the 6.6 text once; polling stops after three failures. |
| Two Talaria processes on one session | Each sees the events; a stop from one shows as `interrupted` in both. |
| Event without `subagent_id` | Ignored with one diagnostic per connection. |
| Goal or log with escape sequences or bidirectional overrides | Shown literally (7.6). |
| Terminal narrower than 12 columns | Dock header cut; panel shows glyph and cut goal only; nothing overflows. |
| Gateway restarted while paused | The flag is cleared by Hermes (H13); the next `delegation.status` shows `spawning on`. |
| Pause pressed while `delegation.status` is unknown (U5) | The confirmation omits the running count: `Pause new subagents for every session on this Hermes gateway? Running ones will continue. y/n` |
| Foreground switch away and back while children run | The old tree is dropped (6.1). On return the rows come back from the list with `seen_live` false; when they finish, no scrollback block is printed for that batch (5.8). Accepted: the block is a record of work this view watched; the panel still showed the rows while they ran. |
| `x` on a queued row | Nothing is sent; the flash says it has not started yet (6.4). Stop all skips queued rows; they can be stopped once they start. |
| A queued sibling without `delegation_id` while others finish | No batch is returned until it starts (and gets the id) or expires (5.8), so one block covers the whole call. |
| `subagent.list` answers without `subagents`, or lists a terminal status | Treated as a failed list; a terminal listed entry for an unknown id creates nothing (5.5). Neither happens at v0.22.4 (H2, H32). |
| Gateway paused while no child is live | The dock is hidden, so only the panel header and the `delegate_task` refusal show the pause; a status-line hint is out of scope for this unit. |
| A child event without `subagent_id` at the pin | H20 sends ids "when known"; such an event raises the one diagnostic per connection (5.1) and is otherwise ignored. That is expected, not a defect. |
| An approval request from a child | Not expected in the issue's scenarios (H34). If one appears, the session's approval card handles it as any other (P1-09); the scenario records BLOCKED (environment). |
