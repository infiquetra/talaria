## 1. What this unit is, and what it is not

Hermes agents keep a task list with the `todo_list` tool: a short plan of steps, each pending, in progress, completed or cancelled. Hermes sends the whole list to clients as the `todo.updated` event every time the tool runs. The phase 1 session reducer (unit P1-05) already stores the newest list as raw JSON. This unit turns that raw list into something a developer can read while the agent works, and leaves a record of it in the terminal's own scrollback when the turn ends.

## 2. Design decisions and why

1. **The full snapshot is the only input.** `todo.updated` carries the whole list every time (`gateway/run_turn_progress.py:871-873`, comment "Task state is application data, not tool chrome: the full snapshot"). Talaria replaces, never merges. It does not read `tool.start` arguments, which may hold a partial merge (`tui_gateway/tool_progress.py:302-303`: "args.todos may be a partial merge — tool.complete is the truth"). Hermes Desktop does apply `tool.start` merges optimistically (`apps/desktop/src/lib/todos.ts:187-209`, `apps/desktop/src/store/todos.ts:84-88`); Talaria does not, because a wrong optimistic row is worse than a row that appears a moment later.
2. **One source.** `tool.complete` for a todo tool also carries `todos` and `revision` (`gateway/local_viewer_events.py:224-226`). Reading both would mean two paths that can disagree; P1-05 reads `todo.updated` only, and so does this unit.
3. **Show while the turn runs, record when it ends.** Hermes's own terminal UI keeps the list in a live panel during the turn and, at turn end, archives it into the transcript and clears the panel (`ui-tui/src/app/turnStore.ts:45-63`, called from `ui-tui/src/app/turnController.ts:750-754`). It places the archive under the user's prompt ("Archive prepended so the trail msg anchors under the user prompt"). Talaria cannot reorder committed scrollback, so its block follows the turn's last cell. Hermes Desktop drops a still-active list at turn end (`apps/desktop/src/app/session/hooks/use-message-stream/gateway-event/message-stream.ts:374-378`) and lingers a finished one for four seconds (`apps/desktop/src/store/todos.ts:69-72`). Talaria follows the terminal UI because it is inline-first: finished output belongs in native scrollback (ADR draft 0009), where the terminal's search and copy work, and a timer-driven linger would break the "zero frames when idle" budget.
4. **A list is shown again as a live panel only when it changes.** Once a list has been committed, the next turn does not show it until the agent writes it again (a higher `revision`). This stops an old plan from reappearing above the composer on every prompt. It holds after a resume too, because `attach` remembers the revision it committed. The memory is per process: a new process that resumes an idle session prints the list once as a `Resumed` block (6.2), and from then on the same rule applies.
5. **Ctrl+T toggles the panel**, as in Claude Code (u12 feature `int.task-checklist`, "Task checklist (Ctrl+T)"). Collapsed, the panel is one row that still names the step in progress. Hermes's terminal UI binds Ctrl+T to its subagent overlay (`ui-tui/src/content/hotkeys.ts:33`, `h.expandAgents`; the handoff's 03-hermes-today also mentions it). Talaria gives Ctrl+T to the checklist, so the phase 3 subagent unit P3-04 must pick another default. Record this in the journal (section 13).
6. **Plain ASCII glyphs**: `[x]` completed, `[>]` in progress, `[ ]` pending, `[-]` cancelled. They match Hermes's terminal UI (`ui-tui/src/lib/todo.ts:5-6`), survive copy and paste out of scrollback, and keep their meaning without colour. Hermes's Python tool marks cancelled items `[~]` (`tools/todo_tool.py:22`), but only in the text it re-injects into the model's context after compression; no client draws that text.
7. **No timers.** Nothing in this unit schedules a redraw. The panel changes only when an event, a key or a resize changes it.
8. **Counts include cancelled items in the total**, as both Hermes clients do (`ui-tui/src/components/todoPanel.tsx:55-67` "(done/total)"; `apps/desktop/src/app/chat/composer/status-stack/index.tsx:90-91` with `apps/desktop/src/i18n/en.ts:3530` "Tasks {done}/{total}"). Every header with cancelled items says how many, so the fraction never looks like lost work.

### 4.3 Rules for test data

## 5. Model: `talaria_core::checklist`

```rust
// crates/talaria-core/src/checklist.rs  (pure; no terminal imports)
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum TodoStatus { Pending, InProgress, Completed, Cancelled }
impl TodoStatus {
    pub fn parse(s: &str) -> Option<TodoStatus>;   // exact lower-case words of H12
    pub fn is_active(self) -> bool;                // Pending | InProgress
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TodoItem { pub id: String, pub content: String, pub status: TodoStatus, pub parent: Option<String> }
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct TreeRow { pub index: usize, pub depth: u8 }
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct ChecklistCounts { pub total: usize, pub completed: usize, pub in_progress: usize, pub pending: usize, pub cancelled: usize }
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Checklist { pub revision: u64, pub items: Vec<TodoItem>, pub skipped: usize }
impl Checklist {
    pub fn from_state(state: &TodoState) -> Checklist;
    pub fn from_values(revision: u64, items: &[serde_json::Value]) -> Checklist;
    pub fn is_empty(&self) -> bool;                // no parsed items, whatever `skipped` is
    pub fn counts(&self) -> ChecklistCounts;
    pub fn is_active(&self) -> bool;
    pub fn tree(&self) -> Vec<TreeRow>;
    pub fn focus(&self) -> Option<usize>;          // position in tree()
}
```

`from_state(state)`: `match u64::try_from(state.revision) { Ok(r) => from_values(r, &state.todos), Err(_) => Checklist { revision: 0, items: vec![], skipped: 0 } }`. A negative revision cannot occur (Hermes clamps at 0, H6); treating it as "no plan" keeps the type conversion lossless.

### 5.1 Parsing an item

For each JSON value, in order:

1. Not an object: skip (`skipped += 1`).
2. `status` missing, not a string, or not one of H12's words (exact, lower case): skip. (Hermes's tool would have turned an unknown status into `pending`, H13; a value that still arrives unknown is not from that tool, so Talaria does not guess.)
3. `id`: a string is trimmed; a number is written in decimal (`serde_json::Number`'s `to_string()`); anything else, or blank after trimming, skips the item.
4. `content`: a string, trimmed; blank or not a string skips the item. Content is kept whole (it may be up to 4,000 characters, H14); the renderer cuts it.
5. `parent`: the same rule as `id` (a trimmed string, or a number in decimal). Blank, any other type, or equal to the item's own `id` gives `None`.
6. Other keys are ignored.

This matches both Hermes clients (`apps/desktop/src/lib/todos.ts:28-40`, `ui-tui/src/app/turnController.ts:80-109`), which stringify both fields with `String(...)`.

Duplicate ids after parsing are kept as separate items (Hermes removes duplicates before storing, H15, so a duplicate means another source).

A list whose items were all skipped has `is_empty()` true. The tracker treats it exactly like an empty list (6.3 step 2): no panel, no block, so its `(n items could not be shown)` line never prints. Hermes's tool cannot produce such a list (H13); it would come from another source, and drawing a header with no rows would say nothing useful.

### 5.2 Tree order

`tree()` returns every item exactly once, parents before children:

1. An item is a child when its `parent` equals the `id` of some item in the list and is not its own `id`; its parent is the **first** item with that id. Otherwise it is a root.
2. Walk roots in list order; for each, emit it with its depth, then walk its children in list order (depth first).
3. A visited set **keyed by item index** (not id) stops cycles; every index is emitted at most once by the walk.
4. Items never reached from a root are appended at depth 0, in list order, without walking their children. This covers cycle members and any item that hangs under a cycle member; such items do not follow the "parents before children" rule.
5. `depth` saturates at 255; the renderer caps indentation at depth 4.

Adapted from `ui-tui/src/lib/todo.ts:15-59` and `apps/desktop/src/lib/todos.ts:86-132`. Unlike Hermes, which keys both its visited set and its children map by id (so a later duplicate id is never emitted), Talaria keeps duplicates and tracks visits by index. Copying the Hermes algorithm as is fails test 6 and test 9.

### 5.3 Counts, activity and focus

- `counts()`: `total` is the number of parsed items (skipped ones are not counted); the others count by status.
- `is_active()`: any `Pending` or `InProgress` item.
- `focus()`: the position in `tree()` of the first `InProgress` item in tree order; if none, of the first `Pending` item; if none, `None`.

## 6. The tracker: `ChecklistTracker`

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum CommitKind { TurnEnded, Resumed }
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ChecklistCommit { pub checklist: Checklist, pub kind: CommitKind }
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Observed { pub commit: Option<ChecklistCommit>, pub live_changed: bool }
pub struct ChecklistTracker { /* live, committed_revision, was_running, expanded */ }
impl ChecklistTracker {
    pub fn new() -> ChecklistTracker;                                    // expanded = true
    pub fn attach(&mut self, todo: Option<&TodoState>, running: bool) -> Option<ChecklistCommit>;
    pub fn observe(&mut self, todo: Option<&TodoState>, turn: &TurnState) -> Observed;
    pub fn live(&self) -> Option<&Checklist>;
    pub fn expanded(&self) -> bool;
    pub fn toggle(&mut self) -> bool;                                    // true when something visible changed
    pub fn reset(&mut self);                                             // keeps `expanded`
}
```

"Running" below means `TurnState::Running`.

### 6.1 State

- `live: Option<Checklist>`: the list in the live panel, or none.
- `committed_revision: Option<u64>`: the revision of the last list written to scrollback.
- `was_running: bool`: whether the turn was running at the previous call.
- `expanded: bool`: panel form; starts `true`; only `toggle` changes it.

"Newer than committed" means `committed_revision` is `None`, or the list's revision is greater than it.

### 6.2 `attach` (called once after the app builds the state from a `session.create` or `session.resume` snapshot)

`running` is `state.turn() == TurnState::Running` (P1-05 sets `Running` from the snapshot's `running: true`).

| Input | Result |
|---|---|
| `todo` is `None`, or parses to an empty list | Nothing. `was_running = running`. |
| Non-empty list, `running: true` | `live = list`. No commit. `was_running = true`. |
| Non-empty list, `running: false` | Commit `Resumed` with the list; `committed_revision = revision`; `live = None`; `was_running = false`. |

The committed revision is kept in memory only. A new Talaria process that resumes the same idle session prints the `Resumed` block again, once; UAT-6 relies on this.

### 6.3 `observe` (called after every reducer update of the foreground session)

Let `list` be `todo` parsed (or `None`), `running` the current turn state, and `before = live.clone()`.

1. **Update while running.** If `running` and `list` is non-empty: if `live` is `Some` (same turn), replace it with `list`; else if `list` is newer than committed, set `live = list`.
2. **Clear.** If `list` is `None` or empty and `live` is `Some`: `live = None`, no commit. (An empty list at revision 1 or more is a real clear, H6; the agent removed its plan.)
3. **Turn end.** If `was_running` and not `running`: if `live` is `Some`, take the newer of `live` and a non-empty `list` (the higher revision; `list` on a tie), return it as a `TurnEnded` commit, set `committed_revision` to its revision and `live = None`. If `live` is `None`, nothing is committed: a list that was never shown live is never committed by `observe`.
4. `was_running = running`; `live_changed = (live != before)`.

A list that arrives while the turn is not running is not shown at that moment, and the tracker records nothing about it. Hermes emits `todo.updated` inside a turn (H7), so this is a late frame. The reducer still stores it; at the next running turn's first reducer update, step 1 shows it if its revision is newer than the last committed one. Test 16 covers this.

### 6.4 State diagram

```text
                 update while running, newer than committed
   ┌────────┐ ─────────────────────────────────────────────► ┌──────┐
   │ Hidden │                                                 │ Live │ ◄─┐ update while running
   └────────┘ ◄───────────────────────────────────────────── └──────┘ ──┘ (replace)
        ▲        turn ends: commit TurnEnded                      │
        │                                                         │ empty list: no commit
        └─────────────────────────────────────────────────────────┘
   attach(idle, non-empty): commit Resumed, stay Hidden
   attach(running, non-empty): go Live
```

### 6.5 `toggle` and `reset`

- `toggle`: flips `expanded`. Returns `true` when `live` is `Some` (the panel changed), `false` otherwise (the flip still happens, so the next list appears in the chosen form).
- `reset`: `live = None`, `committed_revision = None`, `was_running = false`; `expanded` is kept.
- A caller that changes the foreground session calls `reset()`, commits the new session's history, then calls `attach(new.todo(), new.turn() == Running)`, exactly as on resume. `attach` then sets the committed revision again (idle) or shows the list live (running), so the new session's old plan is not shown as new at its next turn (test 19). Phases 1 and 2a have no in-app session switch (P1-12 opens one session per process; the fleet view is phase 3), so this unit calls `reset()` from nowhere in `app.rs`.

### 6.6 Replay-gap resync

P1-12 handles a replay `Gap` by calling `session.resume`, rebuilding the state with `from_snapshot`, and resyncing the link, without re-committing cells already committed. For the checklist the app calls `observe` with the rebuilt state, never `attach` or `reset`. Results: a still-running turn keeps or replaces the live list; a turn that ended during the gap commits the live list once (step 3), using the newer of the live and resynced lists; an idle session whose list was already committed shows nothing (test 39). A turn that began and ended entirely inside the gap was never `Running` to the tracker (`was_running` is false), so nothing is committed at resync; the list stays stored and follows the rule of test 16 at the next running turn. Test 39 covers this case.

### 7.0 Cutting (`cut_to_width`)

If the display width of `text` (`unicode-width`, non-CJK widths; `▸`, `▾`, `·` and `…` are one column) is at most `width`, return it unchanged. Otherwise return the longest prefix made of whole grapheme clusters (`unicode-segmentation`) whose display width is at most `width - 1`, followed by `…`. For `width` 0, return the empty string. The result is never wider than `width`; with a wide character at the cut point it may be one column narrower.

### 7.1 Item rows

`<indent><glyph> <content>`

- indent: two spaces, plus two more per depth level, capped at depth 4 (so at most ten spaces).
- glyph: `[x]` completed, `[>]` in progress, `[ ]` pending, `[-]` cancelled.
- content: first, each maximal run of `\r`, `\n` and `\t` characters becomes one space (a run is not collapsed with ordinary spaces next to it); then P1-06's `sanitize` (ESC becomes `␛`, BEL `␇`, other C0 controls their Control Picture, DEL `␡`, bidirectional and other listed characters `‹U+XXXX›`, for example U+202E becomes `‹U+202E›`); then the whole row is cut with `cut_to_width`. One row per item, never wrapped. Because newlines and tabs are replaced before `sanitize`, they never show as `␊` or four spaces.

Styles (default): in progress bold, glyph cyan; pending plain; completed dim, glyph green; cancelled dim; header bold; hint dim. `plain()` keeps bold and dim and drops every colour (used when `NO_COLOR` is set, as P1-07 does).

### 7.2 Live panel, expanded

```text
▾ Tasks 1/3 · Ctrl+T to collapse
  [x] Read the failing test
  [>] Fix average()
  [ ] Run the test suite
```

- Header: `▾ Tasks <completed>/<total>`, then ` · <cancelled> cancelled` when any are, then ` · <hint> to collapse` when a hint is given. `hint` is `KeyMap::label(Action::ToggleTasks)`, `None` when unbound. When the header is wider than the width, the hint segment is dropped first; if still too wide, the header is cut with `cut_to_width`.
- Rows: the items in `tree()` order.
- Height cap: `max_rows` (the app passes `PANEL_MAX_ROWS`, or 1 on a terminal shorter than `SHORT_TERMINAL_ROWS` rows). `max_rows` of 0 or 1 gives the collapsed form (7.3) whatever `expanded` says. If the header plus all items fit in `max_rows`, show them all. Otherwise show `count = max_rows - 2` item rows and a last row `  … +<hidden> more`, where `hidden` is the number of items not shown (above and below the window). With `count` 0 (`max_rows` 2) the panel is the header and `  … +<total> more`.
- Window: with a focus, `start = focus - 1` (at least 0) when `count >= 2`, else `start = focus`; then, if `start + count > total`, `start = total - count`. With no focus, `start = 0`. Positions are 0-based positions in `tree()`.

### 7.3 Live panel, collapsed

```text
▸ Tasks 1/3 · Fix average() · Ctrl+T to expand
```

One row: `▸ Tasks <completed>/<total>`, then ` · <cancelled> cancelled` when any are, then ` · <focus item content>` when there is a focus (the content prepared as in 7.1, without indent or glyph), then ` · <hint> to expand` when a hint is given. When the row is wider than the width:

1. drop the hint segment;
2. if still too wide, cut the focus content with `cut_to_width` to `max(10, width - (width of the row without the focus content))` columns;
3. if still too wide, cut the whole row with `cut_to_width`.

### 7.4 Committed block (scrollback)

```text
Tasks 3/3 · done
  [x] Read the failing test
  [x] Fix average()
  [x] Run the test suite
```

Header by state, where `active` is pending plus in progress:

| Condition | Header |
|---|---|
| `active > 0`, no cancelled | `Tasks <c>/<t> · <active> not finished` |
| `active > 0`, some cancelled | `Tasks <c>/<t> · <active> not finished, <n> cancelled` |
| `active == 0`, no cancelled | `Tasks <c>/<t> · done` |
| `active == 0`, some cancelled | `Tasks <c>/<t> · done, <n> cancelled` |

For `CommitKind::Resumed`, the header ends with ` (from before this resume)`. The header is cut with `cut_to_width` when wider than the width. Item rows follow in `tree()` order, at most `BLOCK_MAX_ITEMS` (50); beyond that a row `  … +<n> more`. When `skipped > 0`, a last dim row `  (1 item could not be shown)` for one, `  (<n> items could not be shown)` for more. No blank line is added before or after the block. Skipped items appear only here; the live panel's header counts exclude them and it shows no skipped line.

### 7.5 Width edge cases

- Every row of both surfaces, including `  … +<n> more` and `  (<n> items could not be shown)`, is passed through `cut_to_width`.
- Width below 12: the live panel (expanded or collapsed) is only its header, cut. The committed block keeps every row, each cut, because it is the permanent record.
- Width 0: `lines(0)` and `committed_block_lines(.., 0, ..)` return an empty `Vec`.
- No row is ever wider than the width (property test).
- A zero-width or combining character at a cut point never leaves a broken cluster: cut on grapheme boundaries.

### 8.4 Commits

- After each reducer update of the foreground session: commit the cells the commit ledger reports ready (P1-06), then call `observe`; if it returns a commit, call `commit_lines(committed_block_lines(..))`. The block therefore follows the turn's last cell.

- A turn that ends while a full-screen overlay is open still issues the commit; P1-06's `commit_lines` queues it and `close_overlay` writes it once (test 38).
- Replay-gap resync: `observe` only (6.6).
- No in-app foreground switch exists in this phase (6.5).

### 8.5 Colour

The app builds one `ChecklistStyle` at start: `plain()` exactly when it passes `color: false` to P1-07's Markdown renderer (P1-07 leaves that choice to P1-12; a non-empty `NO_COLOR` is the usual reason), else `default()`. This unit reads no environment variable itself. If the merged app has no such choice, use `default()` and report the gap to the phase 2a parent on the pull request.

For UAT-5, copy `todo_frames.jsonl` to `$TMPDIR/hostile.jsonl` and edit the revision 3 payload: the first item's `content` becomes `"Read \u001b[2J the ‮ test"` (JSON escapes) and a fourth item `{"id":"4","content":"x","status":"done"}` is appended. **Live scenarios (UAT-2 to UAT-6).** Operator preconditions as in the issue. The rules below answer how to start Talaria, submit text, read the screen and classify results.

- **Binary.** Build the branch once with `cargo build -p talaria-cli` at the repository root, then set `T="$(pwd)/target/debug/talaria"` there and use `"$T"` everywhere. Never run a `talaria` found on `PATH`: an older install may exit silently or behave differently.
- **One fresh pane and folder per scenario.** UAT-2, UAT-3 and UAT-4 each start a new Talaria process in a new pane `P<n>` opened in a new folder `$TMPDIR/tasksproj-<n>`, so no scenario's scrollback can hold another scenario's block (AC-8 counts blocks). UAT-6 opens a new pane `P6` in UAT-4's folder. The tester may close its own panes afterwards.
- **Submitting.** `herdr pane run` sends text and Enter in one call (herdr 0.9.4 help text). Use it only at a shell prompt (starting Talaria). To submit text to Talaria's composer, use two calls, `herdr pane send-text P<n> "<text>"` then `herdr pane send-keys P<n> enter`, so a pasted newline cannot land in the composer instead of submitting. `Q` and `say hi` contain no double quotes.
- **Reading.** Live-region reads: `herdr pane read P<n> --source visible`. Scrollback reads, in this order until one returns text: `--source recent-unwrapped --lines 80`, `--source recent --lines 80`, `--source visible`. Right after a turn ends the block sits just above the live region, so a visible read normally contains it. Record which source each read used. Herdr takes the pane id before the options. Take each read after the wait it follows has returned.
- **Classifying.** Every read source empty: BLOCKED (environment). A non-empty read that shows the turn's reply but not the expected line: FAIL. A `wait-output` timeout, a model that does not call the todo tool or does not mark the sleep step `in_progress` before the sleep, an approval card (deny it with the card's deny key), or an authentication or connection error from Talaria: BLOCKED (environment), never PASS. Retry such a run in a fresh pane and folder, at most three sessions in all. In UAT-3, if the sleep step ends before both Ctrl+T reads are taken, the Herdr run is BLOCKED (environment) and the operator run decides.

```bash
mkdir -p "$TMPDIR/tasksproj-2"
herdr pane split --current --direction right --cwd "$TMPDIR/tasksproj-2" --no-focus   # call the new pane P2
herdr pane run P2 "$T --profile fixture --provider ollama-cloud --model minimax-m3.1-flash"
herdr pane send-text P2 "Use your todo_list tool to write a plan with exactly three items: create a.txt, run sleep 30, create b.txt. Before each step mark it in_progress with the todo_list tool, and after it mark it completed. Do the steps in this folder. Then reply with the single word: done."
herdr pane send-keys P2 enter
herdr pane wait-output P2 --regex '(?i)\[>\] .*sleep' --source visible --timeout 120000   # panel shows the sleep step
herdr pane read P2 --source visible                                                    # live region read
herdr pane wait-output P2 --regex '(?mi)^\W*done\W*$' --source recent-unwrapped --timeout 180000
herdr pane read P2 --source recent-unwrapped --lines 80                                # scrollback read (fallbacks above)
```

- If the reply wait on `recent-unwrapped` times out while a visible read shows `done` on its own line, repeat the wait with `--source visible`; that is not a timeout.
- The reply regex cannot match the prompt line or the block header, because both have other words on the line.
- Approvals: Hermes asks only for commands matching `DANGEROUS_PATTERNS` (H26), and `sleep` is not one; creating files usually goes through a file tool.
- UAT-3 key presses: `herdr pane send-keys P3 ctrl+t`. One operator run repeats UAT-3 in a terminal outside Herdr with Ctrl+T pressed on the keyboard.
- UAT-4 interrupt: `herdr pane send-keys P4 esc` (P1-08's default), wait for the interrupted notice, then submit `say hi` as above and wait for the reply.
- UAT-6: `/quit` in `P4` prints `Resume this session with:` and `  talaria --resume <stored_session_id> --profile fixture` (P1-12); in the fresh pane `P6` run `herdr pane run P6 "$T --resume <stored_session_id> --profile fixture"`.
- AC checks run `grep` on the saved read text. Patterns allow trailing spaces before an end anchor (` *$`), because a pane read may pad lines.
- Evidence: post each scenario's reads (with their sources), times and result on the pull request as a comment headed `UAT-<n>` with the commit and PASS, FAIL or BLOCKED (reason). Never commit pane reads.
