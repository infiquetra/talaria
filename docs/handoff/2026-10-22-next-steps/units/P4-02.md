Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

## 1. What this unit adds, in one paragraph

A **Providers** overlay in Talaria with three tabs. **Keys** lists every model provider that authenticates with an API key, shows whether a key is saved and whether Hermes lists the provider as ready (it has models; this is not a live check of the key), lets the user paste a new key (checked first, then saved) and removes a provider's credentials after a confirmation. **Accounts** lists every provider that signs in with an account, runs the device-code sign-in (show a code and a link, wait for the user to approve in a browser, cancel on Esc) and signs out. **Endpoints** lists the profile's custom OpenAI-compatible endpoints and lets the user add, test, edit and delete them. Everything acts on the profile Talaria is connected to. Talaria never shows a saved key, never logs or records one, never restarts the gateway and never edits a Hermes file directly: every change goes through a Hermes method or dashboard route.

All routes below are on the gateway's own loopback web listener (the control socket's `api_origin`). Talaria authenticates each request with a fresh `native-http` ticket in the header `x-hermes-gateway-ticket`, sends no `Origin` header, and sends no `profile` query or body field. ## 4. Design

### 4.1 Decisions (with reasons)

D1 to D4, D8 to D12 follow the architecture, Hermes's own clients or an earlier unit. D5, D6 and D7 were proposed by the drafter: the handoff records no operator decision on them. The operator confirms or changes them in the parent's per-run inputs; until then the builder builds them as written.

- **D1. Keys are saved with `model.save_key` on the socket**, not `PUT /api/env`. It is the typed method the architecture names, the one Hermes's terminal UI uses, it returns the refreshed provider row, and the recorder already withholds its `api_key` parameter (`P1-04`'s deny-set). `PUT /api/env` writes the same store through the same function (`save_provider_env_credential`); two write paths for one key would break "one writer per setting". If `P4-00` finds the fallback refuses `model.save_key` on Talaria's ticket, the planner switches this one call to `PUT /api/env {key: <var>, value, provider_setup: true}` and edits the issue; nothing else changes.
- **D2. Removal on the Keys tab is `model.disconnect`**, which also clears the provider's sign-in and every key variable Hermes registers for the provider (H9), including variables shared with other providers. The confirmation says so in words and names the providers that share a variable. Removing one variable while keeping a sign-in (`DELETE /api/env`) is not offered.
- **D3. The Keys list comes from `GET /api/env`**, because only it says which variables are provider keys, whether each is set, and gives a preview; readiness comes from `model.options`. Rows are joined by slug (section 4.3).
- **D4. Before saving, the key is checked with `POST /api/providers/validate`.** Hermes's meaning is kept exactly: `ok:false, reachable:true` blocks (whatever the message, including `Provider returned HTTP <n> for this key.`); `reachable:false` or a failed check saves after a second Enter; no probe saves at once.
- **D5 (drafter-proposed). No reveal.** Talaria shows at most the last four characters of a saved key (from Hermes's own preview). `POST /api/env/reveal` is not called. The architecture allows "a deliberate one-shot reveal"; this unit simply does not add one, and `P4-01`'s settings screen keeps its own.
- **D6 (drafter-proposed). No "make default".** Choosing the profile's main model belongs to `P4-03` (model roles, per the roadmap). The Endpoints tab always sends `make_default: false` and never calls `.../activate`.
- **D7 (drafter-proposed). External sign-ins are never run by Talaria.** For `external` providers, Talaria shows `cli_command` (to sign in) or `disconnect_command` (to sign out) and can copy it; it never executes it.
- **D8. The browser opens only on a key press.** Talaria never opens a URL by itself (the user may be on a remote machine). `o` runs the platform opener for an `https://` URL only.
- **D9. Everything acts on the connected profile.** No `profile` field is sent anywhere. The overlay title names the profile.
- **D10. One write or check at a time.** Writes are `SaveKey`, `Disconnect`, `SignOut`, `SaveEndpoint`, `DeleteEndpoint` and `StartSignIn` (it creates a gateway sign-in session); checks are `CheckKey` and `CheckEndpoint`. While any one of them is in flight, a key that would start another shows `Waiting for Hermes.` and sends nothing. Loads, `Poll` and `CancelSignIn` are neither: they are never blocked and never block (Enter on Accounts while a cancel runs starts the new sign-in). Full rules: 4.12.
- **D11. A typed key never enters `talaria-core`.** This follows `P1-09`'s rule for masked answers ("the value never enters a `talaria-core` event"). The key lives in a `talaria-tui` `SecretField` that holds a `zeroize::Zeroizing<String>` under the same rules as `P1-09`'s `MaskedValue` (65,536 bytes reserved at creation so it never reallocates; no `Debug`, `Clone`, `Display` or `Serialize`). It does not wrap `MaskedValue`: that type offers only `len_chars()` and a consuming `into_inner(self)`, and its file belongs to `P1-09`. The pure state machine sees only text-free events and emits effects that name the variable or slug, not the key (section 4.2).
- **D12. `talaria-core` never imports `hermes-client`** (architecture, Layers; `P0-02`'s layering test). The core defines its own domain shapes; `hermes-client` defines the wire shapes; `talaria-app` converts.
- **D13. The glue that names `talaria-tui` types lives in `talaria-cli`.** `P0-02`'s layering test forbids `talaria-app` from reaching `ratatui` or `crossterm`, and `P1-09` records that `talaria-tui` and `talaria-app` never name each other's types, with `P1-12` in `talaria-cli` converting between them. So `SecretField` routing, lending the key, `ForgetSecret`, drawing and the clipboard call are in `crates/talaria-cli/src/providers_wiring.rs` (section 4.12).

`ProvidersView` carries the title, tab, rows as display strings, the filter, the card (kind, lines, footer), the notice, the banner and `secret_focus: bool` (true while the key card or the form's API key field takes input). It never carries key text; the renderer draws the bullets from `SecretField::len()`.

**Where the key lives.** `crates/talaria-tui/src/providers/secret_field.rs`: `pub struct SecretField(zeroize::Zeroizing<String>)` created with `String::with_capacity(65_536)` (no `Debug`, `Clone`, `Display`; input that would pass the capacity is refused, so the buffer never reallocates), with `handle_key(&mut self, key: &ProvidersKey) -> SecretOutcome { Edited { empty: bool }, Submit, Clear, NotHandled }`, `handle_paste(&mut self, text: &str) -> SecretOutcome`, `len() -> usize` (characters), `value(&self) -> &zeroize::Zeroizing<String>` and `clear()` (zeroes the bytes, keeps the capacity). `Submit` is returned only when the field holds at least one character. There is one `SecretField`, owned by `ProvidersWiring` (4.12); the key card and the endpoint form are never open together, and core emits `ForgetSecret` whenever either opens or closes. Routing, lending and forgetting: section 4.12.

**Error mapping in `talaria-app`.** `CallError::Rpc(RpcError { code, message, .. })` → `Failure::Refused { code, message }` (`-32601` included); `NotConnected`, `Encode`, `InvalidTimeout` → `NotSent`; `TimedOut`, `Unknown`, `BadResult` → `Unknown`. `RestError::{NotLoopback, TlsNotSupported, Ticket, Connect}` and `Timeout { sent: false }`, `Dropped { sent: false }` → `NotSent(<reason>)`; anything with `outcome_unknown()` → `Unknown`; `Unauthorized` → `Http { status: 401 }`; `Forbidden { detail }` → `Http { 403, detail }`; `NotFound` → `Http { 404 }` (core supplies the `<route>` of the 404 text from the kind of load that failed: `/api/env`, `/api/providers/oauth` or `/api/providers/custom-endpoints`); `Refused { status, detail }` → `Http { status, detail }` (a 422's list `detail` arrives as `None`: `P4-01` reads only string details); `Server { status }` → `Http { status }`; `BodyTooLarge`, `BadBody` → `BadReply`. A `BadReply` to a write is shown like `Unknown`. A `ProviderService` outer timeout (below) on validate is a failed check; on start it is `NotSent("no answer in 20 s")`; on poll a failed poll; on cancel ignored.

**`ProviderService`** (`crates/talaria-app/src/providers.rs`). One per `P1-12` `OpenConnection`, built in `app.rs` beside `P4-01`'s `SettingsService` from the socket `Client`, a `RestClient` (`P4-01`'s `NativeHttpMinter` for the connection's profile) and `profile_name`. It outlives the overlay. `execute(&self, effect, secret: Option<Zeroizing<String>>)` takes an owned copy of the key (or `None`) and drops it, zeroed, when the call ends; the loop runs each `execute` in its own spawned task and never awaits it inline. It keeps `open_sign_ins: Mutex<HashSet<String>>` of **session ids**: a successful start adds the id; a final poll answer, a sent cancel or `close()` removes it, so each session is cancelled at most once. A `Poll` whose session id is no longer in the set after its sleep returns no input and sends no request. `close()` runs when the overlay closes and when Talaria quits (quit waits at most 1 s in total), cancels every remaining id, and sets a flag so a start answer that arrives later is cancelled at once (the flag clears on the next `Open`). `execute` maps one effect to one or more calls and returns the inputs; `Poll { after }` sleeps `after` first. Timeouts: socket calls use `Client::call_with(params, CallOptions { timeout: Some(30 s) })`; REST reads and writes keep `P4-01`'s 15 s and 30 s; validate and start are wrapped in `tokio::time::timeout(20 s)`, poll in 10 s, cancel in 5 s.

**Copy and open.** `CopyText(text)`: the app writes `osc52(&text)` through one new `InlineTerminal::copy_to_clipboard(&mut self, text: &str) -> io::Result<()>` in `P1-06`'s `terminal.rs` (the only writer of escape sequences). `osc52` returns `ESC ] 52 ; c ; <base64 of text> BEL` with a hand-written standard base64 encoder (test: `osc52("ab")` is `"\x1b]52;c;YWI=\x07"`). The notice is `Copied to the clipboard if your terminal allows it.` (inside tmux the user's `set-clipboard` setting decides). `OpenUrl(url)`: `opener_argv(url)` returns `Some(vec!["open", url])` on macOS, `Some(vec!["xdg-open", url])` on Linux, and `None` on other systems or when `url` does not start with `https://`; the app spawns it with `std::process::Command::new(argv[0]).arg(argv[1])`, standard streams null, no shell, not awaited (a background task reaps it). `None` or a spawn error makes the loop send `ProvidersInput::OpenFailed` into `update`, and core shows the notice `Could not open a browser. Copy the link instead.` (the same path as `P4-04`'s `McpInput::OpenFailed`; each overlay keeps its own text, because `c` copies the code here and the link there). Core emits `OpenUrl` and `CopyText` only for text that `history::sanitize` leaves unchanged; otherwise the notice `Talaria will not copy or open text that contained control characters.`

**`next_deadline`** returns the next countdown second or the local expiry while a Waiting card is shown, and `None` otherwise. The app arms one timer for it and sends `Tick` when it fires. Poll timing is not a deadline here: the service sleeps inside `Poll`.

**`hermes-client`** (`crates/hermes-client/src/providers_api.rs`): lenient wire structs (`EnvVarWire`, `OauthListWire`, `OauthStartWire`, `OauthPollWire`, `EndpointListWire`, `EndpointBodyWire`, `ProviderValidationWire`, `EndpointValidationWire`; every optional field `Option`, unknown fields ignored, `#[serde(default)]` on lists) and one async function per route of section 5.2, each built on `P4-01`'s `RestClient`. If the merged `RestClient` has no `post_json` or `delete_json`, add `pub async fn post_json(&self, path: &str, body: Option<&Value>) -> Result<Value, RestError>` and `pub async fn delete_json(&self, path: &str) -> Result<Value, RestError>` to `rest.rs`, reusing its single request path (ticket, headers, 401 retry, `RestError`); `P4-03` and `P4-10` need the same, and whichever unit merges first adds them.

**Elsewhere (minimal).** In `talaria-cli`: `mod providers_wiring;` and the calls of section 4.12, at the seam `P1-12` merged for `P1-09`'s masked answers. `LocalAction::Providers(OpenTarget)` in `P2-03`'s table, with `parse_providers_args` giving the usage line through `P2-03`'s usage mechanism. `KeyContext::Providers` with nine actions appended to `P1-08`'s key map (each unit appends a context; on a rebase conflict keep both). ### 4.3 The Keys tab

**Loading.** On open, emit `LoadEnv` and `LoadOptions` together. `LoadOptions` is `model.options {include_unconfigured: true}`: no `session_id`, no `profile`, no `explicit_only`, no `refresh`.

**Rows.** One row per entry of `GET /api/env` with all of: `provider` not empty, `provider_primary` true, `is_password` true, `channel_managed` false, `custom` false. Row fields: `label` = `provider_label` (or `provider` when empty), `slug` = `provider`, `env_var` = the object key, `is_set`, `tail` (below), `shared_with` = the providers in `provider_profiles` other than this row's. A dim second line `also used by <label>, <label>` shows when `shared_with` is not empty.

**Tail.** If `redacted_value` matches `^«redacted:.{4}\.\.\.(.{4})»$`, the key part is `key …` plus the captured four characters. Any other non-null value gives `key saved`. Never show the first four characters or the raw preview. Below, `<key>` stands for `key …wxyz` or `key saved`, and `<key> saved` is written `key …wxyz saved` with a tail and `key saved` without one (never `key saved saved`).

**Status** (first match wins; `<n>` is `total_models`, else the length of `models`; ` · <n> models` is left out when both are absent or zero. No Keys status shows the option row's `warning`: for an `api_key` provider it is Hermes's placeholder hint `paste <KEY_ENV> to activate` (H3), which adds nothing to `no key` and on a set row would wrongly say no key is saved):

| Condition | Text |
|---|---|
| set, options loading | `<key> saved · checking…` (for `key saved`: `key saved · checking…`) |
| not set, options loading | `no key · checking…` |
| set, options failed | `<key> saved` (for `key saved`: `key saved`) |
| not set, options failed | `no key` |
| set, option row `authenticated` true | `ready · <n> models · <key>` |
| set, no option row or `authenticated` false | `<key> saved · not ready` (no warning) |
| not set, option row `authenticated` true | `ready · credential not in this profile's key file` |
| not set otherwise | `no key` (dim) |

When options failed, a footer says `Could not check readiness: <text>. ctrl+r tries again.`

**Order.** Rows with `is_set` first, then the rest; within each group, case-insensitively by label. The order is recomputed on every `EnvLoaded` and never on `OptionsLoaded`, so rows do not jump when readiness arrives. After any reload the selection stays on the same `env_var` (or the nearest row when it is gone).

**Key entry** (Enter on a row, or REQ-5): a card titled `API key for <label>` with the lines `Saved to profile <profile>'s key file as <ENV_VAR>.`, the masked field (`•` per character from `SecretField::len()`, at most 40, then `…`), and the footer `enter save · ctrl+u clear · esc cancel`. The `SecretField` takes printable characters and bracketed paste (paste: trim surrounding whitespace, drop every `\r` and `\n`; inner spaces kept). Backspace deletes one character. Enter on an empty field does nothing: the `SecretField` returns `Submit` only when it holds at least one character.

**Save sequence.**

```text
SecretSubmitted ─► CheckKey{env_var} ─► ok:true ─────────────────────────► SaveKey{slug}
                                    ├─► ok:false, reachable:true ─► show message, stay; the next SecretSubmitted checks again
                                    ├─► ok:false, reachable:false ─► "Could not reach the provider to check the key. Press enter again to save it anyway."
                                    └─► Failure / timeout ──────────► "Could not check the key (<reason>). Press enter again to save it anyway."
                                                                       next SecretSubmitted ─► SaveKey{slug} (no second check)
SecretEdited or SecretCleared after a warning ─► the warning and its "save anyway" state are cleared
SaveKey ─► row ─────► close card, ForgetSecret, update the row, notice "Saved the key for <label>.", LoadEnv
       └─► Failure ─► text (table 4.7); card stays open with the key, except Unknown and BadReply (card closes, ForgetSecret, reloads)
Esc on the card ─► close, ForgetSecret
While CheckKey or SaveKey is in flight: the card shows "Checking the key…" or "Saving the key…", view.secret_focus is false
  (the field takes no edits; printable keys do nothing), Esc still closes the card with ForgetSecret.
KeyChecked arriving after the card closed ─► dropped: no SaveKey, nothing saved, no notice.
KeySaved arriving after the card closed ─► applied: update the row, notice "Saved the key for <label>.", LoadEnv (or its failure text as a notice).
```

**Remove** (Ctrl+D on a row):

- not `is_set` while `model.options` is still loading: notice `Still checking <label>; try again in a moment.`, no call;
- not `is_set` and `model.options` failed: notice `Could not check <label>. Press ctrl+r, then try again.`, no call (readiness is unknown, and removal is destructive);
- not `is_set` and not ready (options loaded): notice `Nothing to remove for <label>.`, no call;
- otherwise a confirmation card: `Remove every saved credential for <label> from profile <profile>? This deletes its API keys (including <VARS>) and any account sign-in for it.` `<VARS>` lists, comma-separated, every env entry with `is_set` true whose `provider` is the slug or whose `provider_profiles` contains the slug; when none is set the clause reads `This deletes any API key Hermes holds for it and any account sign-in for it.` For each listed variable that another provider also uses (from `provider_profiles`, or an entry whose `provider` is another slug), append ` <other label> uses <VAR> too and will lose it.` Footer `y remove · n keep`. `y` or Enter sends `model.disconnect {slug}`; `n` or Esc closes. Success: notice `Removed the credentials for <label>.`, then `LoadEnv`, `LoadOptions`, `LoadOauth`.

The word "including" is deliberate: Hermes removes every registry variable (H9), and `GET /api/env` omits some (R4: `copilot`'s `GITHUB_TOKEN`).

**Entry from the model picker** (`OpenTarget::Provider { slug }`): emit `LoadEnv`, `LoadOptions` and `LoadOauth`; wait until all three have loaded or failed. Then, in order: a Keys row with `slug == provider` opens its key entry; else an Accounts row with `id == slug` switches to Accounts and selects it; else, if the `model.options` row for `slug` has `auth_type == "api_key"` and a `key_env`, open a key entry for that slug and variable (label: the row's `name`); else show the notice `<name> is set up outside Talaria: <warning>.` and stay on Keys, where `<name>` is the option row's `name` (the slug when there is no row) and `: <warning>` is omitted when the row has no warning (`<name> is set up outside Talaria.`).

### 4.4 The Accounts tab

**Rows** from `GET /api/providers/oauth`, in Hermes's order. Status text:

| Condition | Text |
|---|---|
| `status.logged_in` true | `signed in` + ` · <source_label>` when not empty + ` · expires <relative>` when the expiry is known |
| `status.error` present | `status unknown: <error>` |
| otherwise | `not signed in` |

**Expiry.** `talaria-app` converts `status.expires_at` when the list loads: an RFC 3339 string (hand-written parser: `YYYY-MM-DDTHH:MM:SS[.fraction](Z|±HH:MM)`), or a JSON number (above 10^12: epoch milliseconds; else epoch seconds); anything else gives no expiry. It stores `expires_in_s = expiry − now` in `AccountStatus::SignedIn`. Core formats: under 0 → `expired`; under 3,600 s → `in <n> min` (at least 1); under 48 h → `in <n> h`; else `in <n> d`; always rounded down. The text is fixed until the next load (zero idle frames).

A second, dim part says how: `sign in here` (`flow == "device_code"`) or `sign in with <cli_command>` (`external`). `token_preview` is never shown.

A row with `status unknown: <error>` counts as **not signed in** for Enter (a sign-in can be started) and as **signed in** for Ctrl+D (the sign-out confirmation or the hint card is offered; Hermes answers 409 when nothing was stored).

**Enter.** `device_code` and not signed in: start the sign-in (4.5). `device_code` and signed in: notice `Already signed in to <name>. ctrl+d signs out.` `external`: a card `Sign in to <name> outside Talaria: run <cli_command> in a terminal, then press ctrl+r here.` plus `docs_url` when not empty; footer `c copy command · esc close`.

**Ctrl+D.** Not signed in: notice `Not signed in to <name>.`, no call. `disconnectable` true: confirmation `Sign out of <name> in profile <profile>?` with `y sign out · n keep`, then `DELETE /api/providers/oauth/{id}`; success shows `Signed out of <name>.` and reloads Accounts, Keys and `model.options`. `disconnectable` false: a card showing `disconnect_hint` and, when present, `disconnect_command` with `c` to copy it. Talaria never runs it.

### 4.5 The sign-in state machine

```text
          Enter                     start ok                         poll: approved
 Idle ───────────► Starting ───────────────────► Waiting ──────────────────────────────► Approved (final)
                     │  start failed               │ poll: denied / expired / error / cancelled
                     ▼                             ├──────────────────────────────────► Ended(kind)
                  Ended(Failed)                    │ now ≥ arrival of the start answer + expires_in
                                                   ├──────────────────────────────────► Ended(Expired) + CancelSignIn
                                                   │ poll answered 404
                                                   ├──────────────────────────────────► Ended(Gone)
                                                   │ poll answered any other 4xx except 429 (400 to 499)
                                                   ├──────────────────────────────────► Ended(Refused, detail)
                                                   │ 3 failed polls in a row: 429, 5xx, NotSent, Unknown, BadReply,
                                                   │ timeout, or status not in the six known (PollStatus::Other)
                                                   ├──────────────────────────────────► Ended(LostContact)
                                                   │ Esc, Close
                                                   └──────────────────────────────────► Idle + CancelSignIn (once)
 Each Enter that starts a sign-in increments ProvidersState's attempt counter and emits StartSignIn { id, attempt }.
 SignInStarted whose attempt is not the current Starting attempt (Esc, close, or a newer start since) ─► ignored for the
   screen; if it carries a session_id ─► CancelSignIn for it.
 SignInPolled whose session_id is not the current Waiting session ─► ignored (no state change, no new Poll).
 One Poll in flight per session: the next Poll is emitted only when that session's answer arrives.
 Esc while Starting ─► Idle; the late start answer is handled by the attempt rule above.
 Ended: Enter starts again unless retryable == Some(false); with retry_after, Enter is ignored until it has passed.
 Approved: Enter does nothing; Esc closes the card.
```

- **Start**: `POST /api/providers/oauth/{id}/start` with body `{}`, 20 s (the `openai-codex` start can take 10 s or answer 504). Not offered while the socket is disconnected (writes are off).
- **Waiting card**: `Sign in to <name>`, then `1. Open <verification_url>` and `2. Enter the code <user_code>`, then `Waiting for you to approve in the browser… expires in <mm:ss>`. Footer: `o open link · c copy code · esc cancel`. `o` on a URL that does not start with `https://` gives `Talaria opens only https links. Copy the link instead.` While this card is open, Tab does not switch tabs.
- **Poll**: the first poll is `max(poll_interval, 2)` seconds after the start answer (missing, 0 or negative: 2 s), then the same interval after each answer; never two in flight. `pending` schedules the next poll. Polling continues while the socket is disconnected (REST does not depend on it). `reason` is not shown at v0.7.0.
- **Approved**: `Signed in to <name>.` + ` Account: <account_email>.` when present + ` Default model: <model>.` when present. Then `LoadOauth`, `LoadEnv`, `LoadOptions`. The id leaves `open_sign_ins`.
- **Ended texts**: `denied` → `The sign-in was denied.`; `expired` (server or local) → `The code expired.`; `error` → `Sign-in failed: <error_message or "no reason given">`; `cancelled` → `The sign-in was cancelled.`; poll 404 → `Hermes no longer has this sign-in (it ended or the gateway restarted).`; any other poll 4xx except 429 → `Sign-in stopped: <detail or the 4.7 text>.` (at v0.22.4 the route itself answers 400 or 404, lines 873-884, and the ticket check 401 or 403); three failed polls (429, 5xx, transport failure, unreadable reply, timeout or an unknown `status`, in any mix) → `Lost contact with Hermes while waiting. The sign-in may still finish; press ctrl+r on this tab to check.` Each adds ` Press enter to try again.` unless `retryable` is `false`; when `retry_after` is a number, ` Try again in <n> s.` instead.
- **Cancel**: `DELETE /api/providers/oauth/sessions/{session_id}`, at most once per session (the service's set guarantees it), and the notice `Sign-in cancelled.`; its result is ignored except for logging the outcome class.
- **Countdown**: the only timer (`next_deadline`). It repaints once per second while the Waiting card is visible, and stops in every other state. No `expires_in`: no countdown and no local expiry; the server's status still ends it.

Results: any non-empty `models` fills the model choices **and an empty Model field takes the first model, whatever `ok` says** (Hermes returns models with `ok:false` when only the chat route is missing). `ok` → `Reached <resolved_base_url>: <n> model` (`models` when `<n>` is not 1)`.`; when `resolved_base_url` differs from the typed URL the line `Talaria will save <resolved_base_url>, the address that answered.` appears and Save uses it. `ok:false, reachable:true` → Hermes's message, sanitised but not reworded, as a warning (Save still allowed). `reachable:false` → the message as an error (Save still allowed: Hermes accepts endpoints that are offline now). In edit mode with a saved key not retyped, the form says `Testing without the saved key; type the key to test with it.`

Success: the list is replaced by the reply, notice `Saved <name>.`, `ForgetSecret`.

**Delete** (Ctrl+D on an endpoint row): `Delete the endpoint <name> (<base_url>) from profile <profile>? Its saved key is removed too.` plus, when `is_current`, ` It is the profile's default provider, so the default provider is cleared.` Then `DELETE .../{id}` (id percent-encoded with a hand-written encoder: every byte outside `A-Z a-z 0-9 - . _ ~` becomes `%XX`). 404 gives `Hermes no longer has <name>.` and a reload.

### 4.9 Budgets and idle

- Opening the overlay draws its first frame without waiting on any call (rows show `Loading…`).
- No frame takes more than 50 ms; filtering is synchronous over at most a few hundred rows.
- With nothing changing, zero frames. The loop draws only after an input, a reply or a `Tick`; it arms one timer from `next_deadline` and re-arms it after each `update`. The only deadline is the sign-in countdown: `next_deadline` is `None` unless a Waiting card is shown, and then it is the next whole second of the countdown (or the local expiry, whichever is sooner). No polling happens without a Waiting card. Test 32 checks these rules on the view; the loop itself is `P1-12`'s.
- Timeouts: socket calls 30 s (`CallOptions`); REST reads 15 s and writes 30 s (`P4-01`'s client); validate 20 s (the provider probe is 10 s, the endpoint probe 8 s plus a transport probe); sign-in start 20 s; poll 10 s; cancel 5 s (the service's `tokio::time::timeout`).

### 4.10 Secrecy

1. The typed key (provider key or endpoint API key) exists only in the `SecretField` (a `zeroize::Zeroizing<String>` under `P1-09`'s `MaskedValue` rules), and in one owned `Zeroizing` copy per call that the wiring hands to `ProviderService::execute` and that is zeroed when the call ends. It never enters a `talaria-core` input, effect, state or view. `ForgetSecret` (save done, cancel, Ctrl+U, Ctrl+X, a card or form opening or closing, overlay closed) clears it.
2. It never appears in `Debug`, `Display`, tracing output, panic messages, notices, the transcript, the composer, history files, the clipboard or a recording. Wire bodies holding it implement `Debug` by hand as `[redacted]`.
3. Pasting into the key field never reaches the composer or its large-paste collapse.
4. The socket call is `model.save_key`, whose `api_key` the recorder withholds (`P1-04` deny-set). The validate request carries the key in a REST body field named `value`, and the endpoint routes in `api_key`; the recorder's key-name net would not catch `value`, so `P4-01`'s REST client must never log or record request bodies. If it does, stop (issue stop conditions).
5. The clipboard receives only a sign-in code or a command, never a key.
6. An account email from a poll is shown on screen only.

### 4.12 Wiring, in-flight work and lifetimes

**Which crate holds what.** `P0-02`'s layering test forbids `talaria-app` from reaching `ratatui` or `crossterm`, and `talaria-tui` and `talaria-app` never name each other's types (`P1-09`, whose masked answers `P1-12` converts in `talaria-cli`). So:

| Crate | This unit's part |
|---|---|
| `talaria-core` | `ProvidersState`, `update`, `view`, `next_deadline`, `parse_providers_args`; every rule of sections 4.3 to 4.9 and this section |
| `hermes-client` | wire structs and one async function per route |
| `talaria-app` | `ProviderService`; in `app.rs`, building the service and carrying `ProvidersInput` and `ProvidersEffect` (core types both crates can name) through `P1-12`'s application messages |
| `talaria-tui` | `SecretField`, `draw_providers`, `osc52`, the key context; `InlineTerminal::copy_to_clipboard` in `P1-06`'s `terminal.rs` |
| `talaria-cli` | `providers_wiring.rs`: the only code that names both a `talaria-tui` type and `ProviderService` |

**`ProvidersWiring`** (`crates/talaria-cli/src/providers_wiring.rs`), a plain struct holding the overlay's one `SecretField`:

```rust
pub struct ProvidersWiring { field: SecretField }
impl ProvidersWiring {
    pub fn new() -> Self;
    // While view.secret_focus is true, the key goes to the field first:
    // Edited{empty} -> SecretEdited{empty}, Submit -> SecretSubmitted, Clear -> SecretCleared, NotHandled -> Key(key).
    // While it is false, every key becomes Key(key).
    pub fn route_key(&mut self, view: &ProvidersView, key: ProvidersKey) -> ProvidersInput;
    pub fn route_paste(&mut self, view: &ProvidersView, text: &str) -> Option<ProvidersInput>; // None when no field takes paste
    // Some(owned copy) only for CheckKey, SaveKey, and CheckEndpoint or SaveEndpoint whose draft has ApiKeyChange::Typed.
    pub fn secret_for(&self, effect: &ProvidersEffect) -> Option<zeroize::Zeroizing<String>>;
    pub fn forget(&mut self);       // on ForgetSecret: field.clear()
    pub fn secret_len(&self) -> usize; // for draw_providers
}
```

The copy is built without a second unzeroed buffer: `let mut s = Zeroizing::new(String::with_capacity(field.value().len())); s.push_str(field.value());`. The loop's obligations, at the seam `P1-12` merged for `P1-09`'s masked answers (the same place a masked card's keys are routed and its value is handed to a `talaria-app` service):

1. While the overlay is open, keys and paste go through `route_key` and `route_paste` into `update`.
2. For each effect from `update`: `ForgetSecret` → `forget()`; `CopyText(t)` → `terminal.copy_to_clipboard(&t)` and the notice of 4.2; `OpenUrl(u)` → spawn `opener_argv(&u)`, and on `None` or a spawn error send `ProvidersInput::OpenFailed` into `update`; `Close` → `service.close()` in a task and close the overlay; any other effect → spawn a task running `service.execute(effect, wiring.secret_for(&effect))` whose returned inputs come back as application messages and go into `update`.
3. Draw with `draw_providers(&view, wiring.secret_len(), ..)` only after an input, a reply or a `Tick`; arm one timer from `next_deadline` after each `update`.

If `P1-12`'s merged code has no such seam, or using it needs more than `mod providers_wiring;` and these calls in its files, stop (issue stop conditions). The wiring's logic is tested by unit tests in the same file (tests 33 and 34), which drive the real `ProvidersWiring` and the real core with no terminal and no service.

**Writes and checks** (D10). Writes: `SaveKey`, `Disconnect`, `SignOut`, `SaveEndpoint`, `DeleteEndpoint`, `StartSignIn`. Checks: `CheckKey`, `CheckEndpoint`. At most one write or check is in flight across the whole overlay; a key that would emit another shows `Waiting for Hermes.` and emits nothing. A save that follows its own check (the second step of 4.3) is not a second request in flight: the check has answered. Loads, `Poll` and `CancelSignIn` are never blocked and never count.

**Cards during in-flight work.** Key card: 4.3 (field locked, Esc closes, a late check answer is dropped, a late save answer is applied). Endpoint form: 4.6 (same rules). Confirmations (remove, sign out, delete) close when `y` is pressed; their answer arrives as a notice and reloads.

**Loads.** At most one load per list (env, options, accounts, endpoints) is in flight. A load asked for while one runs (Ctrl+R, a reload after a write, a reconnect) sets a "load again" mark; when the running load answers, its answer is applied and the load runs once more. Replies therefore never arrive out of order for one list. `OptionsLoaded` never reorders rows (4.3).

**Notices.** One notice line at a time. A notice stays until another notice replaces it, a card or form opens, the tab changes, or the overlay closes. Reloads, Ctrl+R and filtering do not clear it (UAT-3 and UAT-4 read it after a reload).

**Connection.** `Connection { connected: false }` shows the banner `Not connected to Hermes. Changes are off until Talaria reconnects.`; every write and check key does nothing while it shows (the banner is the explanation; no notice). REST loads and sign-in polling continue. `Connection { connected: true }` removes the banner and emits every load (through the "load again" rule). An unknown outcome that happened while disconnected reloads on reconnect.

**Sign-in identity.** 4.5: start answers carry `attempt`, poll answers carry `session_id`; stale answers are ignored and a stale start is cancelled. The service also skips a poll whose session was cancelled (4.2).

## 5. Request and result shapes

### 5.1 Socket

```json
{"jsonrpc":"2.0","id":"<n>","method":"model.options","params":{"include_unconfigured":true}}
{"jsonrpc":"2.0","id":"<n>","method":"model.options","params":{"explicit_only":false,"include_unconfigured":true,"refresh":false}}
{"jsonrpc":"2.0","id":"<n>","method":"model.save_key","params":{"slug":"ollama-cloud","api_key":"<secret>"}}
{"jsonrpc":"2.0","id":"<n>","method":"model.disconnect","params":{"slug":"ollama-cloud"}}
```

Both `model.options` forms are correct. `P0-03`'s unit specification records that its generator writes a property with a non-null default (`explicit_only`, `refresh`: default `false`) as a plain value that is always serialised, and skips an unset nullable one (`profile`, `session_id`: default null). Hermes accepts `false` for the flags but refuses a present non-string `profile` or `session_id`, including `null` (H1). So test 23 asserts: the keys are a subset of the five; `include_unconfigured` is `true`; `explicit_only` and `refresh` are absent or `false`; `profile` and `session_id` are absent. If the generated type serialises `profile` or `session_id` as `null`, stop and report it against `P0-03` (do not hand-build the JSON and do not use `call_raw`). For `model.save_key` and `model.disconnect`, `session_id` is nullable with default null, so the generated params serialise to exactly `{slug, api_key}` and `{slug}`.

Replies: `{"result":{"providers":[...],"model":"...","provider":"..."}}`; `{"result":{"provider":{"slug":"ollama-cloud","name":"Ollama Cloud","models":[...],"total_models":12,"authenticated":true,...}}}`; `{"result":{"slug":"ollama-cloud","name":"Ollama Cloud","disconnected":true}}`; errors `{"error":{"code":4005,"message":"no credentials found for ollama-cloud"}}`. Send them with `Client::call_with::<methods::legacy::model_options::Marker>` (30 s) and the matching `model_save_key` and `model_disconnect` markers (all three are `NativeMethod` under `P0-03`'s rule); never `call_raw`. `ModelOptionProvider` is an open object in the generated contract with optional `auth_type`, `key_env` and `warning` (H2); verify the generated field names at the pinned commit.

### 5.2 REST

Every request: through `P4-01`'s `RestClient` (`x-hermes-gateway-ticket: <fresh native-http ticket>`, no `Origin`, `Content-Type: application/json` when there is a body, no `profile`). GET uses `get_json`, POST `post_json`, DELETE `delete_json` (section 4.2).

| Call | Request | Success body |
|---|---|---|
| list keys | `GET /api/env` | `{"<VAR>": {is_set, redacted_value, description, url, category, is_password, tools, advanced, channel_managed, provider, provider_label, provider_profiles, provider_primary, custom}, ...}` |
| check a key | `POST /api/providers/validate` `{"key":"<VAR>","value":"<secret>"}` | `{ok, reachable, message}` |
| list accounts | `GET /api/providers/oauth` | `{providers:[{id, name, flow, cli_command, docs_url, disconnect_hint, disconnect_command, disconnectable, status}]}` |
| start sign-in | `POST /api/providers/oauth/<id>/start` `{}` | `{session_id, flow, user_code, verification_url, expires_in, poll_interval}` (seconds) |
| poll | `GET /api/providers/oauth/<id>/poll/<session_id>` | `{session_id, status, error_message, expires_at (epoch seconds), reason, account_email, model, retryable, retry_after}` |
| cancel | `DELETE /api/providers/oauth/sessions/<session_id>` | `{ok, session_id}` or `{ok:false, message}` |
| sign out | `DELETE /api/providers/oauth/<id>` | `{ok:true, provider}` |
| list endpoints | `GET /api/providers/custom-endpoints` | `{endpoints:[{id, name, base_url, model, models, api_mode, context_length, discover_models, has_api_key, api_key_preview, is_current, source}], current:{provider, model, base_url}}` |
| test endpoint | `POST /api/providers/custom-endpoints/validate` (body 4.6) | `{ok, reachable, message, models, model_details?, transport_checked?, resolved_base_url?}` |
| save endpoint | `POST /api/providers/custom-endpoints` (body 4.6) | list + `{ok:true, id}` |
| delete endpoint | `DELETE /api/providers/custom-endpoints/<id>` | list + `{ok:true}` |

Path segments (`<id>`, `<session_id>`) are percent-encoded. Deserialise every reply leniently: unknown fields are ignored, every optional field is `Option`, and `detail` may be a string or a list.

## 7. Edge cases

| Case | Expected behaviour |
|---|---|
| `GET /api/env` fails, `model.options` succeeds | Keys tab shows the load failure; the picker entry path still works when the option row has `auth_type: "api_key"` and `key_env` (4.3) |
| A key with spaces or a newline pasted | Surrounding whitespace trimmed; `\r` and `\n` dropped; inner spaces kept (Hermes trims too) |
| Enter pressed twice quickly | The second is ignored while the first write or check is in flight (D10) |
| Esc while a key check runs | Card closes, key forgotten; the check's answer is dropped; nothing is saved (4.3) |
| Esc then Enter again on a sign-in | Old start or poll answers are ignored; a stale start is cancelled (4.5) |
| A poll answers 429 or an unknown `status` | Counts as a failed poll; three in a row end with the lost-contact text (4.5) |
| Base URL edited after a successful test | Test result cleared; Save sends the typed URL and no discovered models (4.6) |
| Validate says `Provider returned HTTP 500 for this key.` | Blocked like a rejection (D4); Enter checks again later |
| `model.save_key` answers with the synthetic row (`models: []`) | Row shows `ready · key …wxyz` with no model count |
| The env row's slug is not in Hermes's registry | `model.save_key` answers 4002; text from 4.7; nothing saved |
| Variable shared by two providers | One row; `also used by <label>` dim line; removal names the other provider |
| Removing `copilot` | Hermes also removes `GH_TOKEN` and `GITHUB_TOKEN`, which the Keys list does not show as `copilot`'s; the confirmation's "including" covers it; record the observation in the journal if the live run meets it |
| Connection drops during `model.save_key` | `Unknown` text; on reconnect `LoadEnv` and `LoadOptions` run; no retry |
| REST endpoint save times out after sending | `Unknown` text; `LoadEndpoints` now; no retry |
| Gateway restarts during a sign-in | Poll gets 404 or connection errors; ended state as 4.5 |
| Two Talaria windows sign in to the same provider | Each has its own session id; Hermes keeps both until approved or expired; no special handling |
| `poll_interval` is 0, negative or missing | Treated as 2 s |
| `expires_in` missing | Countdown hidden; local expiry not applied; server status still ends it |
| `verification_url` is not https | Shown literally; `o` refuses (4.5) |
| Hostile text in a name or message (escape sequences, bidirectional overrides) | Sanitised; drawn literally; never copied or opened |
| `source_label` is a file path | Shown on screen; scrubbed from posted evidence (home folder to `~`) |
| Endpoint id with `/` or spaces | Percent-encoded in the path |
| Adding an endpoint whose name already exists | Refused locally (4.6); nothing sent |
| Delete of the default endpoint | Confirmation includes the default-provider sentence |
| Edit of an older-format (`custom_providers`) row | Allowed; Hermes converts it to the newer format on save |
| Overlay opened while not connected | REST lists load; `LoadOptions` fails as not sent (Keys statuses read as "options failed"); writes and checks do nothing under the banner; reconnecting reloads every list (4.12) |
| Overlay closed during a sign-in start | The service cancels the session when the start answer arrives |
| 80 by 24 terminal | Columns truncate with `…`; the masked field and the sign-in code are never truncated (the code wraps if needed) |
| Clipboard copy in a terminal without OSC 52 (Operating System Command 52) support | The notice says `Copied to the clipboard if your terminal allows it.`; Talaria cannot detect support; the code and command are also on screen |

## 8. Test notes

- **Order matters.** Write the tests in the issue's order: the pure core tests (1 to 19), the REST client tests (20 to 22), the service tests (23 to 27), the terminal tests (28 to 32), the wiring tests (33, 34), the picker update (35), then the live tests (36 to 38). Each must fail first, against stubs with the fixed names, for its reason: core tests because the stub `update` returns no effects and the stub `view` is empty (tests 1 to 3 because no rows are built); REST tests because the stub functions send nothing; service tests because the stub `execute` returns no inputs and `expires_in_s` is never set; terminal tests because the stub field stores nothing and the stub draws nothing; wiring tests because the stub `secret_for` returns `None` and `route_key` passes every key to core; test 35 because the old notice is still returned; live tests because the stubs fail.
- **Test 9** covers `parse_providers_args` on ``, `keys`, ` Accounts `, `ENDPOINTS`, `keys x`, `foo` (4.2), the Esc order (card, then filter, then overlay), filter terms (every lower-cased word a substring) and `No provider matches "<filter>".`
- **Test 10** covers the notice lifetime, the banner with writes and checks doing nothing, reconnect emitting every load, and the "load again" rule: a reload asked while a load runs gives exactly one more load after the answer (4.12).
- **Test 13** drives two sessions: Esc on a Waiting card, Enter again (attempt 2, new session), then the old session's poll answer `cancelled` and an attempt-1 start answer arrive. The new card is unchanged, no Poll is emitted for the old session, and one `CancelSignIn` is emitted for the stale start's session.
- **Test 27** feeds `talaria-app`'s conversion: `2026-10-22T10:00:00Z`, `2026-10-22T10:00:00.5+02:00`, epoch seconds `1792700000`, epoch milliseconds `1792700000000`, a string `"soon"`, `true` and `null` → the expected `expires_in_s` against a fixed now, or none.
- **Test 28** drives `SecretField` directly: typed characters and Backspace change `len`; paste of `"  sk-a b\r\n"` stores `sk-a b`; Ctrl+U returns `Clear` and `len` 0; Enter on an empty field returns `NotHandled`, never `Submit`; after many inputs the capacity is still 65,536.
- **Test 29** reads `P1-08`'s default `KeyMap` for `KeyContext::Providers` and checks the nine names and keys of 4.8.
- **Test 32** is a view-level check, not a loop test: after `update(Open)` with no replies the drawn buffer shows `Loading…`; 20 calls of `draw_providers` into a 160 by 48 buffer each take under 50 ms (measured with `Instant`, maximum reported); `next_deadline` is `None` with no card and after every list has loaded; with a Waiting card it is at most one second ahead, and after a fake-clock advance and `Tick` it moves one second on; after `Ended` it is `None`.
- **Tests 33 and 34** are unit tests inside `crates/talaria-cli/src/providers_wiring.rs` (`#[cfg(test)] mod tests`), so they run whether or not `talaria-cli` has a library target, with `cargo test -p talaria-cli providers_wiring`. They drive the real `ProvidersWiring` and the real core `update` and `view`, no terminal and no service. Test 33 (proptest) types and pastes random keys, runs check, save, cancel, Ctrl+U and close, feeds every effect through `secret_for` and `forget` as the loop does, and formats every core input, effect, state and view with `{:?}` plus a buffer drawn with `draw_providers`; the key must appear nowhere, and after `ForgetSecret` the field's `len()` is 0. Test 34 checks `secret_for` on every effect variant and that `route_key` gives keys to the field only while `secret_focus` is true.

Test 24 captures `tracing` output with a test subscriber when the workspace already pins one (otherwise with a hand-written `tracing` layer), formats every effect, input and wire body with `{:?}`, and, with the recorder on, scans its file with `P1-04`'s `scan_literals`.
