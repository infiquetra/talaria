# P5-00: Measure the gateway with ten or more concurrent sessions before workflows depend on it (unit P5-00)

Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

## How to use this document

This exploration has no product code. It produces a live probe, offline checks, a results file and a
finding. The issue says what to deliver, the health rule and when to stop. This document holds the
depth: the evidence behind every static reading (`path:line` at Hermes v0.22.4), the exact record
schema with nullability, the per-series procedures with their barriers and deadlines, the loopback
provider's scripts, the event-tracking rules, the privacy rules, the merge rules and the notes for
each offline test. Read section 1 before step 1 of the investigation, sections 2 and 6 while writing
the offline tests, and sections 3 to 5 while writing the live probe.

Every Hermes fact below was read in the v0.22.4 source. Facts marked "verify" were not traced end to
end; check them at the pinned commit before relying on them, and record the answer in the finding.

## 2. The results file

`fixtures/gateway-concurrency/results.json`:

```json
{
  "hermes_release": "v0.22.4",
  "execution_mode": "in-process",
  "runs": [ ... ],
  "recommendations": {
    "default_max_in_flight": 10,
    "topology": "shared",
    "memory_mb_per_session": 42.5,
    "cited_runs": ["A-shared-10", "A-per-session-10"]
  }
}
```

`execution_mode` is `in-process`, `managed-worker` or `unknown`, taken from the operator's answer to
the precondition question (no configuration value is recorded). `recommendations` is computed by
`recommend()` (section 6) and its fields are `null` when no topology has a healthy width.

| Key | Type | Live record | `not-run` record |

Percentiles use nearest rank: sort ascending, take index `ceil(q * n) - 1`; `max` is the last value.
A percentile object is built only from samples that exist; a call that failed or timed out adds no
sample and is counted instead (`rpc_errors`, `timeouts`). A required percentile with zero samples on
a live record is `null` and listed in `unavailable` with reason `no samples`.

### 2.2 Event tracking

The probe tracks sequence per pair (`params.session_id`, `params.replay_epoch`). For each frame:

- same epoch, `seq` equal to the last: `seq_repeats` + 1;
- same epoch, `seq` lower: `seq_decreases` + 1;
- same epoch, `seq` higher by more than 1: `seq_gaps` + 1, and the missing range is remembered;
- new epoch for a known session: `epoch_changes` + 1 (never an anomaly);
- `session.replay_gap`: `replay_gaps` + 1.

After the run's last terminal outcome and before cleanup, for each session with a gap, an epoch
change or a replay gap, the probe calls `session.events.since {session_id, last_sequence, replay_epoch}`
with the last contiguous sequence it holds. A gap is resolved when the returned `events` contain the
missing sequences and `truncated` is false; otherwise it is unresolved.

`events` = `{"observed": int, "seq_repeats": int, "seq_decreases": int, "seq_gaps": int,
"epoch_changes": int, "replay_gaps": int, "unresolved_gaps": int, "peak_events_per_s": int,
"complete_per_admission": int}`.

- `peak_events_per_s`: the largest number of event frames whose arrival times fall in any window
  `[t, t + 1000 ms)`, with `t` the arrival time of a frame (a sliding window over sorted arrivals).
- `complete_per_admission`: the number of admissions for which exactly one `message.complete` was
  received. A healthy run has it equal to the admissions submitted (except series D, see 2.3).

### 2.3 Recovery fields (series D and E)

`recovery` = `{"terminal_with_result": int, "terminal_without_result": int, "unknown": int,
"unresolved": int, "receipt_ms": percentile, "resume_ms": percentile or null,
"next_turn_ms": int or null, "replay_truncated": int, "submit_after_detach_refused": bool or null,
"eviction_evidence": string or null}`.

- `receipt_ms`: from the reconnect (D) or the end of the wait (E) to the first receipt that is
  `terminal` for that admission.
- `unresolved`: admissions still `queued` or `started` at the deadline.
- `replay_truncated`: sessions whose `session.events.since` from the last sequence seen before the
  drop returned `truncated: true` (D only).
- `submit_after_detach_refused`: E only; `true` when the negative submit returned `permission_denied`.
- `eviction_evidence`: `null` unless the run shows positive evidence that the canonical session was
  evicted and rebuilt (no such signal is known at v0.22.4; S3). A wait and a width above 16 are not
  evidence.

In series D, `turn_ms`, `batch_wall_ms`, `turns_completed`, `turns_failed` and
`complete_per_admission` are `null` and listed in `unavailable` with reason
`connection dropped by design`. Turn outcomes for D come from `recovery`. `start_delay_ms` is
measured, because every admission is `started` before the drop.

### 2.4 Observations

`observations` = `{"tool_names": [string] or null, "tool_executions": int or null,
"rate_limit_keys": [string] or null, "failure_examples": [{"status": string, "kind": string}],
"admission_statuses": {"queued": int, "started": int, "unknown": int, "terminal": int}}`.

- `tool_names`: the tool names in the first create's snapshot (names only), on the first record of
  each series; `null` elsewhere.
- `tool_executions`: series C only: sessions with exactly one `tool.start` and one `tool.complete`
  for `todo_list`.
- `rate_limit_keys`: series B only: the key names seen in `session.usage.rate_limit`, never values.
- `failure_examples`: at most three; `kind` is the `failure_reason` or `error` reduced to the
  characters `[a-z0-9_.]` and at most 40 characters (for example `rate_limited`). Never message text.
- `admission_statuses`: the `status` values of the `prompt.submit` replies.

### 2.5 Fixed not-run phrases

A `not-run` record's `notes` is exactly one of:

| Phrase | Allowed by the final evidence gate |
|---|---|
| `stopped after an unhealthy width` | yes |
| `above the operator's width cap` | yes, only if `TALARIA_PROBE_MAX_WIDTH` was set by the operator (recorded in the finding) |
| `toolset refused: <reason code>` | series C only |
| `operator waived` | series B only |
| `unsupported_managed_policy` | series B only |
| `loopback provider refused: <reason code>` | no |
| `timebox reached` | no |
| `stopped: <stop condition>` | no |

### 2.6 Merging records

The record writer takes an exclusive lock on `results.json.lock` in the same directory, reads the
file (or starts an empty one), and replaces records by `id`: a new record always replaces an older
one with the same id. It refuses (and the test fails) when the file's `hermes_release` differs from
the run's. Records from different `run_id`s may coexist; the finding lists each `run_id` with its
date and Talaria commit. The operator's series B lines are imported with the ignored test
`import_operator_records`, which reads the file named by `TALARIA_PROBE_IMPORT` (one `RECORD <json>`
per line), validates each record against this schema and merges it.

## 3. The probe's outbound shapes

```json
{"method": "session.create", "params": {"request_id": "talaria-probe:<run>:<record id>:<n>", "source": "tool", "hidden": true,
  "model": "talaria-probe-stub", "provider": "custom", "base_url": "http://127.0.0.1:<port>/v1",
  "api_key": "talaria-probe-placeholder", "toolsets": []}}
{"method": "prompt.submit", "params": {"session_id": "<from create>", "submission_id": "talaria-probe:<run>:<record id>:<n>:<rep>",
  "text": "Reply with the single word READY.", "finite": true}}
```

- No `title` (S6b). `request_id` and `submission_id` are used exactly once; nothing is retried.
- Series B replaces `model`, `provider`, `base_url` and `api_key` with
  `"model": "minimax-m3.1-flash", "provider": "ollama-cloud"` and nothing else.
- Series C sends `"toolsets": ["todo"]`.
- Never sent: `unattended`, `yolo`, `cwd`, `profile`, `title`.
- `<run>` is eight random lowercase hexadecimal digits; `<n>` is the session index from 0.

**Descriptor gate.** Before a series, the probe calls `runtime.describe` and requires `tool` in
`session_create.sources` and `request_id`, `source`, `model`, `provider`, `base_url`, `api_key` and
`toolsets` in `session_create.parameters`. It does not require `hidden`, because the pinned
descriptor omits it (S6a); `hidden` is checked against the vendored contract's
`CanonicalCreateParams` instead. A missing required item records the series `not-run` with
`stopped: descriptor lacks <name>`.

## 4. The loopback provider

A `tokio` `TcpListener` on `127.0.0.1:0` speaking HTTP/1.1. It answers `POST /v1/chat/completions`;
any other route gets `404` and `unexpected_routes` + 1.

**Classification.** A request is a *turn request* when `stream` is `true` and its last message is
either a `user` message whose content contains `Reply with the single word READY.` or a `tool`
message. Every other request is *auxiliary* (`aux_requests` + 1) and gets a short non-streaming
`chat.completion` with content `probe` and `finish_reason: "stop"`. Auxiliary requests never count
towards the in-flight peak. If the first width-1 run sees a turn request count different from its
turn count, the probe stops with `stopped: turn request classification failed` (verify at the
pinned commit that the main agent streams; S12's fixture shows both modes).

**Scripts.** Frames follow S12 exactly:
`data: {"id":"local","object":"chat.completion.chunk","created":1,"model":"talaria-probe-stub","choices":[{"index":0,"delta":{...},"finish_reason":null}]}`.

| Script | Used by | Frames |
|---|---|---|
| `ready` | A, D, E | 20 content chunks `{"content":"R"}`..., 25 ms apart (about 0.5 s), then `{"delta":{},"finish_reason":"stop"}`, then `data: [DONE]` |
| `slow` | D | as `ready`, 40 chunks 500 ms apart (about 20 s) |
| `todo` | C, first request of a turn | one chunk `{"role":"assistant","content":null,"tool_calls":[{"index":0,"id":"probe-todo","type":"function","function":{"name":"todo_list","arguments":"{\"todos\":[{\"id\":\"1\",\"content\":\"probe\",\"status\":\"pending\"}]}"}}]}`, then `{"delta":{},"finish_reason":"tool_calls"}`, then `data: [DONE]` |
| `todo-followup` | C, request carrying the tool result | as `ready` |

**Peak per repetition.** The provider keeps a counter of turn requests in flight and the peak since
the last `reset_peak()`. The probe calls `reset_peak()` before each repetition's submit barrier and
reads the peak after it. `turn_requests_peak_min` is the smallest peak across repetitions.

## 5. Series procedures

### 5.1 Common shape

1. **Before.** Start the sampler and the foreground task. Wait 5 s; `rss_mb.before` is the median
   of those samples.
2. **Create barrier.** Open the connections (one shared, or one per session). Send all creates
   concurrently and wait for all replies (deadline 60 s for the barrier). Assert
   `distinct_sessions == width`; if not, record the run unhealthy (criterion 1) and stop the series.
3. **Repetitions.** For each repetition: reset the provider peak; send all submits concurrently
   (the submit barrier is the join of the sends); wait until every admission of this repetition has
   its terminal outcome or its per-turn deadline passes. The next repetition starts only then.
4. **Event check** (section 2.2), then **cleanup**: `session.detach {session_id, subscription_id}`
   for every session still subscribed, then close connections (deadline 30 s total).
5. **After.** Wait 60 s after cleanup; `rss_mb.after` is the median of the last 5 s of samples.
   `peak` is the largest sample from the first create to the end of cleanup.
6. Stop the sampler and the foreground task, compute the record, write it, print `RECORD <json>`.

**Clocks.** Every arrival time is taken by the inbound reader the moment it decodes a frame
(`std::time::Instant`). A turn's clock starts when the probe writes its `prompt.submit` frame, so an
event that arrives before the submit reply has a positive duration and is never clamped. Events are
matched to an admission by `params.admission_id` when present; otherwise by session and order (the
probe sends one turn per session at a time). An event that arrives before the reply is buffered by
session id until the reply names its admission.

### 5.2 Deadlines

| What | Deadline | On expiry |
|---|---|---|
| A single RPC (create, submit, receipt, resume, detach, describe) | 30 s | `timeouts` + 1; the outcome is unknown, never success |
| Create barrier | 60 s | criterion 1 fails; stop the series |
| Per turn, loopback | 60 s after the submit frame | `timeouts` + 1; keep the admission id |
| Per turn, series B | 300 s | as above |
| Series D receipts | 120 s after reconnect | remaining admissions counted `unresolved` |
| Whole record | 15 min | stop the record, clean up, record unhealthy |
| Cleanup | 30 s | note `cleanup incomplete` in `notes`; continue |

Nothing is resubmitted after a timeout. The test prints `UNHEALTHY <criteria>` for that record and
continues with the series rule; only a failed width-1 control makes the test fail.

### 5.3 Per series

| Series | Provider | Widths and topologies | Repetitions | Specific steps |
|---|---|---|---|---|
| A | loopback `ready` | 1, 5, 10, 16, 20; shared and per-session | 3 | Each topology ascends on its own. A width that fails criterion 1 stops larger widths in that topology only (`stopped after an unhealthy width`). |
| B | `minimax-m3.1-flash` on `ollama-cloud` | 1, 5, 10, 16; shared | 1 | Operator run. A create refused with `unsupported_managed_policy` records all four `not-run` with that phrase. |
| C | loopback `todo` then `todo-followup` | 10; shared | 1 | `toolsets: ["todo"]`. A refused create records `toolset refused: <reason>`. |
| D | loopback `slow` | 10; shared | 1 | After every submit reply says `started` (or the first `message.start` per session arrived; deadline 30 s), remember each session's last `seq` and epoch, close the WebSocket without `session.detach`, wait 5 s, connect a new client with a fresh ticket. Poll `prompt.receipt {session_id, admission_id, include_result: true}` once per second per admission until terminal (120 s). Then for each session: `session.resume {session_id}`, `session.events.since` from the remembered position, `session.detach` with the new `subscription_id`. |
| E | loopback `ready` | 20; shared | 1 (plus one extra turn) | After all 20 turns complete: detach all, wait 60 s. Then `session.resume` on the earliest session (timed, `resume_ms`), submit one more prompt (timed to its `message.complete`, `next_turn_ms`), detach with the new `subscription_id`. ### 5.4 The sampler

`ps -A -o pid=,ppid=,rss=,time=` every 500 ms. The tree root is the gateway `pid` from `identify`
(S11). `rss` is KiB. `time` is `[[dd-]hh:]mm:ss[.ff]` (Linux `00:01:02`, macOS `1:02.50`).
`cpu_s_estimate` is the sum, over processes present in both the first and the last sample of the
batch, of the change in `time`. It misses children that start and exit between samples; the finding
labels it an estimate. A malformed line is skipped and counted in `sampler_bad_lines`. If `ps` exits
non-zero or the root pid disappears, `resources` is `null` with reason `sampler failed`.

## 6. The health rule and recommendations

Criteria (the issue's numbering):

| # | Holds when | Applies to |
|---|---|---|
| 1 | `create_refused`, `admissions_unknown`, `timeouts` and `turns_failed` are 0; `rpc_errors` is empty; `distinct_sessions` equals width; `turns_completed` equals width times repetitions | A, B, C, E (D: only the create and admission parts) |
| 2 | `start_delay_ms.p95` is at most the baseline's `p95` plus 1,000 ms; in loopback series `turn_requests_peak_min` equals width | A, B, C, D, E (B without the peak part) |
| 3 | `foreground_rtt_ms` exists, `p95` at most 50, `max` at most 250, `foreground_errors` 0 | all |
| 4 | `rss_mb.after` within 20% of `rss_mb.before` | all |
| 5 | `seq_repeats`, `seq_decreases` and `unresolved_gaps` are 0 and `complete_per_admission` equals the admissions submitted | A, B, C, E |
| 6 | every admission `terminal_with_result`; `unknown` and `unresolved` 0; in E also `submit_after_detach_refused` true and the extra turn completed | D, E |
| 7 | `tool_executions` equals width and every turn's status is complete | C |

Baseline for criterion 2: the same series and topology at width 1 (A-shared-1, A-per-session-1,
B-shared-1). C, D and E use A-shared-1. If the baseline record is not live, criterion 2 fails with
`unavailable` reason `no baseline`.

`healthy(record, baseline) -> (bool, Vec<u8>)`. `highest_healthy(records) -> Option<u32>` takes the
records of one series and topology and returns the largest width `w` such that every width up to and
including `w` is live and healthy; `None` when width 1 is not.

`recommend(results) -> Recommendations`:

1. `hs` = `highest_healthy` of A-shared; `hp` = of A-per-session.
2. If both are `None`: every field `null`; the finding reports "no healthy width" and the operator
   decides (a stop condition for phase 5 planning, not a default of 1).
3. `topology` = `shared` if `hs >= hp` (treating `None` as 0), else `per-session`.
4. `default_max_in_flight` = `min(highest of the chosen topology, 10)`.
5. `memory_mb_per_session` = `(peak - before) / width` of the chosen topology's record at that width.
6. `cited_runs` = the record ids used in steps 3 to 5.

## 7. Privacy rules (test 7)

Files checked: `results.json`, the finding, `live_gateway_concurrency.rs`, `concurrency_probe/mod.rs`.

- **Filesystem paths:** reject the macOS home root (`/Users` followed by a slash), `/home/`, `/private/`, `/tmp/`, `/var/`, `/root/`, `~/`
  and `[A-Za-z]:\` at a token start. HTTP routes (`/v1/chat/completions`) and URLs are allowed.
- **Tickets and keys:** reject `hermes-gateway-ticket.` and any run of 40 or more `[A-Za-z0-9_-]`
  characters, except a 40-character lowercase hexadecimal commit id in the finding.
- **Names:** reject the values of `USER` and `LOGNAME` as whole words, and every name in
  `TALARIA_PRIVATE_NAMES` (comma-separated, supplied by the operator at run time, never committed).
  Profile names other than `default` and `fixture` are caught by that list.
- **Allowed public constants:** `talaria-probe-stub`, `talaria-probe-placeholder`, `custom`,
  `ollama-cloud`, `minimax-m3.1-flash`, `http://127.0.0.1:<port>/v1`, `fixture`, `default`.
- **Serialisation allowlist:** the record writer emits only the keys of section 2; free text exists
  only in `notes` (fixed phrases) and `observations.failure_examples[].kind` (sanitised).
