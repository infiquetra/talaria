## 3. The `python-final` tag target

Decision 2 and the risks document say the tag goes on "the v0.6.5 commit". The roadmap's unit P0-02 step 1 says "tag the current `main`", and the P0-02 issue follows the roadmap: it tags the commit where its branch starts and stops if Python paths changed since `v0.6.5`. The issue for this unit therefore says `main` is tagged where the P0-02 branch starts and leaves the choice of commit to P0-02. Both give the same Python client on 2026-10-22:

- The tag `v0.6.5` points at the commit titled "test(acceptance): skip installed-identity when the local talaria is absent".
- `git diff --stat v0.6.5 origin/main -- talaria tests pyproject.toml` prints nothing: the package, the tests and the project file on `main` are identical to the tag. The six commits after the tag do not touch those paths.

The issue therefore says the tag goes on the last Python commit on `main`, which is what P0-02 step 1 does when it runs. If a Python change merges to `main` before P0-02 runs, that change is in the tag, which is the intent: the tag is the last Python-era commit.

## 4. Hidden sessions (decision 8, reading (b))

Verified at Hermes v0.22.4:

- `CanonicalCreateParams` (the parameters of `session.create`) has `profile` (string or null) and `hidden` (boolean, default false). The handler rejects a non-boolean `hidden` (`gateway/session_controls.py:441` to 443) and marks the new session hidden (lines 481 and 482). A comment at line 439 calls this "Bot Mode's forever-chat mint: born hidden from the sidebar".
- `CanonicalListParams` (the parameters of `session.list`) has `include_hidden` (default false), `limit`, `profile`, `scope` and `title`. `session.list` skips rows that are hidden or archived unless `include_hidden` is set (`gateway/session_controls.py:550`).

The handler is `list_sessions` (`gateway/session_controls.py:511`). The default scope is `live` (line 517), and its loop skips hidden or archived rows unless `include_hidden` is set (lines 548 to 550). Scope `stored` passes `include_hidden` to `stored_picker_sessions` (lines 519 to 522). A `title` lookup (lines 523 to 540) returns a hidden chat regardless.

Consequence for the issue set: the gateway already hides the session, so the session picker (unit P2-07) needs no client-side filter and must not pass `include_hidden: true` by default. The resident-agent unit (P3-09) must pass `include_hidden: true` to find its agents. These were read at v0.22.4 only; verify both at the pinned commit before relying on them.

## 6. Why the issue makes four choices on the operator's behalf

1. **Part 2 stops for the alternative on decisions 1, 2 and 3.** Decision 1 changes the text of ADR-0010. Decision 2 (a new repository) leaves it unclear where the ADRs belong. Decision 3 (a rename) changes the title of every moved ADR. Stopping costs a delay; running costs a wrong pull request. Decisions 4 to 8 change the issue set, not the ADR text, so Part 2 can run and the journal entry records them.
2. **The date is the date of the `decisions recorded` comment.** The issue body has no record of when the last box was ticked, and the body's last-edited time moves with any later edit. A comment has a fixed timestamp, and the operator already posts it to release Part 2.
3. **The journal's rationale cites existing handoff figures, never new ones.** The launch figure the handoff supports is 1.2 s to a usable composer against a live backend (`02-current-state.md`, from research report u13) and 107 ms at the 95th percentile for keystrokes while a reply streams (the same document, from u02). Neither was re-measured for this issue. The 0.4 s and 1.1 s cold-launch figures belong to the bytecode-compile advice in decision 7 and are not the figure to cite.
4. **`CLAUDE.md` is in scope for four sentences.** The unit that rewrites it later (P0-02) is blocked by this one, and its builder reads `CLAUDE.md` first. Leaving the file saying "ADR-0001 through ADR-0006 are accepted" after this pull request merges would make the repository contradict the ADR folder this unit exists to fix.

## 7. Dependent decisions and gates
