## 3. Re-deriving the three-way file list

The roadmap's list was written against the 2026-10-22 tree. Run this at the start of the work, on a clean checkout of the newest `origin/main`, and paste its summary into the pull request. It is a build-time tool: do not commit it.

```python
# classify.py: run with `python3 -I classify.py` from the repository root.
import subprocess
import sys

files = subprocess.check_output(["git", "ls-files"], text=True).split("\n")
files = [f for f in files if f]

REMOVE_DIRS = ["talaria/", "tests/", "scripts/", "src/", "docs/acceptance/", "docs/plans/",
               "docs/reviews/", "docs/code-reviews/", "docs/work-sessions/", "docs/brainstorms/",
               "docs/ideation/", "docs/evidence/", "docs/design/", "docs/releases/",
               "docs/examples/"]
REMOVE_FILES = ["package.json", "package-lock.json", "tsconfig.json", "vitest.config.ts",
                "pyproject.toml", "uv.lock", ".python-version", "GEMINI.md", "IDEA.md",
                ".prettierignore", ".github/copilot-instructions.md",
                ".github/workflows/validate.yml", "docs/install.md", "docs/themes.md",
                "docs/terminal-ui.md"]
REWRITE = ["README.md", "AGENTS.md", "CLAUDE.md", "llms.txt", "docs/00-index.md",
           "docs/README.md", ".github/workflows/release.yml"]
KEEP_DIRS = [".github/ISSUE_TEMPLATE/", "platform-specs/", "docs/analysis/",
             "docs/engineering-journal/", "docs/formats/", "docs/handoff/"]
KEEP_FILES = [".gitattributes", ".gitignore", ".github/CODEOWNERS",
              ".github/PULL_REQUEST_TEMPLATE.md", ".github/dependabot.yml",
              "docs/configuration.md", "docs/public-safe-summary.md", "LICENSE", "CHANGELOG.md"]

groups = {"remove": [], "rewrite": [], "keep": [], "unclassified": []}
for f in files:
    if any(f.startswith(d) for d in REMOVE_DIRS) or f in REMOVE_FILES:
        groups["remove"].append(f)
    elif f in REWRITE:
        groups["rewrite"].append(f)
    elif any(f.startswith(d) for d in KEEP_DIRS) or f in KEEP_FILES:
        groups["keep"].append(f)
    else:
        groups["unclassified"].append(f)

named = REMOVE_FILES + REWRITE + KEEP_FILES
absent = [f for f in named if f not in files]
for name, members in groups.items():
    print(f"{name}: {len(members)}")
print("unclassified:", *groups["unclassified"], sep="\n  ")
print("named but absent:", *absent, sep="\n  ")
sys.exit(1 if groups["unclassified"] else 0)
```

Rules for what the script finds:

| Finding | What to do |
|---|---|
| A new file under a remove folder (for example a new plan under `docs/plans/`) | Remove it with the folder. Name it in the pull request. |
| A new file under a keep folder (for example a new journal entry, or the unit specifications under `docs/handoff/2026-10-22-next-steps/units/`) | Keep it. |
| A new file outside every group (for example a new top-level file) | Stop and report it on the issue. Do not guess its group. |
| A named file that is absent | Note it in the pull request and continue; there is nothing to remove or rewrite. |
| A file added by unit P0-01 under `platform-specs/04-architecture/adrs/` | Keep it (keep folder). |

Leave the untracked, git-ignored `corpora/` directory alone. It is not part of the repository and the script never sees it.

### 4.5 `crates/talaria-cli/src/main.rs`: the placeholder binary

The binary exists so the workspace has something to build, run and measure. It is not the client; unit P1-12 replaces it. It has no argument-parsing dependency. Its whole behaviour:

| Arguments | Standard output | Standard error | Exit code |
|---|---|---|---|
| `--version` or `-V` | `talaria 0.7.0-dev` and a newline (the version is `env!("CARGO_PKG_VERSION")`) | nothing | 0 |
| `--help` or `-h` | three lines, each ending in a newline: `talaria <CARGO_PKG_VERSION>` (built from the same constant, so it cannot drift); `This build is a placeholder while Talaria is rewritten in Rust; it does not connect to Hermes yet.`; `Options: --version, --help` | nothing | 0 |
| no arguments | nothing | `talaria: this build is a placeholder and does nothing yet. Run talaria --help.` and exactly one newline | 2 |
| anything else (only the first argument is examined) | nothing | ``talaria: unknown argument `<arg>`. Run talaria --help.`` with every control character in `<arg>` (Unicode general category Cc) and every character with the Unicode `Bidi_Control` property (exactly twelve: U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069) replaced by `?`, the argument cut to its first 64 Rust `char`s (Unicode scalar values, not bytes or grapheme clusters), and exactly one newline at the end | 2 |

Structure: a pure `fn respond(args: &[String]) -> Response` where `struct Response { stdout: String, stderr: String, code: u8 }`, and a `main` that collects `std::env::args_os().skip(1).map(|a| a.to_string_lossy().into_owned())` (so an argument that is not valid Unicode never panics), calls `respond`, writes both streams with `print!` and `eprint!` (the messages already end in their newline) and exits with `std::process::ExitCode::from(code)`. Only the first argument decides the result: `["--version", "extra"]` gives the same `Response` as `["--version"]` (test 9), and `["x", "--version"]` reports `x` as unknown (test 12). The unit tests in `main.rs` call `respond` directly, so `cargo llvm-cov` sees every branch without depending on subprocess instrumentation. Cutting and replacing are both per `char`, so their order does not change the count.

```yaml

  contents: read

      fail-fast: false

        os: [macos-14, ubuntu-latest]

      - name: Check out repository
        uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5

      - name: Install the pinned toolchain
        run: |
          rustup toolchain install

      - name: Format
        run: cargo fmt --check
      - name: Clippy
        run: cargo clippy --all-targets -- -D warnings
      - name: Test
        run: cargo test --workspace
      - name: Whitespace
        run: git diff --check origin/main...HEAD

        run: |
          ! git grep -nE '^(<{7}|={7}|>{7})( |$)' -- . || (echo "conflict marker" && false)

    name: rust-coverage
```

## 8. Links into removed files

Save this script outside the repository (for example as `"$TMPDIR/linkscan.py"`) and run it from the repository root after the removal commit. It is a build-time check, not a committed test. It resolves every relative Markdown link in every tracked `.md` file and in `llms.txt` (which uses Markdown links) and prints `file: link` for each target that does not exist. With `--written` it reports only the files this unit writes plus `CHANGELOG.md`, which is issue AC-17 (it must print nothing); without it, it reports everything, which gives the count for the pull request.

```python
# linkscan.py: run with `python3 -I linkscan.py [--written]` from the repository root.
import os, re, subprocess, sys

WRITTEN_FILES = {"README.md", "AGENTS.md", "CLAUDE.md", "CHANGELOG.md", "llms.txt",
                 "docs/00-index.md", "docs/README.md"}
WRITTEN_DIRS = ("tools/", "fixtures/", ".github/", "crates/")
only_written = "--written" in sys.argv[1:]

files = subprocess.check_output(["git", "ls-files", "*.md", "llms.txt"], text=True).split()
for f in files:
    if only_written and f not in WRITTEN_FILES and not f.startswith(WRITTEN_DIRS):
        continue
    text = open(f, encoding="utf-8").read()
    for m in re.finditer(r"\]\(([^)#\s]+)", text):
        link = m.group(1)
        if link.startswith(("http://", "https://", "mailto:")):
            continue
        target = os.path.normpath(os.path.join(os.path.dirname(f), link))
        if not os.path.exists(target):
            print(f"{f}: {link}")
```

### 9.2 Reading the workspace graph

`layering.rs` runs `cargo metadata --format-version 1 --locked --all-features --manifest-path <root>/Cargo.toml`. `--all-features` matters: without it, an optional dependency that only a feature turns on (for example a future feature of `talaria-core` that enables `ratatui`) is absent from the graph and the test would pass; a comment in the test says so. The cargo binary is `std::env::var("CARGO")`, which cargo is documented to set when it runs tests (not verified here: check it on the first run); if the variable is unset, fall back to `cargo` on `PATH` and say in the pull request which was used. The root is `concat!(env!("CARGO_MANIFEST_DIR"), "/../..")`. Parse with `serde_json::Value`. The graph is under `resolve.nodes`: each node has `id` and `deps`, each dep has `pkg` and `dep_kinds` (a list of `{ "kind": null | "build" | "dev", "target": ... }`). Count an edge if any of its `dep_kinds` has `kind` null (normal) or `"build"`; ignore `"dev"`. Map package ids to names through `packages[].id` and `packages[].name`. Compute each crate's closure with a breadth-first walk. The failure message names the crate, the forbidden crate and the path between them (for example `talaria-core -> crossterm`), so a reader knows what to remove.

Test 4 (`workspace_holds_the_seven_planned_crates`) reads `workspace_members` and each member's `manifest_path`, turns the path into one relative to the root, and asserts: each of the seven REQ-10 packages is a member whose manifest is `crates/<name>/Cargo.toml`; every member whose manifest is under `crates/` is one of the seven; every other member's manifest is under `tools/`. Later units add tool crates under `tools/` (P0-04, P1-04, P1-11, P1-13) without touching this test.

Test 8 (`every_crate_inherits_the_workspace_settings`) uses a plain text check, so the unit adds no TOML parser: `cargo metadata` does not report lint settings or whether a key was inherited, and a `toml` dependency would be a new pin outside REQ-12. A "section" is the lines after a header line up to the next line starting with `[`. For the root manifest, the `[workspace.lints.rust]` section has a line `unsafe_code = "forbid"`. For each member manifest (paths from `cargo metadata`), the `[lints]` section has a line `workspace = true`, and the `[package]` section has the lines `version.workspace = true`, `edition.workspace = true`, `rust-version.workspace = true`, `license.workspace = true`, `repository.workspace = true` and `publish.workspace = true`. Ignore surrounding whitespace. A failure names the manifest (repository-relative) and the missing line. A comment in the test says why it reads text.

Test 14 (`toolchain_and_external_versions_are_pinned_exactly`) is also a text check. In `rust-toolchain.toml`, the `channel = "<v>"` line holds an exact `x.y.z` (three dot-separated numbers), compared numerically with 1.98.1 (at least), and equal to the value of the `rust-version = "<v>"` line in the root's `[workspace.package]` section. In the root's `[workspace.dependencies]` section, skip blank lines and lines starting with `#`; every other line is one entry (`name = "<req>"` or `name = { ... }`); an entry containing `path =` is skipped; for the rest, the version requirement (the quoted string itself, or the value of `version = "..."` inside the braces) starts with `=`. A failure names the entry. This is why every entry stays on one line.

`--locked` keeps the test from rewriting `Cargo.lock`. If CI shows `cargo metadata` needing the network after the build already fetched everything, add `--offline` and say so in the pull request.

### 9.3 Reading repository files from tests

`repository.rs` reads files relative to `concat!(env!("CARGO_MANIFEST_DIR"), "/../..")`. It never uses an absolute path in an assertion message: print the repository-relative path. It reads `ci.yml` as text; it does not parse YAML (no YAML dependency in this unit).

Test 1 asks git, not the disk: it runs `git -C <root> ls-files -- <every REQ-4 path>` (the folders with a trailing `/`, the files by name) and asserts the output is empty, printing any paths it lists. The reason is local leftovers: `git rm -r talaria scripts` leaves the git-ignored `__pycache__/` folders behind (on 2026-10-22 a working checkout held them under `talaria/` and `scripts/`), so a test that checked whether `talaria/` exists would pass in CI and fail on the builder's machine. If `git` cannot run, the test fails with a plain message saying so; it never passes by default.

Test 3's match rule: a baseline command is present when some line of `ci.yml`, with leading whitespace removed and an optional leading `run: ` removed, equals the command exactly. This holds for one-line `run:` steps and for lines inside a `run: |` block. Test 3 also asserts the substrings `name: rust-check (${{ matrix.os }})`, `name: rust-coverage` and `fetch-depth: 0`, and the absence of `uv `, `npm ` and `pytest`.

### 9.4 The installed-binary test

`tests/cli.rs` runs `env!("CARGO_BIN_EXE_talaria")` with `--version`, `env_clear()` and only `PATH` set to `/usr/bin:/bin`, so it proves the binary does not depend on the developer's environment. When the test process itself has `LLVM_PROFILE_FILE` set (it does under `cargo llvm-cov`), copy that one variable back onto the child. Without it, an instrumented child writes a default `default.profraw` into its working directory (standard LLVM behaviour, not measured here), which `.gitignore` does not cover, and the child's lines go uncounted. It asserts the exact standard output `talaria <CARGO_PKG_VERSION>\n` and exit code 0. `/usr/bin:/bin` is the one fixed absolute value the issue's test-first rule allows: it is the system command path, not a path on the builder's machine.

### 9.5 Coverage: what it counts, and sizing the UAT-6 failure

The floor counts hand-written lines in every member, including inline `#[cfg(test)]` modules (decided in section 5.1); generated code under `/generated/` is excluded. Read the first summary table to see whether files under `tests/` are listed, record both answers in the `DECISIONS.md` entry, and paste the table in the pull request for the operator.

For UAT-6, the added uncalled function must be large enough that the total falls below 80% whatever the starting figure. With C covered lines out of T, adding U uncovered lines gives C / (T + U), which is below 0.8 when U > 1.25 C - T. The worst case is T = C (100%), so U > C / 4 always suffices. The issue asks for at least C / 3 lines and at least 60. Take C from the first run's summary, and write the function as that many trivial statements (for example `let _ = n + 1;` lines in a body that is never called).
