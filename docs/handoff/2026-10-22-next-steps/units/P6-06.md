`voice.toggle status` only reads: it builds the status payload and runs the requirements probe `tools.voice_mode.check_voice_requirements` (`tools/voice_mode.py:1500`), which returns `available`, `audio_available`, `stt_available`, `missing_packages`, `details` (a newline-joined string, `tools/voice_mode.py:1520-1536`), `environment`. If the probe import or call raises, the handler logs it and still returns success with only `enabled`, `record_key`, `tts` (`tui_gateway/methods_voice.py:702-714`): absent availability fields mean "unknown", not "no". The `enabled` and `tts` it returns describe the process-wide flags (H2), not the session.

Order inside `voice.record`: the action check (4019), then the wake-owner check returning `{status: "busy", reason: "wake_owned"}` as a success, then the voice-mode check (4015), then the busy-session check (4016) (`tui_gateway/methods_voice.py:803-816`). So a fresh voice-off session answers `wake_owned`, not 4015, while another client holds the wake word.

`voice.toggle` and `voice.tts` carry no `session_id`: their closed schemas are `{action?, profile?}` and `{text, profile?}` with `additionalProperties: false` (contract `VoiceToggleParams`, `VoiceTtsParams`). The wake-owner check (`tui_gateway/methods_voice.py:807-809`) and the busy-session check (4016, `:814-816`) run for `stop` too; only the voice-mode check (4015, `:812-813`) is `start`-only. `VoiceToggleResult` also carries `stop_hint` (set on `on`) and `record_key` (Hermes's own key); Talaria decodes and ignores both.

`voice.toggle on|off|tts` write `os.environ` (`tui_gateway/methods_voice.py:717-754`). Talaria never sends them.

The `voice.record` docstring: "``start`` emits ``voice.transcript`` when silence stops the capture; ``stop`` forces transcription. Three silent captures emit ``no_speech_limit``" (`tui_gateway/methods_voice.py:800-801`). A spoken stop phrase and the no-speech limit both turn the session's voice off before the event (`:780-790`). A stop-phrase transcript carries `{stop_phrase: true, text}` (`:784`, `:338`); `typed: true` is emitted only by the sidecar's typed-stop path (`tui_gateway/methods_prompt.py:258-260`), which the canonical gateway calls with `emit=False` (`gateway/session_controls.py:745`).

**Ordering (the reason for issue REQ-8).** `start_continuous` reports `listening` (`hermes_cli/voice.py:382`) before it returns to the handler that sends the `recording` reply (`tui_gateway/methods_voice.py:852-865`). `stop_continuous(force_transcribe=True)` reports `transcribing`, then starts a background thread (`hermes_cli/voice.py:410-421`) whose `_finish_forced_stop` delivers the transcript (or the stop phrase) and `idle` (`:428-455`), possibly before the handler sends `{status: "stopped"}` (`tui_gateway/methods_voice.py:820-824`). `stop_continuous` is idempotent (`hermes_cli/voice.py:397-398`).

**H18. `idle` closes every capture.** The record handler starts captures with `auto_restart=False` (`tui_gateway/methods_voice.py:857`). A silence-ended capture reports `transcribing` (`hermes_cli/voice.py:483`), delivers the transcript, stop phrase or no-speech event, then waits up to 60 s while speech output plays (`:516-526`) before reporting `idle` (`:530-532`, `_deactivate` at `:195-200`); a stop phrase or the no-speech limit reports `idle` at once, and a forced stop ends in `_finish_stop`'s `idle`. Until `idle` the loop is still active, so a new `start` is a no-op that returns `recording` without a new capture (`:349-351`). Hence a transcript never moves Talaria's phase; `idle` does, with a 120 s fallback (section 4 rule 4). Code-read.

### 1.6 Configuration defaults (`voice:` block)

`hermes_cli/config_defaults.py:1243-1262`: `record_key: "ctrl+b"`, `submit_mode: "direct"` ("direct submits immediately; draft = editable transcript"), `max_recording_seconds: 120`, `auto_tts: False`, `client_direct: True`, `silence_threshold: 200`, `silence_duration: 3.0`, `barge_in: True`, `stop_phrases: ["stop"]`. `submit_mode` must be `direct` or `draft` (`hermes_cli/config.py:1011-1017`). ### 1.7 Speech cannot be cancelled by a request

- `voice.tts` starts `_speak_text_with_barge` on a thread and registers its stop event in `_fd_speak_pipelines` (`tui_gateway/methods_voice.py:341-358`).
- `_tts_stream_stop` (called by `voice.record start`, `:829`, and by turning speech output off, `:742-747`) returns at once when no streaming pipeline exists, so it neither sets the whole-reply stop events nor calls `stop_playback` (`:194-210`).
- Only `_fd_trip`, the full-duplex listener, sets those stop events (`:296-323`), and the listener is armed only when the process flag `HERMES_VOICE` is on and `voice.barge_in` is true (`:235-238`). On the shared owner, `/voice on` sets the per-session mode, not the flag.
- Conclusion (code-read): once `voice.tts` is speaking, Talaria cannot stop it. Re-verify; [`P6-08`](https://github.com/infiquetra/talaria/issues/281) may propose an upstream cancel.

### 1.8 Hermes's terminal UI behaviour used as reference

- Push-to-talk calls `voice.record {action, session_id}` with an optimistic `REC` badge, reverted on failure (`ui-tui/src/app/useInputHandlers.ts:414-445`).
- Transcript handling: stop phrase and no-speech limit turn voice off with a notice; `draft` appends to the input; `direct` clears the input and submits; a transcript for another destination is queued there (`ui-tui/src/app/createGatewayEventHandler.ts:480-540`). Talaria differs on purpose: a typed draft is kept, and a transcript for another session becomes a notice there (issue REQ-11).
- The default record key is `ctrl+b` (`ui-tui/src/lib/platform.ts:56-87`). Talaria uses `alt+r` because Herdr takes Ctrl+B ([`P1-08`](https://github.com/infiquetra/talaria/issues/205)).

### 1.9 Unused alternatives (recorded so nobody rediscovers them)

- REST `POST /api/audio/transcribe {data_url, mime_type?}` → `{ok, transcript, provider}` (25 MiB limit) and `POST /api/audio/speak {text}` → `{ok, data_url, mime_type, provider}` (`hermes_cli/web_routers/audio.py:86-146`, `:293-347`; models `hermes_cli/web_models.py:86-88`, `:235-236`). These need audio capture and playback in the client, so they suit a remote gateway ([`P6-01`](https://github.com/infiquetra/talaria/issues/274)), not this unit.
- `GET /api/audio/voice-config` returns provider keys for client-direct voice (`hermes_cli/web_routers/audio.py:149-175`). Never used: it would put provider keys in Talaria's memory.
- Wake word methods `wake.*` and the event `wake.detected` (`tui_gateway/methods_voice.py:539-698`).

## 3. Request and notice tables

### 3.1 Requests (what Talaria sends, and only this)

All voice requests are hand-built JSON sent with [`P1-02`](https://github.com/infiquetra/talaria/issues/199)'s `call_raw` (issue REQ-2): no `profile`, no null, `action` always present, `session_id` only where listed below. `/voice on` and `/voice off` send their frames one at a time, each after the previous reply, and `/voice on` re-reads `full` every time; if `slash.exec` fails, its notice (3.2) is shown and only `config.get voice` follows. `/voice status` may send its two reads in parallel and shows one notice once both have answered or failed.

| `/voice off` | `slash.exec {session_id, command: "voice off"}`; `config.get {key: "voice", session_id}` | same notices |

`<message>` everywhere is the `CallError` message cleaned like a transcript (issue REQ-11), cut to 120 characters with `…`, with one trailing `.` removed (the template adds its own); an empty message becomes `no message given`. `/voice` arguments (case-insensitive, trimmed, inner white space collapsed): empty or `status` → Status; `on` → On; `off` → Off; `read` or `tts` → Read(None) (toggle); `read on` → Read(Some(true)); `read off` → Read(Some(false)); anything else (including `tts on` and `tts off`) → the unknown-option notice. `/voice` is `LocalAction::Voice` with `takes_argument: true` in [`P2-03`](https://github.com/infiquetra/talaria/issues/223)'s table; the argument is the part [`P2-03`](https://github.com/infiquetra/talaria/issues/223) splits off after the name.

## 4. State machine

`VoiceState` (one per session id, inside `VoiceService`) holds: `phase`, `pending: Option<Start | Stop>` (the record call in flight), `capture_auto_submitted: bool`, `partial: Option<String>`, `label: Option<String>`, `clock_started: Option<Duration>`, `read_aloud: bool`, `detaching: bool`, `unavailable: bool`.

Inputs: `ModeRead(Option<String>)`, `SubmitModeRead(Option<String>)`, `Press`, `RecordReply { start: bool, status, reason }`, `RecordFailed { start: bool, code: Option<i64>, message, dropped: bool }`, `Event(VoiceEventKind)`, `TurnCompleted { assistant_markdown: Vec<String>, outcome }`, `VoiceStopped`, `Command(VoiceCommand)`, `ConnectionOpened`, `DetachBegins`, `Tick(Duration)`. Effects: `SetMode { on }`, `ReadMode`, `ReadSubmitMode`, `ReadRequirements`, `Record { start }`, `Speak(String)`, `Submit(String)`, `AppendToDraft(String)`, `NoticeIn { session_id, text }`, `Notice(String)`, `StopBeforeDetach`.

```text
            ModeRead(off)                ModeRead(on)
 Unknown ───────────────► Off ◄──────────────────────► Ready
                           ▲   stop phrase / no speech /    │ Press (nothing pending)
                           │   4015 / VoiceStopped           ▼
                           │                             Starting ── busy / error ──► Ready
                           │                                │ "listening" or reply "recording"
                           │                                ▼
                           └─────────────────────────── Recording ── Press ──► Stopping
                                                            │ "transcribing"          │ reply "stopped"
                                                            ▼                         ▼   (failed stop → Ready)
                                                       Transcribing ◄────────────────┘
                                                            │ "idle" (or 120 s)
                                                            ▼
                                                          Ready
 ConnectionOpened from any phase → Unknown (+ ReadMode; REQ-7's drop notice if the phase was Starting,
 Recording, Stopping or Transcribing)
```

Rules:
1. Press is ignored while `pending` is set, and in Starting, Stopping, Transcribing.
2. A reply clears `pending`. It changes the phase only if the phase is still the one the call was sent in (Starting for `start`, Stopping for `stop`). So `recording` after `listening` is a no-op; `stopped` after a transcript and `idle` (phase Ready) or after a stop phrase (phase Off) is a no-op.
3. An error reply clears `pending`; if the phase is still the sent-in phase it moves to Ready (Off for 4015, Unknown for a drop), with the 3.2 notice. For `stop`, every outcome except `stopped` (a `busy` status with or without reason, 4016, 4019, 5025) moves Stopping to Ready with its notice, never to Transcribing; 4015 answers only `start`. -32601 on either: rule 10.
4. `listening` sets Recording from Starting or Ready and starts the clock if not started; `transcribing` sets Transcribing from Recording or Stopping; `idle` sets Ready from Starting, Recording, Stopping or Transcribing, leaves Ready, Off and Unknown as they are, and clears the partial line and label. In other phases `listening` and `transcribing` change nothing. A transcript event never changes the phase (H18). If Transcribing lasts 120 s of `Tick` time without `idle`, the phase moves to Ready with no notice.
5. A new `start` resets `capture_auto_submitted`. The first direct-mode transcript on an empty composer sets it and emits `Submit`; every later transcript of the capture is appended.
6. `DetachBegins` sets `detaching`; in Starting or Recording it emits `StopBeforeDetach`. While `detaching`, transcripts and partials are dropped.
7. `TurnCompleted` with outcome Completed, flag on and focused: join the cells with `"\n\n"`, `speakable_text`, emit `Speak` unless `None`.
8. `Tick` advances the `REC m:ss` clock (minutes unbounded, `REC 61:05`; cleared on leaving Recording, so Starting shows `0:00`) and rule 4's Transcribing timer.
9. `ModeRead(Some("voice_only" | "all"))` moves Unknown or Off to Ready unless `unavailable`; other phases are unchanged. Any other value, or `None` (absent), moves every phase to Off and clears partial and label; a pending reply then changes nothing (rule 2). A failed mode read delivers no input, so the phase stays (section 5).
10. -32601 on any voice call: `unavailable` set, `pending` cleared, phase Off, `read_aloud` false; the unavailable notice once, before REQ-14's `Read-aloud is off` notice when the call was `voice.tts`. While `unavailable`, a press emits only that notice again and sends nothing, and `Command(Read(Some(true)))` or a toggle to on emits it and keeps the flag off. `ConnectionOpened` clears `unavailable`.
11. Labels: a `voice.status` state other than the three is cleaned (control characters dropped, cut to 24 characters); if nothing is left it is ignored and any earlier label stays. Labels are stored in every phase except Unknown and Off. A label replaces the segment text in Ready, Stopping and Transcribing (tone `Muted`, ` +read` still appended); in Starting and Recording `REC m:ss` stays. Cleared by the three known states, a transcript, Off and `ConnectionOpened`.
12. Partials are stored per session; the view draws only the focused session's line: `heard: ` plus the text, newlines as spaces, measured in display columns with the width function [`P1-10`](https://github.com/infiquetra/talaria/issues/207) uses; when wider than the composer, the text is cut so the line plus `…` (one column) fits. Never a notice, never scrollback.
13. `VoiceStopped` for a known session: phase Off, partial and label cleared, `capture_auto_submitted` unchanged, `ReadMode` for that session. For an unknown session id: nothing.
14. Read-aloud: `Command(Read(..))` always emits the on or off notice, even when the flag is unchanged. `TurnCompleted.assistant_markdown` holds the `text` of every `Cell::Assistant` (interim ones included) after the last `Cell::User`, in order; with no `Cell::User`, nothing is read. A `voice.tts` reply of `speaking` or any other status: nothing. 4020: its notice, flag kept. 5026 or -32601: flag off, notice. Timeout or drop: flag kept, `Read-aloud got no answer from the gateway.`
15. Detach (detail of rule 6): `StopBeforeDetach` makes the app wait for a pending `start` reply; after `recording` (or `listening`) it sends `stop`; after a `busy` or error reply it sends nothing. In Stopping it only waits for the pending `stop` reply; in Transcribing, Ready, Off or Unknown nothing is sent. "Confirmed" means any reply to that `stop`, success or error, inside the 500 ms budget; otherwise the 3.2 standard-error line goes to the app's error writer, which is injected so test 22 can read it.
16. `composer_empty` is the focused composer's state, passed on every `update`; a session's state uses it only when that session is focused, since transcripts for other sessions never submit.

## 5. Edge cases

| Case | Behaviour |
|---|---|
| `voice.record` reply lost (timeout) | drop notice; phase Unknown; `ReadMode`; never resend `start` |
| `voice.partial` after a transcript in the same capture | shown again until the next transcript or `idle` |
| two transcripts in one capture | rule 5: one automatic submit at most |
| transcript text with control characters | cleaned (issue REQ-11) before submit, append or notice |
| `config.get voice` answers `invalid_params` (no session yet) | stay Unknown, no notice, retry once the session exists |
| `submit_mode` absent | Direct (H9: absent unless set in `config.yaml`) |
| read-aloud on, reply only code | speaks `(code omitted)` |
| read-aloud on, two turns finish quickly | two `voice.tts` calls; the gateway may overlap them (H1); not mitigated |
| gateway without voice extras | status shows `no` or `unknown` and details; `voice.record` gives 5025 |
| another client holds the wake word | `busy`/`wake_owned` notice; live test 28 prints `BLOCKED` |
| `-32601` on any voice method | `unavailable` set for the connection; cleared on `ConnectionOpened` (rule 10) |
| no `idle` after a transcript | Transcribing for 120 s of `Tick` time, then Ready (rule 4) |
| press while unavailable | the unavailable notice again; nothing sent |
| `slash.exec` fails | `Could not change voice mode: <message>.`; then `config.get voice` only |
| `config.get voice` fails other than `invalid_params` | phase unchanged, no notice; `/voice status` shows `Mode: unknown (<message>)` |
| `VoiceStopped` for an unknown session | ignored |
| a turn finishes in a session with no user cell | nothing read |
| reconnect during a capture (Starting to Transcribing) | REQ-7's drop notice, phase Unknown, `start` never resent (test 10) |

## 6. Speakable text rules

Steps, in order, on the joined Markdown:

1. Fenced code blocks (opening ``` or `~~~` with any info string, to the matching close or the end) → `(code omitted)`. Indented (four-space) code is not detected and stays prose.
2. Tables in the forms [`P1-07`](https://github.com/infiquetra/talaria/issues/204)'s renderer (pulldown-cmark with tables) accepts: a header line containing `|`, followed by a delimiter row matching `^\s*\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)*\|?\s*$` that contains at least one `|`, plus following lines up to a blank line or a line without `|` → `(table omitted)`. A line with pipes but no delimiter row is prose.
3. Images `![alt](dest)` → `alt` (an empty alt leaves nothing); links `[text](dest)` and reference links `[text][ref]` or `[text][]` → `text`; reference definition lines (`[ref]: dest`, up to three leading spaces) → removed.
4. Tokens starting `http://` or `https://` (to the next white space) → `(link)`; trailing `.`, `,`, `;`, `:`, `!`, `?` or `)` characters of the token stay after `(link)`.
5. Inline code: a run of n backticks and the next run of exactly n backticks on the same line → the content between them, with one leading and one trailing space removed when both are present (so double-backtick spans work). An unmatched run stays.
6. First, a line holding only three or more `-`, `*` or `_` (spaces allowed) → removed. Line-start markers: `#` runs, `>`, `-`, `*`, `+`, `1.`-style numbers, followed by a space → removed. Paired `**`, `__`, `*`, `_`, `~~` around text → removed; unpaired stay.
7. Characters in the Unicode control category → removed; white space runs (including newlines) → one space; trim.
8. If no character satisfies `char::is_alphanumeric` (Unicode letters and digits) → `None`.
9. Length, counted in Unicode scalar values: if the result exceeds `max_chars`, let `w = max_chars - 18`; take the first `w` characters; keep through the last `.`, `!` or `?` in them; else cut at the last space; else keep all `w`; trim; append ` (reply truncated)`. An empty prefix gives `(reply truncated)`. With `max_chars` below 18 (direct calls only; the loader allows 100 to 10,000), an over-limit result is its first `max_chars` characters, trimmed, with no suffix.

## 9. Design reasoning

- **Why the gateway does the audio.** The local gateway already has recording, voice-activity detection, transcription with hallucination filtering, stop phrases and speech output. Doing audio in Talaria would add native dependencies to a single static binary and duplicate all of it. The cost is that remote gateways need a different path, which belongs with [`P6-01`](https://github.com/infiquetra/talaria/issues/274).
- **Why per-session mode, not `voice.toggle`.** H2, H3 and H7: on the shared owner the toggle changes a process-wide flag that every client sees.
- **Why read-aloud uses `voice.tts`.** H6 shows the gateway will not speak a local session's replies; `voice.tts` is the one request that speaks text on the gateway machine. The cap exists because of 1.7.
- **Why the voice segment ranks high.** A microphone open on the gateway machine is a privacy matter; the segment sits right after "needs you" in priority, so it is the last thing a narrow terminal drops after the connection and pending questions. Position stays near the end of the line, just before the external segment.
- **Why no `voice_turn`.** H16: it moves the turn to a different model with no reasoning, which changes the answer quality of a coding agent. Left for the operator.
