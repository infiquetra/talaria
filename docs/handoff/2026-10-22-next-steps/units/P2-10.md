## 1. What this unit is, and what it is not

It gives a developer three slash commands and one display:

| Command | What the developer sees | Hermes call |
|---|---|---|
| `/context` | A block in scrollback: the model, tokens used of the window, a 5 by 20 grid with one cell per percent of the window, a table of what fills it (system prompt, tool definitions, rules, skills, MCP, subagent definitions, memory, conversation, free space), the source of the figure, and the context files Hermes found with whether each was loaded | `session.context_breakdown` |
| `/compact [focus]` (alias `/compress`) | While it runs, a live line `✻ Compacting conversation · <n>s`. Then a block with Hermes's own report: `✓ Compressed: 32 → 24 messages`, the approximate request size before and after, and any note. `--preview` reports without changing anything; `here [N]` keeps the last N exchanges verbatim | `session.mutate` with `operation: "compress"` |
| `/usage` (aliases `/cost`, `/stats`) | A block with the session's tokens, cache, API calls, latency, throughput, context, compactions, rate limits, cost (or "not reported"), and, only for a Nous Portal sign-in, the plan's dollar bars | `session.stats` and `usage.bars` in parallel |
| (automatic) | When Hermes compacts during a turn: a live line `✻ Compacting context · <n>s`, then a one-line record in scrollback after the turn | the `status.update` event, kinds `compacting` and `compacted` |

It is not: a settings screen for compaction thresholds (phase 4), cost in the fleet view (phase 3), `/context all` per-skill and per-toolset tables (no canonical method serves them, H8), the plan windows of other providers (they come from `model.options`, which `P2-06` owns; operator question 1), or a change to the session reducer (`P1-05`).

## 2. Design decisions and why

1. **Methods the socket serves, never the refused legacy ones.** The legacy methods `session.compress` and `session.usage` are refused on the native socket (H3); the `session.usage` event is a different thing and is read. Compaction goes through `session.mutate` (operation `compress`); counters come from `session.stats`; the breakdown from `session.context_breakdown`, which the gateway's session authority serves itself (H6). `usage.bars` is not a `session.` verb, so the legacy fallback serves it on a connection with the interactive grant (H4).
2. **Raw `/compact` arguments go to Hermes unparsed.** A payload holding only `focus` is parsed by Hermes's own `parse_compress_args`, so `--preview`, `--dry-run`, `here [N]`, `up to here [N]`, `--keep N` and focus text behave exactly as in every Hermes client (H15). Desktop and Hermes's terminal UI send it the same way (H34, H36). Talaria never parses these words.
3. **Fences come from `P2-06`'s ledger.** No `session.resume` re-read before each compaction (Hermes's terminal UI does that; it re-attaches and returns the whole transcript). A fence refusal is retried once with the fences Hermes returns, through `retry_after_fence`.
4. **A lost reply is retried exactly.** A compaction whose outcome is unknown keeps its request in the ledger. Typing the same `/compact` line again resends the identical request (same `request_id`), and Hermes answers with the first attempt's receipt instead of summarizing again (H21).
5. **Scrollback is not rewritten after a compaction.** Finished output lives in the terminal's scrollback (architecture decision record draft 0009). Hermes's terminal UI repaints its transcript from a fresh `session.resume`; Talaria prints the report and one dim line saying the scrollback above is unchanged and the model now sees a summary.
6. **The context figure is hidden, not wrong, after any compaction.** A manual compaction evicts the session's agent (H24); an automatic one rewrites the conversation mid-turn (H27). Until the next usage reading the old percentage is wrong by several times (Desktop's own comment, H35). After this Talaria's commit, another client's, or a `status.update` `compacted`, the status line's context segment, `/usage`'s `Context` row and `/context`'s last-reading line are hidden for that session until a `session.usage` or `message.complete` carries `usage.context_percent` again.
7. **Blocks and notices wait for the turn.** A block or notice that becomes ready while the foreground turn is `Running` (which includes waiting on an approval or question) is held and committed right after the turn's last cell, so it never splits a streaming reply. Otherwise it is committed at once.
8. **Cost is shown only when Hermes reports it.** No live source of session cost was found at v0.22.4 (H31, unverified absence). The cost row says `not reported by Hermes for this session` until `usage.cost_usd` arrives; it never estimates from token counts.
9. **No retry loops and no polling.** One call per command (two for `/usage`). Desktop polls and retries the breakdown on a backoff (H35); Talaria answers what the developer asked, once.
10. **Pure core.** Parsing, the report model, the tracker and every text live in `talaria-core` as pure functions over `serde_json::Value` and the generated types; the clock is passed in as milliseconds.
11. **Prose wraps, tables are cut.** Long texts (T-C13 is about 200 columns) must stay readable in a narrow pane, so prose rows wrap with `P1-06`'s `wrap_lines`; only the grid and aligned table rows are cut with `…` (section 7.0.1).

### 4.4 Rules for test data and the mock gateway

1. Replies and events in tests come from section 4.2 and 4.3 (built from the contract and the cited Hermes code) or from the recorded `fixtures/frames/context-compaction.jsonl`. Nothing else: a stub that invents a field, a status or an error reason is a defect.
2. Every hand-built reply must deserialize into the generated `hermes_contract` result type for its method (tests 1, 8 and 16 assert this; the compaction replies into `SessionMutateResult`), because the closed schemas refuse unknown keys. Every hand-built event payload must deserialize into its contract payload type too: `session.usage` into `SessionUsagePayload`, `status.update` into `StatusUpdatePayload`, and the `session.updated` payload (no contract event type, H25) into `SessionMutateResult`. Step 0 (b) of the issue checks this once for every file in `tests/data/context/`; a payload that fails is a defect in the test data, never a reason to loosen the type.
3. The mock gateway (`crates/talaria-app/tests/support/mock_gateway.rs`) gets opt-in handlers for `session.context_breakdown`, `session.stats`, `usage.bars` and `session.mutate` with operation `compress`. Each takes a per-test script: reply with a given value, refuse with a given `RpcError`, delay, or close before replying. Defaults stay unchanged for other tests. The handler records every request it receives, so tests assert the exact params.
4. The mock never answers `session.compress` or `session.usage` with anything but `-32601` (`unknown method: <name>`, `data.reason: "unknown_method"`), as the real socket does (H3).
5. No test file holds an absolute path, a home directory, a user name or a profile name other than `default` or `fixture`. Context file `path` values use `<cwd>/...`; Talaria never displays `path`.

### 5.1 Parsing the breakdown

- Negative integers become 0; `percent` is clamped to 0 to 100; `used` is clamped to `max` when `max > 0` (Hermes already clamps; a value above is drift).
- Categories keep Hermes's order and its `label` text (already translated); `color` is ignored (CSS variables, H28). Talaria colours a glyph by the category id (section 7.5).
- `ContextSource` from `context_source`: the three known strings, else `Other(raw)`.
- `estimated` is `context_estimated` as sent.
- Files keep Hermes's order; `path`, `chars` and `loaded` are not kept (the status decides what is shown; `path` is a full path on the gateway's machine and would leak into screenshots).

### 5.2 Grid and rows

Grid (H29), with integer arithmetic: for each category in order, `n = (tokens × 100 + max / 2) / max` (round half up); if `n == 0` and `tokens > 0`, `n = 1`; push `n` cells of `Category(i)`; stop at 100 cells; fill the rest with `Free`. Hermes uses Python's `round`, which rounds exact halves to even; the two differ only at an exact half, and test data avoids exact halves. With `max > 0` and no categories, the grid is 100 `Free` cells.

Rows: one per category, `tenths_of_percent = (tokens × 1000 + denom / 2) / denom` where `denom` is `max` when above 0, else `estimated_total`, else the row shows `0.0`. Then, only when `max > 0`, a free row: label `Free space`, glyph `·`, tokens `max − estimated_total` (0 if negative), tenths over `max`.

Rules, in order:

1. **Source.** `stats` is `Ok` with `api_calls > 0`: `Gateway`. Else `stored.calls` is `Some(n)` with `n > 0`: `LastReading`. Else `Nothing`. `stats_error` is `Some(e.clone())` whenever `stats` is `Err(e)`, whatever the source.

4. **Cost** always from `stored` (H31): `cost_status` `included` gives `Included`; `cost_usd` present, finite and not negative with status `actual` or `estimated` gives `Amount` with that status; present with no status gives `Amount { status: None }`; everything else (absent, NaN, negative, status `unknown` or any other word) gives `NotReported`.
5. **Rate limits** (H13), only when `rate_limit` is an object whose `captured_at` is a number above 0. Buckets in this order with these names: `requests_min` "requests per minute", `requests_hour` "requests per hour", `tokens_min` "tokens per minute", `tokens_hour` "tokens per hour". A bucket is shown when it is an object with integer `limit > 0` and integer `remaining >= 0` (`remaining` clamped to `limit`). Wrong types skip the bucket, never panic.
6. **Plan** only when `plan` is `Some` with `available: true`: `name = plan_name`, `status`, `spendable = total_spendable_display`, `renews = renews_display`, bars from `plan_bar` and `topup_bar` (`fill` clamped to 0 to 1; non-finite gives 0).
7. **Stale context.** When `context_stale` is true, `context` is `None` whatever the source (section 2, decision 6; the issue's decision 5). The app passes `tracker.context_hidden(sid)`.
8. **Nothing.** Only `source`, `stats_error` and `cost` matter; the renderer prints the no-calls line, or the error row when `stats_error` is set (section 7.3).

`interpret` mapping from `P2-06`'s outcome (every variant of P2-06's enum is covered, so the `match` is exhaustive):

| `MutationOutcome` | `CompactResult` |
|---|---|
| `OtherStatus { status: "preview", result }` | `Preview { lines }` from `lines` (non-strings skipped; a missing or empty array gives `Preview { lines: [] }`) |
| `OtherStatus { status: "noop", result }` | `NoChange { summary }` |
| `Committed(receipt)` with integer `revision` | `Compacted { summary, message_count, revision }` |
| `Committed(receipt)` without integer `revision` | `Unreadable` |
| `OtherStatus` with any other status; `Deferred(_)`; `NeedsConfirmation(_)` | `UnknownStatus { status }` (`"deferred"`, `"confirmation_required"` for the two P2-06 variants, which Hermes does not send for `compress`) |
| `Refused { reason, field, .. }` | `Refused { text: refusal_text(reason, field, sid) }` |
| `FenceRefused { .. }` (only reached when the one retry also failed) | `Refused { text: T-C7 }` |
| `Unknown` | `Unknown` |
| `NotSent { reason: "fences unknown" }` | `NotSent { text: T-C9 }` |
| `NotSent { reason }` otherwise | `NotSent { text: T-C14 with <reason> }` |
| `Unreadable` | `Unreadable` |

A `summary` is read when it is an object with a string `headline`; `token_line` and `note` when non-empty strings; the four booleans default to false when absent or not booleans. `message_count` when a non-negative integer.

`refusal_text` (section 7.4 has the exact strings): `session_busy` with `field: "compression"` T-C1; `session_busy` T-C2; `unknown_execution` T-C3; `compression_checkpoint_required` T-C4; `runtime_coordination_required` T-C5; `unsupported_compress_options` T-C6; `revision_conflict` and `stale_generation` T-C7; `not_found` T-C10 (with `sid`); `permission_denied` T-C11; any other reason T-C12.

`settle_as`: `Refused { reason: "session_busy", field: Some("compression"), .. }` becomes `MutationOutcome::Unknown`; every other outcome is returned unchanged (cloned). Why: Hermes stores an exact-retry receipt only when a compaction commits (H21, H39). When a resend of a kept request meets a compaction that is still summarizing, Hermes refuses it with the compression lock (H17). P2-06's `settle` forgets a request on any refusal, so without this the next `/compact` would build a new request, and if the first compaction committed meanwhile, the new one would be admitted and summarize the conversation a second time. Settling the refusal as `Unknown` keeps the request; the next identical line resends it and gets the stored receipt. If the lock belonged to another client's compaction, the resend later meets a fence refusal, is retried once with new fences, and compacts once, which is what the developer asked for.

`compact_end` tells the tracker how the call ended, in this order: `Committed { revision }` when `interpret` gives `Compacted { revision, .. }`; `Unknown` when `settle_as(outcome)` is `MutationOutcome::Unknown` (a timeout, a drop, or the compression-lock refusal) or when `interpret` gives `Unreadable` (Hermes may have committed); `NothingChanged` for everything else (preview, no change, any other refusal, not sent, unknown status). Why: a compaction whose outcome is unknown may still commit in Hermes, and its `session.updated` event can arrive after the call ended. The tracker must treat that event as this Talaria's own (no "another client" notice) and must already hide the figure (section 6.2).

### 5.5 Request flow for `/compact`

```text
LocalAction::Compact with the argument text a ("" for none, as P2-03's dispatch passes it)
  -> tracker.begin_compact(sid, now)        Err(AlreadyRunning) -> block T-C8, stop
  -> ledger.build(sid, "compress", compact_payload(a), true)
       Err(NotSent) -> tracker.finish_compact(sid, CompactEnd::NothingChanged); block from interpret(NotSent, sid); stop
  -> outcome = MutationClient::send_with(&request, CallOptions { timeout: Some(timeouts.compact) })   // 660 s
  -> if outcome is FenceRefused:
       if let Some(r2) = ledger.retry_after_fence(&request, &outcome) { request = r2; outcome = send_with(&request, ..) }
  -> ledger.settle(&request, &settle_as(&outcome))   // keeps the request on Unknown (and on a compression busy refusal)
  -> tracker.finish_compact(sid, compact_end(&outcome))
  -> block from interpret(&outcome, sid), through HeldBlocks (section 6.4)
```

`MutationClient::send_with(&self, request: &MutationRequest, options: CallOptions) -> MutationOutcome` (async) is `P2-06`'s `send` with `Client::call_with` instead of `Client::call`: the same params, the same mapping of results and errors (`TimedOut` and `Unknown` to `MutationOutcome::Unknown`), no retries. Add it to `crates/talaria-app/src/mutation.rs` only when that file has no way to pass a timeout.

A second identical `/compact` line after an `Unknown` outcome makes `ledger.build` return the kept request, so the resend has the same `request_id` (H21). If the receipt then comes back, the block is the normal committed block. A different argument string builds a new request (the ledger forgets the kept one, as `P2-06` defines).

### 6.1 State per session

| Field | Start | Meaning |
|---|---|---|
| `stale: bool` | false | the context figure must be hidden (status line, `/usage`, `/context` last reading) |
| `own_in_flight: bool` | false | this Talaria has a compaction call outstanding |
| `known_revision: Option<i64>` | None | the highest compaction revision this view knows: its own commits and every `session.updated` compress it has seen |
| `manual_since: Option<u64>` | None | when the outstanding manual compaction started |
| `auto_since: Option<u64>` | None | when the current automatic compaction started |
| `last_notice_auto: bool` | false | an `AutoCompacted` notice was given and no `compacting` has arrived since |
| `own_unsettled: bool` | false | this Talaria's last compaction ended with an unknown outcome, so its commit may still arrive as a `session.updated` event |

### 6.2 Transitions

| Input | Change | Notices |
|---|---|---|
| `begin_compact` while `own_in_flight` | none | `Err(AlreadyRunning)` |
| `begin_compact` otherwise | `own_in_flight = true`, `manual_since = now`, `own_unsettled = false` | none |
| `finish_compact(Committed { revision: r })` | `own_in_flight = false`, `manual_since = None`, `known_revision = max(known_revision, r)`, `stale = true` | none |
| `finish_compact(Unknown)` | `own_in_flight = false`, `manual_since = None`, `own_unsettled = true`, `stale = true` | none |
| `finish_compact(NothingChanged)` | `own_in_flight = false`, `manual_since = None` | none |
| `session.usage` whose `payload.usage.context_percent` is an integer | `stale = false` | none |
| `message.complete` whose `payload.usage.context_percent` is an integer | `stale = false`, `auto_since = None` | none |
| `message.complete` otherwise | `auto_since = None` | none |
| `status.update` kind `compacting` | `auto_since = auto_since.or(now)`, `last_notice_auto = false` | none |
| `status.update` kind `compacted` | `auto_since = None`, `stale = true`; if `last_notice_auto` is false, set it true | `AutoCompacted` when it was false |
| `session.updated` with `payload.operation == "compress"` while `own_in_flight` | `stale = true`; `known_revision = max(known_revision, revision)` when `revision` is an integer | none |
| `session.updated` compress while `own_unsettled` (and not `own_in_flight`) | `stale = true`; `own_unsettled = false`; `known_revision = max(known_revision, revision)` when `revision` is an integer | none (it is almost always this Talaria's own late commit) |
| `session.updated` compress, integer `revision`, `known_revision` is `Some(k)` with `revision <= k` | none | none |
| `session.updated` compress, integer `revision` above `known_revision` (or `known_revision` is `None`) | `stale = true`, `known_revision = Some(revision)` | `CompactedElsewhere { revision, headline: payload.summary.headline when a string }` |
| `session.updated` compress without an integer `revision` | `stale = true` | none (no revision to deduplicate on) |
| anything else, or a payload of the wrong shape | none | none |

Kinds are compared exactly. A `status.update` text is never shown (the line and the notice use Talaria's own words); a hostile text therefore cannot reach the screen through this unit.

Why `compacted` hides the figure: the reading before an automatic compaction describes the conversation before it was summarized (section 2, decision 6; the issue's decision 5). The next API call of the same turn sends a fresh `session.usage` (H26), which shows it again.

Why an event during this Talaria's own compaction gives no notice: Hermes holds a compression lock while a compaction runs and refuses a second (H17), so such an event is almost always this Talaria's own commit arriving before its reply. In the narrow race where another client's commit lands just before this Talaria's request takes the lock, that client's notice is lost; the figure is still hidden and this Talaria's own request meets a fence refusal and is retried once. That loss is accepted.

Why an unknown outcome hides the figure and expects a late event: a timed-out or dropped compaction may still commit in Hermes (H39), and Hermes then publishes its receipt as `session.updated` (H24). Hiding at once errs on the safe side: the figure comes back with the next usage reading. The first compress event after the unknown end is treated as this Talaria's own, so it gives no "another client" notice. If this Talaria's compaction in fact never committed and another client's commit is the next event, that client's notice is lost; the figure is still hidden. That loss is accepted, as in the race above. A resend through the same `/compact` line clears `own_unsettled` at `begin_compact`; its committed receipt then sets `known_revision`, so the late event (same revision) gives nothing.

`compacting_line`: `Manual` when `manual_since` is set (manual wins), else `Auto` when `auto_since` is set, else none.

### 6.3 Where the tracker is fed

`app.rs` calls `observe` for every event of a session (order relative to the reducer does not matter: the tracker reads only the raw payload), `begin_compact` and `finish_compact` around the compaction call, and `context_hidden` when it builds `StatusInputs`: when true, `context_percent` is `None` (and `context_estimated` false), so `P1-10`'s segment disappears. The same flag is passed as `context_stale` to `UsageReport::build`, and as `last: None` to `prebuild_block`. A session switch calls `forget` on the old session (there is no in-app switch yet; the method is tested on the tracker only).

### 6.4 Held blocks

`turn_active` is true when the foreground session's `TurnState` (`P1-05`: `Idle`, `Running`, `Finished(_)`) is `Running`; a pending approval or question happens inside a `Running` turn. `push` with `turn_active` false returns the block at once (with any older held blocks first); with true, it holds it. When `TurnState` changes from `Running` to anything else, `app.rs` first commits the turn's final cells, then calls `release` and commits the blocks in order. Notices are blocks too, which is why the automatic-compaction notice says the compaction happened "during this turn". A block for a session that is not in the foreground is committed at once (there is only one session per process in phase 2).

### 7.0.1 Fitting rows to the width

All blocks start with the typed command line exactly as typed (sanitized), dim. Every row passes through `P1-06`'s `sanitize`. Numbers use a comma every three digits (`34,120`). No blank lines inside a block. Width is measured per grapheme with ratatui's `CellWidth::cell_width`, as `P1-06` does.

- **Prose rows wrap** with `P1-06`'s `wrap_lines(lines, width)`: the typed line, headers, the `/usage` rows, the source line, the dim scrollback line, every T-C text, notes, notices, error rows and preview lines. Nothing is lost at any width above 0.
- **Fixed rows are cut**: the five grid rows, the category table rows and the context-file rows. A fixed row wider than `width` keeps whole graphemes up to `width − 1` columns and ends with `…`.
- Below 39 columns the grid is left out. At width 0 every renderer returns no rows.

### 7.6 The example `context_demo`

`crates/talaria-tui/examples/context_demo.rs`: `context_demo [--width <cols>] <frame-log>` (default width 80) replays a frame log through `ContextTracker`, `HeldBlocks` and the renderers, with no terminal and no escape sequences. It reads the file itself, line by line with `serde_json`, as `docs/formats/frame-log.md` (`P1-04`) defines version 3: it skips the header and `dropped` records, takes each `frame` record with `dir` `"in"` whose `frame.method` is `"event"`, and passes `frame.params.type`, `frame.params.payload` and the record's `tMs` to the tracker. It uses no `P1-04` reader type, so `talaria-tui` gains no dependency on another Talaria crate (section 5.6). A turn is active from a `message.start` (or `message.delta`) until `message.complete`. It prints `live| <text>` each time the compacting line appears or disappears (the text when it appears, with seconds from the frames' `tMs`; empty text when it disappears; not on every second), and `scrollback| <row>` for each row committed (notices and blocks, after `HeldBlocks` releases them).

| Case | Behaviour |
|---|---|
| `/context` while a turn streams | Call goes out at once (H9: it does not wait behind the turn on the socket); block held until the turn ends |
| `/context` reply after the session ended or the view quit | Dropped silently |
| Breakdown with `context_max` 0 but categories present (old Hermes) | Header without `/ <max>`; no grid; percentages over `estimated_total`; no free row (7.1) |
| Breakdown with `context_max > 0` and no categories | 100 free cells; only the free row (7.1) |
| Category tokens sum above `context_max` | Grid stops at 100 cells; free row 0 |
| 30 categories (future Hermes) | All rows shown; glyph `▪` for unknown ids |
| Label with control characters or bidirectional overrides | Shown with `P1-06`'s visible stand-ins |
| `/usage` with stats failing and no last reading | Error row (7.5) and the `Cost` row; never the no-calls line |
| `/usage` during a turn | Block held; figures are those of the moment the reply arrived |
| `/usage` right after any compaction | No `Context` row until the next reading |
| `/compact` with no session | `P2-03`'s no-session text; no call |
| `/compact` twice quickly | Second gets T-C8; no second call |
| `/compact` mid-turn | Hermes refuses (T-C2); nothing changes; the queue is untouched |
| A prompt submitted while compaction runs | Admitted and queued by Hermes (H23); Talaria's normal queue display (`P2-08`) shows it |
| Compaction reply lost (timeout or drop) | T-C13; request kept; same line resends it (H21); figure hidden; a later `session.updated` for it gives no "another client" notice (6.2) |
| Resend while the first compaction still runs | T-C1; the request stays kept (`settle_as`); the next identical line gets the receipt once it commits |
| Compaction commits and a queued prompt starts at once | The report block is held until that turn ends; the context figure stays hidden until that turn's first usage tick |
| Another client compacts | One `CompactedElsewhere` notice per revision; figure hidden until the next reading |
| Another client's commit event arrives while this Talaria's own compaction is in flight | Figure hidden; no notice (accepted loss, 6.2) |
| `status.update` `compacted` with no earlier `compacting` | One `AutoCompacted` notice; figure hidden |
| Heartbeat `compacting` repeated | One live line; `since` unchanged |
| Turn interrupted during automatic compaction | `message.complete` clears the live line |
| Narrow terminal (under 39 columns) | No grid; prose wraps; fixed rows cut with `…`; at width 0 no rows |

### 10.1 The live test

`live_context_usage_and_compaction`: reads every frame log in `TALARIA_LIVE_FRAMES` (recorded by the scenario of section 9 into a temporary directory). For each, it asserts the section 9 evidence, runs every reply through `Breakdown::from_result`, `UsageReport::build` and `interpret`, and records what `session.stats` answered right after the compaction (U1). It prints `LIVE_CONTEXT_RESULT: PASSED` and, on a separate line, `LIVE_CONTEXT_STATS_AFTER_COMPACTION: api_calls=<n>`; with no logs or missing preconditions it prints `LIVE_CONTEXT_RESULT: SKIPPED (<reason>)` and passes, unless `TALARIA_LIVE_REQUIRE=1`, when a skip fails. Its red run is taken with a recording present and `TALARIA_LIVE_REQUIRE=1`, so it reaches the stubs.

### 10.2 The property test (test 24)

Generator (`proptest`): a sequence of 0 to 64 steps for one session id; `now_ms` starts at 0 and grows by 0 to 10,000 per step. Each step is one of:

- `begin_compact`;
- `finish_compact` with `Committed { revision }` (0 to 20), `Unknown` or `NothingChanged`;
- `observe` with a type chosen from `session.usage`, `message.complete`, `status.update`, `session.updated` and `other.event`, and a payload chosen from: the right shape for that type with random values (`context_percent` an integer 0 to 100, absent, or the string `"5"`; `kind` from `compacting`, `compacted`, `other` or the number 5; `operation` from `compress`, `model` or absent; `revision` an integer 0 to 20, absent, or the string `"7"`; `summary.headline` a short string or absent), or arbitrary JSON (null, booleans, numbers, short strings, and arrays and objects of those, nesting depth at most 2).

Invariants: no step panics; the number of `AutoCompacted` notices is at most the number of `compacted` events, and two `AutoCompacted` notices always have a `compacting` event between them; no two `CompactedElsewhere` notices carry the same `revision`, and each one's `revision` is above every integer revision passed in earlier `finish_compact(Committed { .. })` steps and `session.updated` compress events; `context_hidden` is true right after any step that produced a notice or a `finish_compact` with `Committed` or `Unknown`.

## 11. Live scenario rules (UAT)

- Build the branch and run it by absolute path, `T=<checkout>/target/debug/talaria`. Each scenario uses a fresh Herdr pane `P<n>` started in a fresh folder `$TMPDIR/ctxproj-<n>`, with `--profile fixture --model minimax-m3.1-flash --provider ollama-cloud`.
- The pane must be at least 100 columns wide and 40 rows high. Before starting Talaria, send `tput cols; tput lines` to the pane's shell and read the answers; below either, enlarge the pane or the scenario is BLOCKED (environment). Prose wraps at any width, but the scenario greps expect unwrapped header lines, and 40 rows keep a whole `/context` block (about 20 rows) and the composer on screen for a `visible` read.
- Type into Talaria with two calls: `herdr pane send-text P<n> '<text>'`, then `herdr pane send-keys P<n> enter`.
- Wait for a reply with `herdr pane wait-output P<n> --regex '<pattern>' --source visible --timeout 120000`.
- Read with `herdr pane read P<n> --source visible` for the live region and `--source recent-unwrapped` for scrollback; if `recent-unwrapped` comes back empty, use `visible` and say so. (Herdr wants the pane id before the options.)
- For sixteen turns, loop: send `Reply with only the word <word>.`, then wait for the word on its own line.
- All reads empty, a wait timeout, an unexpected approval card (deny it), or a connection error is BLOCKED (environment), never PASS. At most three fresh sessions per scenario.
- Each result goes on the pull request with the scenario id, the commit, and the pane reads.
- UAT-3 (compaction): after `/compact focus on the numbers`, read every 2 s for at most 11 minutes and stop at the first line containing `✓ Compressed`, `No changes from compression`, `Compression aborted`, `Compression refused` or `No answer from Hermes`. Then classify: `✓ Compressed: <a> → <b> messages` with `a > b` continues the scenario; `✓ Compressed with fallback`, `Compression aborted`, `Compression refused` and `No changes from compression` are BLOCKED (environment: the summary model failed or nothing was removable, H19, H20); the T-C13 text is FAIL with every read attached. If no read caught `✻ Compacting conversation` because the result came within 2 s, the evidence says so.
- UAT-4 (busy refusal): `/compact` must be sent while the reply streams. Wait with `herdr pane wait-output P4 --regex '^\s*20\s*$' --source visible --timeout 120000`, read the pane, then send `/compact` at once. If `300` was already on screen in that read, or the first result is any compaction headline instead of T-C2, the run is BLOCKED (environment: the model finished too fast) and is retried once with `Count from 1 to 1000, one number per line.` Take the read for the T-C2 check with `herdr pane wait-output P4 --regex 'Hermes cannot compact while' --source visible --timeout 120000` followed at once by a `visible` read, before sending the next command, because later output can push it off the visible screen. The "no `✓ Compressed`" check runs over every read of the scenario.
- UAT-2 (`/usage` then `/cost` in one pane): the read after `/cost` still shows the `/usage` block above it, so count only the lines from the typed `/cost` line down: `herdr pane read P2 --source visible | sed -n '/^ *\/cost *$/,$p'`.
