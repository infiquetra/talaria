## 0. What this unit is, in one paragraph

Two small features that let a Hermes session be watched from more than one terminal. First, `talaria attach <session>` opens an existing session by its full id, the start of its id, or its title, in whichever served profile it lives, without the operator having to know the profile; it then behaves exactly like `talaria --resume <id> --profile <p>` from unit P1-12 (history, live stream, `/quit` detaches and leaves the session running). Second, inside the terminal multiplexer Herdr (built for running coding agents in panes) or inside tmux, the fleet view of unit P3-02 gains an action, `o` by default, that splits the current pane and types `talaria attach <id> --profile <p>` into the new pane's shell, so two sessions sit side by side. Talaria never draws two sessions in one process ([05-architecture.md](../05-architecture.md#the-screen): "Side-by-side sessions are the multiplexer's job"). The roadmap row is [07-roadmap-and-work-units.md](../07-roadmap-and-work-units.md#phase-3--the-fleet-many-agents-in-the-background) ("P3-08 Attach anywhere"; its "Hermes calls" column is "—" because the unit adds no new Hermes method: it reuses `session.list` and P1-12's `session.resume`); the parity row is "Agent view, background sessions (`--bg`), attach" in [04-prior-art.md](../04-prior-art.md#claude-code-parity-checklist).

## 4. Design decisions and their reasons

1. **Attach is resume plus a better lookup.** P1-12's `--resume <id>` needs the exact id and the right `--profile`. `talaria attach` finds the session across served profiles from the start of its id or its title, then hands a resolved `Launch` to P1-12's `run`. No second session engine. Rejected: a separate attach mode with its own screen (duplicates P1-12, and two code paths drift).
2. **Resolution is client-side and read-only.** Talaria lists the live and stored scopes (F4, F5) and matches rows itself. It never sends `session.list {title}` across profiles: that lookup goes through `resolve_titled_session`, which calls `resolve_local_target`, which restores or adopts the matched session (`gateway/session_local_migration.py` lines 46 to 67), so an ambiguous title would wake sessions the operator did not choose. Only the session finally chosen is resumed.
3. **The fast path makes no extra call.** With `--profile` and a full id (F9 shapes), `attach` skips the listing and the served-profile check entirely, so "open in new pane", which always passes both, starts as fast as `--resume`. The cost: an unserved `--profile` on the fast path gets P1-12's own failure (P1-01's `NeverDiscovered`, exit 1), not A4 (exit 2). Accepted (edge case 10.19).
4. **A new pane is a shell with a typed command.** Herdr's `pane split` takes no command (M2), so Talaria splits, then types the command with `pane run` (M4). For tmux the same shape is used on purpose (split, then `send-keys`): a pane whose command exits closes at once (M10), which would hide an error and P1-12's resume hint. With a shell, both stay visible and the pane is reusable. Rejected: `tmux split-window ... -- talaria attach ...` (errors vanish); `split-window -k` (tmux 3.7 and later only, and it leaves a dead pane rather than a usable shell); wrapping in `sh -c` (another quoting layer, not portable to the user's shell).
5. **The command runs this exact binary.** The command line starts with `std::env::current_exe()`, never a bare `talaria`, so the new pane runs the same build as the fleet view (a stale `talaria` elsewhere on `PATH` has misled testers before).
6. **Ensure runs at most once.** `attach` runs P1-01's ensure step itself before finding (6.2 step 4) and then hands P1-12 a `Launch` with `no_ensure: true`, so P1-12 does not run `hermes gateway ensure --json` a second time. Discovery (reading the gateway's `identify`) may run up to three times (step 4, inside P2-07's `SideConnection::open`, inside P1-12's `run`); discovery never starts a gateway.
7. **Two viewers of one session are normal.** Hermes Desktop does the same (F13); approvals reach every attached viewer and the first answer wins (unit P3-02's specification, fact F11). The fleet view's own peek may stay open while the new pane attaches; UAT-3 runs exactly that case live.
8. **Focus stays in the fleet view by default** (`[panes] focus = false`), so the operator can open several sessions in a row (`o`, `j`, `o`) and Herdr's guidance for background panes holds (M6). Operator question 1 may flip the default.
9. **One connection at a time.** The attach resolver's side connection is closed before P1-12 opens the session's link, so draft decision 0007 point 2 ("one connection per Talaria process") holds at every moment.
10. **No new Hermes method.** Everything uses `session.list` and P1-12's `session.resume`.
11. **`Opened` means typed, not started.** Herdr acknowledges admission of the typed text, not its execution (M4). Talaria reports `Opened` and acknowledges the row (P3-01's `FleetHandle::acknowledge`) once the split and the typing were accepted. The operator chose to look at the session by pressing `o`; that is the acknowledgement. Whether the new Talaria started is visible in the new pane, and a failure there stays on screen (decision 4).

## 6. `talaria attach`

### 6.1 Grammar

```text
talaria attach [--profile <name>] [--no-ensure] [--record <path>] [--] <SESSION>
```

- `<SESSION>`: a full session id, the start of one (section 6.3 says how many characters), or a session title. Quote titles with spaces. A reference that starts with `-` must come after `--` (`talaria attach -- -my-title`), as for any clap positional.
- `--profile`, `--no-ensure`, `--record`: the meanings P1-12 gives them (its REQ-1 and REQ-6). `--profile` is validated only as P1-12 validates it (blank refused, a usage error, test 20); any other name, `.` and `..` included, is checked against the served profiles (A4, test 18) or, on the fast path, by P1-12 (edge case 10.19, test 22). On the fast path P1-12 resolves the name with P1-01's `resolve_profile`, which matches it against the served list in memory and builds no folder path from it, so `.` and `..` end in `NeverDiscovered` (exit 1) with no file-system access. `--record` is passed through unchanged to `Launch.record`.
- `talaria attach --help` prints clap's help for the subcommand on standard output and exits 0 (clap's default).
- Refused as usage errors (exit 2, standard output empty): no `<SESSION>`; any other option, including `-c`, `--continue`, `--resume`, `--model`, `--provider`, `--effort`, `-p`, `--bg`; a second positional argument; a reference that fails `validate_reference` (text A1). Clap's own text passes P0-02's neutralising rule. Test 20 asserts, for each clap-refused case: standard error starts with `error: ` and contains the offending token (`--model`, `-c`, `--resume`, the second positional's text) or, for the missing reference, `<SESSION>`; for a blank reference, the exact A1 lines.

### 6.2 Order

1. Parse. Validate the reference (A1 on failure, exit 2).
2. Check for a terminal exactly as P1-12 REQ-3 does (same two lines, exit 2), before any network call or subprocess.
3. **Fast path**: `fast_path(request)` is `Some`. Build P1-12's `Launch { mode: StartMode::Resume(Some(reference)), profile, folder: <launch folder>, record, no_ensure: <the user's --no-ensure>, model/provider/effort: None, bench_replay: None }` and call P1-12's `run::run`. No ensure here, no listing, no served-profile check: P1-12 does its own ensure and discovery exactly as for `--resume`.
4. **Ensure and discover**: P1-01's `discover_with(home, EnsurePolicy::Run { .. })` (or `EnsurePolicy::Never` with `--no-ensure`). Its errors map through P1-12's `LaunchFailure` (exit 1). Keep the names of `Endpoint::profiles()`, in their order, as `served`.
5. **Find**: `find_session(home, request, served, now)` (6.4). Write its notes (A6, then A5) to standard error, on success and on failure; on failure then print `failure.render()` to standard error and exit with `failure.exit_code`.
6. **Hand over**: build the `Launch` of step 3 with the found key's `session_id` and `profile`, and `no_ensure: true` (step 4 already ensured; design decision 6). Call P1-12's `run::run`. From here on, everything (first frame, `── Resumed: <title> ──`, the folder notice of P1-12 REQ-10, `/quit` detaching without `end_reason`, the resume hint) is P1-12's.

The ensure subprocess and the listing both run before P1-12's first frame. That is the second exception to P1-12 REQ-4's "no network or subprocess before the first frame", alongside its own `--resume` list.

### 6.3 Resolution (`resolve`, pure)

Input: the validated reference `r` and the merged rows (P2-07's `merge`, live winning, keyed by `RowKey { profile, session_id }`). Let `lr` be `r` in lower case, `sid` each row's `session_id` and `lsid` that `session_id` in lower case. The row's contract field `id` (the lineage root in the stored scope, F2) is never read by `resolve`; neither is `source`.

| Tier | A row matches when | Kind |
|---|---|---|
| 1 | `sid == r` (exact, case-sensitive) | `ExactId` |
| 2 | Tier 2 applies only when all three hold: `lr` contains only `[0-9a-z_-]`; `lr` is not a prefix of `local-` (so `loca`, `local` and `local-` never match every local session); and the part of `lr` after an optional leading `local-` has at least 4 characters. A row matches when `lsid.starts_with(lr)`, or `lsid` starts with `local-` and `lsid[6..].starts_with(lr)` | `IdPrefix` |
| 3 | `row.title == r` and `row.title` is not empty | `Title` |
| 4 | `row.title.to_lowercase() == lr` and `row.title` is not empty | `TitleIgnoringCase` |

The first tier with at least one match decides: one match gives `One`, several give `Many` (ordered as P2-07's `order`: live first, newest first, then by key), none in any tier gives `NoMatch`. The function does not depend on the input order of the rows (property test 11). A short prefix that many ids share (for example `2025`, which starts every stored id of that year) gives `Many` and text A3: an error, never a wrong open (edge case 10.20). If one conversation is listed under two `session_id`s (a live row and a stored row whose lineage tip differs; not observed, not ruled out), `merge` keeps both rows and a title or prefix gives A3 listing both: the operator picks with more of the id. Deduplicating by lineage is out of scope.

### 6.4 Finding (`find_session`)

1. **Served-profile check, before any connection.** If `request.profile` is `Some(name)` and `name` is not in `served`, return A4 (exit 2). No ticket is minted (F16) and no `session.list` is sent. Otherwise the ticket profile is `ticket_profile(request, served)`: `--profile` when given; else `default` when served; else the first served name. (`served` is never empty: P1-01's discovery fails with `HomeNotServed` first.)
2. **Open** P2-07's `SideConnection::open(home, <ticket profile>)`. If it fails, return A7 (exit 1) with the P2-07 phrase for the `SideOpenError` variant (6.6, `<reason>`); nothing is listed. Its scope is `SideScope::Host { profiles }` (every served profile) or `SideScope::ProfileOnly { profile, why }` (the host ticket or upgrade was refused and P2-07 fell back to a profile-scoped ticket).
3. **Profiles in scope** (this set is "the configured scope" everywhere below): with `--profile`, that one profile; without it, on a host scope, every served profile in `served` order; on a profile-only scope, that one profile, and note A6 is added **only when `--profile` was not given** (with `--profile` the search is exactly what was asked).
4. **List**, all at once: for each profile in scope, `session.list {profile, scope: "live", limit: 200}` and `session.list {profile, scope: "stored", limit: 200}`, with the `profile` key only on a host scope (P2-07 REQ-2; never `title`, never `include_hidden`). All calls are in flight together on the one side connection (section 5, concurrency). Timeout 10 s each.
5. **Decode** rows with `DirectoryRow::from_list_row(profile, origin, row)`; skip rows that fail. A call that fails (refusal, timeout, drop, reply too large) is recorded with its reason (6.6, `<reason>`) and adds one A5 note naming its profile and scope. A profile is **failed** only when both of its calls failed; when one call failed, the other call's rows are searched and the A5 note says which scope was not searched.
6. **Close** the side connection (always, on every path, including every error return after step 2) before returning.
7. **Decide**:
   - Every profile in scope failed: A7 (exit 1), with the reason of the first failed call in `served` order, live before stored. Every error return below is an `AttachFailure` whose `notes` hold the notes gathered so far (A6, then A5 lines in `served` order, live before stored).
   - `One(c)`: return `AttachTarget { key: c.row.key, notes }` (notes: A6, then the A5 lines in `served` order, live before stored).
   - `Many(cs)`: A3 (exit 2), after the notes.
   - `NoMatch`, the reference's shape is `FullLocal`, `Stored` or `LocalShort`, and the configured scope holds exactly one profile, which is not failed: return that profile with `session_id = reference` (pass-through). Hermes resolves `local-<16 hex>` itself (F7) and opens a full id as given, so a session older than the 200 newest rows is still found. An unknown id answers `not_found` (F14), which P1-12 reports with its own text (exit 1). Passing a full `Stored` id through is the same thing `talaria --resume <id> --profile <p>` does.
   - Otherwise `NoMatch`: A2 (exit 1), after the notes. Prefix and title search sees only each scope's 200 newest rows (`LIST_LIMIT`); an older session is found only by the pass-through above (full id or `local-<16 hex>` with one profile in scope), which A2's next step points to.

### 6.5 What the hand-over sends

P1-12's resume by id: `session.resume {session_id, display_projection: true}` on a new profile-scoped link for the found profile. Nothing else is added by this unit.

### 6.6 Texts and exit codes (standard error; every echoed Hermes string and the reference pass P1-06's `sanitize`)

| Id | When | Text | Exit |
|---|---|---|---|
| A1 | Empty, too long or control character | `talaria: the session to attach to is empty.` / `talaria: the session reference is longer than 200 characters.` / `talaria: the session reference contains a control character.` then `Next step: pass a session id, the start of one, or a title.` | 2 |
| A2 | No match | `talaria: no session matches "<ref>" in the profiles <p1>, <p2>.` then `Next step: run "talaria fleet list" or "talaria --resume" to see sessions, or pass the full id with --profile <name>.` The names are the profiles searched (not failed), in `served` order; with one: `in the profile <p>.` | 1 |
| A3 | Several matches | `talaria: <n> sessions match "<ref>":` then `candidate_lines`, then `Next step: use more of the id, or add --profile <name>.` | 2 |
| A4 | `--profile` not served (non-fast path) | `talaria: the profile <name> is not served by the gateway (served: <p1>, <p2>).` then `Next step: pick a served profile, or ask the operator to serve <name>.` | 2 |

## 7. Open in a new pane

### 7.1 Detection (`detect`)

- `Off`: none.
- `Herdr` or `Auto` with Herdr present: `HERDR_ENV == "1"`, `HERDR_PANE_ID` non-empty, `HERDR_BIN_PATH` non-empty gives `Herdr { bin: HERDR_BIN_PATH, pane: HERDR_PANE_ID }` (M1).
- `Tmux` or `Auto` without Herdr: `TMUX` and `TMUX_PANE` non-empty give `Tmux { bin: "tmux", pane: TMUX_PANE }` (M7). The `tmux` binary is found on `PATH` when run.
- `Auto` with both present: Herdr (U6, edge case 10.12).
- `Herdr` forced but its variables absent, or `Tmux` forced but its variables absent: none.

### 7.2 Direction (`choose_direction`)

`Right` and `Down` settings are used as given. `cols` and `rows` are Talaria's own terminal size (inside a multiplexer, the pane Talaria runs in). `Auto`: `Right` when `cols >= 120` and `cols >= 2 * rows`; otherwise `Down`. Examples: 160 by 48 gives right; 200 by 120 gives down; 100 by 30 gives down; 120 by 40 gives right.

### 7.3 The two steps

Herdr (all arguments as separate list items; no shell):

```text
<HERDR_BIN_PATH> pane split --current --direction <right|down> [--cwd <folder>] <--focus|--no-focus>
   → stdout JSON; new pane id = .result.pane.pane_id (non-empty string)
<HERDR_BIN_PATH> pane run <new pane id> <command line as ONE argument>
```

tmux:

```text
tmux split-window <-h|-v> [-d] -t <TMUX_PANE> [-c <folder>] -P -F '#{pane_id}'
   → stdout "%<n>" plus a newline; new pane id = the trimmed line, which must match ^%[0-9]+$
tmux send-keys -t <new pane id> -l <command line as ONE argument>
tmux send-keys -t <new pane id> Enter
```

`-h` for right, `-v` for down; `-d` only when `focus` is false. `#{pane_id}` is one argument (no shell, so no quoting). `parse_new_pane` returns `None` for anything else (empty output, invalid JSON, a missing or empty `pane_id`, a tmux line that is not `%<digits>`).

The folder is the launch folder P1-12 keeps (`Launch.folder`) when it still exists, else the folder option is left out and the multiplexer chooses. Each step runs with a 5 s timeout through `CommandRunner`; on a timeout `SystemRunner` kills the child as section 5 says.

### 7.4 The command line (`attach_command_line`, pure)

```text
'<exe>' attach '<session_id>' --profile '<profile>'
```

- Each of the three variable parts is wrapped in single quotes.
- The exe path: refused `UnsafeExePath` (T8b) when it contains a single quote, a backslash, a control character (C0, DEL, C1) or is not valid UTF-8. A home folder whose name holds an apostrophe therefore cannot use "open in new pane"; T8b says why and `talaria attach` by hand still works.
- The session id and the profile: refused `UnsafeArgument` (T8) when either contains a single quote, a backslash or a control character, when the session id is outside `^[A-Za-z0-9._:@][A-Za-z0-9._:@-]{0,199}$` (no leading `-`: the new pane's argument parser would read `'-x'` as an option, since the template has no `--`; Hermes-created ids never start with `-`), or when the profile is outside `^[A-Za-z0-9_-][A-Za-z0-9._-]{0,63}$` (wider than F10, so local names derived from a profile home's folder still pass, but never `.` or `..`). Hermes strings never reach a shell unquoted.
- `--profile` is always written, `default` included, so the new process takes the fast path (4.3).
- The whole line must be at most 1,000 bytes (below macOS's canonical input limit, M4), else `TooLong` (T8c). Only a long exe path can reach it (the id is at most 200 bytes, the profile 64).
- Inside single quotes `sh`, `bash` and `zsh` treat every character literally; `fish` also interprets `\\` and `\'`, which is why a backslash is refused in every part.

### 7.5 `open_in_pane`

1. If `request.exe` no longer exists on disk (`std::fs::metadata` fails; on Linux a rebuilt binary's `current_exe()` reads `... (deleted)`), return `Refused(BinaryGone)`; nothing runs. `fleet_actions::execute` passes `current_exe()` as obtained when the action runs; if that call fails it passes an empty path, which this step refuses the same way.
2. `attach_command_line(exe, key)`; on refusal return `Refused`.
3. `detect`; none gives `NoMultiplexer { command, off: setting == Off }`.
   (Steps 1 to 3 run in this order, so outside a multiplexer a refused line shows T8 to T9, never T3.) The folder option is `request.cwd` only when that folder still exists (`std::fs::metadata` succeeds and it is a directory); otherwise it is left out.
4. Run the split command. Exit code not 0, a timeout, or `parse_new_pane` giving `None` returns `SplitFailed` with the reason of 7.6.
5. Run the typing commands in order (tmux: stop at the first failure). A failure returns `TypeFailed` (the new pane is left open; Talaria never closes a pane).
6. Return `Opened` (decision 11: typed, not proven started).

### 7.6 Texts (shown through P3-02's notice line; `<title>` is P3-02's `title_or_untitled`, sanitised, cut to 40 characters; `<mux>` is `Herdr` or `tmux`, exactly as `Multiplexer::name` returns it)
