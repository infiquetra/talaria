# P2-06: Model, provider and effort picker that changes this session by default (unit P2-06)

Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

## How to use this document

Read the issue first: it says what to build, which tests to write first, the acceptance scenarios and when to stop. Come here for the evidence and the detail: section 2 lists every Hermes fact the unit relies on, with the file and line at Hermes v0.22.4; section 3 shows how Hermes Desktop, Hermes's own terminal UI and Claude Code present the same feature; section 4 is the design (states, keys, layout, every user-visible text); section 5 gives exact request and result shapes; section 6 the mock-server rules; section 7 the edge cases; section 8 the inputs and expected values for each test; section 9 the facts a planner re-checks at the pinned commit. Fact ids (H1 to H47) and text ids (T1 to T39) are cited from the issue. Everything here is public: no local paths, no private names; profile names are only `default` and `fixture`.

## 1. What this unit adds, in one paragraph

A developer working in Talaria wants to change the model, the provider or the reasoning effort of the session in front of them without restarting, the way Claude Code's `/model` picker works. Hermes already does the work: `model.options` lists every provider with its models, sign-in state, prices, capabilities, rate limits and subscription usage; `session.mutate` with operation `model` switches the session's model (and optionally its effort in the same commit), and operation `reasoning` changes only the effort. Talaria adds a full-screen picker overlay (opened with `/model` or Alt+P), a `/model <name>` and `/effort <level>` shorthand, favourites, a confirmation card for the guarded switches Hermes asks about, correct handling of a change made while a turn runs (Hermes holds a model pick, and an effort sent through `config.set`, until the turn ends), a check that a saved default still exists before a new session uses it, and an explicit "also use this for new sessions" choice that Talaria stores on its own side. The unit also provides the revision-fenced `session.mutate` helper that the other phase 2b units reuse.

### 2.4 How Hermes's own clients present it

Hermes's terminal UI (`ui-tui`):

- The picker loads `model.options` with `include_unconfigured: true` and the session id, then walks three steps: provider, model, effort ([`ui-tui/src/components/modelPicker.tsx` lines 117 to 155](https://github.com/NousResearch/hermes-agent/blob/v0.22.4/ui-tui/src/components/modelPicker.tsx#L117-L155)). The effort step lists the ladder, `none` and "keep current", and is skipped when `capabilities[model].reasoning` is false; unknown capabilities keep the step (lines 27 to 45). Ctrl+G toggles "persist: global"; the picker emits `/model <model> --provider <slug> [--reasoning <level>] --global|--tui-session` (lines 47 to 59, 399 to 414). A provider that is not signed in opens an inline key entry (`model.save_key`) for api-key providers (lines 255 to 317, 449 to 472).
- On the canonical gateway, `/model` becomes a `session.mutate` `model` operation; any flag other than `--provider`, `--reasoning` and the session flags is refused locally ("unsupported canonical model option"), so `--global` does not work there ([`ui-tui/src/app/slash/canonicalSessionControls.ts` lines 20 to 54](https://github.com/NousResearch/hermes-agent/blob/v0.22.4/ui-tui/src/app/slash/canonicalSessionControls.ts#L20-L54)). It reads the fences with a fresh `session.resume` before each mutation (lines 72 to 80), keeps the exact params of a request whose reply was lost so that reissuing the same command re-presents it (lines 16 to 18, 97 to 166), asks "switch anyway" for `confirmation_required` and reports, without asking again, a confirmed send that is refused again (lines 197 to 226), and prints a "switched for the next turn" line for `deferred` (lines 266 to 295). `/reasoning <level>` is the `reasoning` mutation; `--global` goes to `config.set` ([`ui-tui/src/app/slash/canonicalSessionCommands.ts` lines 124 to 145](https://github.com/NousResearch/hermes-agent/blob/v0.22.4/ui-tui/src/app/slash/canonicalSessionCommands.ts#L124-L145)).

## 4. Design

### 4.1 Settled decisions and why

1. **Hermes calls that change a session.** `session.mutate` operation `model` (model, provider and, when changed, effort in one commit) and operation `reasoning` (effort only). `config.set {session_id, key: "reasoning", value}` with the default session scope, only after `reasoning` was refused because a turn runs (decision 5). Never `config.set` with key `model` (H32), never `scope: "global"` (H33), and never `slash.exec` for `/model` (the shared gateway refuses registry commands there; `P2-03` H21).
2. **"Default for new sessions" is Talaria's own setting.** The socket has no way to write the profile's default model at v0.22.4 (H18, H32, H34), and no unit before phase 4 makes HTTP calls (the roadmap puts the dashboard API in phase 4, `P4-00` and `P4-03`). Talaria stores the choice per Hermes profile in its own file and passes it to `session.create` when it starts a session without `--model`, `--provider` or `--effort` (section 4.6), after checking that the saved model still exists (H36). Rejected: writing the effort with `config.set ... scope: "global"` (H33) while the model stays Talaria-side, because a half-Hermes, half-Talaria default is confusing and the global write also changes other clients' sessions; writing the profile through the dashboard API now, because that is phase 4. Whether to also write the Hermes profile default later is operator question 1.
3. **Fences are tracked, not re-read.** Talaria seeds each session's revision and generation from the create or resume snapshot (H43), then adopts them from `session.info` partials, `session.updated` and every mutation result, never moving backwards (H28). A fence refusal names the current fences (H26): adopt them and retry once with a new `request_id`. Hermes's terminal UI re-reads with `session.resume` instead; that returns the whole transcript and re-attaches the viewer, which a long session should not pay for each pick. A consumer that must re-read anyway (`P2-09`) adopts the read's numbers into the ledger before `build`.
4. **A lost reply is retried exactly.** When a mutation's outcome is unknown (timeout, dropped connection), Talaria keeps the exact request. If the developer makes the same pick again, Talaria resends the identical request (same `request_id`), and Hermes answers with the first attempt's receipt (H27). A different pick discards the kept request.
5. **Effort during a turn is held by Hermes, not Talaria.** Hermes defers a model pick (H22) but refuses `session.mutate reasoning` with `session_busy` during a turn (H21). `config.set` key `reasoning` with session scope stores the level in Hermes and commits it at the turn boundary, before a deferred model pick (H35, H40). Talaria tries `session.mutate reasoning` first (it returns a fenced receipt when the session is idle) and sends `config.set` once after a busy refusal. Rejected: a client-side hold re-sent when Talaria sees the turn end (the first draft). It imitated a Hermes feature (architecture principle 1), was lost when Talaria quit, and a re-send refused busy again had no further trigger. Effort chosen together with a model rides in the model pick, which Hermes defers itself.
6. **Confirmation is a card, never automatic.** A `confirmation_required` result or event opens a card; only an explicit "switch anyway" resends the whole pick (`reasoning` included, H38) with the token. A confirmed resend that comes back `confirmation_required` again is reported, not asked again (as Hermes's terminal UI does).
7. **The picker is an overlay.** Architecture principle 2 and requirement R2 put pickers on the alternate screen, leaving nothing behind; `P1-06` provides `open_overlay`, `draw_overlay` and `close_overlay`, and `P2-07`'s session picker uses them. While the overlay is open, transcript commits queue (`P1-06` REQ-16) and appear when it closes. The first draft made it an inline live section because Claude Code's picker is inline; that contradicted the architecture and was dropped. The confirmation card stays a live section, like `P1-09`'s approval cards, because it can arrive while no picker is open.
8. **Providers that are not set up are listed but never switched to.** Key entry and sign-in are `P4-02`'s. Talaria requests `explicit_only: true, include_unconfigured: true` (H6): configured providers' models can be picked; every other canonical provider appears once in a "Not set up" group, and Enter on it explains how to set it up (T14) without sending anything.
9. **No secret and no account label is shown.** Rows show `key_env` names (variable names), never values; subscription accounts are shown as "account 1", "account 2" in Hermes's order, never by `label` or `id`, so that screenshots attached as evidence to a public pull request cannot leak an account name.
10. **Pure core.** All state, filtering, key handling and text live in `talaria-core` as pure functions. Request ids are built by the ledger from the launch id and a counter (`<launch_id>-m<n>`; H27 needs uniqueness per session and principal, not randomness), so the core needs no random source. Core text is not sanitised; drawing sanitises (section 4.4).

### 4.3 States

**Per-session pick state** (`PickState`, one per session that this window has changed):

```text
                 pick (model or effort)          Committed                  notice T1/T3/T4
 Idle ─────────────────────────────► Sending ─────────────────────────► Idle
   ▲                                    │  Deferred ───────────────────► Deferred{target, from_model} ──(session.updated
   │                                    │                                   │     model receipt, or session.info whose
   │                                    │                                   │     model != from_model)──► Idle
   │                                    │  NeedsConfirmation ──► Confirming{conf, confirmed:false}
   │                                    │  FenceRefused ──(retry once, new id)──► Sending
   │                                    │  FenceRefused again ──► Idle + T10
   │                                    │  Refused session_busy / unknown_execution (reasoning)
   │                                    │        ──► SettingEffort ──(config.set reply)──► Idle + T31
   │                                    │                         ──(refused)──► Idle + T24/T25/T29..
   │                                    │                         ──(Unknown/Unreadable)──► Idle + T38
   │                                    │                         ──(NotSent)──► Idle + T35
   │                                    │  Refused other ──► Idle + T6/T24..
   │                                    │  Unknown ──► Idle + T11 (request kept in the ledger)
   │                                    ▼
   │            Confirming ──Accept──► Sending (whole pick + confirm, new id, confirmed:true)
   │                       ──Decline─► Idle + T8 (nothing sent; deferred form when from an event)
   │            Sending(confirmed:true) ── NeedsConfirmation ──► Idle + T9 (not asked again)
   └──── session.updated status "refused" (any window's pick) ──► Idle + T13
         session.updated status "confirmation_required" ──► Confirming (from any state but Sending)
```

- Only one request per session is in flight. A pick made while `Sending` or `SettingEffort` replaces the next pick to send (latest wins) and is sent when the in-flight one settles.
- `Deferred` remembers `from_model`, the model the session ran when the deferred result arrived (the catalogue's `model`, else the last `session.info` model, else none). It clears on: a `session.updated` with `operation: "model"` and no `status` (the commit's receipt broadcast, H25, H45: Hermes sends it for every stored pick it commits, the "cancel" included); a refusal or confirmation event; a new pick, which is sent normally (Hermes keeps the latest, H22); or, as a fallback when the receipt was missed (a reconnect), a `session.info` whose `model` is present and differs from `from_model`. A `session.info` whose `model` equals `from_model` never clears it: Hermes publishes such a full `session.info` while the turn runs and when it ends, before the stored pick commits (H44). The target is never compared exactly (Hermes may store the resolved name, H39). When `from_model` is unknown, only the receipt, an event or a new pick clears it. A pick equal to the committed model while `Deferred` is sent: it replaces the stored pick and so cancels the switch.
- T13 is shown for every `status: "refused"` event of the session, whichever window made the pick: it is true information about this session's model. If Talaria restarted while a pick was deferred, it holds no `Deferred` state; the event still shows T13, and a confirmation is re-asked by Hermes on attach (H42).
- A `session.updated` with `operation: "model"` and no `status` is a receipt broadcast (H25): adopt its fences, show nothing (the `session.info` that follows updates the status line).
- `SettingEffort` sends `config.set` exactly once. Its reply cannot say whether Hermes committed or held the level (H35); T31 says the level applies when the turn ends, which is right in the held case and harmless if the turn ended in between. When the turn ends, Hermes commits it and publishes `session.updated` and `session.info`; nothing more is shown. `EffortSetReturned` with `Err(Unknown)` or `Err(Unreadable)` gives T38 and nothing is resent; `config.set` has no `request_id`, so there is no exact retry, but making the same change again is safe: it starts over with `session.mutate reasoning` and, if still busy, stores or commits the same level (H47). `Err(NotSent)` gives T35; `Err(Refused)` maps as in 4.9. The params are built with exactly three keys: `scope` and `confirm_expensive_model` are left out, never sent as `null` (H47).
- With scope `ThisSessionAndNew` and `/effort <level> --default`, the save happens on the `reasoning` receipt (`Committed`), or on `EffortSetReturned` `Ok` (the T31 reply) when the level went through `config.set`; never on a refusal or an unknown outcome.
- **Confirmation card.** `Confirming` is kept per session. The newest confirmation for a session replaces an older one (its token supersedes). `app.rs` draws the card (`ModelConfirmSection`) for the foreground session's `confirmation()` only while no overlay and no `P1-09` card is open; otherwise it waits and appears when they close or when the session comes to the front, so a confirmation is never dropped. Card keys are fixed and have no `KeyContext`: `app.rs` routes them after `P1-09`'s prompt stack and before the composer, only while the composer draft is empty (`P1-08`'s `Composer::is_empty()`) and after the same 250 ms guard `P1-09` uses when a card takes focus: Enter or `y` is `ConfirmKey::Accept`, Esc or `n` is `ConfirmKey::Decline`, Ctrl+C keeps `P1-12`'s meaning, every other key is ignored while the card has the keys. With a non-empty draft the card does not take keys, its keys line reads T7's draft form, and keys go to the composer, so Enter submits the draft, never the switch. A pick made then (for example `/model x` from the draft) closes the card without a notice and is sent normally; Hermes keeps the latest pick. `ModelsInput::Confirm` with no open confirmation does nothing.

**Picker state** (`PickerState`): `Closed`; `Open { session_id, load: Loading | Loaded(Catalog) | Failed(String), refreshing: bool, filter: String, selected: Option<RowKey>, effort: EffortControl, scope: Scope, current_effort: Option<Effort>, window_top: usize, pending_card: bool }`. Opening with a cached catalogue for the same session shows it at once with `refreshing: true` while the new `model.options` call runs; a load result for a session that is no longer the picker's is ignored. On first load, `selected` is the current model's row in its provider group (not its favourite copy), else the first selectable row.

**Threading.** `app.rs` runs each `ModelsEffect` that needs the network or disk on a background task (`tokio::spawn` of `ModelService::execute`) and feeds the returned `ModelsInput` values back through its event loop, as the roadmap's rules for every unit require. Drawing never awaits.

### 4.4 The picker

**Opening.** `/model` with no argument (`P2-03`'s local command table, `LocalAction::Model`), or the composer action `model_picker` (default `alt+p`, in `KeyContext::Composer`; Claude Code uses Option+P). Effects on open: `OpenOverlay`, `LoadOptions { session_id, refresh: false }` and `ReadEffort { session_id }`. With no session open: notice T19, nothing sent, no overlay. Every open starts with scope `ThisSession`, an empty filter and the effort control at the read level.

**Request.** `model.options {session_id, explicit_only: true, include_unconfigured: true}`; Ctrl+R adds `refresh: true`. Never `profile` (the connection is profile-scoped). `ReadEffort` is `config.get {session_id, key: "reasoning"}` (`methods::canonical::config_get`); a `null` `value` is read as `medium`, Hermes's unset level (H31). `EffortReadFailed` (any failure): the control becomes `Hidden`, the footer's effort part is the dim text `effort: could not be read`, and Enter never adds `reasoning` (an effort-only change is impossible; a same-model Enter is the no-op with T26's no-effort form). With `unknown_method` the same, plus notice T29 (`read the effort`). For `/effort` alone, `EffortReadFailed` gives T39 (T29 for `unknown_method`).

**Rows.** One flat list, in this order:

1. `Favourites` header and one row per favourite (`provider::model` key; label `<provider name> / <model>`), in starring order. A favourite whose provider row is not authenticated, or whose model is not in that row's `models`, shows dim with the badge `not listed`; Enter on it shows T37 and sends nothing; Ctrl+F on it removes it. Hidden when there are no favourites.
2. For each provider with `authenticated: true`, in Hermes's order: a header row, then one row per model in `models` order.
3. `Not set up (<n>)` header, then one row per provider whose `authenticated` is false or absent, in Hermes's order (selectable, so Enter can explain how to set it up; never sent). A not-set-up provider that is the current one (`is_current`) is listed here too, with the `● current` marker.

Header row text: `<name>` (or `<slug>` when `name` is blank), then, joined by ` · `: `current` when `is_current`; usage (below); limit (below); `prices loading` when `pricing_pending`; `free tier` when `free_tier`; `showing <len> of <total_models>` when `total_models` is larger than the number of models.

Usage segment: with `usage.windows` non-empty, up to two windows as `<label> <used_percent rounded half up>%`; with `usage.accounts`, `<n> accounts: <r> ready, <l> limited` (omit a zero count; an `unknown` or `unavailable` account counts in `n` only); otherwise nothing. A window at 90% or more uses the warning colour, at 100% or more the error colour.

Limit segment: `limit.scope == "account"`: `rate-limited until <HH:MM>` (local time of `resets_at`; `rate-limited` alone when null or unparseable). `scope == "models"`: no header segment; each listed model row shows `rate-limited until <HH:MM>`.

Model row text: two leading columns for markers (`★` favourite, `●` current), the model id, then right-aligned: badges and price. Badges, in order: `fast` when `capabilities[model].fast`; `no effort` when `capabilities[model].reasoning` is false; `unavailable` when the model is in `unavailable_models` (dim; Enter explains it, never sends); `rate-limited until HH:MM` (above). Price: from `pricing[model]`: `free` when `free` is true; else `<input> in · <output> out` when both are non-empty and not `?`; else nothing. The current row is the one whose model equals the result's `model` under the provider whose `slug` equals the result's `provider` (or, when `provider` is empty, the provider with `is_current`).

Not-set-up row text: `<name>`, then `needs <key_env>` when `key_env` is set, then `set up with hermes model`. Hermes's own `warning` text is not shown (it tells Hermes's terminal UI user to paste a key, which Talaria cannot take in this phase).

Width: at 60 columns or fewer, prices are dropped; at 40 or fewer, badges too. Text is cut with `…`. Every string from Hermes (names, model ids, labels, `confirm_message`, refusal `detail`) passes through `P1-06`'s `history::sanitize` when the overlay or the card draws it. Notices are drawn by `P1-06`'s commit path, which sanitises every span (`P1-06` REQ-11).

**Layout** (the overlay fills the alternate screen; three lines of chrome):

```text

 > glm▏
 Favourites
 ★ Ollama Cloud / minimax-m3.1-flash                                free
 Ollama Cloud · current · session 42% · weekly 12%
 ● minimax-m3.1-flash                                               free

```

The title line reads `Switch model · this session` or `Switch model · this session and new sessions on <profile>`, with ` · refreshing…` appended while a reload runs over a cached catalogue. The filter line shows `> ` and the filter text (placeholder `type to filter` when empty). The list fills the rows between the filter line and the footer (terminal rows minus 3, never fewer than 3), scrolled so the selected row is visible. The footer shows the effort control and the key hints (hints dropped first as width shrinks); when the selected model has `reasoning: false` the effort part is the dim text `effort: not offered by this model`; while refreshing the hints are replaced by T30. States: `Loading models…` (one dim row) while the first load runs; T16 on failure; T17 when the catalogue has no models at all; T18 when the filter matches nothing. Closing the overlay (`close_overlay`) restores the transcript and writes queued lines.

**Filtering.** Split the filter on whitespace into lower-cased terms; a model row matches when every term is a substring of the lower-cased `"<provider name> <slug> <model>"`. A header is shown when at least one of its rows matches; `Not set up` rows match on `"<name> <slug>"`. Favourites rows match the same way. Filtering keeps Hermes's order (no ranking). When the selected row stops matching, select the first matching selectable row.

**Effort control.** Starts at the current effort (`config.get` value, H31). Left and Right move along `none (off), minimal, low, medium, high, xhigh, max, ultra`, stopping at the ends. Shown as `effort: <current>` when unchanged and `effort: <current> → <new>` when changed. Moving the selection to another model keeps the chosen level. Unknown capabilities keep the control (H8). On a model with `reasoning: false` the control is hidden and Left and Right do nothing; the chosen level is kept for the next model that offers effort.

**Keys.** While the overlay is open, `app.rs` resolves every key in `KeyContext::ModelPicker` before any other context, so Ctrl+G and Ctrl+R are `model_scope` and `model_refresh` here and never reach `P2-13`'s `open_editor` or `history_search`; with the overlay closed they keep `P2-13`'s meanings. The five actions below with names are configurable in `[keys]` under that context; the rest are fixed. `model_picker` (default `alt+p`) is in `KeyContext::Composer`.

| Key | Action |
|---|---|
| printable characters | add to the filter |
| Backspace | delete the last filter character |
| Ctrl+U | clear the filter |
| Up, Down | previous or next row, skipping headers (not-set-up rows, `unavailable` and `not listed` rows can be selected; Enter explains them) |
| PageUp, PageDown | move by the visible list height |
| Home, End | first or last selectable row |

Enter on a not-set-up row shows T14 and keeps the picker open; on an `unavailable` model T15; on a `not listed` favourite T37.

**Applying** (Enter on a selectable model row `(provider slug p, model m)`):

- `m` and `p` are the current ones, the effort is unchanged, and this window holds no `Deferred` state for the session: with scope `ThisSession`, close with T26 and send nothing; with `ThisSessionAndNew`, save `m` and `p` (not the effort: the developer did not choose one, and the displayed level may be Hermes's unset `medium`; a saved effort stays as it was) and show T5.
- `m` and `p` are the current ones, the effort changed, and no `Deferred` state: `session.mutate` `reasoning` with `{effort: <level>}`.
- otherwise (another model, or any pick while `Deferred`): `session.mutate` `model` with `{model: m, provider: p}` plus `reasoning: <level>` only when the effort changed and the model offers reasoning.

The overlay closes as soon as the request is built. Results arrive as notices. A confirmation card that arrives while the overlay is open waits (`pending_card`) and shows when it closes.

### 4.5 Commands

- `/model` alone opens the picker.
- `/model <model> [--provider <id>] [--effort <level>] [--default]`: no picker; sends `model` with `{model}` plus `provider` when given and `reasoning` when given; `--default` sets scope `ThisSessionAndNew`. The model is the first word; flags come after it in any order. A first word that starts with `--` (for example `/model --effort high glm-5`), a repeated flag, an unknown flag, a flag without its value, a missing model, or an effort that does not parse (`--effort default` included: use `/effort default`) gives T22 and sends nothing.
- `/effort` alone: `config.get` reasoning, then notice T27 with the value.
- `/effort <level> [--default]`: `reasoning` with `{effort: <level>}`; with `--default`, the level is saved as the default effort once the change succeeds (the `reasoning` receipt, or the `config.set` reply when it was held, 4.3). `/effort --default` without a level, and any extra word, gives T23. `/effort default` sends `{effort: null}` (the profile's level, H16); with `--default` it removes the saved effort. An unknown level gives T23. A busy refusal goes to `config.set` as in 4.3.

Both are entries in `P2-03`'s `LocalCommandTable`: `model` (`args_hint: "[<model> [--provider <id>] [--effort <level>] [--default]]"`, `takes_argument: true`, `LocalAction::Model`) and `effort` (`args_hint: "[<level>|default] [--default]"`, `takes_argument: true`, `LocalAction::Effort`). Hermes's own `/reasoning` and `/fast` are not intercepted (they pass through `P2-03`; `/fast` display is `P2-15`'s).

### 4.6 Saved choices: `~/.talaria/models.json`

The file lives in the folder of `P1-08`'s `config.toml` (`~/.talaria/`, created with mode 0700 when missing; the file 0600), like `P2-13`'s history file. It is machine-written; people do not edit it. Shape:

```json
{"version":1,
 "favourites":["ollama-cloud::minimax-m3.1-flash"],
 "defaults":{"fixture":{"model":"minimax-m3.1-flash","provider":"ollama-cloud","effort":"high"}}}
```

- `defaults` is keyed by the Hermes profile name the connection serves (`P1-12`'s `OpenConnection.profile_name`). Each of `model`, `provider`, `effort` may be absent.
- Read once at start (missing file: empty, no notice). Written atomically (write `models.json.tmp` in the same folder, flush, rename) after every change.
- A file that is not valid JSON, has another `version`, has the wrong types, or holds an `effort` that `Effort::parse` rejects gives notice T21 once; favourites and saved defaults are then off for this run, and Talaria never overwrites the file (writes are skipped with T21 again at most once per run).
- What a save writes (scope `ThisSessionAndNew`, after `Committed` or `Deferred`, or at once when nothing is sent):
  - `model` and `provider`, always together, for any Enter on a model row and for `/model ... --default`: from the model receipt when committed (Hermes's resolved names), else the row's `m` and `p`, else the `--provider` flag. A deferred `/model <name> --default` without `--provider` has no provider yet, so its save waits for the `session.updated` model receipt (which carries both) and is dropped on a refusal event or when Talaria quits first. A saved model therefore always has a saved provider, which the stale check needs.
  - `effort` only when the developer chose one: the control was moved, `--effort` was given, or `/effort <level> --default` (the receipt's `effort`, or the level sent). A no-op Enter or a model-only pick never writes the displayed level.
  - Fields not written keep their saved values. `/effort default --default` removes `effort`; `/effort <level> --default` writes only `effort`.

**Launch** (used where `P1-12`'s `plan` builds a `NewSession`; `P2-14`'s headless mode inherits it). In this order:

1. Command-line flags win: when `--model` or `--provider` is given, the saved `model` and `provider` are not used; when `--effort` is given, the saved `effort` is not used. `-c` and `--resume` never use saved defaults (a resumed session keeps its model).
2. Stale check, only when a saved `model` or `provider` would be used: call `model.options {explicit_only: true}` without `session_id` (H37) on the open connection, then `check_saved_default`. Drop the saved `model` and `provider` together, with T36, when: the saved provider is not among `providers`, or its row's `authenticated` is not true (`ProviderNotSetUp`); the saved model is not in the row's `models` and the list is complete, meaning `total_models` is absent or equal to the list's length (`ModelNotListed`); or the call failed or timed out (`ListUnreadable`). A model absent from an incomplete list is kept (Hermes shows only part of a long catalogue). The effort is not affected. This costs one `model.options` (about 1.2 s on the operator's machine) before `session.create`, only when a saved model or provider applies; the first frame is not delayed.
3. `apply_saved_default`: each remaining saved field fills the matching `NewSession` field (`model`, `provider`, `reasoning`). A field whose create parameter the gateway does not offer (`runtime.describe`'s `session_create.parameters`, `P1-12`'s check) is dropped with notice T28; flags keep `P1-12`'s refusal.
4. When `session.create` is refused (a JSON-RPC refusal: nothing was created) and the request carried any saved field, Talaria retries once without the saved fields, with a new `request_id`, and shows T20 in the new session. An unknown outcome (lost reply) is not retried this way; `P1-12`'s rules apply. At v0.22.4 the only refusals a saved field can cause are an effort that does not parse (Talaria rejects those on read) and a blank model (never saved), so this is a guard for later releases.

The new session's `CanonicalSnapshot` carries `revision` and `execution_generation`; `app.rs` feeds them as `ModelsInput::SessionOpened` (also after `-c` and `--resume`).

### 4.7 Budgets and idle

- Opening the picker draws within one frame from the cached catalogue, or the `Loading models…` row; no frame waits on the network.
- Filtering 2,000 model rows takes under 2 ms at the 95th percentile (bench `model_filter`, the same bar as `P2-03`'s palette).
- No spinner and no timer: the loading row is static text, so an idle picker draws no frames (the zero-idle-frames budget).
- `refresh: true` can take seconds and holds the connection's request queue (H5, H13), so interrupts and approval answers wait behind it; the title shows `refreshing…` and the footer names the delay (T30). A normal open can also take up to 5 s when the current provider is a custom endpoint (H41).

### 4.8 The app services

- `crates/talaria-app/src/mutation.rs` `MutationClient::send(&self, request: &MutationRequest) -> MutationOutcome` (async): builds `methods::canonical::session_mutate::Params` with `serde_json::from_value(request.to_params())` (an `Encode` error becomes `NotSent`), calls `P1-02`'s `Client::call::<methods::canonical::session_mutate::Marker>`, and passes `serde_json::to_value(&result)` to `classify_result`. `expected_generation` stays present for `model` and `reasoning` (H15). Every `CallError` maps through `classify_error` (`Rpc` by code and data; `TimedOut` and `Unknown` to `Unknown`; `BadResult` to `Unreadable`; `NotConnected`, `Encode`, `InvalidTimeout` to `NotSent`). It never retries; the reducer decides. If the generated result type does not keep the open object's extra fields (`status`, `confirm`, `confirm_message`, `target_model`, `model`, `provider`, `effort`, `revision`, `execution_generation`), test 36 fails and the unit stops: never fall back to `call_raw`.
- `crates/talaria-app/src/models.rs` `ModelService::execute(&self, effect: ModelsEffect) -> Vec<ModelsInput>` (async): `LoadOptions` calls `model.options` (`methods::legacy::model_options::Marker`, `NativeMethod`) and returns `OptionsLoaded` or `OptionsFailed` (reason text for T16; `unknown_method` for `-32601`, T29); `ReadEffort` calls `config.get` (`methods::canonical::config_get::Marker`) and returns `EffortRead` or `EffortReadFailed`; `Mutate` calls `MutationClient::send` and returns `MutationReturned { request, outcome }`; `SetEffort` calls `config.set` (`methods::canonical::config_set::Marker`) with exactly `{session_id, key: "reasoning", value}` (`value` is the level's wire word, `none` for off, `reset` for `None`; no `scope`) and returns `EffortSetReturned`; `SaveFile` writes atomically and returns `FileSaved` or `FileFailed`; `OpenOverlay`, `CloseOverlay` and `Notice` are handled by `app.rs` directly. Timeouts: `P1-02`'s `default_timeout` (120 s) for every call; a `TimedOut` load becomes T16 with the reason `Hermes did not answer within 120 s`.
- `app.rs` feeds `SessionOpened` from every create or resume snapshot, every session event's type name and raw payload to `SessionEvent` (for fences, `session.updated` and `session.info`), `ForegroundChanged`, and `CardOpened` when a `P1-09` card takes focus.
- `ModelService` holds `P1-02`'s client handle and the path of `~/.talaria/models.json`; tests pass a temporary folder.

## 6. Mock-server rules

The mock (`crates/talaria-app/tests/support/mock_gateway.rs`, created by `P1-09` and extended by `P1-12`) gets four handlers, built from the pinned contract (H2, H14, H31, H35) and checked against the recorded fixture, never invented, plus two opt-in switches on `P1-12`'s handlers that are off by default, so existing tests see no change. `P1-12`'s rule 7 (no method outside its list exists) is extended by exactly these four methods.

- `model.options`: accept only the H2 keys, flags as JSON booleans, else `{"code":4001,"message":"invalid_params","data":{"reason":"invalid_params"}}`. With `session_id`, reply with a scripted `ModelOptionsResult` that validates against the generated type; without `session_id`, a second scripted result (the profile's view, H37). A scripted delay is allowed (to test the loading row) and a scripted failure.
- `config.get`: accept only `session_id`, `profile`, `key`, `cwd`; `key: "reasoning"` replies `{"value": <scripted, may be null>, "display":"show"}`.
- `config.set`: accept only `session_id`, `profile`, `key`, `value`, `scope` (`confirm_expensive_model` and a `scope` that is not `session` or `global`, `null` included, give `invalid_params`, H47); for `key: "reasoning"`, refuse a `value` that is not an effort word or `reset` with `invalid_params`; reply `{"key":"reasoning","value":<value>,"scope":<scope or "session">}` and record the frame (tests assert no `scope` was sent). A scripted mode `refuse` answers `permission_denied`; `drop` closes the connection before replying.
- `session.mutate`: accept only the H14 keys; refuse a missing `expected_generation` for `model` and `reasoning` with `invalid_params`; apply H16's payload rules; keep a scripted revision and generation and answer `revision_conflict` or `stale_generation` with both numbers in `data` when they differ; keep receipts by `request_id` (identical request gives the stored result, a different one `admission_conflict`); scripted modes: `busy` (model gives `deferred`, reasoning gives `session_busy`), `guarded` (gives `confirmation_required` with token `tok-1` unless `payload.confirm == "tok-1"`; `guarded-twice` refuses the confirmed send too), `unresolvable` (`model_resolution_failed`), `drop` (close the connection before replying).
- Switch `create_refusal`: `session.create` carrying `reasoning` from a scripted list is refused with `{"code":4001,"message":"invalid_params","data":{"reason":"invalid_params","field":"reasoning"}}`, the shape of `gateway/session_policy.py` lines 614 to 616 through the contract registry (`P1-12` H2). Off by default.
- Switch `describe_without`: `runtime.describe` answers the recorded handshake result with one named key removed from `session_create.parameters`. Off by default.
- Events the mock can push: `session.info` partial (H28), `session.updated` receipt, deferred refusal and deferred confirmation (H23), all with the exact field sets of section 5.
- Every refusal reason the mock uses appears in section 2 (H2, H15, H16, H19, H21, H26, H27, H29, H35). A reply the contract does not define is a stop condition.

## 7. Edge cases

| Case | Behaviour |
|---|---|
| `providers` empty, or every provider has `models: []` | T17; Ctrl+R still works |
| A provider with `name` blank | Use `slug` |
| `authenticated` absent on a row | Treated as not set up |
| `model` in the result names a model missing from its provider's `models` | No row is marked current; the title still works |
| Result `provider` empty | The current row is under the provider with `is_current: true`; if none, no current marker |
| The same model id under two providers | Two rows; the pick sends the row's `slug`, so there is no ambiguity |
| A model id or name with control or bidirectional characters | Drawn through `history::sanitize` (visible stand-ins) |
| `pricing[model]` missing, or `input`/`output` empty or `?` | No price |
| `used_percent` above 100 or negative | Clamp to 0..999 for display; colour by the clamped value |
| `resets_at` unparseable | `rate-limited` without a time |
| `capabilities` missing for the selected model | Effort control shown (Hermes's rule: unknown keeps the dial, H8) |
| `config.get` `value` is `null` | Read as `medium` (H31's unset level) |
| `can_disable_reasoning: false` and the user picks `none` | Sent anyway; Hermes clamps on the wire (H17, `agent/reasoning_effort.py`); not Talaria's call |
| Effort `ultra` | Sent as `ultra`; the status line shows Hermes's wire level (`P1-10`) |
| Opening the picker twice | The second open only refocuses |
| An approval or clarification card from `P1-09` takes focus while the picker is open | The overlay closes; the filter is lost; no notice |
| The foreground session changes while the picker is open | The overlay closes; a pending load result is ignored |
| A mutation result arrives for a session that is no longer in front | Notices go to that session's transcript (shown when it is brought back); fences are adopted |
| Two picks in quick succession | One in flight; the second waits and is sent after the first settles (latest wins) |
| A pick while `Deferred` | Sent normally, even when it equals the committed model (that cancels the switch); Hermes replaces the deferred pick (H22) |
| A typed alias was deferred | `Deferred` clears on the `model` receipt broadcast, or on a `session.info` whose model differs from `from_model`, never on an exact match with the typed name (H39, H45) |
| A full `session.info` with the old model arrives while a pick is deferred (auto-title, end of turn) | `Deferred` stays (H44); a same-model pick is still sent and cancels the switch |
| `config.set` for a held effort times out or the connection drops | T38; nothing resent; the same `/effort` again starts over (H47) |
| `config.get` for the effort fails | Control hidden, footer `effort: could not be read`; picks send no `reasoning`; `/effort` alone gives T39 |
| Effort changed during a turn, then Talaria quits | Hermes still commits it at the turn boundary (H35); a gateway restart before then loses it (gateway memory) |
| Effort changed during a turn and a model pick with its own effort is deferred | Hermes applies the effort first, then the pick, whose level wins (H35, H40) |
| `session.updated` for another `session_id` in its payload | Ignored for display; fences not adopted for this session |
| `session.updated` without `status` | Receipt broadcast: fences only |
| `session.updated` refusal when this window made no pick | T13 shown anyway: it is this session's model |
| `session.updated` confirmation for a pick this window did not make (another window), or while another card or the overlay is open, or for a background session | Kept as that session's `Confirming`; the card appears when the session is in front with no overlay or `P1-09` card open (never dropped); a newer confirmation replaces it |
| Esc on a card raised by `session.updated` | T8's deferred form; the pick stays pending in Hermes and is asked again on the next attach (H42) |
| Talaria restarts while a pick is deferred | No `Deferred` state; the refusal or confirmation event still arrives and is handled; a commit shows only in the status line |
| Fence refusal twice in a row | T10; nothing more is sent |
| A fence refusal reports lower numbers than the ledger holds | The retry uses the larger (monotonic adoption) |
| Unknown outcome, then the same pick again | The identical request is resent (H27); Hermes returns the first receipt |
| Unknown outcome, then a different pick | The kept request is discarded; the new pick gets a new id |
| Fences unknown at pick time (a snapshot path did not feed `SessionOpened`) | T33; the next `session.info` partial (after a turn) supplies them |
| `models.json` missing | Empty; created on the first save |
| `models.json` with an unknown top-level key and `version: 1` | The key is ignored when read and dropped on the next write (say so in the pull request; do not preserve it); any other `version` is T21 |
| Saved default whose provider is no longer set up, or whose model is gone | Dropped before create with T36 (4.6 step 2) |
| Saved model absent from an incomplete list (`total_models` larger) | Kept |
| Terminal narrower than 40 columns | Badges and prices dropped; names cut with `…`; the footer shows only `enter · esc` |
| Terminal shorter than 6 rows | List of 3 rows; `P1-06`'s too-small rule applies below that |
