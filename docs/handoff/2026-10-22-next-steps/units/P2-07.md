### 1.7 How the reference clients present these features

- **Hermes's own terminal UI** (`ui-tui/src/components/activeSessionSwitcher.tsx`): one overlay listing live sessions first, then resumable history; at most 12 visible rows; titles cut at 64 characters; the model shown after its last `/` (`:1-60`); Ctrl+R reloads, Esc cancels, Up and Down move, Enter opens (`:591-680`); it lists with `session.list` live, then `session.list` `scope: "stored"`, each with `limit: 200`, fetched independently so one failure keeps the other (`:368-420`). `/title` with no argument prints the current title from `session.list`; `/title <t>` renames (`ui-tui/src/app/slash/canonicalSessionCommands.ts:84-121`).
- **Hermes Desktop** lists sessions across profiles in its sidebar through dashboard REST routes (`GET /api/profiles/sessions/sidebar`), searches, renames, archives, deletes and branches ([u06](../research/u06-hermes-desktop-catalog.md), row F01). Its rename travels as `session.mutate` `rename` without a generation; its branch as `session.mutate` `branch` with one (`canonical-protocol.ts:418-446`).
- **Claude Code** ([u12](../research/u12-claude-code-parity.json), rows `sess.resume`, `sess.name`, `sess.branch`, `int.export-copy`): `/resume` opens a picker (background sessions marked `bg`; opening a running one moves the current conversation to the back); `/rename` names the session and shows the name in the prompt bar; `/branch` copies the conversation so far into a new branch, switches to it and keeps the original reachable with `/resume`; `/export` writes the conversation as plain text, to a file when given a name.

## 2. Design decisions and why

### 2.1 Overlay, not inline

The picker takes the alternate screen through [`P1-06`](https://github.com/infiquetra/talaria/issues/203)'s overlay API and leaves nothing behind (requirement R2). It is the same mechanism as [`P2-02`](https://github.com/infiquetra/talaria/issues/222)'s transcript pager. Opening a session from it writes a separator and the new session's recent history into scrollback through [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s resume path, the way Claude Code's resume does.

### 2.2 A side connection for listing, picker renames and exports

This is a **proposed exception** to decision 2 of architecture decision 0007 ([ADR-0007](../../../../platform-specs/04-architecture/adrs/0007-attach-to-the-hermes-session-authority.md)), which says "One connection per Talaria process. A second connection is an exception path ... not the architecture." The operator decides it through the parent issue (operator question 4 in the issue). If the operator rejects it, the builder stops; the alternative is a host-scoped foreground link, which changes [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s tested wire shapes and is a different unit. The exception is recorded in `docs/engineering-journal/DECISIONS.md`.

[`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s foreground link is profile scoped (F4), so it cannot list other profiles. Changing the foreground link to a host scope would make every foreground call need a `profile` key and would change [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s tested wire shapes. Instead this unit opens a **side connection**: a second WebSocket with a host-scoped interactive ticket, no session tracking, no reconnect loop. It carries `session.list` for every served profile, renames of picker rows, and every export. When it opens and closes, and what happens when it drops, is in section 2.9.

Two more reasons: an export reply larger than 8 MiB closes the connection that receives it (F41), and it must never be the foreground link; and a slow list of many profiles must never delay a keystroke or an event on the foreground link.

The side connection uses [`P1-01`](https://github.com/infiquetra/talaria/issues/198)'s handshake unchanged, so it sends `client.capabilities {server_requests: true}` after `gateway.ready`, as decision 3 of the same draft requires of every connection. It subscribes to no session, so no session's server requests are addressed to it; any server request that does reach it is refused at once through [`P1-02`](https://github.com/infiquetra/talaria/issues/199)'s responder with [`P1-09`](https://github.com/infiquetra/talaria/issues/206)'s not-supported refusal (`ServerRequestPolicy::Refuse`), never left waiting. Test 11 asserts it.

If the host-scoped ticket or upgrade is refused, the side connection falls back to a profile-scoped ticket for the foreground profile and the picker says so (section 5.2). If even that fails, the picker shows the error and Ctrl+R retries.

Rename and branch of the **foreground** session (`/rename`, `/branch`) go over the foreground link: branch must, because Hermes attaches the calling connection to the child (F30); rename does so for symmetry and so it works when the side connection is not open.

### 2.3 Fences: adopt the refusal's revision, retry once (through [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s ledger)

[`P2-06`](https://github.com/infiquetra/talaria/issues/230) owns the one fenced-mutation helper of the set: `talaria_core::mutation::{Fences, MutationRequest, MutationOutcome, MutationLedger, classify_result, classify_error}` and `talaria_app::mutation::MutationClient`. This unit builds no second helper and defines no type with those names. It uses the single `MutationLedger` instance that `crates/talaria-app/src/app.rs` holds after [`P2-06`](https://github.com/infiquetra/talaria/issues/230) merges, for both the foreground link and the side connection, so request ids (`<launch_id>-m<n>`) never repeat within the process.

A mutation must present the session's current `revision` (and, for branch, `execution_generation`). For the foreground session, [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `Fences` already tracks both from the resume snapshot (F15), every `session.info` event (F31) and every receipt. A picker row that is not the foreground session has no tracked fences, and reading them would need `session.resume`, which attaches a viewer and refreshes the session's policy (side effects, F16 and `gateway/session_controls.py:608-613`).

Rule (the "adopt-and-retry rule"):

1. Rename of a row with no tracked fences: seed them with `ledger.fences_mut(&session_id).adopt(Some(0), Some(0))`, then `ledger.build(&session_id, "rename", {title}, false)`. `adopt` is monotonic, so the seed never lowers a real value, and with `with_generation: false` the request carries no `expected_generation` key. Rename of the foreground session and every branch build from the tracked fences (`with_generation: true` for branch).
2. If Hermes refuses `revision_conflict` (`MutationOutcome::FenceRefused` with an integer `revision`, F21): for **rename**, call `ledger.retry_after_fence` once; it returns a new request with a new `request_id` at the refusal's fences. For **branch**, do the same only if the refusal's `execution_generation` equals the generation just sent; otherwise stop with the "a turn ran" text.
3. A second fence refusal stops with the "changed while renaming" text (rename) or the "a turn ran" text (branch). No third attempt.
4. `stale_generation` on branch stops with the "a turn ran" text (the user must see the newer messages first).

Why rename retries when Hermes Desktop does not (F32): Desktop's fence protects a shared title edited from two windows. In a terminal picker the operator has just typed the exact title they want; the first attempt at a seeded revision is a probe, not an edit of something they saw. The retry is bounded to one, uses the revision Hermes itself named, and a lost race still ends in a plain message. Hermes's own source expects this ("the client retries once without a re-read", F21). This is recorded in `docs/engineering-journal/DECISIONS.md`.

**Unknown outcome.** When a mutation's connection drops before the reply ([`P1-02`](https://github.com/infiquetra/talaria/issues/199)'s unknown outcome, `MutationOutcome::Unknown`), `ledger.settle` keeps the request. The next identical action (same session, operation and payload) gets the same request back from `ledger.build`, so Hermes replays the receipt rather than applying twice (F22). This works on any Talaria connection, including a newly opened side connection, because every ticket Talaria mints has the same subject (F22a). A kept request is dropped when Hermes answers it, or when the user asks for a different payload (a different title). It is not dropped when a prompt is submitted: unlike Hermes Desktop (F32), no hook in the prompt path is needed, and a late resend is still safe because Hermes either replays the stored receipt or, if the first attempt never arrived, applies it now or answers `revision_conflict`, which the rule above handles. `stale_generation` also arrives as `FenceRefused`; for branch it always stops.

**Sending with `profile`.** [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `MutationRequest::to_params()` has no `profile` key (F6). Over the side connection (host scope), this unit sends `request.to_params()` with `"profile": "<name>"` inserted, through the side connection's call, and maps the reply with [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `classify_result` and `classify_error` exactly as `MutationClient::send` does. Over the foreground link it calls `MutationClient::send` unchanged. If the merged `MutationClient` can already be built over any [`P1-02`](https://github.com/infiquetra/talaria/issues/199) client and accepts extra params, use it for both instead and say so in the pull request.

### 2.4 Switching the foreground session: open first, then let go

Opening a row must never leave the operator without a session. So the order is: open the target (resume), and only when that succeeded, untrack and detach the old session (without `end_reason`, as [`P1-12`](https://github.com/infiquetra/talaria/issues/209) REQ-19 does), then replace the foreground state. Same profile: resume on the existing link. Other profile: open a new profile-scoped link for the target profile through [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s `ConnectionService::open` with the profile changed, resume there, then detach the old session on the old link and close it. Events for the old session that arrive after the switch are dropped (they no longer match the foreground session id and subscription). A detach answered `detached: false` counts as done (F16a).

**A switch in flight.** From the moment a switch or branch is sent until it ends (success, failure or timeout), `app.rs` holds a "switch in flight" flag. While it is set, even after Esc closed the overlay, submitting a prompt keeps the draft and shows `Switching sessions. Send again when the switch finishes.`, and `/resume`, `/rename`, `/branch` and `/export` show the same text and send nothing. This closes the window in which a prompt could go to the session being left. Test 25b asserts it.

### 2.5 No cost column at v0.22.4

The roadmap asks for title, age, model and cost. `session.list` rows carry no cost (F11): no row field carries it. Per-session counters exist elsewhere: the dispatcher serves `session.stats {session_id}` (`gateway/session_controls.py:220`), which returns the same dict as the `session.usage` event (`gateway/session_usage.py:183-190`), and the contract's legacy `session.usage` method describes "token / context / cost counters". Whether those carry a usable cost for a session that is not loaded is not checked here (verify at the pinned commit before relying on it), and one call per row would break the listing budget. The per-session cost Hermes Desktop shows comes from dashboard REST routes, which need a `native-http` ticket and belong to phase 4 ([`P4-00`](https://github.com/infiquetra/talaria/issues/249), [`P4-01`](https://github.com/infiquetra/talaria/issues/250)). So the picker shows no cost column. This is final for this unit: the issue overrides the roadmap row's "cost" because no list row carries it; `session.stats` and the dashboard routes are candidates for the later unit of operator question 1. Operator question 1 in the issue only decides whether a later unit adds cost from the dashboard routes; it does not change this unit's columns. If a later pinned release adds a cost field to `CanonicalSessionListRow`, a follow-up adds the column.

"Age" is the time since `started_at` (the only time on a row). Rows are grouped live first, then earlier, each newest first.

### 2.6 Redaction on by default for exports

Hermes's `/save` exports without redaction unless asked. Talaria's exports default to `redact: true`: an export leaves Hermes's store, is often shared, and Talaria's security rule is that secrets are never recorded ([05-architecture.md, security](../05-architecture.md#security)). The picker's export dialog shows the state and `x` toggles it; `/export --no-redact` turns it off for one export. The default lives in one constant, `talaria_core::directory::export::REDACT_BY_DEFAULT: bool = true`, and tests 27 and UAT-4 assert it. If the operator's answer to operator question 2, recorded on the parent issue before this unit merges, is "follow /save", flip the constant and those two assertions; nothing else changes. The decision is recorded in `docs/engineering-journal/DECISIONS.md`.

### 2.7 Branch only the foreground session

Claude Code's `/branch` works on the current conversation and switches into the branch. A branch of a non-foreground row would need fences Talaria does not hold and would attach the side connection to the child (F30). So `b` in the picker works only on the row of the current session; on any other row it says to open it first.

### 2.8 Sources shown

All sources the scopes return are listed (terminal, Hermes Desktop, cron, messaging), each non-terminal row tagged with its source, so the operator sees one list as in Hermes's own picker. Opening a messaging or Desktop session may be refused by Hermes; the refusal text is shown and the operator stays where they were.

### 2.9 Lifetimes, fences after a switch, timeouts and one action at a time

**What `LIVE` and `EARLIER` mean.** `LIVE` lists the rows of the live scope: sessions the gateway holds in memory (F12), whether or not a turn runs. A session Talaria left with `/resume` or `/quit` stays there until the gateway restarts (F14). `◐` marks a row whose `running` is true. `EARLIER` lists the rows of the stored scope (F13).

**Side connection lifetime.** There is no reconnect loop. The side connection is opened only by a user action, and only when none is open: opening the picker, Ctrl+R in the picker, a rename of a picker row that is not the foreground session, or an export (from the dialog or `/export`). Each such action makes one open attempt, plus the one profile-scoped fallback of section 2.2. It closes:

1. when the overlay closes and no side call is in flight, or, when calls are in flight, as soon as the last of them ends;
2. after an export started by `/export` ends, when the overlay is not open;
3. when the gateway closes it or the connection drops. `is_closed()` is then true, and the next user action opens a new one. This is how test 16's second rename reaches a new side connection.

A drop fails every call in flight on it with `SideCallError::Dropped`. A list call becomes `ListFailed` with the reason `connection closed`. A mutation becomes `MutationOutcome::Unknown` and the ledger keeps it. An export writes nothing.

**Fences after a switch.** Every successful resume that changes the foreground session (picker Enter, `/resume <id>`, and the child after a branch) feeds the new snapshot's `revision` and `execution_generation` into [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s ledger. Both are required fields of `CanonicalSnapshot` (F15). Feed them the way `app.rs` does after launch: [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `ModelsInput::SessionOpened { session_id, revision, execution_generation }`, then `ForegroundChanged` ([`P2-06`](https://github.com/infiquetra/talaria/issues/230) unit specification, section 4.8). If the merged code seeds the ledger elsewhere, call that, or call `ledger.fences_mut(<new id>).adopt(Some(revision), Some(execution_generation))` directly, and say which in the pull request. Tests 21 and 18 assert the next mutation carries the snapshot's values.

A row that has never been tracked is seeded with 0 (section 2.3, rule 1). A row that was the foreground session earlier in this process keeps its tracked revision, because `adopt` never lowers a value; it sends that revision, not 0. If `build(.., with_generation: true)` for a branch answers `NotSent { reason: "fences unknown" }`, Talaria sends nothing and shows [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s text `Talaria has not learned this session's revision yet; try again in a moment.`

**Timeouts.** `session.list` 10 s; rename 15 s; branch 30 s; `session.export` 60 s; `session.detach` 2 s ([`P1-12`](https://github.com/infiquetra/talaria/issues/209) REQ-6). `session.resume` (a switch, or the child after a branch) uses [`P1-02`](https://github.com/infiquetra/talaria/issues/199)'s `default_timeout`, 120 s, as [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s own resume does. Opening the side connection uses [`P1-01`](https://github.com/infiquetra/talaria/issues/198)'s connect and handshake limits. A resume that times out is an open failure with the reason text `Hermes did not answer within 120 s`. The current session stays in front. Hermes may have attached the target anyway; its late events are dropped by the foreground filter (section 2.4). Esc closes the overlay at any time (section 5.3); the "switch in flight" flag stays set until the call ends.

**One session action at a time.** A rename, a branch, an export and a switch never overlap. While one is in flight, the picker is in `Waiting` and ignores keys except Esc and Ctrl+C. After Esc, `/resume`, `/rename`, `/branch` and `/export` show `Another session action is still running. Try again when it finishes.` and send nothing. While a switch or branch is in flight, the "Switching sessions" text of section 2.4 is shown instead, and prompts are refused too. A rename or an export never blocks a prompt. A list refresh (Ctrl+R) is not a session action and may run during a rename or an export.

**The list after an action.** A successful rename refreshes the list (section 7.1). An export does not refresh it. Exporting a row Hermes had not loaded loads it into memory (F39), so that row may move from `EARLIER` to `LIVE` at the next refresh.

## 4. Request and result shapes

All requests are JSON-RPC 2.0 frames: `{"jsonrpc":"2.0","id":<n>,"method":"<name>","params":{...}}`. Ids are [`P1-02`](https://github.com/infiquetra/talaria/issues/199)'s. Session ids are opaque strings; examples use placeholders.

### 4.1 Listing (side connection, host scope)

For each served profile `<p>`, two requests, sent in parallel:

```json
{"method":"session.list","params":{"profile":"<p>","scope":"live","limit":100}}
{"method":"session.list","params":{"profile":"<p>","scope":"stored","limit":100}}
```

Profile-only fallback (side connection is profile scoped): the same two requests without `profile`, for the foreground profile only. The rule for every call on the side connection: a host-scoped side connection always sends `profile` (`session.list`, `session.mutate`, `session.export`); a profile-scoped one never does (the gateway would strip its own profile anyway, F5, and the exact frames stay minimal).

Generated parameter types come from the contract's `x-canonical-methods` entries and their schemas `CanonicalListParams`, `SessionMutateParams` and `SessionExportParams`. The legacy `methods` list has an older `session.list` entry without `scope`; never generate from it.

Result:

```json
{"sessions":[{"session_id":"<sid>","id":"<sid>","title":"fixture picker one","source":"tui","started_at":1792700000.5,"message_count":4,"model":"minimax-m3.1-flash","running":false}],"scope":"live"}
```

Stored rows also carry `resolved_id` (equal to `session_id`). `title` may be `""`. `model` may be null or missing.

### 4.2 Opening a row (owned by [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s resume path)

```json
{"method":"session.resume","params":{"session_id":"<sid>","display_projection":true}}
{"method":"session.detach","params":{"session_id":"<old sid>","subscription_id":"<old sub>"}}
```

The resume is sent on the link of the row's profile (the current link, or a new profile-scoped one). Never send `profile` on the foreground link; never send `end_reason`.

### 4.3 Rename

Foreground session, foreground link:

```json
{"method":"session.mutate","params":{"session_id":"<sid>","request_id":"<launch_id>-m7","expected_revision":7,"operation":"rename","payload":{"title":"Fix the average"}}}
```

Request ids come from [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `MutationLedger` (`<launch_id>-m<n>`). Picker row, side connection (host scope): the same plus `"profile":"<p>"`, and `expected_revision` 0 (the seed of section 2.3) unless the ledger tracks the session's fences. No `expected_generation` key at all (not even null).

Success: `{"session_id":"<sid>","revision":8,"execution_generation":3,"operation":"rename","title":"Fix the average"}`.

Conflict: `{"code":4001,"message":"revision_conflict","data":{"reason":"revision_conflict","revision":12,"execution_generation":3}}`. Retry (from `retry_after_fence`): new `request_id` (`<launch_id>-m8`), `expected_revision: 12`.

Duplicate title (F27): `{"code":-32603,"message":"internal error"}`.

### 4.4 Branch (foreground link only)

```json
{"method":"session.mutate","params":{"session_id":"<sid>","request_id":"<launch_id>-m7","expected_revision":7,"expected_generation":3,"operation":"branch","payload":{}}}
```

With a title: `"payload":{"title":"Try the other fix"}`. Success:

```json
{"session_id":"<sid>","revision":8,"execution_generation":3,"operation":"branch","branched_session_id":"<child sid>","copied_messages":12}
```

Then `session.resume {session_id: "<child sid>", display_projection: true}` on the foreground link, then `session.detach` of the parent's subscription.

### 4.5 Export (side connection)

```json
{"method":"session.export","params":{"session_id":"<sid>","profile":"<p>","format":"md","redact":true}}
```

Profile-only fallback: without `profile`. Result: `{"format":"md","filename":"hermes_session_<sid>.md","content":"<text>"}`.

## 5. Screen layout and texts

### 5.1 The overlay: layout rule and worked screens

The overlay fills the screen. Screen rows, from the top (row 0): the header; up to two banners (section 5.2); the body (group headers, rows and `UNAVAILABLE` lines); the notice line (row `rows - 2`; blank when there is none); the footer (row `rows - 1`). Body height is `rows - 3 - banners`. The body shows a window of its lines starting at the smallest offset that keeps the cursor row visible (offset 0 when it fits).

Every line starts with a one-column left margin (one space). Widths are display widths from `unicode-width`'s `UnicodeWidthStr::width` (not the CJK variant; `▸`, `●`, `◐`, `…`, `·` and `↑↓` are one column each). `cut(text, n)`: when the text fits in `n` columns it is padded with spaces to `n`; otherwise the longest prefix of whole characters that fits in `n - 1` columns, then `…`, padded to `n` (a wide character is never split). Snapshot tests compare each screen row with trailing spaces removed; styles (dim, reversed) are not part of the text and are checked only where a test says so.

**Header** (row 0): left text ` Sessions · <filter> · <n> shown`, where `<filter>` is `all profiles` or `profile <p>` and `<n>` is the number of visible rows. Right text: `Loading <p>…` (first pending profile in served order) while any list call is pending and no cached rows are shown; `Refreshing…` while calls are pending over cached rows; `Search: "<q>"` when a query is set and not being typed; else none. The right text ends at the last column. When the left text, two spaces and the right text do not fit in the width, the right text is left out. The left text is cut to `width - 1`.

**Row line**: margin, cursor (2 columns: `▸ ` on the selected row, else two spaces), state (2 columns: `● ` the foreground session, else `◐ ` when `running` is true, else two spaces), then the shown columns below joined by two spaces:

| Column | Shown when | Width | Content |
|---|---|---|---|
| profile | width ≥ 40 and the visible rows have more than one profile | `P` = the widest visible profile name, at most 12 | `cut(profile, P)` |
| title | always | `T` = the rest (formula below) | `cut(sanitize(title), T)`; `untitled session` (dim) when the title is `""` |
| model | width ≥ 60 | `M` = the widest visible short model, at most 20 (0 hides the column) | `cut(short_model, M)` |
| age | always | 5 | `format_age`, right aligned |
| messages | width ≥ 80 | 9 | `<n> msgs` (`1 msg`), right aligned |
| source | width ≥ 100 and a visible row has a source tag | `S` = the widest visible tag, at most 10 | the tag (dim), `cut(tag, S)`; the tag is the source when it is not `tui` or `cli`, `desktop` for `gui` and `desktop`, else empty |

`T = width - 1 - 4 - (sum of the other shown column widths) - 2 * (number of shown columns - 1)`. With the caps above, `T` is at least 12 at every size the overlay draws.

Group headers ` LIVE (<n>)` and ` EARLIER (<n>)` are their own lines (not selectable), each left out when the group is empty. A final group ` UNAVAILABLE` lists one dim line per failed profile and scope pair: `   <p>: could not list <live|earlier> sessions (<reason>).` (three spaces of indent). Notice and banner lines are the margin and the text cut to `width - 1`.

**Footer**: at width 110 or more, `↑↓ move · Enter open · r rename · b branch · e export · / search · Tab profile · Ctrl+R refresh · Esc close` (107 columns); from 60 to 109, `↑↓ Enter r b e / Tab Esc`; below 60, none. In search typing mode: `type to filter · Enter keep · Esc clear`. In the rename editor: `Enter rename · Esc cancel`. In the export dialog: section 5.3. Each is the margin plus the text cut to `width - 1`.

**Too small**: when the width is below 24 or the height is below 6, the overlay draws only row 0: ` Window too small for the session list. Esc closes.` cut to the width.

### 5.2 Banners and empty states

| When | Text |
|---|---|
| Side connection is profile scoped | `Showing only the profile <p>: Hermes did not allow a connection across profiles (<reason>).` |
| Side connection failed | `Could not reach Hermes to list sessions (<reason>). Ctrl+R tries again.` |
| Cached rows shown while refreshing | `Refreshing…` at the header's right instead of `Loading <p>…` |
| Nothing pending, no rows at all | body: `No sessions found.` |
| Rows exist but none matches the query or filter | body: `No session matches "<q>".` or `No sessions in profile <p>.` |
| A row could not be read (`from_list_row` gave None) | notice: `<n> rows from Hermes could not be read and are not shown.` |
| A list reply holds exactly 100 rows (the `limit`) | notice: `<p>: only the newest 100 <live|earlier> sessions are listed.` (the first such pair in served order; a row-read notice wins). It counts the rows Hermes sent, before unreadable rows are skipped. |

`<reason>` in these lines and in the `UNAVAILABLE` lines is one fixed phrase per failure kind: `connection closed` (the connection dropped), `no answer within 10 s` (a list timeout), the refusal's `data.reason` (for example `profile_mismatch`; `code <n>` when there is none), `gateway not found` (`SideOpenError::Discovery`), `ticket refused` (`SideOpenError::Ticket`), `connection refused` (`SideOpenError::Connect`) and `handshake failed` (`SideOpenError::Handshake`). Each passes through `history::sanitize`.

Before discovery returns, the only profile known is the foreground one: the header shows `Loading <foreground profile>…` (or `Refreshing…` over cached rows), and Tab and Shift+Tab do nothing until the served profiles arrive.

### 5.3 Rename editor, export dialog, waiting

The rename editor replaces the notice line: `New title for "<old>": <text>▏`. It starts with the current title (`""` when untitled). Editing keys: printable characters insert at the caret; Backspace, Delete, Left, Right, Home, End; paste inserts its first line; at most 200 characters are held (more are dropped with the notice `The title was cut to 200 characters.`). Enter applies `clean_title`; Esc closes the editor and sends nothing.

The export dialog replaces the notice and footer lines with three lines:

```text
 Export "<title>"
 Format: [m] Markdown   [j] JSON   [h] HTML          Secrets: redacted (x to include them)
 Saves to <folder>/<file name> · Enter export · Esc cancel
```

The selected format is shown reversed; the default is Markdown. With redaction off the right part reads `Secrets: included (x to redact them)`. The `Saves to` path is the launch folder with `~` for the home folder, and the file name is the predicted one (`hermes_session_<sid>.<ext>`); the real name comes from Hermes and the free-name rule (section 7.5).

While a call runs (`PickerMode::Waiting`) the notice line shows `Renaming…`, `Branching…`, `Exporting…` or `Opening…`. Keys are ignored except Esc and Ctrl+C, which close the overlay; the call still finishes and its notice is written to scrollback instead (section 5.6). For an open or a branch, the "switch in flight" rule of section 2.4 applies until it ends.

In the rename editor only the editing keys, Enter, Esc and Ctrl+C act. In the export dialog only `m`, `j`, `h`, `x`, Enter, Esc and Ctrl+C act. Every other key is ignored in both.

### 5.4 Formats

`format_age(started_at, now)`: `None` gives `—`. Let `d = now - started_at`. `d < 60` (including negative, from clock skew): `now`. `d < 3600`: `<floor(d/60)>m`. `d < 86400`: `<floor(d/3600)>h`. `d < 7*86400`: `<floor(d/86400)>d`. `d < 56*86400`: `<floor(d/604800)>w`. Otherwise the UTC date `YYYY-MM-DD`. Boundaries for the test: 59.9 → `now`, 60 → `1m`, 3599 → `59m`, 3600 → `1h`, 86399 → `23h`, 86400 → `1d`, 604799 → `6d`, 604800 → `1w`, 4838399 → `7w`, 4838400 → date.

`format_size(bytes)`: under 1,024: `<n> B`; under 1,048,576: one decimal and `KiB`; otherwise one decimal and `MiB` (`1.0 KiB`, `8.5 MiB`).

### 5.5 Search and filter

`/` opens the search line in place of the notice: `Search: <q>▏`. While typing, every printable character (including `q`, `r`, `b`, `e`, `j`, `k`) is query text; Backspace deletes (on an empty query it closes search mode); paste inserts the first line; the query is capped at 100 characters. Enter keeps the query and returns to list mode; Esc clears the query and returns. Matching (`matches`): the query, trimmed and lower-cased with `char::to_lowercase`, is a literal substring of any of these fields, each also lower-cased with `char::to_lowercase`: the title, the short model (text after the last `/`), the profile name, the `session_id`, the source. The listed row `id` (a lineage root) is not searched. An empty query matches everything.

Keys in search typing mode: printable characters are query text; Up, Down, PageUp, PageDown, Tab, Shift+Tab, Ctrl+R, Backspace, Enter, Esc and Ctrl+C keep their meaning; Home and End move the cursor row (not a caret); every other key is ignored.

The profile filter cycles with Tab: `All`, then each served profile in `Endpoint::profiles()` order, then `All` again; Shift+Tab goes back. It is kept for the life of the process (not saved to disk).

The cursor is kept on the same `RowKey` across refreshes, filter and query changes when that row is still visible; otherwise it moves to the first visible row.

**How a key is resolved**, in this order:

1. Esc and Ctrl+C are fixed (below), in every mode.
2. In search typing mode and in the rename editor, a printable key without Ctrl or Alt is text and is never looked up. The other keys these modes accept (sections 5.3 and 5.5) keep their meaning; search looks them up in `SessionPicker` (so a rebound `picker_down` still moves the cursor row), and the editor's editing keys are fixed.
3. In the export dialog, keys are looked up in `SessionPickerExport` only.
4. In list mode, keys are looked up in `SessionPicker`.

So `q` closes the overlay in list mode and is query text in search. A `[keys]` rebinding is checked against its own context only: `picker_close = ["j"]` takes `j` from `picker_down` (an explicit entry beats a default, [`P1-08`](https://github.com/infiquetra/talaria/issues/205) REQ-3), while `picker_format_json = ["k"]` changes nothing in list mode.

Esc and Ctrl+C are fixed and cannot be bound to picker actions: `KeyChord::parse(text, KeyContext::SessionPicker)` (and the same for `SessionPickerExport`) returns `Err("esc and ctrl+c are fixed in the session picker")` for them, so [`P1-08`](https://github.com/infiquetra/talaria/issues/205)'s loader reports it with its usual unparseable-chord notice and keeps the defaults for that action. In these contexts a printable key needs no modifier (unlike the composer context). Esc: in search typing mode it clears the query and returns to list mode; in the rename editor or export dialog it closes them and returns to list mode; in list mode it closes the overlay. Ctrl+C always closes the overlay. Neither ever interrupts the agent or touches the composer's draft. In search typing mode Home and End move the cursor row (there is no caret to move). While the overlay is open it receives every key.

There is no default key that opens the picker; `/resume` opens it (Ctrl+R in the composer belongs to [`P2-13`](https://github.com/infiquetra/talaria/issues/228)'s history search, and Claude Code has no key for it either). This unit adds a `session_picker_open` action to `KeyContext::Composer`, unbound by default, so a user can bind one in `[keys]`.

Slash commands (registered in [`P2-03`](https://github.com/infiquetra/talaria/issues/223)'s `LocalCommandTable`, each taking an optional argument):

| Command | Summary shown in the palette | Behaviour |
|---|---|---|
| `/resume [id]` | `Open another session, from any profile` | No argument: open the picker. With an id: switch to that session in the foreground profile. |
| `/rename [title]` | `Rename this session` | No argument: show the current title. With a title: rename the foreground session. |
| `/branch [title]` | `Copy this conversation into a new session and switch to it` | Branch the foreground session. |
| `/export [--no-redact] [file]` | `Save this conversation to a file` | Export the foreground session; format from the extension, Markdown without a file name. |

## 7. Flows

### 7.1 Opening the picker

1. `/resume` (no argument): the application opens the overlay at once with `PickerInput::Opened` (cached rows from the last opening in this process, if any, shown with `Refreshing…`), draws the first frame, and only then starts the side connection. No network call precedes the first frame.
2. `DirectoryService::open`: `discover_with(EnsurePolicy::Never)` (never starts the gateway), then mint a host-scoped interactive ticket for the foreground profile's id, connect, handshake. On a ticket or upgrade refusal, retry once with a profile-scoped ticket (scope note set). On any other failure: `SideFailed`.
3. `start_list`: a new list generation; for each profile (host scope) or the foreground profile (fallback), two calls (section 4.1) with a 10 second timeout each. Each reply becomes `PickerInput::Listed` or `ListFailed` with the generation; replies of an older generation are dropped.
4. Rows are merged and ordered on every `Listed` (live rows replace stored rows with the same key).

Ctrl+R repeats step 3 (and step 2 if the side connection closed). After a successful rename the list is refreshed the same way.

### 7.2 Opening a row (Enter)

1. Selected row is the foreground session: notice `You are already in this session.`, overlay closes.
2. Otherwise `PickerEffect::Open(key)`; mode `Waiting(Open)`; `app.rs` sets the "switch in flight" flag. Held prompts ([`P1-12`](https://github.com/infiquetra/talaria/issues/209) REQ-5) refuse the switch before this step.
3. `switch_foreground`: if `key.profile` is the foreground profile, `SessionService::open(SessionRequest::ById { session_id })` on the current link. Else build the launch for that profile, `ConnectionService::open` (a new profile-scoped link), then `SessionService::open` on it.
4. On failure: close the new link if one was opened; clear the "switch in flight" flag; notice "Open failed"; the foreground session is untouched.
5. On success: remember whether the old session had an open approval or question ([`P1-05`](https://github.com/infiquetra/talaria/issues/202)); feed the new snapshot's fences to [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s ledger (section 2.9); `Link::untrack` the old session; `session.detach` it (2 second limit, no `end_reason`; `detached: false` counts as done, F16a); close the old link when the profile changed; replace the foreground state; clear the "switch in flight" flag; close the overlay; commit the "Switched" notice, then [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s `── Resumed: <title> ──` separator and the last 50 cells; refresh the status line inputs ([`P1-10`](https://github.com/infiquetra/talaria/issues/207)) and the exit hint profile.

"Replace the foreground state" changes exactly these: the session id and stored session id, the subscription id, [`P1-05`](https://github.com/infiquetra/talaria/issues/202)'s `SessionState` (built from the snapshot), the link (only when the profile changed), the profile name, the foreground title field (the snapshot's `info.title`), the tracked fences (above), the status-line inputs and the exit hint's profile. The launch folder (`Launch.folder`) never changes, so exports still go there.

`/resume <id>` (the id trimmed): when the id equals the foreground session's `session_id`, step 1 (`You are already in this session.`, nothing sent; `switch_foreground` returns `AlreadyHere`). Otherwise the held-prompt check of step 2, then steps 3 to 5 for the foreground profile. Detaching the session just resumed can therefore never happen.

### 7.3 Rename

1. `r` on a row (or `/rename <title>`). For `r`, open the editor with the row's current title. `/rename` with no argument, or with an argument that is only whitespace, prints the current title (section 5.6) and sends nothing; any other argument goes through step 2.
2. Enter: `clean_title`. Empty or too long: text in the editor, no call. Equal to the row's current title after cleanup: `The title is unchanged.`, no call.
3. Build the request with [`P2-06`](https://github.com/infiquetra/talaria/issues/230)'s `MutationLedger::build` (section 2.3): the foreground session over the foreground link at its tracked fences; any other row over the side connection with `profile`, after `seed_untracked`. `build` returns a kept request for the same session and payload.
4. Send (15 second timeout), then `ledger.settle` (which adopts the receipt's fences). Applied: update the row title to `result.title` (when a string); when this is the foreground session, update the foreground title field in `app.rs` that [`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s separators read (the status line and [`P2-02`](https://github.com/infiquetra/talaria/issues/222)'s pager, when merged, read the same field; scrollback already written is never changed); notice `Renamed to "<title>".`; refresh the list.
5. Refused: a `FenceRefused` gets one `retry_after_fence`; a second one stops with the section 5.6 text; other refusals stop with their text (-32603 gives the "may already use that title" text). Unknown: the ledger keeps the request; unknown-outcome text.

### 7.4 Branch

1. `/branch [title]`, or `b` on the foreground session's row. `b` on another row: text, no call.
2. A title argument goes through `clean_title` (empty after cleanup means no title; too long refuses).
3. A turn running per [`P1-05`](https://github.com/infiquetra/talaria/issues/202): text, no call.
4. Request over the foreground link with `MutationLedger::build(.., with_generation: true)` (tracked revision and generation), payload `{}` or `{title}`; 30 second timeout; set the "switch in flight" flag; kept-request rule as for rename.
5. Applied: read `branched_session_id` (a non-empty string, else treat as `Refused { reason: "invalid_result" }`) and `copied_messages`. Then the switch of section 7.2 steps 3 to 5 with the child id on the current link (same profile). Notice `Branched into ...` (title from the child snapshot's `info.title`, else `untitled session`) instead of the "Switched" notice.
5a. The child's resume fails or times out: clear the flag; the parent stays in front, still attached; nothing is detached; show the "Branch made, child failed to open" text. Talaria does not detach the child. The gateway attached the connection to the child inside the branch call (F30) and discarded that resume's result, so the branch reply carries no `subscription_id` (`gateway/session_controls.py:785-790`) and Talaria holds no id to detach. The child's events are dropped by the foreground filter (section 2.4), and the subscription ends when the link closes. Opening the child later from the picker reuses that subscription (F16).
6. Refused: clear the flag; section 5.6 texts; `revision_conflict` whose generation equals the one sent (`branch_may_retry`) is retried once with `retry_after_fence`.

### 7.5 Export

1. `/export [--no-redact] [file]` (foreground session), or `e` on a row and Enter in the dialog.
2. `parse_export_args`: tokens split on whitespace; `--no-redact` (anywhere) turns redaction off; any other token starting with `--` is `UnknownOption`; at most one other token, the file (`TooManyPaths` otherwise, text `Use /export [--no-redact] [file] with one file name; file names cannot contain spaces.`). A file without a `.md`, `.json` or `.html` extension (case-insensitive) is `BadExtension`. No file: Markdown, automatic name.
3. Resolve the target before calling Hermes. An explicit file is the operator's own choice and is used as typed after two expansions: a leading `~/` means the home folder, and a relative path is joined to the launch folder ([`P1-12`](https://github.com/infiquetra/talaria/issues/209)'s `Launch.folder`). An absolute path and `..` components are accepted; Talaria never rewrites what the operator typed. A name starting with a dot is accepted when it has a valid extension (`.notes.md`); `.md` alone has no extension (Rust's `Path::extension` gives `None`), so it is `BadExtension`. If the file exists, refuse now (no call). If its parent folder does not exist, refuse now with `The folder for <path> does not exist.` (no call; no folder is created). Only Hermes's `filename` is reduced to a safe name (step 6): `../../x.md` from Hermes becomes `x.md` in the launch folder.
4. Open the side connection if needed. Call `session.export` (60 second timeout) with `session_id`, `profile` (host scope only), `format`, `redact`.
5. Check the result: `content` and `filename` are strings; else `The gateway returned no export. Nothing was written.` A refusal gets its section 5.6 text.
6. Automatic name: `safe_file_name(filename, format, session_id)` takes the part after the last `/` or `\`, keeps letters, digits, `-`, `_`, `.` and spaces, refuses names that are empty, start with `.`, or do not end in `.<extension>` of the chosen format; in each refused case it falls back to `hermes_session_<sanitised id>.<extension>`. Then the first of `candidate_names(name)` that does not exist in the launch folder.
7. Write with `create_new(true)` (never overwrite, even in a race) and, on Unix, mode `0o600`. Write all bytes; on any error remove the partly written file. Notice `Exported ...` with the path shown relative to the launch folder when inside it (`./<name>`), else with `~` for the home folder.
8. The export cell in the transcript never contains the content.

## 8. Mock gateway rules

The mock is `crates/talaria-app/tests/support/mock_gateway.rs`, made by [`P1-09`](https://github.com/infiquetra/talaria/issues/206) and extended by [`P1-12`](https://github.com/infiquetra/talaria/issues/209) and [`P2-06`](https://github.com/infiquetra/talaria/issues/230). This unit adds handlers (never changing existing behaviour) with handlers built from the pinned contract and the facts above:

1. `session.list`: validate exactly F10 (after removing `profile` when it names the mock's own profile; route other profile names to per-profile row sets only when the ticket was minted with host scope, else answer `profile_mismatch`). Return rows shaped exactly as `CanonicalSessionListRow`. Sort live rows newest first (F12). Configurable per profile and scope: rows, a refusal, a delay, or silence (for timeouts).
2. `session.mutate`: validate the key set (F17; accept and remove `profile` as F4 and F5 do), payload (F18) and the generation rule (F19). Keep `runtime_revision` and `runtime_generation` per session. Apply F20 in order: missing session, revision, generation. Refusals carry `revision` and `execution_generation` (F21). A repeated `request_id` with the same digest replays the first answer (F22). Rename: apply F25 cleanup; a title held by another session answers -32603 `internal error` with no data (F27). Branch: refuse `session_busy` when the session is marked busy; create a child id `child-<n>` with the copied message count and the derived title of F28 (`next_title_in_lineage` over the mock's titles: `X` gives `X #2`, untitled gives `branch` then `branch #2`); attach the calling connection to the child, reusing the actor's subscription id on a later resume (F16, F30). `session.detach` answers `detached: false` for a subscription the connection does not hold (F16a).
3. `session.export`: validate F35 and F36; `not_found` for a session with no messages; `export_too_large` for a session marked large with format `json`; return `filename` per F37 and the configured content. One test makes the content 9 MiB so the frame exceeds the 8 MiB cap (F41).
4. Tickets: the mock's control socket can refuse host scope (for the fallback test) and records the scope and profile of every ticket minted. Every ticket has the same subject (F22a), so a receipt replays across connections.
5. Server requests: the mock can send one server request (for example an approval request) on the side connection; it records the reply.
6. Every mock rule cites, in a comment, the Hermes source it follows at Hermes v0.22.4 (for example `// gateway/session_controls.py lines 319 to 330`) or the recorded frame, never a fact number from this document (the roadmap forbids planning codes in source comments). A rule not backed by the source or a recorded frame is a defect (the v0.6.2 lesson).

## 9. Edge cases

| Case | Behaviour |
|---|---|
| Only one profile served | No profile column; filter cycles `All` and that profile; no banner. |
| A profile appears in `parked_profiles` | Not listed (only served profiles are). |
| A row has `title` `""` | `untitled session` (dim); search matches the empty title only through other fields. |
| Two rows with the same `session_id` in different profiles | Different keys; both shown. |
| The same `session_id` in live and stored | Live row kept. |
| `started_at` null | Age `—`; sorted after dated rows in its group. |
| A row whose required field has the wrong type | Skipped; counted in the notice. |
| A list reply arrives after the overlay closed | Dropped (generation). |
| A list reply arrives after Ctrl+R | Dropped when its generation is older. |
| 2,000 rows | Only visible rows are drawn; filtering stays within the budget (section 10). |
| Title with escape bytes or bidirectional overrides | Drawn literally through `history::sanitize`; never interpreted. |
| Very wide characters in a title | Cut by display width (`unicode-width`), never splitting a character. |
| Rename to the same title with different spacing | `clean_title` equal: no call. |
| Rename while the same row's earlier rename is unknown | The kept request is resent if the title is the same; a different title drops it and builds a new one. |
| Rename of a picker row in the foreground profile via the side connection while also foreground | Uses the foreground's tracked revision; either connection works; foreground title updated. |
| Branch of an untitled session | Child titled by Hermes: `branch` when no session holds it, else `branch #<highest + 1>` (F28). Talaria shows the snapshot's `info.title`. |
| Branch when Hermes answers without `branched_session_id` | `Hermes refused the branch (invalid_result).`; no switch. |
| Branch succeeded, child resume refused | "Branch made, child failed to open" text; stay on the parent; the parent is not detached. |
| Switch while the old session has queued prompts | They stay queued in Hermes; the "Switched" notice says it keeps running. |
| Switch while a composer draft exists | The draft is kept (it is not session state). |
| Held prompts ([`P1-12`](https://github.com/infiquetra/talaria/issues/209) REQ-5) when switching | Switching is refused while prompts are held: `Wait until the held prompts are sent, then switch.` |
| Side connection closes mid-list | Pending profiles become `ListFailed` with `connection closed`; Ctrl+R reopens. |
| Export file name from Hermes is `../../x.md` | `safe_file_name` keeps `x.md`; never leaves the folder. |
| Export to a path inside a folder that does not exist | Refused before any call. |
| Export of a session in another profile with the fallback side connection | The row cannot be in the list (only the foreground profile is listed), so it cannot happen. |
| Export while offline | Side connection fails to open: `Could not reach Hermes to list sessions (<reason>). Ctrl+R tries again.` for the picker, or `The connection to Hermes dropped during the export. Nothing was written.` for `/export`. |
| Terminal resized while the overlay is open | Redraw at the new size; cursor row kept visible. |

## 10. Performance budgets and the benchmark

Budgets (160 by 48) and where each is checked:

| Measure | Budget | Checked by |
|---|---|---|
| `/resume` Enter to the overlay's first frame, with a mock gateway that answers after 500 ms | ≤ 50 ms, and the first frame is drawn before any side-connection call | test 37b (`cargo test`, every run) |
| A search keystroke with 2,000 rows (filter and draw) | ≤ 16 ms at the 95th percentile, ≤ 33 ms worst | the benchmark (test 37, release build) |
| A cursor move with 2,000 rows | ≤ 16 ms at the 95th percentile | the benchmark |
| Idle overlay with nothing pending | 0 frames in 1 second | test 37c (`cargo test`, every run) |

The benchmark (`crates/talaria-tui/benches/session_picker.rs`, `harness = false`) builds a `PickerState` with 2,000 rows across the two profiles `default` and `fixture` (titles `fixture row <n>` with mixed widths, models cycling three names), runs 100 warm-up then 1,000 timed iterations of `update` plus `SessionPickerView::draw` into a `Buffer`, sorts the durations and reports the nearest-rank 95th percentile (`sorted[949]`) and the maximum. It prints `picker_filter_p95_us=<n> picker_filter_max_us=<n> picker_move_p95_us=<n>` and exits non-zero on a budget breach. It runs in [`P1-11`](https://github.com/infiquetra/talaria/issues/208)'s `bench` job as one added step (`cargo bench -p talaria-tui --bench session_picker`); this unit does not change `tools/bench/`.

Tests 37b and 37c run against the mock gateway in `crates/talaria-app/tests/session_picker_keys.rs`. They count frames through the test terminal backend the app's tests already draw into ([`P1-12`](https://github.com/infiquetra/talaria/issues/209)). If the merged code has no way to count draws, this unit adds `crates/talaria-app/tests/support/frame_counter.rs` (new, owned by this unit): a `ratatui` `TestBackend` wrapper that counts `draw` calls. It is test support only; product code does not change for it. 37b asserts the order (the first overlay frame is drawn before the mock records any frame from the side connection) and the elapsed time (≤ 50 ms in a debug build; the budget guards against waiting on the 500 ms reply, so a debug build has ample margin). 37c opens the overlay, lets every list call answer, then counts 0 draws over the next 1 second with no input.

Live: live test 39a prints `picker_open_ms=<n>` for five openings (from `DirectoryService::open` until every profile's two list calls have answered) and `picker_open_median_ms=<n>`. Test 39a does not fail on the median, so it is not gated in continuous integration (which never runs live tests). The median is an acceptance gate instead: UAT-1 is FAIL when it is above 1,000, and AC-11 needs UAT-1 to pass. A slow picker therefore cannot pass acceptance.

### 11.1 The recorded fixture

Who and when: the developer records it during implementation, after the code passes tests 1 to 37c, on the operator-prepared gateway (the issue's operator preconditions).      │ Esc, Ctrl+C, q      │  └──────► Search ──┘
     │                     │ r                         Enter (valid)

     │                     │ e                         Enter
     │                     ├──────► Export dialog ────────────────► Waiting(Export) ─► List (+notice)
     │                     │ b (foreground row)
