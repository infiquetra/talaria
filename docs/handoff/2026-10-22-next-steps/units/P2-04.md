## 1. What the unit does, in one picture

```text
 key / paste / tick (talaria-tui reads the terminal; P1-12's loop sends AppMessage)
        │
        ▼
 talaria-app  P1-12 update (pure) ──► AttachmentsState::{on_key, on_paste, on_tick, on_event, on_submit}
        │                               uses talaria-core (pure): mention_at, MentionState, route_paste,
        │                               drop_candidates, CollapseRule, ChipStore, expand, sniff_image
        │ AttachmentEffect                        ▲ AppMessage::Attachment(AttachmentEvent)
        ▼                                         │
 talaria-app  AttachmentService (tasks, off the input thread) ──► hermes-client Client::call_with
        │   complete.path {session_id, word}                 2 s
        │   image.attach_bytes {session_id, content_base64, filename}   30 s
        │   file.attach {session_id, path}                   default timeout
        │   drop checks (stat, read), ClipboardImageReader (pngpaste / osascript / wl-paste / xclip)
        ▼
 submit: prompt.submit {session_id, text, submission_id, attachments?}
        │
 talaria-tui  MentionSection (LiveSection) draws a MentionView; the composer draws label highlights
```

The domain logic (what is a query, what is a dropped path, when to collapse, how labels expand, how the list moves between states) is pure and lives in `talaria-core`. The one instance of the state (`AttachmentsState`) is a field of `P1-12`'s `AppState` and is changed only by `P1-12`'s pure `update`. Input and output (gateway calls, file checks and reads, clipboard tools) run in `talaria-app`'s `AttachmentService`. Drawing lives in `talaria-tui`, which holds no protocol or session state. This follows the layer table and principle 4 in [05-architecture.md](../05-architecture.md#layers).

## 3. Request and result shapes

All frames are JSON-RPC 2.0. Identifiers and paths below are placeholders.

### 3.1 `complete.path`

```json
{"jsonrpc":"2.0","id":17,"method":"complete.path","params":{"session_id":"<sid>","word":"@calc"}}
{"jsonrpc":"2.0","id":17,"result":{"items":[
  {"text":"@file:src/calc.py","display":"calc.py","meta":"src"},
  {"text":"@file:tests/test_calc.py","display":"test_calc.py","meta":"tests"}]}}
```

`kind` is absent on path items (it rides only on slash completions). A bare `@`:

```json
{"result":{"items":[{"text":"@diff","display":"@diff","meta":"git diff"},
  {"text":"@staged","display":"@staged","meta":"staged diff"},
  {"text":"@file:","display":"@file:","meta":"attach file"},
  {"text":"@folder:","display":"@folder:","meta":"attach folder"},
  {"text":"@url:","display":"@url:","meta":"fetch url"},
  {"text":"@git:","display":"@git:","meta":"git log"},
  {"text":"@hermes","display":"@hermes","meta":"agent profile (primary)"}]}}
```

Talaria's filter (REQ-4) drops `@hermes` and every other item without `:` that is not `@diff` or `@staged`.

### 3.2 `image.attach_bytes`

```json
{"jsonrpc":"2.0","id":18,"method":"image.attach_bytes","params":{
  "session_id":"<sid>","content_base64":"iVBORw0KGgo...","filename":"6f1c...e2.png"}}
{"jsonrpc":"2.0","id":18,"result":{"attached":true,"path":"<profile home>/cache/images/upload_ab12.png",
  "mime":"image/png","name":"upload_ab12.png","count":1,"remainder":"",
  "text":"[User attached image: upload_ab12.png]","bytes":70}}
```

Talaria keeps `path` and `mime` and ignores the rest. It never shows `path` on screen.

### 3.3 `file.attach`

Inside the session folder:

```json
{"method":"file.attach","params":{"session_id":"<sid>","path":"<project>/docs/notes.md"}}
{"result":{"attached":true,"name":"notes.md","path":"<project>/docs/notes.md",
  "ref_path":"docs/notes.md","ref_text":"@file:docs/notes.md","uploaded":false}}
```

Outside it:

```json
{"method":"file.attach","params":{"session_id":"<sid>","path":"<tmp>/other/notes.txt"}}
{"result":{"attached":true,"name":"notes.txt","path":"<profile home>/attachments/notes.txt",
  "ref_path":"<profile home>/attachments/notes.txt",
  "ref_text":"@file:<profile home>/attachments/notes.txt","uploaded":true}}
```

A second attach of a file with the same name returns `name` `notes-2.txt` (H15). Under `attachments.storage: workspace` the copy lands in `<project>/.hermes/attachments/` and `ref_path` is relative.

### 3.4 `prompt.submit` with attachments

```json
{"method":"prompt.submit","params":{"session_id":"<sid>","submission_id":"<uuid>",
  "text":"[Image #1] What colour is this image? One word.",
  "attachments":[{"path":"<profile home>/cache/images/upload_ab12.png","mime":"image/png"}]}}
```

Without images the `attachments` key is absent. Never `attachments: []`, never `queued`, never the unattended flag. A retry after an unknown outcome repeats this frame exactly (H32).

### 3.5 Refusals

```json
{"jsonrpc":"2.0","id":18,"error":{"code":4001,"message":"invalid_params","data":{"reason":"invalid_params"}}}
{"jsonrpc":"2.0","id":19,"error":{"code":-32601,"message":"unknown method: file.attach","data":{"reason":"unknown_method"}}}
```

## 4. Interfaces in full

Names are this unit's unless an owner is named. Signatures may gain lifetimes or error types but not lose capabilities. The test author adds every signature below with an `unimplemented!()` body before writing tests, so the red run is a panic in the named test, not a compile error.

```rust
// crates/talaria-core/src/attachments/mod.rs
pub mod chips; pub mod expand; pub mod mention; pub mod paste; pub mod drop; pub mod sniff;
pub use chips::{ChipStore, Chip, ChipId, ChipKind, ImageState, ChipError, CollapseRule};
pub use expand::{Expanded, ExpandError, Attachment};

// chips.rs
pub struct CollapseRule { pub lines: usize, pub chars: usize }   // 0 disables a rule
impl CollapseRule {
    pub const HERMES_DEFAULT: CollapseRule = CollapseRule { lines: 5, chars: 2000 };
    pub fn should_collapse(&self, text: &str) -> bool;  // CRLF -> LF, trailing '\n' removed, chars().count()
}
pub struct ChipId(u64);
pub enum ImageState { Pending { session: SessionId }, Ready { session: SessionId, path: String, mime: String }, Sent }
pub enum ChipKind {
    Paste { text: String, lines: usize },
    Image { n: u32, state: ImageState },
    File { n: u32, name: String, ref_text: String, session: SessionId },
}
pub struct Chip { pub id: ChipId, pub label: String, pub kind: ChipKind }
pub enum ChipError { TooManyImages }
pub struct ChipStore { /* paste counter (process-wide), chips, paste bytes held */ }
impl ChipStore {
    pub fn new(paste_budget_bytes: usize) -> ChipStore;             // 16 MiB in production
```

## 5. State machines

### 5.1 The mention list

"Open" means a query exists at the caret and the list is not dismissed for this word: any phase except `Closed` and `Dismissed`.

```text
Closed ──(edit; mention_at = Some)──► Waiting ──(tick: 60 ms since the last edit)──► Requested (request sent)
   ▲                                    ▲ edit restarts the 60 ms                    │ tick at 150 ms: view shows "Searching…"
   │                                    │                                            │ reply for the current generation
   │                       ┌────────────┴─────────────────────────┬──────────────────┼─────────────────────┐
   │                       ▼                                      ▼                  ▼                     ▼
   │                Items (≥1 after filter)                    Empty           Unavailable(reason)   (stale reply: ignored)
   │                       │ Tab/Enter: accept()                                (refusal, 2 s timeout,
   │                       │   keep_open → Waiting (query at once, no wait)      lost connection)
   │                       │   else → Closed
   ├──── Esc while open ──► Dismissed{word} ──(word changes)──► Waiting
   └──── mention_at = None (caret moved, space typed, submit, session change) ──► Closed
```

A reply whose generation is not the current one is dropped in every phase. The clock is never read inside core: `P1-12`'s loop passes `Instant`s in `AppMessage::Tick` and on edits, and schedules the next tick from `next_deadline()`.

### 5.2 An image label

```text
begin_image ──► Pending ──ImageStaged──► Ready ──receipt + mark_sent──► Sent (label is plain text from now on)
                   │                        │  │
                   │ AttachFailed           │  │ submit refused (not invalid_params): stays Ready, display returns
                   ▼                        ▼  │ refused invalid_params, or voice_stopped: dropped (section 5.4)
                                               │ unknown outcome: stays Ready (section 5.4)
               removed (notice)   label edited or deleted, or session changed: dropped
```

`Pending` blocks submit (REQ-17). On a session change, image and file chips are dropped and their labels stay as plain text (REQ-20).

### 5.3 A dropped path

```text
paste ──route_paste──► Drop(candidates) ──ResolveDrop effect──► service: for each candidate in try order,
  resolve (~/ to the OS home; relative against info.cwd, else the launch folder), stat (following links);
  folders and missing paths are skipped; the FIRST candidate that is an existing regular file wins and ends the search
     ├─ none is a regular file ──► DropNotAFile ──► original text: collapse rule, else insert (folders stay text)
     ├─ in the credential deny-list (section 6.12) ──► DropRefused "Talaria does not attach credential files."
     ├─ unreadable ──► DropRefused "Talaria cannot read <name>."
     ├─ image (sniff) ──► size check ──► DropImage ──► begin_image at the current caret ──► AttachImage
     ├─ unsupported image ──► DropRefused
     └─ other file ──► size check ──► AttachFile ──► FileAttached ──► ref_text or [File #n: name] at the current caret
```

Nothing is inserted while the check runs. The result lands at the caret as it is when the event arrives; text typed in the meantime stays where it was typed. A result for a session that is no longer in the foreground is dropped. The path sent to `file.attach` is the winning candidate made absolute lexically (`~/` expanded, a relative path joined to the folder, `.` and `..` segments removed) and never canonicalised, so a symbolic link is sent as the link path; Hermes decides inside or outside from it. Inserted `ref_text` is followed by one space unless whitespace already follows the caret; `[File #n: name]` and `[Image #n]` labels get no space (the user types one). Every inserted string (`ref_text`, a label, an accepted item) passes the composer's safe-text rule (`P1-08` REQ-12) inside `replace_range`, and an insertion never opens the list (`on_edit` with `typed: false`).

### 5.4 The submit outcome

`P1-12`'s submit path reports the reply of each `prompt.submit` to `AttachmentsState::on_submit_outcome`:

| Reply | `SubmitOutcome` | Labels |
|---|---|---|
| any `AdmissionStatus` (`status` `queued`, `started`, `unknown` or `terminal`) | `Receipt` | `mark_sent`: images become `Sent`, paste and file chips are released (H34: the bytes were captured at admission) |
| a refusal whose reason is `invalid_params` while `attachments` was sent | `Refused` | image chips dropped (labels become plain text) with the notice `Hermes no longer has the attached images; attach them again.` (H35: a staging file may have been cleaned up); paste and file chips stay live; `display` returns to the composer |
| any other refusal | `Refused` | all chips stay live; `display` returns to the composer |
| `CallError::TimedOut` or `Unknown` | `Unknown` | all chips stay live; nothing is marked sent |
| `{voice_stopped: true}` | `VoiceStopped` | nothing was admitted; `P1-12` clears the composer, so reconcile drops the chips |

This unit writes no retry path. Before `P2-08` merges, `P1-12` never resends after an unknown outcome (`P1-12` REQ-14), and the user may submit again (a fresh `submission_id`). `P2-08` owns the retry (its REQ-9); its ledger must keep each submission's `attachments` beside its `text` and resend them unchanged (H32). `AttachmentsState` keeps the last submitted `Expanded` until its outcome arrives so `P2-08` can read it.

## 8. Clipboard commands

| Platform | Step | Command | Success when |
|---|---|---|---|
| macOS | 1 | `pngpaste <tmp>/clip.png` | exit 0 and the file is non-empty |
| macOS | 2 | `osascript -e 'clipboard info'` | output contains `«class PNGf»` or `«class TIFF»` |
| macOS | 3 | `osascript -e` with the script below | exit 0, output is not `fail`, and the file is non-empty |
| Linux (Wayland) | 1 | `wl-paste --list-types` | a line equal to `image/png` |
| Linux (Wayland) | 2 | `wl-paste --type image/png` with standard output to `<tmp>/clip.png` | exit 0 and non-empty |
| Linux (X11) | 1 | `xclip -selection clipboard -t TARGETS -o` | output contains `image/png` |
| Linux (X11) | 2 | `xclip -selection clipboard -t image/png -o` with standard output to the file | exit 0 and non-empty |

The macOS write script, copied from `hermes_cli/clipboard.py` lines 181 to 189 at v0.22.4:

```applescript
try
  set imgData to the clipboard as «class PNGf»
  set f to open for access POSIX file "<tmp>/clip.png" with write permission
  write imgData to f
  close access f
on error
  return "fail"
end try
```

Each command gets 3 s. `NotFound` moves to the next step of the next backend. Any other failure (a non-zero exit, `fail`, a timeout, an empty file, a macOS permission error) counts as no image and moves on; when every step fails the result is `Empty`. On Linux, when neither `wl-paste` nor `xclip` exists, the result is `NoTool`. Talaria does not convert other image types to PNG (Hermes does, for Wayland). A Wayland clipboard without `image/png` is no image from Wayland, and the reader then tries the X11 steps, as Hermes does (H37); only when `xclip` also finds no image is the result `Empty`. Windows and WSL are out of scope for phase 2. `<tmp>` is a private temporary directory (mode 0700) created with `tempfile` and removed after the bytes are read. The bytes then go through `sniff_image` and the 20 MiB cap like a dropped file. The image label is inserted only after a successful read. A quiet probe (an empty or whitespace paste) shows no notice in any outcome, including `NoTool`.

## 10. Design reasoning and rejected alternatives

1. **`clipboard.paste` rejected.** It reads the gateway host's clipboard (the same machine in phase 2, so it would work for bytes), but its handler lives in the older sidecar and fails with "session not found" for every gateway-owned session (H21), and it queues the image where admission never looks. Hermes's own terminal UI reads the clipboard locally on the native socket for the same reason (H24).
2. **`paste.collapse` rejected.** Its result is not used for sending by any Hermes client (H24; the classic command line expands its own placeholder before sending). It writes a file per paste that nothing removes, and its placeholder carries an absolute path into the profile home, which would show on screen and in screenshots used as evidence.
3. **`image.attach_bytes` over writing into the cache folder.** Hermes's terminal UI writes straight into `<profile home>/cache/images/` for a local gateway. Talaria does not know the profile home path, and the bytes call works unchanged for the remote gateways of phase 6.
4. **Image labels kept in the text.** Claude Code inserts `[Image #N]` "you can refer to by position" (u12 feature `in.image-paste`). Hermes's terminal UI strips its image tokens, so "compare these two" loses which is which. Keeping the labels costs a few tokens.
5. **Thresholds.** Claude Code collapses above 800 characters or 3 lines (u12 feature `int.large-paste`); Hermes defaults to 2000 characters or 5 lines (H23). Talaria uses Hermes's defaults, because the backend's users are used to them and both are configurable. The operator may choose otherwise.
6. **Labels as plain text plus atomic delete.** Atomic spans inside the editing buffer would change `P1-08`'s buffer model. Plain-text labels (Hermes's approach) need only a lookup, and atomic Backspace and Delete cover the common case of removing a label. Reconciling after every edit, and never reviving a dropped payload, keeps a hand-typed or copied label from silently re-attaching an old image.
7. **Files over `file.attach`, not by inserting an absolute `@file:` path.** Hermes does not expand a reference outside the session folder (H10: it becomes a warning the model sees, not content), so a typed absolute path to a file elsewhere gives the model nothing. `file.attach` copies it into the profile's `attachments/` folder, which the reference guard admits.
8. **Profile mentions filtered.** `@<profile>` items exist for multi-agent interfaces that route text to another profile; Talaria has no such routing in phase 2, and inserting `@name` would be sent as plain text.
9. **Per-process paste numbering, per-draft image and file numbering.** Paste labels recalled from history (Up) must still find their text, so paste numbers never repeat. `P1-08`'s history is in memory only and stores the draft as typed (labels included), so a label can never meet a paste from an earlier run. Image and file labels refer within one message ("compare [Image #1] with [Image #2]"), so they restart per draft, taking one more than the highest number already written in the draft so a recalled plain `[Image #1]` never collides.
10. **State in `talaria-app`, logic in `talaria-core`.** The architecture's layer table forbids session or protocol state in `talaria-tui`, and principle 4 wants one pure update. The first draft put the chip store and the list inside a terminal-crate router; that broke the layer rule. `P1-12`'s `AppState` and pure `update` already exist for exactly this, so the state rides there, and `talaria-tui` only draws a `MentionView` and label highlights.
11. **Drop checks off the input thread.** Deciding whether a dropped path names a file needs a file-system call, which can block on a network mount. `route_paste` stays pure and only finds candidates; the service checks them. Inserting the result at the caret as it is on arrival is simpler and more predictable than holding typed keys.
12. **Shared completion actions.** `P2-03` defines `completion_next`, `completion_prev`, `completion_accept` and `completion_close`. Two sets of actions for the same keys would conflict in `keys.rs` and in the person's configuration. Enter stays the composer's `submit`, routed to whichever list is open, as `P2-03` does for its palette.
13. **No change to the bench.** `P1-11` owns `--bench-replay` and fixes its probe text and key path; opening this list there would change another unit's measured path and tests. This unit measures its own added work per keystroke (test 30) and keeps `P1-11`'s rows green.
14. **Session change drops image and file payloads.** Staged images live in the old session's profile cache and file references may point into its folder; sending them to another session could be refused or wrong. Paste text is local and stays.
15. **Credential files refused on drop.** `file.attach` copies a file from outside the session folder into the profile's `attachments/` folder, where Hermes's reference guard checks the copy's new path, so a dropped `~/.ssh/id_ed25519` would reach the model. Talaria refuses the same paths Hermes refuses as references (H36), plus its own and Hermes's homes. Rejected: no check (leaks a key on a careless drop) and asking for confirmation (a new prompt surface for a rare case).
16. **Any admission receipt marks images sent.** Hermes captures the bytes when it commits the admission (H34), whatever the turn's later status, so `unknown` and `terminal` receipts are receipts. An `invalid_params` refusal with images most likely means a staging file was cleaned up (H35), so keeping the labels Ready would loop forever.
