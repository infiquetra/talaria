## 1. What this unit adds

```text
talaria -p --output-format stream-json "prompt"                                   (one turn)
talaria -p --input-format stream-json --output-format stream-json < lines.jsonl   (many turns)

standard input (stream-json, line order)   standard output (one JSON object per line)
                                            {"type":"system","subtype":"init",...}
1 {"type":"user","text":"A"}       ──►      {"type":"submitted","turn":1,...}
                                            {"type":"text","turn":1,...}           (zero or more)
                                            {"type":"tool_use","turn":1,...}       (zero or more)
                                            {"type":"tool_result","turn":1,...}
2 {"type":"interrupt"}             ──►      (turn 1 stopped)  {"type":"result",...}  exit_code 130
3 {"type":"user","text":"B"}       ──►      {"type":"submitted","turn":2,...} ... {"type":"result",...}
end of input                       ──►      detach once, exit with the last result's exit_code
```

Each turn is a P2-14 headless turn driven by P2-14's state machine. This unit adds the records, the input reader and the loop over turns.

|---|---|
| `TooLong` | `line <n> is longer than 1048576 bytes.` |

pub enum InputFormat { Text, StreamJson }      // encodes "text" | "stream-json"

pub enum StreamRecord {
    // encoder adds "stream_version":1 and "turn":null
    Init { session_id: String, profile: String, model: Option<String>, provider: Option<String>, input_format: InputFormat, elapsed_ms: u64 },
    Submitted { turn: u32, admission_id: String, status: String, elapsed_ms: u64 },
    Text { turn: u32, text: String, elapsed_ms: u64 },
    ToolUse { turn: u32, tool_id: String, name: String, context: String, input: serde_json::Value, elapsed_ms: u64 },
    ToolResult { turn: u32, tool_id: String, name: String, is_error: Option<bool>, output: String, duration_ms: Option<u64>, elapsed_ms: u64 },
    Warning { turn: Option<u32>, text: String, elapsed_ms: u64 },
    Gap { turn: u32, elapsed_ms: u64 },
    InputError { turn: Option<u32>, line: Option<u64>, what: String, elapsed_ms: u64 },
}

pub const STREAM_VERSION: u32 = 1;
pub const MAX_OPEN_TOOL_STARTS: usize = 4096;
pub const MAX_TOOL_OUTPUT_BYTES: usize = 65_536;

/// One line, keys in section 5's order, no trailing newline.
pub fn encode(record: &StreamRecord) -> String;

pub struct StreamProjector {
    turn: u32,
    starts: std::collections::HashMap<String, u64>,   // tool_id -> now_ms at tool.start, at most 4,096
    gap: bool,
    warned: std::collections::HashSet<&'static str>,
}

impl StreamProjector {

    /// Sets the gap flag and returns the `Gap` record.

### 4.2 `crates/talaria-app/src/headless/stream_input.rs`

```rust
pub enum InputRecord { User { text: String }, Interrupt }
pub enum InputError { TooLong, NotUtf8, NotJson, NotObject, NoType, UnknownType(String), BadKeys(&'static str), BadText, NoUserRecord }
pub enum InputItem { Record(InputRecord), Error(InputError) }

pub const MAX_LINE_BYTES: usize = crate::headless::input::MAX_STDIN_BYTES;   // 1,048,576
pub const INPUT_QUEUE: usize = 64;

/// One line without its `\n`; a trailing `\r` is removed here. `Ok(None)` for blank.
pub fn parse_input_line(line: &[u8]) -> Result<Option<InputRecord>, InputError>;

/// `(line number, item)` in line order; the channel closes at end of input or after the
/// first `InputItem::Error`. `NoUserRecord` is never sent by the reader (the service decides it).
pub struct InputReader { pub items: tokio::sync::mpsc::Receiver<(u64, InputItem)> }

/// One blocking thread; `blocking_send` into a bounded channel of `queue` items, so a full
/// channel pauses reading.
pub fn spawn_input_reader<R: std::io::Read + Send + 'static>(input: R, queue: usize) -> InputReader;
```

### 4.4 Changes to P2-14's module (adapt to the merged names)

1. `HeadlessEffect::Observed { event_type: String, payload: serde_json::Value }`: emitted by `step` exactly once for each `message.delta`, `tool.start` or `tool.complete` input it applies as our admission's (envelope `admission_id` equals ours), when applied: at once after the submit reply, or in hold order when the reply releases held events. P2-14's own service ignores it.
2. `StopCause::Record` and `StopCause::OutputClosed`: handled by `step` exactly like `Signal(2)` at every stop point; `judge` returns (`Interrupted`, 130) and (`Interrupted`, 141); texts of section 3.5. Nothing in the machine ends a run: run continuation is the stream service's decision.
3. `OutputFormat::StreamJson` in `headless/mod.rs`; P2-14's `run_print` dispatches it to `run_stream`.
4. `service.rs`: the loop that executes `HeadlessEffect`s (submit with the added submission id, receipt, cancel, interrupt, declines, recover, timers, detach) moves into one function both services call, for example `pub(crate) async fn execute_effect(...)`. Behaviour unchanged; P2-14's flow tests are the regression check.

Nothing else in P2-14 changes. Not needed as machine changes: the turn number (the service builds the submission id, P2-14 `Submit { text }`), the caller-owned detach (the stream service defers executing `Detach`), and the gap signal (the service sees `Gap` and `Recover` itself).

## 5. Record formats (golden lines for test 9)

```json
{"type":"system","subtype":"init","stream_version":1,"turn":null,"session_id":"20261022_120000_ab12cd","profile":"fixture","model":"minimax-m3.1-flash","provider":"ollama-cloud","input_format":"text","elapsed_ms":180}
{"type":"submitted","turn":1,"admission_id":"adm-1","status":"started","elapsed_ms":210}
{"type":"text","turn":1,"text":"Listing","elapsed_ms":900}
{"type":"tool_use","turn":1,"tool_id":"call_1","name":"terminal","context":"ls","input":{"command":"ls"},"elapsed_ms":1400}
{"type":"tool_result","turn":1,"tool_id":"call_1","name":"terminal","is_error":false,"output":"a.txt\n","duration_ms":350,"elapsed_ms":1750}
{"type":"warning","turn":1,"text":"Hermes did not return the turn's usage figures.","elapsed_ms":2600}
{"type":"gap","turn":1,"elapsed_ms":2000}
{"type":"input_error","turn":null,"line":1,"what":"line 1 is not valid JSON.","elapsed_ms":200}
```

The `result` line is P2-14's `render_json` output for the turn (without its trailing newline handling changing). A `warning` or `input_error` carries the turn in flight, else the last turn started, else `null`.

`stream-v1.md` lists, for a Hermes consumer: `tool_id` (Hermes `tool_call_id`), `elapsed_ms` (Hermes `timestamp`, wall clock), `is_error` and `duration_ms` may be `null`, four extra record types, and P2-14's `result` keys (Hermes: `tokens`, `replay_gap`). `result.duration_ms` is time from process start to the end of that turn; `elapsed_ms` is time from process start to the record.

## 6. Behaviour step by step

### 6.1 Start-up

1. P2-14's start-up and argument checks, then section 3.2's checks.
2. Signal handlers and the deadline start before any read (P2-14).
3. Text input: `assemble_prompt` (P2-14). Stream input: refuse a terminal, `spawn_input_reader`.
4. `ConnectionService::open`, `SessionService::open` (P2-14 REQ-4, REQ-5). On failure, write P2-14's `result` (status `not_started`, exit 4) and nothing else.
5. Write `system`. Keep the opening snapshot's `open_prompts` and `unknown_admissions`.

### 6.2 The turn loop

```text
 ┌─► take the next item (wait if none)
 │     user record ──► turn n = n+1; HeadlessRun::new(text); feed Opened(live state)
 │     interrupt  ───► warning "nothing to interrupt." ─────────────────────────────┐
 │     error ────────► input_error; detach; exit 2                                   │
 │     channel closed ► end (n == 0: input_error NoUserRecord, exit 2)               │
 │                                                                                    │
 │   drive the turn: execute effects (Detach deferred); every Event, Gap, Recovered │
 │   and ServerRequest also updates the live state; Observed ► projector ► records; │
 │   first Gap input or Recover effect ► `gap` + mark_gap                            │
 │   meanwhile, head item: interrupt ► Stop(Record); error ► Stop(Record), then     │
 │   input_error after the result; user record ► leave it                           │
 │   signal/deadline ► Stop(cause); write error ► Stop(OutputClosed)                │
 │                                                                                    │
 │   Finish(result): P2-14 warnings as `warning` records, then the `result` line,   │
 │   then P2-14's render_stderr to standard error                                   │
 │     exit 0, or 130 from Record ──────────────────────────────────────────────────┘
 └──── (loop)          anything else ► end with that code
 end: execute the deferred Detach once (unless P2-14's exceptions apply), return the code
```

Rules:

1. Text input has exactly one turn; its source is the assembled prompt.
2. Live state for `Opened` of turn n>1: `open_prompts` starts from the opening snapshot; `approval.request` and `clarify.request` events (any admission) add a row with their `prompt_id`, `kind`, `admission_id` and `execution_generation`; `approval.settled` and `clarify.settled` remove it by `prompt_id`; a `Recovered` input replaces the set with its `open_prompts`. `unknown_admissions` is the count of `pending` rows with `status: "unknown"` in the latest `session.info` event's raw payload (S23), else the opening snapshot's count.
3. A turn is in flight from taking its user record to writing its `result`. Items are taken in line order, so an interrupt applies to the latest user record before it.
4. A second interrupt during a stop gives `interrupt ignored: the turn is already stopping.` once per turn.
5. A stop (signal, deadline, closed output) between turns ends the run at once: no submit, no new record.
6. P2-14's `ExitNow` (second signal): write the `result` from the `HeadlessResult` it carries, then return its code without detaching.
7. The deferred detach is skipped in P2-14's no-detach cases (second stop, link failure, gone session, expired stop budget).

### 6.3 Exit code (first match wins)

| Case | Code |
|---|---|
| Usage error | 2 (nothing written) |
| Not started | 4 |
| Signal or `--timeout`, during or between turns | 129, 130, 143, 124 |
| Closed output | 141 |
| Input error, including no user record | 2 (overrides an earlier turn's 0) |
| A turn whose exit is not 0, not stopped by `Record` | that code; later input unread |
| End of input after at least one turn | the last turn's `exit_code`: 0, or 130 when `Record` stopped the last turn |

Example (UAT-4): turn 1 stopped by a record (130), turn 2 completes (0), end of input: exit 0.

### 6.4 Writing

One `BufWriter` over standard output, flushed after every line. The first write error of any kind feeds `Stop(StopCause::OutputClosed)` to the turn in flight (or ends the run between turns); later records are dropped without trying. The 50-millisecond budget runs from the `Observed` effect (or the decision to write a non-event record) to the flush.

## 7. Event-to-record table

| Observed event (ours) | Record |
|---|---|
| `message.delta`, `text` a non-empty string, no gap in this turn | `text` |
| `message.delta`, `text` `null`, `""`, not a string or missing; or after the gap | none |
| `tool.start` | `tool_use`; store `starts[tool_id] = now_ms` if fewer than 4,096 are stored, else the cap warning once |
| `tool.complete` | `tool_result`; `duration_ms` = `now_ms - starts.remove(tool_id)`, else `null` |
| payload not an object | none; the non-object warning once per type |

Field rules: `tool_id` = `tool_id` if a string, else `tool_call_id` if a string, else `""`. `name` = `name`, else `tool_name`, else `"tool"`. `context` = string or `""`. `input` = `args` if an object, else `{}`. `is_error` = the boolean, else `null`. `output` = `result` if a string, else compact JSON of `result`, else `""`; if longer than 65,536 UTF-8 bytes, cut at the largest character boundary at or below 65,536 and append `...` (so at most 65,539 bytes). A second `tool.start` with a stored `tool_id` replaces the stored time.

Every other event type (S20) gives no record. `approval.*`, `clarify.*`, `session.info` and server requests update the live state (6.2 rule 2) and P2-14's machine, never records.

## 9. Edge cases

| Case | Behaviour |
|---|---|
| Delta before the submit reply | held by the machine; its `text` follows `submitted` |
| Same tool name twice at once | told apart by `tool_id` |
| `tool.complete` without a start | `duration_ms` `null` |
| More than 4,096 open starts | records still written; `duration_ms` `null` for the unstored; one warning |
| Commentary between tool calls | in `text` records, not in `result.text` (S9) |
| Unstreamed commentary (S16) | not shown; `result.text` is the answer |
| Gap, then deltas | no `text`; full `result.text` with P2-14's warning |
| 64 items waiting | reader pauses; the service takes items only in order |
| Interrupt after the last turn, then end of input | warning is the last line; exit is the last turn's code |
| Input ends during a turn | the turn finishes normally; the run ends after its `result` |
| Blocked session before turn 2 | turn 2 exits 3 by P2-14's rule; its `result` written; run ends 3 |
| Standard output is a terminal | allowed; JSON escaping covers control characters |
| Time limit between turns | no submit, nothing new on standard output, P2-14's time-limit text on standard error, exit 124 |

## 11. Decisions and the reasons for them

1. **Shared type names, Talaria's own fields.** Claude Code wraps whole messages and partial events (research report u12, row `head.stream-io`); Hermes uses flat records (S3, S4). Talaria reuses Hermes's type names so its records look familiar, but its fields differ (section 5), so consumers must be Talaria-aware. Rejected: copying Hermes's fields exactly (its `tool_result` has no `tool_id` fallback rules and its result differs from P2-14's); Claude Code's envelopes. Revisit if the operator wants drop-in compatibility with either.
2. **The result record is P2-14's object.** One result parser for `json` and `stream-json`.
3. **No init on a failed start.** Talaria writes init only with a session id; the stream still ends with a `result`.
4. **Line order, one turn at a time, stop on failure.** Line order makes interrupts unambiguous; sending prompts to Hermes's queue would run later prompts after an earlier failure. Revisit for a pipelined mode.
5. **A closed output stops the turn (141).** A consumer that stopped reading cannot learn the outcome; turns would spend money unseen. Rejected: P2-14's "ignore a broken pipe", which suits one object at the end.
6. **`interrupt` is the only control record.** Answering questions would reopen P2-14's settled no-answer rule.
7. **Raw payloads.** S12: the contract's closed types omit three sent fields, and Talaria's open generated types would drop them silently. P2-14 found the same for `message.complete` (P2-14 H13).
8. **Live state from events, not a new call.** The `session.info` method has no `pending`; the `session.info` event has it (S23), and approvals arrive as events, so no extra wire call is needed before turn n>1.
