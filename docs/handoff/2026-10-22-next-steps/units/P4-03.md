# P4-03: Model roles: main, auxiliary, Mixture of Agents, fallbacks and delegation (unit P4-03)

Status: `proposed`. The GitHub issue for this unit is the contract; this document is its reference specification. If they disagree, the issue wins and the disagreement is reported on the issue.

**How to use this document.** The issue says what to build, which tests to write first, and when the unit is done. This document holds the evidence behind it: every Hermes fact with its file and line at Hermes v0.22.4 (section 2), the facts nobody could confirm (section 3), the screen and its behaviour in full, including every text, key and diff line (section 4), the Rust interfaces (section 5), the rules for the mock REST server (section 6), the edge cases (section 7), notes for each test (section 8), fixtures and live runs (sections 9 and 10), and the list a planner re-checks before the unit starts (section 11). Read sections 2 and 4 before writing any test. Hermes links point at the `v0.22.4` tag; re-check each one at the release pinned in `crates/hermes-contract/PINNED` when the unit starts.

Terms used throughout:

- **Model role**: one place in a Hermes profile's configuration that names a model: the main model, a fallback entry, an auxiliary ("helper") task slot, the delegation (subagent) route, or a Mixture of Agents slot.
- **Dashboard API**: the REST routes under `/api/` that the gateway's own loopback HTTP listener serves (unit `P4-00`, static reading S1). `P4-01` owns the client: one fresh single-use `native-http` ticket per request in the `x-hermes-gateway-ticket` header, minted for one profile. Hermes binds every ticketed request to the ticket's profile (W14), so Talaria never sends a `profile` query or body field (`P4-01` decision 2; its mock answers 403 to one).
- **Route**: a `{provider, model}` pair, optionally with an endpoint (`base_url`).
- **Mixture of Agents (MoA)**: a Hermes execution mode in which several "reference" models advise and one "aggregator" model acts. Presets are named sets of these slots.

## 1. What the unit delivers

A "Model roles" page inside Talaria, opened with the local command `/models` or from the settings page list that `P4-01` provides. It has five sections in Hermes Desktop's order: Main, Fallbacks, Helpers (auxiliary), Subagents (delegation), Mixture of Agents (Desktop's sub-pages are main, fallbacks, auxiliary, delegation, moa in [`apps/desktop/src/app/settings/config-subpages.ts` lines 12 to 24](https://github.com/NousResearch/hermes-agent/blob/v0.22.4/apps/desktop/src/app/settings/config-subpages.ts#L12-L24)). Each section reads its values from Hermes, lets the user change them with a provider-then-model picker and small editors, shows a key-level diff, and writes through the route Hermes itself uses for that role. Nothing is written over the gateway socket.

The roadmap's phase 4 row for this unit names `/api/model/*` and `config.set`. `config.set` cannot serve here: on the canonical socket it refuses key `model` and accepts no model-role key (S4), so the generic configuration write `PUT /api/config` takes its place, as in Hermes Desktop (D7).

The Claude Code parity rows this unit covers ([../04-prior-art.md](../04-prior-art.md#claude-code-parity-checklist); [../research/u12-claude-code-parity.json](../research/u12-claude-code-parity.json)):

- "Model fallback chains" (phase 4): Claude Code's `model.fallback` row, "configured fallback models take over when the primary model is unavailable".
- `sub.model`, "a subagent's model comes from its definition, a per-call choice, the `CLAUDE_CODE_SUBAGENT_MODEL` setting, or the main model": Talaria's equivalent is the profile-wide delegation route.
- `model.picker`, "switches the model and saves it as the default for new sessions": Talaria's session picker (`P2-06`) switches the session; this unit is the place that saves the Hermes profile default, its context override and its default effort.

Ownership across the set: `P4-01` makes `model` and `model_context_length` read-only in its generic form because this unit owns them; `P2-06` hands "the Hermes profile's default model or effort" to this unit; `P4-02` hands "choosing the profile's main model ... and make this endpoint the default" to this unit. `P4-01`'s generic form may still list `fallback_providers`, `agent.reasoning_effort`, `delegation.*`, `auxiliary.*` and `moa.*`; this unit does not change `P4-01`'s code and its pull request reports the overlap for the planner.

## 4. Design

### 4.1 Entry, layout and sections

- **Open:** the local command `/models` (no argument). With any argument, the composer's local-command error line shows `Usage: /models` and nothing opens. The "Model roles" row in `P4-01`'s settings page list opens it too. Hermes v0.22.4 has no `/models` command ([`hermes_cli/commands.py`](https://github.com/NousResearch/hermes-agent/blob/v0.22.4/hermes_cli/commands.py) defines `model` and `moa` only); the planner re-checks this at the pinned commit.
- **Profile:** the page edits the profile Talaria's connection is attached to. `ModelRolesState::new(profile)` takes any name; the service checks that the endpoint serves it (else `P4-01`'s T4: `Profile <name> is not served by this gateway, so its settings cannot be opened here.`), builds a `RestClient` with a `NativeHttpMinter` for it exactly as `P4-01`'s `SettingsService` `Load` does, and sends `model.options {explicit_only: true, include_unconfigured: true, profile: <name>}` when the name differs from the connection's profile (service test 48). In v0.7.0 only `/models` and the settings row open it. After a gateway restart the client is rebuilt on the next load from the endpoint's current `api_origin`. With no connection (no endpoint or no `api_origin`), the page opens with every section empty and the single line `Model roles need the Hermes gateway, and Talaria is not connected. Ctrl+R retry · Esc close` (mirrors `P4-01`'s T2; Ctrl+R emits `LoadAll` again; reconnecting is the application's job).
- **Load order:** opening emits `LoadAll` (the four REST reads of the issue's REQ-2, in parallel) and `LoadCatalog { refresh: false }` together. The REST reads never wait on the catalogue: each REST request uses its own HTTP connection and a ticket minted over its own control connection (`P1-01` specification section 8: "Each mint opens a new control connection"), not the session socket that `model.options` occupies. Until the catalogue arrives, no `(not in the model list)` mark is drawn and the picker shows `loading models...`.
- **Overlay:** a full-height overlay through `P1-06`'s `open_overlay`/`draw_overlay`. The transcript stays underneath; closing returns to the composer.
- **Header and tabs:** line 1 `Model roles - profile <name>`; line 2 the tab row `1 Main  2 Fallbacks  3 Helpers  4 Subagents  5 Mixture of Agents` with the current tab drawn reversed; a section in `Failed` state adds ` (stale)` after its tab name. The footer shows the section's keys (`?` lists all).
- **Sections:**
  1. **Main** (`Main model`):
     - `Model: <model> (via <provider>)`.
     - Context: `Context window: <n> tokens (auto-detected)` when `config_context_length` is 0; `Context window: <n> tokens (set; auto-detected <a>)` when it is above 0 (`auto-detected unknown` when `auto_context_length` is 0); `Context window: unknown` when both are 0; `Context window: checking...` until info answers. Numbers use `,` thousands separators.
     - Capabilities: `Can use: <list>` naming `tools`, `images`, `reasoning` for each true `supports_*`; then `Max output: <n> tokens` and `Family: <family>` when present; `Capabilities: unknown` when the map is empty.
     - Effort: `Default effort: <level>`, or `Default effort: inherited` for `""` or absent; a mapping value shows `Default effort: <effort> (set in config.yaml)` and is read-only.
     - `Applies to new sessions. Running sessions keep their model; change a session with /model.`
     - When `P2-06`'s Talaria saved default exists: `Talaria starts new sessions with <provider>/<model> (your Talaria default), which overrides this.`
     - No main model: `No main model set. Choose one with Enter.`
  2. **Fallbacks**: numbered chain `1. <model> (via <provider>)`; markers `[endpoint]` (entry has `base_url`), `[key set]` (`api_key`, `key_env` or `api_key_env`), `same as main model`, `duplicate: Hermes skips it`, `(ignored by Hermes until saved)` (a string entry); legacy `fallback_model` entries below a rule, read-only, labelled `Legacy entry (fallback_model): edit with the hermes fallback command`; the empty state `No fallback models. When the main model fails, the turn fails.`
  3. **Helpers** (auxiliary): one row per slot with the label and hint (`Title gen - Session titles`; an unknown built-in or plugin slot shows its key or the plugin's `label`), then `follows main model` for `auto`/`""`/`main` (`follows main model (none set)` with no main model), else `<model> (via <provider>)`, then `effort: <level>` or `effort: inherited` (`null` or `""`), `[endpoint]`, and `!` on stale pins. Plugin rows show `from plugin <plugin>`; an inheriting plugin row shows `follows <inherit_from>: <effective model>`.
  4. **Subagents** (delegation), rows in order: `Route: follows main model` (both `""`), `Route: <model> (via <provider>)` (both set), `Route: <provider>, model inherited` (provider set, model `""`) or `Route: <model>, provider inherited` (model set, provider `""`); plus `Direct endpoint: <base_url>` when set, drawn as its own row under any route form; `Effort: inherited` or a level; `Fallback: inherits the main chain` (`null`), `Fallback: no fallback` (`[]`) or `Fallback: own chain`; then the own chain's numbered entries, with the same markers and string-entry treatment as Fallbacks (M17); a hint line `Other subagent limits are in Settings.`
- **Scrolling:** every list (sections, the MoA detail pane, the picker) keeps the selected row visible; when rows are cut off, the first visible row is replaced by `↑ <n> more` and the last by `↓ <n> more`. PageUp and PageDown move by the visible height. Long Helpers lists (twelve built-ins plus plugin rows) and the MoA detail pane scroll this way at 80x24 (test 42).
  5. **Mixture of Agents**: left pane, the preset list (`* ` marks the default; `(off)` a disabled preset); right pane, the selected preset: `Enabled: yes|no`, `References:` with one row each (`<model> (via <provider>)`, `(off)` when disabled, `effort: <level>|inherited`), `Aggregator: <model> (via <provider>)`, `Advisors run: once per user turn | every tool step | every <N> tool steps`, `If an advisor fails: say so (loud) | carry on (silent)`, `Advisor timeout: inherit | <n> s`, `Reference temperature: provider default | <n>`, `Aggregator temperature: provider default | <n>`; below both, read-only `Active preset: <name>|none` and `Privacy filter: off | display | full`. When the raw file has no `moa.presets` (M9), a notice: `No presets of your own. Hermes shows its example preset below; saving writes it into this profile, and enabled presets then appear as models under "Mixture of Agents".` When every reference is disabled: `No reference is enabled.`

### 4.2 States

Per section: `Loading`, `Loaded(values)`, `Failed(reason)` (with `Ctrl+R to retry`), `Unavailable(reason)` (the route answered 404, or `P4-00` marked it unreachable: read-only, `This Hermes has no <route>.`). Page-wide: `Pending(section, changes)` (at most one section has unapplied changes), `Reviewing(lines)`, `Applying`, `ConfirmExpensive { message, slot }`, `OfferStaleReset(slots)`, `Conflict(fresh values)`, `OutcomeUnknown` (then an automatic re-read), `PartialHelpers { saved, unknown, not_saved }` (texts: 4.4b), `NotConnected` (4.1), and a one-line notice after success: `Saved. Applies to new sessions.`

### 4.4 Apply flows (one section at a time)

Every apply: (1) build the request from the pending changes; (2) show the review (below); (3) on Enter, re-read and compare (below); a difference goes to `Conflict` with the fresh values, and nothing is written; (4) write; (5) re-read and show the read-back values; (6) show the notice. When `RestError::outcome_unknown()` is true during (4), go to `OutcomeUnknown`: re-read, show what Hermes now holds, never claim success. A write that was not sent (`Connect`, `Ticket`, `Timeout { sent: false }`, `Dropped { sent: false }`) keeps the changes pending with `The change was not sent: <reason>.`

Not saved: <slots>.` (`none` when empty; an unknown outcome adds `Unknown: <slot>.`, 4.4b), keeps the unsaved slots pending, and reads Helpers back. | `GET /api/model/auxiliary`: `provider`, `model`, `base_url`, `reasoning_effort` of the changed slots only |
| Fallbacks | `PUT /api/config` | `{config: {fallback_providers: [<every entry, in order, with all its keys>]}}` (the whole list, W10). Rows missing a provider or model block the apply with `Entry <n> needs a model`. A former string entry is saved as `{provider, model}`. | the raw read's `fallback_providers`, the whole list |
| Subagents | `PUT /api/config` | `{config: {delegation: {<only changed keys>}}}`: `model` and `provider` together when the route changed (`""`, `""` for inherit); `base_url`, `api_key`, `api_mode` set to `""` when a direct endpoint was present and the user chose a provider route or inherit (D6); `reasoning_effort` (`""` for inherit); `fallback_providers` (`null`, `[]` or the whole list). | the raw read: only the `delegation.*` keys being written |
| Mixture of Agents | `PUT /api/model/moa` | `{default_preset, active_preset, presets}` only: the whole preset map in display order, each preset with every field it was read with (the shown example preset included on a first save). Local validation (W8 rules, same wording and order, plus the timeout and policy rules) runs first and blocks the apply. | `GET /api/model/moa`: `default_preset`, `active_preset` and `presets` |

**Stale reset after a Main write.** When the Main write reply has a non-empty `stale_aux`, after the Main read-back the page shows `These helpers still use another provider: <task (provider), ...>. Make them follow the main model? y/n`. `y` builds a Helpers pending change (inherit for each listed slot) and opens its review: a Helpers apply with its own diff, conflict re-read and read-back. `n` closes the question. The offer appears only when Main has nothing pending after its read-back; when (b) stopped and Main still has a pending change, no offer appears, the `!` marks stay, and the user resets later with `R` (one pending section, 4.4c). `R` in Helpers does the same for the slots `stale_helpers` returns: it adds an inherit change for each stale slot to the Helpers pending set (replacing any pending change of that slot) and opens the review. Talaria resets only the stale slots; Desktop's `__reset__` resets all (D2).

#### 4.4a Where the shown and written values come from

| Section | Values shown and used to build a write | Never from |
|---|---|---|
| Main | model and provider: `/api/model/info` (the auxiliary reply's `main` until info answers); context and effort: the raw read's `model_context_length` and `agent.reasoning_effort` (absent: `0`, `""`) | |
| Fallbacks | the raw read's `fallback_providers` (absent: `[]`) and `fallback_model` (absent: none) | the effective read (M16) |
| Subagents | the raw read's `delegation.model`, `.provider`, `.base_url`, `.api_key`, `.api_mode`, `.reasoning_effort` (absent: `""`) and `.fallback_providers` (absent: `null`) (defaults: M13) | the effective read (M16) |
| Helpers | `/api/model/auxiliary` (stored slot values, M4) | |
| Mixture of Agents | `/api/model/moa`; the raw read only for "does the file have `moa.presets`" | |

The page never sends the effective configuration (`GET /api/config` with defaults) anywhere and does not load it. A raw string holding `${...}` is shown as written (the variable name, never its value; a secret-named key still shows `[key set]`), and an entry or key the user did not change is sent back with that exact text, so the reference stays a reference. An entry the user edits keeps its other keys' raw text.

#### 4.4b When an apply stops

After any stop, the section reads back (except where the table says "no read-back"), and the pending set becomes exactly the pending changes whose target value the read-back does not show. Pending changes otherwise survive every stop; the user retries with Ctrl+S (a new review against the fresh values) or drops them with `u`.

| Where it stops | Shown | Read-back | What stays pending |
|---|---|---|---|
| Local validation (MoA W8 rules, `Entry <n> needs a model`) | the problems, no review | no | everything |
| Conflict at the re-read | `Changed outside Talaria since you opened this page` and the fresh values | the fresh values replace the shown ones | everything |
| Main (a) `ConfirmRequired`, answer `n` | nothing more is sent | no | everything |
| Main (a) refused, failed (5xx), not sent or sign-in | the 4.5 text; (b) is not sent | yes, except not sent and sign-in | per the read-back rule (normally everything) |
| Main (a) outcome unknown | 4.5 unknown text; (b) is not sent | yes | per the read-back rule |
| Main (a) saved, then (b) refused, failed, not sent, sign-in or unknown | `Saved: model. Not saved: <context, effort>.` (`Unknown:` instead of `Not saved:` for an unknown outcome), then the 4.5 text; no stale offer | yes | (b)'s keys, unless the read-back shows them |
| Helpers slot k: `n`, refused, failed, not sent or sign-in | `Saved: <slots>. Not saved: <slots>.` then the 4.5 text | yes | slots k onward |
| Helpers slot k: outcome unknown | `Saved: <slots>. Unknown: <slot k>. Not saved: <later slots>.` | yes | slot k only if the read-back does not show it; later slots |
| Fallbacks, Subagents, MoA write: refused, failed, not sent, sign-in or unknown | the 4.5 text | yes, except not sent and sign-in | per the read-back rule |

#### 4.4c One pending section, and the pending-changes prompt

At most one section holds pending changes. Changing section, Ctrl+R and Esc with pending changes ask `You have unapplied changes in <Section>. a apply · d discard · Esc stay`. `a` opens the review of that section exactly as Ctrl+S does (the diff always comes before a write); when that apply ends with nothing pending, the interrupted action (section change, reload or close) then runs; when it stops (4.4b) or the user leaves the review with Esc, the interrupted action is cancelled and the user stays on the section. `d` drops the pending changes and runs the action. The stale offer (`y`) and `R` only ever create Helpers changes while no other section holds pending changes: the offer is shown only when Main has nothing pending, and `R` is pressed inside Helpers, which can only be reached after the prompt has emptied any other section.

#### 4.4d Review (diff) format

Title `Review changes to <Section> - profile <name>`; one line per key path, `<key path>  <before> -> <after>`; footer `Enter apply  Esc back`. Values: strings as written, `null` or absent as `(not set)`, `""` as `""`. A non-empty value under a key that `P4-01`'s `is_secret_key` accepts prints `[key set]` (the masker walks maps and lists); an empty or absent one prints `""` or `(not set)` like any other value, so clearing `delegation.api_key` reads `delegation.api_key  [key set] -> ""`. `key_env` and `api_key_env` hold environment variable names, not secrets, and `is_secret_key` does not accept them (`P4-01` H32); they are never masked, and in fallback entry summaries they only produce the `[key set]` presence marker. That marker in a summary means "this entry carries its own key setting" (`api_key`, `key_env` or `api_key_env`), not a masked value. Section specifics:

- Main: `model.provider`, `model.default`, `model_context_length` (`0 (auto)` for 0), `agent.reasoning_effort`.
- Helpers: `auxiliary.<task>.provider`, `.model`, `.base_url`, `.reasoning_effort` for each changed slot.
- Fallbacks (a list-valued key): `fallback_providers (before):` then each entry `  <n>. <model> (via <provider>) [endpoint] [key set]`, then `fallback_providers (after):` in the same form; extra lines `Entry <n> was ignored by Hermes; saving makes it active.` for former string entries.
- Subagents: `delegation.<key>` per changed key; `delegation.fallback_providers` in the list form above.
- Mixture of Agents: `moa.default_preset`, `moa.active_preset`, then per preset `moa.presets.<name>: added`, `removed`, or `changed (<field>, <field>)`; a first save adds `This writes Mixture of Agents presets into this profile for the first time.`

### 4.5 Errors shown to the user

Mapped from `P4-01`'s `RestError` (the client keeps a string `detail` for 403 and other 4xx and none for 5xx).

| `RestError` | Text (one line, then the detail on the next line, sanitised) |
|---|---|
| `Refused { status: 400, detail }` | `Hermes refused this change:` then the detail when present |
| `Refused { status: 422, detail: Some(d) }` | `Hermes found a problem:` then `d` |
| `Refused { status: 422, detail: None }` | `Hermes found a problem with the request.` (list form, U2) |
| `Server { status: 503 }` from `/api/model/set` (any 503 from that route: W3 is its only source, W16) | `Hermes needs a restart before it can change models.` then `Run the doctor to restart the gateway.` (Talaria never restarts here.) |
| `Server { status }` other | on a write `Hermes could not save the change.`, then a read-back (a received 5xx is not `outcome_unknown()`, but Hermes may have saved part of a Main or Helpers apply, so the read-back decides what stays pending, 4.4b); on a read the section becomes `Failed` with `Hermes could not read <route>. Ctrl+R to retry.` |
| `Forbidden { detail }` | `Hermes refused this profile (<detail>). This is a Talaria defect; please report it.` (no selector is ever sent) |
| `NotFound` | the section becomes `Unavailable`: `This Hermes has no <route>.` (Hermes answers `No such API endpoint: ...`, W15) |
| `Unauthorized`, `Ticket(_)` | `Talaria could not sign in to the dashboard API.` then `Run the doctor.` On a read the section becomes `Failed` with this text instead of the no-answer text (last values stay visible, tab marked `(stale)`, Ctrl+R retries); on a write nothing was saved and the changes stay pending |
| `Connect`, `NotLoopback`, `TlsNotSupported`, `Timeout { sent: false }`, `Dropped { sent: false }` on a read | the section becomes `Failed`: `Hermes did not answer. Ctrl+R to retry.`; last values stay visible, the tab marked `(stale)` |
| the same on a write | `The change was not sent: <reason>.`; changes stay pending |
| `BodyTooLarge`, `BadBody` | on a read the section becomes `Failed` with `Hermes sent a reply Talaria could not read. Ctrl+R to retry.`; on a write it counts as `outcome_unknown()` (the write may have happened, as in `P4-01`) |
| `outcome_unknown()` true | `The result of the last change is unknown. These are the values Hermes holds now.` after a re-read |

### 4.6 Labels for when a change takes effect

Main: `Applies to new sessions.` (W4). Helpers, fallbacks, subagents, MoA: `Applies to new sessions.` while U1 is unverified, with the footer note `Sessions already running may keep their current setting.` When U1 is settled, the planner edits these strings; every string lives in one table in `crates/talaria-core/src/model_roles/text.rs`.

### 4.7 Untrusted text

Model names, provider names, labels, hints, plugin names, `confirm_message` and every `detail` come from Hermes and are drawn through `P1-06`'s `history::sanitize` (control and bidirectional-override characters become visible stand-ins). Long values are cut with `...` at the column edge, never wrapped into the next row.

## 6. Mock REST server rules

The mock is `P4-01`'s `crates/hermes-client/tests/support/mock_rest.rs` (a `tokio::net::TcpListener` on `127.0.0.1:0`, one HTTP/1.1 request per connection, every request recorded). This unit adds six handlers there. The service tests in `crates/talaria-app/tests/model_roles_service.rs` include the same file with `#[path = "../../hermes-client/tests/support/mock_rest.rs"] mod mock_rest;` and add the dev-dependencies it needs to `crates/talaria-app/Cargo.toml`. Each handler is built from the route source in section 2, never from imagination; each scripted reply validates against the shapes in section 5 and the recorded fixtures in section 9.

## 7. Edge cases

| Case | Behaviour |
|---|---|
| No main model configured (M1 empty) | Main shows `No main model set. Choose one with Enter.`; helpers show `follows main model (none set)`; no helper is stale (D2) |
| `/api/model/info` slow | Main shows provider and model from the auxiliary reply's `main` first; the context line shows `checking...` until info answers |
| `/api/model/info` degraded (empty record, status 200) | Main keeps the auxiliary `main` route; context `unknown`; capabilities `unknown` |
| `model.options` slow (about 1.2 s) or failing | The page draws at once; the picker shows `loading models...`; on failure `Could not load the model list. Ctrl+R to retry.` and Enter does nothing |
| A stored model is not in the catalogue | Shown as stored, with `(not in the model list)`; never silently replaced |
| A helper slot on a local endpoint pinned to another provider | Not stale (W5); shows `[endpoint]` |
| Plugin row that inherits | Shows `follows <base>`; `i` is not offered; a pin writes the row's own values |
| Unknown built-in slot from a newer Hermes | Shown with its key as label; editable (the server validates the task name) |
| Fallback entry with inline `api_key` | Shown `[key set]`; the value never reaches the view, the diff, a log or a fixture; it is sent back unchanged on save (D5) |
| Route identity for markers | `route_identity`: provider and model trimmed and lower-cased; `base_url` trimmed, trailing `/` removed, lower-cased. Hermes also collapses provider aliases (M12); Talaria does not, so the markers are best-effort labels and never block an apply |
| Fallback entry equal to the main route | `same as main model` when provider and model match the main route (identity rule) and the entry has no `base_url` |
| Duplicate entry | `duplicate: Hermes skips it` on every entry, legacy rows included, whose identity matches an earlier entry in the order `fallback_providers` then `fallback_model` |
| Legacy `fallback_model` present | Shown read-only below the chain; a key cannot be removed through `PUT /api/config` (W10), so the hint names the `hermes fallback` command |
| String entry in `fallback_providers` | Split at the first `/` when it is at position 1 or later (`"openrouter/a/b"` is provider `openrouter`, model `a/b`); otherwise provider `""` and model the whole string, an incomplete row. Marked `(ignored by Hermes until saved)`; saving writes a mapping and adds the diff line |
| MoA never configured (M9) | The notice; the example preset is part of the first PUT and the review says so. It arrives `enabled: true` (W17) and is written as shown: the user switches it off with Space before saving to keep a `moa` model row from appearing (S3) |
| Deleting the only preset | Refused: `A profile keeps at least one preset.` (D4) |
| Deleting the default or active preset | Default moves to the first remaining preset; active is cleared (D4) |
| Preset name | Trimmed, non-empty, unique, at most 64 characters, no control characters; else `Choose another name` |
| Every reference disabled | Allowed by Hermes's validator (it checks completeness, not enabled); shown with `No reference is enabled.` |
| Main effort stored as a mapping | Read-only with `(set in config.yaml)`; `e` is not offered |
| Subagent direct endpoint set | Shown; choosing a provider route or inherit clears it in the same apply, with the three keys visible in the review |
| Subagent route with exactly one of provider and model set | `RoleRoute::Partial`; shown `Route: <provider>, model inherited` or `Route: <model>, provider inherited`; never produced by the picker; Enter (a new pick) or `i` replaces it and sends both keys |
| Subagent route and direct endpoint both set | Both rows shown; choosing a route or inherit clears the endpoint (D6); the endpoint is never edited here (`P4-02` owns endpoints) |
| Own-chain entry that is a string or incomplete | As in Fallbacks: split, `(ignored by Hermes until saved)`, the same diff line (M17); an own chain with no usable entry is labelled `Fallback: own chain (no usable entry, so Hermes ignores it)` |
| A raw value holding `${...}` (fallback entry key, `delegation.*`) | Shown as written (`[key set]` for a secret-named key); sent back as the same text unless the user changed that key (4.4a, M16) |
| Not connected | The single not-connected line of 4.1; Ctrl+R retries |
| Another client changed what this apply writes | `Conflict` (4.4); a change to other keys only refreshes the shown values |
| Gateway restarted mid-session | The REST calls mint fresh tickets per request; the next load rebuilds the client from the current `api_origin`; a socket drop affects only the picker's catalogue |
| Terminal narrower than 80 columns | Hints collapse first, then the hint column; the key footer wraps to two lines; no row overflows |
