## 1. What this unit is, and what it is not

Five small client-side features that Claude Code users reach for many times a day, none of which needs a Hermes method:

| Feature | Default key or trigger | Claude Code reference (research report u12) |
|---|---|---|
| Edit the draft in an external editor | Ctrl+G (also Alt+G) | `int.edit-external`: "Opens the prompt in the default text editor." |
| Search earlier prompts | Ctrl+R | `in.history-search`: "Searches prompt history." `in.history`: "History is stored per working directory." |
| Suspend to the shell | Ctrl+Z, then `fg` | `in.suspend`: "On Unix, Ctrl+Z suspends Claude Code to the shell; run fg to resume." |
| Bell and desktop notification | needs you, done, failed | `int.bell`: "play a sound or send a notification when Claude finishes" |
| Herdr pane state | working, blocked, idle | Herdr's own integration contract (section 2.2) |

The parity checklist row "External editor (Ctrl+G), history search (Ctrl+R), keybindings, suspend (Ctrl+Z)" and the row "Bell and notifications when done or waiting" are both marked "Client" and phase 2 ([../04-prior-art.md](../04-prior-art.md#claude-code-parity-checklist)). The roadmap row lists no Hermes calls ([../07-roadmap-and-work-units.md](../07-roadmap-and-work-units.md#phase-2--coding-parity)). The fleet-wide versions (alerts for background sessions, status-line counters) belong to unit P3-06; this unit covers the foreground session only and builds the pieces P3-06 reuses. Only the live test (11.5) calls one Hermes method, `config.get`, to decide whether its approval part can run.

Claude Code's history search cycles three scopes (this session, this project, all projects) with Ctrl+S (research report u12). Talaria offers two scopes on Tab, because Ctrl+S may never reach Talaria (terminal flow control; unit P1-08 REQ-1 keeps it unbound) and the "this session" scope is already what Up and Down browse in the composer.

Not in this unit: vim mode (phase 6), focus tracking, a keybinding editor screen, Warp's OSC 777 protocol, reading Hermes's own bell settings, a slash command to test notifications, headless mode (P2-14), persisting Herdr's sequence number.

### 1.1 Crate placement (why the pieces live where they do)

Unit P0-02 REQ-13 forbids `talaria-app` from reaching `ratatui` or `crossterm`, over normal edges, transitively; `talaria-tui` depends on both, so `talaria-app` can never depend on `talaria-tui`. Unit P1-08 makes `talaria-app` a development dependency of `talaria-tui` (its demo and tests), never the reverse. Consequences:

- `HistoryEntry` and `Scope` live in `crates/talaria-core/src/prompt_history.rs`, which both crates already depend on. `talaria-app`'s `PromptHistory::snapshot` returns `Arc<[talaria_core::prompt_history::HistoryEntry]>`; `talaria-tui`'s search box takes the same slice.
- `talaria-app` decides (it owns the tracker call, the editor and history logic, the Herdr reporter and the suspend system calls) and emits effects. The code that already holds `InlineTerminal` and `TerminalGuard` executes the terminal effects. In unit P1-12's plan that is `crates/talaria-cli/src/run.rs` (P1-12 specification, section 4: `run.rs` builds the services; `talaria-cli` depends on both `talaria-app` and `talaria-tui`). Re-verify against P1-12's merged code; the issue's stop condition covers a different shape.
- The demo program is `crates/talaria-tui/examples/comforts_demo.rs`, beside P1-08's `composer_demo.rs`, using `talaria-app` as the development dependency P1-08 already declared. Its pseudo-terminal tests are in `crates/talaria-tui/tests/comforts_pty.rs`.
- Escape custody: P1-06's test 28 scans `crates/talaria-tui/src/**/*.rs` except `terminal.rs` for escape bytes and `queue!`, `execute!`, `crossterm::cursor`, `crossterm::terminal`; P0-04's boundary scan reads every `.rs` file under `crates/` (tests and examples included) and allows `enable_raw_mode`, `disable_raw_mode`, `execute!`, `queue!` and the alternate-screen commands only in `terminal.rs` (P1-06 specification, "Escape custody scope"). So `history_search.rs` and `comfort_route.rs` contain no escape byte, and every mode change, raw mode included, is a method in `terminal.rs`. Files under `tests/` and `examples/` may write escape bytes as ordinary literals. P1-08's composer custody scan also reads `src/keys.rs` for `unsafe`, `tokio` and the crate names `talaria_core`, `talaria_app` and others: the three new `Action` variants add none of them.

## 3. Keys and routing

Three actions join unit P1-08's `Action` enum in `crates/talaria-tui/src/keys.rs`, all in `KeyContext::Composer` (the only context P1-08 defines; P1-08 checks conflicts per context):

| Action | Config name | Default chords | Where it works |
|---|---|---|---|
| `OpenEditor` | `open_editor` | `ctrl+g`, `alt+g` | Composer focused, no card, no overlay, no search |
| `HistorySearch` | `history_search` | `ctrl+r` | Composer focused, no card, no overlay |
| `Suspend` | `suspend` | `ctrl+z` | Everywhere: composer, card, search, queue selection, overlay |

Rules carried from P1-08: no default on F1, F2, Ctrl+B or Ctrl+S; no chord belongs to two actions; `[keys]` can rebind or unbind (empty list). Check against P1-08's 20 defaults: none uses `ctrl+g`, `alt+g`, `ctrl+r` or `ctrl+z`. Because `Suspend` must work in every state, test 34 also checks that no action in any context (later units add contexts) has `ctrl+z` as a default.

Routing order after this unit (extending P1-08 REQ-14). The order is a pure function so it can be tested without a terminal:

```rust
// crates/talaria-tui/src/comfort_route.rs
pub enum Focus { Composer, Search, Card, QueueSelection, Overlay }
pub enum Route { Suspend, Search, Card, QueueSelection, Overlay, OpenEditor, HistorySearch, Composer }
pub fn route(action: Option<Action>, focus: Focus) -> Route;
```

1. `Some(Suspend)` gives `Route::Suspend` in every focus.
2. `Focus::Search` gives `Route::Search` (the search box takes every other key).
3. `Focus::Card` gives `Route::Card` (P1-09); `Focus::QueueSelection` gives `Route::QueueSelection` (P2-08, once merged); `Focus::Overlay` gives `Route::Overlay`.
4. `Focus::Composer` with `Some(OpenEditor)` or `Some(HistorySearch)` gives that route.
5. Anything else gives `Route::Composer`.

The key is resolved with `KeyMap::resolve` in `KeyContext::Composer` (the only context P1-08 defines) **whatever the focus**, before the composer or any other owner sees it, so `ComposerOutcome` does not change and `ctrl+z` becomes `Suspend` under a card, the search box, queue selection or an overlay too. The code that routes keys (P1-12's, wherever its merged code converts and dispatches `Key` values) calls `route` and acts on the result: `Route::Suspend`, `Route::OpenEditor` and `Route::HistorySearch` start this unit's features; every other route hands the **raw key** to its owner, which interprets it with its own rules (so `ctrl+g` under a card reaches the card as a key, not as `OpenEditor`). If a later unit adds a context with its own resolution, it must keep `ctrl+z` unbound there (test 34).

## 4. The external editor

### 4.1 Resolution (pure)

`resolve_editor(config: Option<&str>, env: &dyn Fn(&str) -> Option<String>, is_executable_on_path: &dyn Fn(&str) -> bool) -> Result<Vec<String>, EditorError>`

1. `[editor] command` from `~/.talaria/config.toml` when it is non-blank.
2. `$VISUAL` when non-blank.
3. `$EDITOR` when non-blank.
4. The first of `editor`, `nano`, `pico`, `vi`, `emacs` for which some `PATH` folder holds an executable file of that name (Hermes's chain and its executable check, H16). The result is the plain name, never a path.
5. `vi`.

Steps 1 to 3 are split with `shell_words::split` (R3): `code --wait` gives `["code", "--wait"]`; `'/opt/My Editor/bin/ed' -w` gives `["/opt/My Editor/bin/ed", "-w"]`. An unterminated quote is `EditorError::Parse(reason)` and gives notice E5. Hermes splits on whitespace only and uses `VISUAL ?? EDITOR`, so a blank but set `VISUAL` stops its search; Talaria skips blank values and respects quotes, which opens the same editor in every ordinary case. The production `is_executable_on_path` checks the execute permission bits (`std::os::unix::fs::PermissionsExt`, any of `0o111`) of a regular file in each `PATH` folder.

### 4.2 Hand-off sequence

```text
 1. snapshot = composer.text()
 2. file = private temporary file "talaria-prompt-XXXXXX.md" in the temporary folder (mode 0600),
    contents = snapshot, flushed.  Failure: notice E6; stop here (terminal never released).
 3. input.pause()                     # section 8.1; returns once the key thread stopped polling
 4. terminal.release()                # section 8.2 (bytes only)
 5. guard.leave_raw()                 # section 8.6
 6. started = now()
 7. status = run argv + [file path], stdin/stdout/stderr inherited, cwd = the session's folder,
    environment inherited unchanged; wait on a blocking thread (tokio spawn_blocking)
 8. guard.enter_raw()                 # raw mode back BEFORE any probe (T6)
 9. terminal.reacquire(&mut probe)    # section 8.3: resets, discard input, probe, place, write queued
10. input.resume()
11. apply the result table below; delete the file (always, also on error)
12. flush the waiting alert (section 7.4); full repaint of the live region
```

Step 9's production probe closure is: discard pending terminal input with `rustix::termios::tcflush(stdin, QueueSelector::IFlush)` (ignore an error), then P1-06's cursor probe with a 200 ms deadline (`probe_startup` in P1-06's plan; use the merged name). It runs inside `reacquire`, after the reset bytes are written and flushed, so the reply is read in raw mode from the main screen.

Signals while the terminal is released (T5, T8): before the first editor launch, register `signal_hook::flag::register` for `SIGINT` and `SIGQUIT` once for the life of the process (the flags are never read). Ctrl+C or Ctrl+\ pressed in a normal-mode editor then ends only the editor (it gets E2's signal form), while Talaria keeps running and restores the terminal. Accepted side effect: after the first Ctrl+G, an external `kill -INT` no longer ends Talaria; Talaria in raw mode never receives `SIGINT` from the keyboard, and `SIGTERM` and `SIGHUP` keep P1-12's handling. A Ctrl+Z pressed in a normal-mode editor (or an editor that stops its group itself, as vi does) stops Talaria too, because both are in the foreground group; the shell shows the job, `fg` resumes both, and Talaria simply keeps waiting for the editor. The `SIGCONT` watch (6.4) ignores continues while the terminal is released.

While the editor runs, the application keeps processing network events. The reducer updates state; commits and live frames are queued by `terminal.rs` and written once inside step 9. Herdr reports continue (they are subprocesses, not terminal writes).

### 4.3 Result table (`EditResult`)

| Case | `EditResult` | Draft after | Notice |
|---|---|---|---|
| Exit 0, raw text differs, cleaned text non-empty | `Loaded(cleaned)` | replaced with `Composer::load(cleaned)` (not sent) | none |
| Exit 0, raw text identical to the draft, editor ran ≥ 1 s | `Unchanged { hint: false }` | unchanged | none |
| Exit 0, raw text identical to the draft, editor returned in < 1 s | `Unchanged { hint: true }` | unchanged | E4 |
| Exit 0, raw text differs, cleaned text empty, draft was non-empty | `Cleared` | `Composer::clear()` | E7 |
| Exit 0, raw text differs, cleaned text empty, draft was empty (for example the editor added only a newline) | `Unchanged { hint: false }` | unchanged (still empty) | none |
| Exit non-zero | `Failed(E2 text)` | unchanged | E2 |
| Killed by a signal | `Failed(E2 signal text)` | unchanged | E2 (signal form) |
| Spawn failed (not found, not executable) | `Failed(E1 text)` | unchanged | E1 |
| File unreadable after exit, larger than 1 MiB, or not valid UTF-8 | `Failed(E3 text)` | unchanged | E3 |
| Temporary file could not be created | `Failed(E6 text)` | unchanged; editor not started; terminal never released | E6 |

"Identical" compares the file's raw bytes, decoded as UTF-8, with the draft exactly as written to the file, **before** cleaning. So a draft with trailing spaces that the editor did not touch is `Unchanged` (E4 still appears on a quick return), never `Loaded`. Test 23 covers an empty draft left empty and a draft `x  ` left as is.

An empty result does not keep the old draft anywhere: P1-08's composer has no public way to add a history entry after construction (`load` and `clear` add none, P1-08 REQ-14), and this unit must not touch `src/composer/`. Notice E7 tells the person what happened.

Cleaning (the same rules as P1-08 REQ-10 for bracketed pastes, applied in this order): `\r\n` and `\r` become `\n`; every control character except `\n` and `\t` is removed (ESC, DEL, C1 U+0080 to U+009F); then trailing whitespace and trailing newlines are removed (an editor's final newline must not become a blank line). Leading whitespace is kept. Worked examples (test 21): `edited\x1b[31m\r\n` gives `edited[31m`; `a\r\nb` gives `a\nb`; `x\n\n` gives `x`.

The editor receives `Composer::text()` exactly as typed. When unit P2-04 has merged, the draft may hold its labels (`[Pasted text #1 +40 lines]`, `[Image #2]`); they travel to the editor as plain text and P2-04's rules decide what an edited, removed or retyped label means (its REQ-17 and test 10). Unit P2-08's queued prompts are not part of the draft and are untouched.

### 4.4 Edge cases

- **The editor is a graphical editor without a wait flag** (`code` without `--wait`): it returns at once, the file is unchanged, E4 explains. The temporary file is deleted after reading, so a late save is lost; E4 says why.
- **A turn streams while the editor is open:** nothing is drawn; the reply's finished blocks are committed in order after the editor closes.
- **An approval arrives while the editor is open:** the card appears after the editor closes; the alert is written then, once; the Herdr state switches to `blocked` at once.
- **Ctrl+G on an empty draft:** opens an empty file; that is fine.
- **Very large draft (for example a 10,000 character paste):** written as is; no limit on the way out, 1 MiB on the way back.
- **The editor leaves the terminal in a strange mode** (alternate screen, mouse reporting): `reacquire` leaves the alternate screen (`ESC [ ? 1049 l`) and turns mouse reporting off (`ESC [ ? 1000 l`, `ESC [ ? 1002 l`, `ESC [ ? 1003 l`, `ESC [ ? 1006 l`) before probing, as Codex does after an external program.
- **Ctrl+C or Ctrl+Z inside the editor:** section 4.2, "Signals while the terminal is released". Test 48 covers Ctrl+C.

### 4.5 Error-reason mapping for E1, E3 and E6

`<reason>` is never the standard library's display text for these kinds (for example the `NotFound` kind displays as "entity not found"). Map explicitly: `NotFound` gives `not found`; `PermissionDenied` gives `permission denied`; any other kind gives the kind's display text. `<argv0>` is the command as configured, never a resolved absolute path. No reason ever contains a path.

## 5. Prompt history

### 5.1 File

- Location: `~/.talaria/history.jsonl` (the folder P1-08's config lives in; created with mode 0700 if missing; the file with mode 0600).
- Format: one JSON object per line, UTF-8, `\n` line ends:

```json
{"v":1,"ts":1792659315,"folder":"<workspace key>","text":"fix the failing test"}
```

  `v` is the format version (1). `ts` is Unix seconds. `folder` is the workspace key unit P1-12 computes with `workspace_key` (the git top level, else the folder), as a string. `text` is the prompt exactly as submitted (P1-08 REQ-8: trailing whitespace removed, leading kept).
- Appending: on every `ComposerOutcome::Submit(text)` the application appends one line with a single `write` on a file opened in append mode, so two Talaria processes appending at once do not interleave inside a line on a local filesystem.
- Not saved to the file: text that starts with a space (the shell's "ignore space" habit); text longer than 100,000 characters. Both still join this run's in-memory views (`snapshot`, so Ctrl+R finds them until exit); test 14 asserts this. Masked answers (`sudo`, `secret`, vault codes) never pass through the composer, so they can never reach this file.
- `[history] save = false`: the file is neither read nor written. Ctrl+R then searches this run's submits only.
- A failed write gives notice H1 once per run; history then works in memory only.

### 5.2 Compaction

- When: after the first frame, on a blocking task (`tokio::task::spawn_blocking`), never before the first frame. Trigger: the file's size from metadata is over 4 MiB (no line count is taken at start).
- What: stream the file once, keep the newest valid lines such that at most 5,000 lines and at most 1 MiB in total remain, write them to a temporary file in the same folder (mode 0600), flush, and rename it over the original (atomic on one filesystem). After compaction the whole file fits in what the next start reads.
- A line appended by another process during that window may be lost; this is accepted and documented in `docs/configuration.md`.
- A failure (read, write or rename) gives notice H2 once and leaves the original file in place; the temporary file is removed.
- `PromptHistory::compact(&self) -> std::io::Result<bool>` returns whether it compacted, so test 16 can call it directly.

### 5.3 Loading

- At start, before the composer is built (so `Composer::with_history` can take the entries; P1-08 offers no later setter): read at most the last 1 MiB of the file (seek to `len - 1 MiB` and drop the first partial line). This bounds the start-up cost; the launch budget (first frame ≤ 100 ms) is checked by unit P1-11's bench job.
- Skip lines that are not valid JSON, have the wrong version, or lack `text`; never fail start-up because of the file.
- Two views: **all** (every loaded entry, oldest first) and **this folder** (entries whose `folder` equals the current workspace key). The composer is seeded with the newest 1,000 entries of **this folder** among the loaded ones, with consecutive duplicates removed (P1-08 REQ-7 rules).
- New submits during the run are appended to both views.

### 5.4 Search box (Ctrl+R)

Shared types (pure, `crates/talaria-core/src/prompt_history.rs`, section 1.1):

```rust
pub struct HistoryEntry { pub text: String, pub ts: i64, pub this_folder: bool }
pub enum Scope { ThisFolder, AllFolders }
```

View state (`crates/talaria-tui/src/history_search.rs`): `HistorySearch` holds the entries, a private cache of each entry's Unicode lowercase form (built once in `open`), the query, the scope, the selection, the saved draft and the chords bound to `history_search`.

| Input | Effect |
|---|---|
| Ctrl+R (from the composer) | Open. `saved_draft = composer.text()`, `query = ""`, scope `ThisFolder`, `selected = 0`. |
| Printable character, paste | Append to the query (paste: first line only, controls removed); `selected = 0`. |
| Backspace | Remove the last grapheme from the query; on an empty query, nothing. |
| Up, or a `history_search` chord again | Select the next older match (stop at the oldest). |
| Down | Select the next newer match (stop at the newest). |
| Tab | Toggle scope (this folder, all folders); `selected = 0`. |
| Enter | With a match: `Accept(text)`; the app calls `composer.load(text)`; nothing is sent. With no match: nothing. |
| Esc, Ctrl+C | `Cancel`; the composer shows `saved_draft` exactly as before (text and caret). |
| Ctrl+Z | Never reaches the box: `route` sends it to suspend first; the box is still open after `fg`. |
| Anything else | Ignored. |

Matching: case-insensitive substring (Unicode lowercase of both sides, the entries' forms from the cache), newest first, each distinct text shown once (at its newest position). An empty query lists the newest entries.

Drawing (a `LiveSection` that replaces the composer while open):

```text
╭ search history · this folder · tab: all folders ─────────────────────────╮
│ › test▏                                                                   │
│ ▸ fix the failing test                                            2h ago │
│   run the tests and summarise failures (+3 lines)                 1d ago │
│   add a test for average()                                        3d ago │
╰ enter: put in composer · esc: cancel ─────────────────────────────────────╯
```

- At most 5 match rows; fewer when the screen is short (the live region cap from P1-06 applies).
- A multi-line entry shows its first line and ` (+N lines)`.
- The matched part is bold; the selected row is reversed; ages are `now`, `Nm`, `Nh`, `Nd`, `Nw` ago.
- Every row passes through unit P1-06's `sanitize`; rows are cut with `…` at the width.
- Empty states: no history at all: one dim row `No prompt history yet.`; no match: `No earlier prompt matches "<query>".` (query cut at 30 characters); the scope label stays visible so the person can press Tab.
- Below 20 columns: no border, the query row and one match row.

## 6. Suspend and resume

### 6.1 Guard (`job_control_available() -> bool`)

Unix only, with the safe `rustix` functions of R1:

- `rustix::process::getpgrp()` equals `rustix::termios::tcgetpgrp(stdin)`, and
- `getpgrp()` is not `rustix::process::getsid(None)`; otherwise Talaria is the session leader and nobody can resume it (for example `exec talaria` in a shell, or Talaria as a pane's direct command).

If either check fails (or a call errors): notice S1 and do nothing else. On a non-Unix build: notice S1's non-Unix form.

### 6.2 Sequence

```text
 1. input.pause()
 2. terminal.release()                     # leaves an open overlay's alternate screen too
 3. guard.leave_raw()
 4. expected.store(true); continued.store(false)   # shared Arc<AtomicBool> flags (6.4)
 5. suspend_process(&continued):
      kill_current_process_group(Signal::TSTP)     # stops the whole process group, as Codex does
      ... process stopped; the shell prints its job line; the person runs fg ...
      wait_for_continue(&continued, started_at_kill, &now, 1 s):
        loop { if continued is set -> Resumed; if now() - start >= 1 s -> NotStopped; sleep 1 ms }
        (the flag is read BEFORE the deadline in every pass, so a resume after any pause is Resumed)
 6. expected.store(false)
 7. guard.enter_raw()                      # before any probe (T6)
 8. terminal.reacquire(&mut probe)          # re-enters the overlay if one was open
 9. input.resume()
10. re-send the current Herdr state with a new seq (section 7.5)
11. write the waiting alert; full repaint (live region, or the overlay through its owner)
12. NotStopped: notice S2
```

The wait in step 5 starts right after the kill: a process that was stopped does not run until `fg`, so the first check after `fg` finds the flag set at once. Because the flag is checked before the deadline, a resume after 10 seconds (UAT-4) or an hour is `Resumed`, never S2; checking the deadline first would show a false S2 after every long pause (test 55 drives `wait_for_continue` with a fake clock 10 s past the kill). A process whose stop was ignored finds it unset for 1 second and reports `NotStopped`, so the terminal is never left released. The `kill` with the current process group targets every process in it, so child processes (a running status-line command) stop and resume with Talaria; stopping only the calling process would leave them running.

### 6.3 What keeps running

- **The session keeps running in the Hermes gateway.** Talaria holds no agent state (architecture principle 1). A turn started before Ctrl+Z goes on.
- **The connection:** while stopped Talaria answers no heartbeat. After `fg`, unit P1-03's liveness logic decides: if its deadline passed it reconnects and replays from the last sequence number (or resumes from a snapshot on a replay gap). This unit adds no connection code. How the gateway treats a silent client meanwhile is **unverified** at v0.22.4 and does not matter for correctness, because replay covers it.
- **Approvals:** an approval left unanswered for `approvals.timeout` (300 seconds by default, H10) is resolved by Hermes; its `approval.settled` event arrives at the gateway's next pending-prompt snapshot (H7), possibly at the end of the turn, and the card disappears (P1-09). Until then the pane stays `blocked` while the agent may keep working: the pane mirrors the card (issue decision 8), and test 53 pins that a turn end with a need open stays `blocked`. Verify at the pinned commit when the event follows a timed-out approval.
- **Alerts for things that happened while stopped** fire after `fg` through the normal rules. A gap recovery's snapshot is not a launch snapshot, so a need it brings is not `restored` (7.1) and alerts once.
- **Herdr** keeps showing the last reported state while Talaria is stopped (D10: the agent keeps its identity); Talaria re-sends the state after `fg`.

### 6.4 A continue Talaria did not expect (`spawn_sigcont_watch`)

`kill -STOP` cannot be caught. `spawn_sigcont_watch(expected: Arc<AtomicBool>, released: Arc<AtomicBool>, continued: Arc<AtomicBool>, on_unexpected: impl Fn() + Send + 'static)` registers `SIGCONT` twice, both safe (R2): `signal_hook::flag::register` on `continued` (read by `wait_for_continue`), and a `signal_hook::iterator::Signals` set whose `forever()` iterator a dedicated thread blocks on. The thread does no polling and no periodic wake-up (issue REQ-17). On each delivery: if `expected` or `released` is set it does nothing (the flag stays for `wait_for_continue`); otherwise it clears `continued` and calls `on_unexpected`, which sends an application message. A delivery the thread reads only after `expected` was cleared again costs one extra in-place repaint, which is harmless. The application then calls `reassert_modes` (raw mode, bracketed paste, keyboard flags when supported, cursor hidden, mouse reporting off) and forces a full repaint of the live region in place, without moving the viewport and without probing. External `SIGTSTP` (from `kill -TSTP`) keeps its default action and is not handled (non-goal; a terminal in raw mode never sends it).

## 7. Attention

### 7.1 The tracker (pure, `crates/talaria-core/src/attention.rs`)

Inputs (`Activity`), fed for the **foreground session only**, by `activities_for` (7.6):

| Activity | Fed when |
|---|---|
| `TurnStarted { at }` | P1-05's turn state moves into running (from `message.start`, including an automation turn that starts without a submit (H22), or a turn already running in the launch snapshot) |
| `TurnEnded { outcome, at }` | P1-05's turn state moves from running to finished; `outcome` is P1-05's reduced outcome (Completed, Failed, Interrupted; H3) |
| `NeedOpened { key, summary, restored, at }` | an approval or clarification appears in `SessionState::open_prompts` (P1-05), or a masked request appears in `PromptService::masked_requests` (P1-09, `MaskedRequestInfo { id, kind: MaskedKind, .. }`); `restored = true` only when it came from the launch snapshot of `-c` or `--resume` |
| `NeedClosed { key }` | a prompt leaves `open_prompts` (P1-05 removes it on `approval.settled` or `clarify.settled` only: answered here or elsewhere, timed out, or denied before an interrupt; H7, H20, H21), or a masked id leaves `masked_requests` for any reason (answered or refused here, `request.cancel` with any reason, orphaned when a connection is replaced; H9) |
| `SessionChanged { session_id, label }` | the foreground session changed, or its title became known (`session.title`, H13); `label` is the title, else the last component of the session's folder, else `session` |

`NeedKey` is `Prompt(PromptKey)` (P1-05's key: session id, prompt id, execution generation) or `Masked(String)` (P1-09's `MaskedRequestInfo::id`).

Rules:

- Derived pane state: `Blocked` when at least one need is open; else `Working` when a turn is running; else `Idle`.
- `TurnEnded` with no running turn changes nothing and alerts nothing (a repeated `message.complete` only merges usage in P1-05; a replay cannot ring twice).
- `TurnEnded` while a need is open ends the turn (and may alert `done` or `failed` by 7.2) but the pane stays `Blocked`, so `pane` is `None`; the later `NeedClosed` gives `Idle` (test 53).
- `SessionChanged` with a new `session_id` clears all open needs and the running turn (pane `Idle` unless the new session's activities follow) and keeps the alerted-key memory (keys contain the session id). With the same id it only updates the label.
- Outputs (`AttentionOutput { alert: Option<Alert>, pane: Option<PaneReport> }`): `pane` is `Some` only when the derived state or its message changed. `pane()` returns the current report for re-sending after `fg`.

### 7.2 Alert rules

| Situation | Alert kind | Fires when |
|---|---|---|
| A need opens with `restored = false` and its key is not in the alerted-key memory | `NeedsYou` | at once |
| A need opens with `restored = true` | none | never (the person just opened Talaria and can see it) |
| Turn ends Completed, duration ≥ `done_after_seconds` | `Done` | at once |
| Turn ends Completed, duration shorter | none | |
| Turn ends Failed | `Failed` | at once, whatever the duration |
| Turn ends Interrupted | none | the person caused it |

- Duration is measured from the `at` of the `TurnStarted` the tracker saw, which for a turn already running at launch is the moment Talaria first saw it. A turn restored that way may therefore ring `done`; that is intended (the person is waiting for it).
- Channels: the kind must be listed in `[notifications] bell` for a BEL and in `[notifications] desktop` for an OSC 9 notification. A kind in neither list produces no alert.
- Urgency: `NeedsYou` is more urgent than `Failed`, which is more urgent than `Done`.
- Rate limit: if the previous **emitted** alert was emitted less than 2 seconds earlier, a new alert is emitted only when it is more urgent than that previous alert; otherwise it is dropped (the pane state still updates). A dropped alert does not reset the 2 second window. So a second `NeedsYou` within 2 seconds of a `NeedsYou` **is dropped** (deliberately: the person was alerted a moment ago and the pane already reads `blocked`); a `Done` never swallows a following `NeedsYou`.
- A dropped `NeedsYou` still marks its key as alerted, so the same need reopened later (a replay or resync) does not ring (test 7).
- Memory: alerted need keys are remembered in memory only, the newest 256; a key older than those may alert again. Nothing is persisted across runs.

Alert text (`Alert.text`, before the `Talaria: ` prefix is added):

| Kind | Text |
|---|---|
| NeedsYou, approval | `needs you: approval: <first line of command, or of description when command is empty or blank>`; when both are blank: `needs you: approval` (no colon after it) |
| NeedsYou, clarification | `needs you: question: <first line of question>` |
| NeedsYou, `sudo` | `needs you: password for sudo` |
| NeedsYou, `secret` | `needs you: a secret` |
| NeedsYou, `vault.code` | `needs you: a vault code` |
| NeedsYou, `vault.unlock_prompt` | `needs you: a password manager unlock` |
| Done | `done: <label>` |
| Failed | `failed: <label>` |

Cut rule (one rule for all three cuts in this unit): a cut "to N characters" counts Unicode scalar values of the part being cut, and when the part is longer than N it becomes its first N − 1 characters followed by `…`, so the result is exactly N characters. The summary part (after `approval: `, `question: `, `done: ` or `failed: `) is cut to 60. The OSC 9 body after `Talaria: ` is cut to 120 (7.3). Herdr's `--message` is cut to 80 (7.5).

### 7.3 Alert bytes (`crates/talaria-tui/src/terminal.rs`, pure `alert_bytes`)

- BEL: `0x07`.
- OSC 9: `ESC ] 9 ; Talaria: <body> BEL`. The body is the alert text with every C0 control, DEL, C1 control (U+0080 to U+009F) and the zero-width and bidirectional characters P1-08 REQ-12 drops (zero-width space U+200B to U+200F, U+202A to U+202E, U+2066 to U+2069, a leading joiner) removed, then cut to 120 characters (7.2). Test 41: a 200-character body gives 119 characters and `…`.
- Inside tmux (environment variable `TMUX` non-empty): the OSC 9 is wrapped as `ESC P tmux ; ` + payload with each `ESC` doubled + `ESC \`. BEL is written bare. (T4, unverified.)
- Order: BEL first, then OSC 9 (as Hermes does, H14).
- Never wrapped in synchronized output; written between frames.

### 7.4 When alerts are written

- Only while the terminal is held (not released for the editor or a suspend). An alert produced while released is kept, only one: a new one replaces the kept one when it is at least as urgent; it is written right after `reacquire`.
- Never in headless mode (`talaria -p`, unit P2-14), which has no terminal UI. Headless mode also never reports to Herdr and never calls `release-agent`: this unit wires the tracker, alerts and `HerdrReporter` into the interactive path only. If P2-14's author wants Herdr state for scripts, that is P2-14's change.

### 7.5 Herdr pane state (`crates/talaria-app/src/comforts/herdr.rs`)

Active when `HERDR_ENV=1`, `HERDR_PANE_ID` and `HERDR_BIN_PATH` are non-empty, and `[herdr] report_state` is true.

Report command (argument list, no shell):

```text
<HERDR_BIN_PATH> pane report-agent --source talaria --agent talaria --state <idle|working|blocked>
    --seq <n> [--message <text>] [--agent-session-id <session id>] <HERDR_PANE_ID>
    [-- talaria --resume <session id> [--profile <profile>]]
```

- First report: `idle`, sent once right after the first frame (so Herdr shows the agent before any submit; UAT-5).
- `--message` only for `blocked`: the need's text without the `needs you: ` prefix, controls removed, cut to 80 characters (7.2).
- `--agent-session-id` and the resume arguments only when the foreground session id is known. The resume command's first word is always the plain name `talaria` (D7 forbids a path). `--profile <profile>` is left out for the `default` profile, as P1-12's exit hint does.
- The resume arguments are omitted when any argument would contain an apostrophe or a control character, or exceed D7's limits.
- `seq` = the larger of (last seq + 1) and the injected clock's current Unix time in milliseconds. Within one process it always rises. Across restarts it rises as long as the wall clock does not step back between the two processes; the last value is not persisted (non-goal). `from_env` takes the clock as `now_ms: fn() -> u64` so test 27 can drive it.
- Coalescing: at most one report process at a time. A newer state replaces any waiting one; when the running report finishes, only the newest waiting state is sent (D8).
- Each process has standard input, output and error set to null and a 2 second limit; on timeout it is killed. Any failure (not found, non-zero exit, timeout) produces notice R1 once per run; reporting continues silently after that.
- Re-send the current state (`AttentionTracker::pane`) after `fg` (6.2 step 10) and when the foreground session changes (with the new session id). The session id first becoming known (for example when `session.create` answers after the first frame of a fresh start) counts as a session change, so a report carrying `--agent-session-id` and the resume arguments goes out even when the pane state did not change (the live test asserts such a report).
- On exit (`/quit`, the composer's exit request, end of input), after the terminal is restored: run `pane release-agent --source talaria --agent talaria --seq <n> <HERDR_PANE_ID>` and wait at most 500 ms. On a crash, Herdr's safety net applies (D9).
- The state does not change while the connection is down; the last reported state stands.

### 7.6 The mapping (`activities_for`, `crates/talaria-app/src/comforts/mod.rs`)

```rust
pub fn activities_for(
    before: &talaria_core::session::SessionState,      // P1-05's reduced state before the event
    after: &talaria_core::session::SessionState,       // and after it
    masked_before: &[MaskedRequestInfo],               // P1-09's open masked requests before
    masked_after: &[MaskedRequestInfo],                // and after
    restored: bool,                                    // true only while building the launch snapshot
    at: std::time::Instant,
) -> Vec<Activity>;
```

It compares the two reduced states (turn state, `open_prompts`) and the two masked lists, so it never re-reads a Hermes payload: the reducer in `talaria-core` stays the only interpreter of events (architecture, layers). It maps P1-05's reduced outcome `Completed`, `Failed`, `Interrupted` to this unit's `TurnOutcome::Complete`, `Failed`, `Interrupted`.

Call points. The application calls it after **every message it handles that can change the reduced state or P1-09's masked list**, with the state and list from just before and just after that message:

- each event its loop accepts (P1-12 REQ-13 already drops replayed events at or below the snapshot cursor);
- each server request given to `PromptService::on_server_request`, each `request.cancel` given to `on_request_cancel`, and each `on_connection_replaced`;
- each local answer or refusal of a card or masked prompt (`answer_masked`, a refusal, `execute` of an answer effect). Here the session state does not change, so the same `SessionState` is passed as `before` and `after`; only the masked lists differ. Without this call point a sudo prompt answered here leaves the pane `blocked` until some later event (test 54 drives it through `app::update`).

And once with `restored = true` after the launch snapshot of `-c` or `--resume`. Gap recovery snapshots use `restored = false`. Summaries for `NeedOpened` come from the prompt cell (command, description, question) or the masked kind. Order within one call: `NeedClosed`, then `TurnEnded`, then `TurnStarted`, then `NeedOpened`. Module paths in the signature are P1-05's and P1-09's names as planned; use the merged paths.

Replay tests cannot store an `Instant`, so they build one from a base plus 10 ms per frame (11.1).

### 7.7 State diagram

                 TurnStarted                    NeedOpened
        Idle ─────────────────► Working ─────────────────────► Blocked
         ▲  ◄─────────────────    │   ◄────────────────────────  │

## 8. Terminal additions (`crates/talaria-tui/src/terminal.rs`)

Unit P1-06 made `terminal.rs` the only writer of escape sequences and the only place that changes terminal modes (its REQ-17, enforced by its test 28 and P0-04's boundary scan). `InlineTerminal` itself never touches raw mode (P1-06 specification: "`InlineTerminal` alone never touches raw mode, so every test runs without a terminal"); raw mode belongs to `TerminalGuard`. This unit adds to both and moves or renames nothing.

### 8.1 Pausing the key thread

P1-06's key thread polls crossterm with a 25 ms timeout (P1-06 specification, section 3, step 6). Add to `InputThread`:

```rust
pub fn pause(&self) -> std::io::Result<()>;   // returns once the thread has stopped polling; at most 100 ms
pub fn resume(&self);
```

While paused the thread does not call crossterm's `poll` or `read`, so a child program (the editor) and the cursor probe get every byte. This is the Rust form of H17.

### 8.2 `InlineTerminal::release(&mut self) -> io::Result<()>` (bytes only)

1. If an overlay is open, leave the alternate screen and remember it.
2. Clear the live region and reset the scroll region (`ESC [ r`).
3. Move the cursor to column 0 of the viewport's top row, so the child's or the shell's output starts where the live region was and no committed line is overwritten.
4. Disable bracketed paste, pop the keyboard enhancement flags if they were pushed, reset attributes, show the cursor.
5. Mark the terminal released: `commit_lines` queues rows, `draw_live` and `draw_overlay` draw nothing, `alert` keeps one alert (7.4).

### 8.3 `InlineTerminal::reacquire(&mut self, probe: &mut dyn FnMut() -> io::Result<ProbeReply>) -> io::Result<()>`

The caller has already called `TerminalGuard::enter_raw`.

1. Leave any alternate screen a child left behind and turn mouse reporting off (4.4); flush.
2. Call `probe()` (production: discard pending input, then P1-06's probe with 200 ms; tests: a closure returning a fixed `ProbeReply` that records that it ran after step 1's bytes).
3. Enable bracketed paste; push the keyboard flags if the start-up probe found support.
4. Place the viewport at the probed cursor with P1-06's placement rule (its REQ-3: write `\r\n` if the column is not 0; when the cursor is unknown, the bottom of the screen). After `fg` the shell has printed its job line, so the old row is wrong; this is why the probe is repeated (T7).
5. Re-enter the overlay if one was open.
6. Write the queued rows once, in order; forget the last frame so the next `draw_live` repaints in full.
7. Write the kept alert, if any; clear the released flag.

A probe error counts as "cursor unknown" (bottom of the screen); it is not returned as an error.

### 8.4 `InlineTerminal::alert(&mut self, bytes: Vec<u8>, urgency: u8) -> io::Result<()>` and `pub fn alert_bytes(text: &str, bell: bool, desktop: bool, in_tmux: bool) -> Vec<u8>`

As section 7.3. `alert` writes nothing while released and keeps the bytes under 7.4's rule (`urgency`: 2 needs you, 1 failed, 0 done).

### 8.5 `InlineTerminal::reassert_modes(&mut self) -> io::Result<()>`

For section 6.4: bracketed paste, keyboard flags, cursor hidden, mouse off, then a full repaint flag; the viewport does not move. The caller also calls `TerminalGuard::enter_raw`.

### 8.6 `TerminalGuard::leave_raw(&self) -> io::Result<()>` and `TerminalGuard::enter_raw(&self) -> io::Result<()>`

Leave and re-enter raw mode with crossterm's raw-mode functions (allowed only in `terminal.rs`, P0-04). The guard's `Drop` and the panic hook still leave raw mode once at exit; leaving it twice is harmless (P1-06 specification, section 3.3).

### 8.7 `InlineTerminal::is_released(&self) -> bool`

The flag of 8.2 step 5; the application also mirrors it into the `released` flag of 6.4.

## 12. Design reasoning and rejected alternatives

- **The edited text goes into the composer, not straight to the agent.** Hermes's terminal UI submits it at once (H16). Claude Code returns it to the prompt. Loading is safer (the person sees what will be sent and can still change it) and matches the parity target. The operator may reverse this (section 14, question Q1).
- **Ctrl+R searches prompts; Ctrl+Z suspends.** Hermes's terminal UI uses these keys for other things (H18). Talaria's parity target is Claude Code, and all keys are rebindable.
- **Talaria keeps its own history file** rather than reading Hermes's `.hermes_history`: that file belongs to another program, lives under the Hermes home (which may be on another machine when the gateway is remote), and the repository rule is to prefer transport interfaces over Hermes internals.
- **Talaria has its own `[notifications]` table** rather than reading Hermes's `display.bell_on_complete` and `display.bell_on_prompt` with `config.get`: those are Hermes's classic-CLI preferences, default off, and configuration screens are phase 4. The operator may prefer one setting for both (Q2).
- **No focus tracking.** Telling "the person is looking at this pane" apart would need focus reports (`ESC [ ? 1004 h`), which P1-06 does not enable and multiplexers forward unevenly. The 20 second threshold and the rate limit carry the load. Revisit if the operator finds alerts noisy.
- **Urgency instead of a flat rate limit.** A flat "one alert per 2 seconds" dropped an approval that followed a `done` by one second, which is the one alert that matters. The urgency rule keeps the burst protection and never lets a less urgent alert hide a needs-you. It does drop a second needs-you within 2 seconds of the first, on purpose: the person was just alerted and the pane already reads `blocked`.
- **The pane mirrors the card, even after a Hermes timeout.** A timed-out approval keeps its card until `approval.settled` (H7), and the pane stays `blocked` with it. A local timer from `timeout_s` would make the pane and the screen disagree, and the settled event arrives at the latest at the turn's end.
- **A blocking signal wait, not a poll.** The `SIGCONT` watch blocks on `signal_hook::iterator::Signals` so the process has no new periodic wake-up (REQ-17).
- **Raw mode stays on `TerminalGuard`.** P1-06 keeps `InlineTerminal` free of raw-mode calls so its tests need no terminal. This unit keeps that split: `release`, `reacquire` and `reassert_modes` write bytes only, and `leave_raw` and `enter_raw` live on the guard. The probe is a closure so tests can check it runs after the reset bytes.
- **Compaction by size after the first frame.** Counting lines needs the whole file, and a file of large prompts can be very big; a size check from metadata is free, and doing the work on a blocking task after the first frame keeps the launch budget.
- **An empty editor result clears without keeping the old draft.** P1-08's composer has no public way to add a history entry after construction, and this unit must not edit it. Notice E7 makes the clear visible. If the operator wants Up to bring the old draft back, P1-08 needs a `push_history` method first.
- **`SIGINT` caught while released, not a separate process group for the editor.** Giving the editor its own group would need `tcsetpgrp` and `SIGTTOU` handling, more system calls for no benefit; catching `SIGINT` is how POSIX `system()` keeps its caller alive (T8).
- **Herdr reporting through the command line, not the socket API.** The command is documented, stable and needs no client library; the socket API's request names exist (`pane.report_agent`, `pane.report_agent_session`, `pane.release_agent`) but their JSON was not documented on the page read.
- **No persisted `seq`.** Persisting would add a file write per report; Herdr's own guide accepts a timestamp. A backward clock step across a restart is rare and only delays the sidebar until the clock passes the old value or Talaria's state changes again.
- **No `unknown` Herdr state** while the connection is down: the session is still running in the gateway, and flapping the sidebar on every reconnect helps nobody.
- **Warp's OSC 777** (H14) is left out: it needs version sniffing of Warp builds, and no parity row asks for it.

## 14. Open questions for the operator

None of these blocks the build; the defaults below are what the issue specifies.

- **Q1. Ctrl+G result.** Default: load into the composer, unsent (Claude Code). Alternative: submit at once, as Hermes's terminal UI does. A change touches REQ-4, test 21 and UAT-1.
- **Q2. One bell setting or two.** Default: Talaria's own `[notifications]` table. Alternative: read Hermes's `display.bell_on_prompt` and `display.bell_on_complete` with `config.get` so one setting governs every Hermes client (both default to off in Hermes, which would silence Talaria by default).
- **Q3. Default channels.** Default: bell for `needs_you` and `failed`; desktop for all three; `done` after 20 seconds. Some people want no bell at all by default.
- **Q4. Prompt history on disk.** Default: on, with the leading-space opt-out and 0600 permissions. Alternative: off by default for privacy.
- **Q5. Herdr reporting.** Default: on whenever Talaria runs inside Herdr.
- **Q6. Empty editor result.** Default: clear with notice E7. Alternative: keep the old draft in recall, which needs a `push_history` method on P1-08's composer first.
- **Q7. Does `[keys]` rebinding satisfy the parity row's "keybindings"?** Default: yes; this unit makes the three new keys rebindable through `~/.talaria/config.toml` (P1-08's mechanism) and builds no keybinding screen. If the operator rules that the phase 2 check needs more (for example an in-app list of bindings), the builder stops (issue, Stop conditions) and the operator decides which unit owns it.
