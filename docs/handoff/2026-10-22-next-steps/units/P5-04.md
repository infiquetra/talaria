## 1. What this unit delivers

The `talaria-workflow` crate gains two modules:

1. `talaria_workflow::staffing`: the staffing table (`<talaria home>/staffing.toml`), the roster (Hermes's `model.options` result, parsed into providers, models, prices, rate limits and usage windows), the roster cache and its source, route resolution (an `agent()` call's `tier`, `model`, `provider` and `effort` become one concrete model, provider and effort), `StaffedLaunch` (the run's launch resolver: route, then `P5-03`'s `ExplicitLaunch::complete`), the start-of-run tier check, the pre-run cost estimate, the roster report that `P5-09`'s `talaria workflow roster` prints, and staffing drift detection for resumed runs.
2. `talaria_workflow::schedule`: the scheduler that implements `P5-02`'s `AdmissionGate`. It bounds how many workflow agents run at once (globally and per profile and provider), holds back calls for a provider or model that Hermes reports as rate-limited until the reset time, halves widths on rate-limit failures, authorises one retry of a rate-limited call, and enforces the run's money and token budgets. It accounts tokens and money from the run journal, so a resumed run starts with the spend and the widths it already had.

It also ships `examples/roster.rs` and `examples/staffed_run.rs`, which the acceptance scenarios use, and one bounded amendment to `P5-02` (section 8.4).

What it deliberately does not do:

| Concern | Owner |
|---|---|
| The script engine, `AgentRequest`, `Effort`, `BudgetSnapshot`, the engine's own budget check | `P5-01` |
| The journal, call keys, attempts, `AdmissionGate`, `GatePermit`, `LaunchResolver`, `JournaledBackend`, resume (except the amendment in section 8.4) | `P5-02` |
| `ExplicitLaunch`, `LaunchDefaults`, `HermesPort`, `SchemaTurnPolicy`, `WireFactory`, receipt usage | `P5-03` |
| Rendering scheduler events in the progress tree | `P5-05` |
| `talaria workflow run/resume/list/stop`, command-line budget flags, where run folders live | `P5-06` |
| `talaria workflow roster` (the command), the `talaria-workflows` skill, ultracode | `P5-09` |

## 3. The staffing file

### 3.1 Location and absence

`staffing.toml` in the Talaria home. This unit owns the rule, because `P1-08` has no function for it (S7): `pub fn talaria_home() -> Option<PathBuf>` returns `TALARIA_CONFIG_DIR` when it is set and non-empty, else `<user home>/.talaria` (the rule in the repository's `docs/configuration.md`), and `None` when there is no user home. `StaffingTable::default_path(talaria_home)` joins `staffing.toml` to the folder it is given. `P5-06` and `P5-09` call these two functions instead of re-deriving the rule. A missing file is not an error: it is an empty table (no tiers, default limits, no budget). A file that exists but cannot be read or parsed is an error that names the path and, for parse errors, the line and column.

### 3.2 Format (version 1)

```toml
# Talaria staffing table: which Hermes model each workflow tier uses.
version = 1                     # optional; only 1 is accepted

[defaults]
tier = "builder"                # optional; used by agent() calls that name neither tier nor model

[tiers.survey]                  # read-only sweeps, counting, listing
model = "minimax-m3.1-flash"
provider = "ollama-cloud"
note = "free; good enough for listing files"   # optional, shown in the roster report

[tiers.builder]
model = "<a strong coding model>"
provider = "<its provider slug>"
effort = "high"                 # optional: none, minimal, low, medium, high, xhigh, max, ultra

[tiers.judge]
model = "<the strongest model available>"
provider = "<its provider slug>"
effort = "high"

[limits]
max_in_flight = 10              # 1..=64; default 10

[providers.ollama-cloud]        # optional per-provider width
max_in_flight = 4               # 1..=64; default: the global value

[budget]                        # optional defaults; command-line flags (P5-06) win
money_usd = 5.00                # > 0, finite
tokens = 2000000                # > 0
```

Rules:

| Key | Rule | Error text (problem part) |
|---|---|---|
| top level | only `version`, `defaults`, `tiers`, `limits`, `providers`, `budget` | `unknown key '<k>'` |
| `version` | integer 1 | `version must be 1` |
| tier name | matches `^[a-z][a-z0-9_-]{0,31}$` | `tier name '<n>' must be lower case letters, digits, '-' or '_', at most 32` |
| `tiers.<n>.model` | required, non-blank, at most 256 characters | `model is required` |
| `tiers.<n>.provider` | required, non-blank (a Hermes provider slug, for example `ollama-cloud`, `custom:local`) | `provider is required` |
| `tiers.<n>.effort` | one of the eight effort values (H31), lower case | `effort must be one of none, minimal, low, medium, high, xhigh, max, ultra` |
| `tiers.<n>` other keys | only `model`, `provider`, `effort`, `note` | `unknown key '<k>'` |
| `defaults.tier` | names a defined tier | `defaults.tier names undefined tier '<n>'` |
| `limits.max_in_flight`, `providers.<slug>.max_in_flight` | integer 1 to 64 | `max_in_flight must be between 1 and 64` |
| `budget.money_usd` | finite number greater than 0 | `money_usd must be a positive number` |
| `budget.tokens` | integer greater than 0 | `tokens must be a positive integer` |

Strings are taken as written, never trimmed or case-folded; a blank string (only whitespace) is refused. Parse with the `toml` crate and serde `deny_unknown_fields`; map serde's span to a 1-based line and column.

`StaffingTable::TEMPLATE` is exactly the text above with the whole `[defaults]` block, all three `[tiers.*]` blocks, the `[providers.ollama-cloud]` block and the `[budget]` block commented out (each line prefixed with `# `), and `[limits] max_in_flight = 10` left active. It therefore parses to zero tiers, no default tier, width 10, no provider widths and no budget. It is for `P5-09` and `P5-06` to offer; this unit never writes into the user's Talaria home.

`DEFAULT_MAX_IN_FLIGHT: u32 = 10` is the one constant for the default width. `P5-00` measures the gateway's safe width; until its finding exists the default stays 10, and if the finding is below 10 only this constant changes (tests 1, 3, 4, 15 and UAT-1 read it).

## 4. The roster

### 4.1 Reading it

A `RosterSource` fetches the `model.options` result for one profile. `LinkRosterSource::new(wires: Arc<dyn WireFactory>)` (`P5-03`'s trait; the live factory is its `LinkWireFactory`, S5) opens one wire per profile with `wires.open(profile)`, keeps it for the run, and calls `wire.call("model.options", {}, 15 s)`. It never sends `profile` (H34), `refresh: true` (H5: that probes every custom endpoint and busts caches), `include_unconfigured` (H21) or `explicit_only`. Errors: a JSON-RPC refusal is `RosterError::Rpc { code, message }`; `5098` is shown as "the Hermes gateway is running older code than is installed; the operator restarts it" (H3), and agents never restart it; a profile the gateway does not serve is `RosterError::NotServed(profile)`; a timeout is `Timeout`. If `P5-03` exposes no public live `WireFactory`, build the same thing from `P1-03`'s `GatewayDial::new(home, profile)` and `P1-02`'s client inside `staffing/source.rs`.

`RosterCache` holds the latest roster per profile and is the only caller of the source:

| Method | Behaviour |
|---|---|
| `RosterCache::new(source, clock, min_interval)` | empty cache; `min_interval` is 30 s in production |
| `load(profile)` | always reads now; stores and returns it |
| `get_or_load(profile)` | the cached roster, or `load` when there is none |
| `refresh(profile, force)` | reads now if `force` or the last read of that profile is at least `min_interval` old; otherwise returns the cached one; a failed read keeps the previous roster and returns the error |
| `cached(profile)` | the cached roster, if any |

Run start (both examples, and `P5-06`): (1) `talaria_home()` and `StaffingTable::load`; (2) `cache.load(run_profile)`, the first and only `model.options` call before the run; a failure prints the error and exits 1; (3) `check_tiers` on that roster; problems print and exit 2 (`roster` prints the full report first); (4) build the snapshot (section 4.5) and create the run folder; (5) `StaffingResolver::new(table, roster)`; (6) `Scheduler::start`, which uses `get_or_load(run_profile)` and so reads nothing new. A resume repeats steps 1 to 3, reads the stored snapshot for drift and prices, and goes on from step 5.

### 4.2 Parsing

`Roster::from_model_options(value, profile, now)` keeps, per provider row:

| Roster field | From | Rule |
|---|---|---|
| `slug`, `name` | `slug`, `name` | required; a row without them is skipped with a warning |
| `authenticated` | `authenticated` | `true` only when the value is `true`; null or absent counts as `true` for rows returned without `include_unconfigured` (H6) |
| `models` | `models` | strings only, order kept; non-strings skipped |
| `unavailable` | `unavailable_models` | set |
| `prices` | `pricing` | per model, `Price { input, output, cache }` parsed with section 4.3; `free: true` makes both `Free` |
| `pricing_pending` | `pricing_pending` | bool |
| `limit` | `limit` | section 4.4 |
| `usage` | `usage` | section 4.4 |
| `warning` | `warning` | string or none |

Unknown keys are ignored (the row schema allows extra keys, H8). `current_model` and `current_provider` come from the result's `model` and `provider` (H2). A result whose `providers` is not an array is `RosterError::Malformed`.

### 4.3 Prices

`parse_price(s) -> PriceValue`:

| Input | Result |
|---|---|
| `"free"` | `Free` |
| `"$3.00"`, `"$0.0005"`, `"$15"` | `Usd(3.0)`, `Usd(0.0005)`, `Usd(15.0)` dollars per million tokens |
| `""`, `"?"`, `"$"`, `"$abc"`, `"3.00"` (no dollar sign), negative, NaN, infinite | `Unknown` |

Leading and trailing spaces are not trimmed (Hermes never writes them); anything not matching `^\$[0-9]+(\.[0-9]+)?$` or exactly `free` is `Unknown`. Cost of a turn priced this way: `input_tokens × input / 1,000,000 + output_tokens × output / 1,000,000`. `Free` contributes 0; `Unknown` makes the turn unpriced. Cache prices are parsed but not used (the journal's usage has no cache token counts, H27).

The formatter rounds (H33), so a parsed price is exact for the printed decimal, not for the catalog's true price: `"$0.01"` may stand for $0.014. That error belongs to Hermes's display and is accepted.

### 4.4 Availability

`Roster::availability(provider, model, now) -> Availability`, evaluated in this order; the first match wins:

| # | Condition | Result |
|---|---|---|
| A1 | no row for `provider` | `Missing` |
| A2 | row `authenticated` false | `Unauthenticated` |
| A3 | `model` not in `models` | `NotOffered` |
| A4 | `model` in `unavailable` | `Unavailable` |
| A5 | `limit.scope == "account"` and (`resets_at` null or unparseable, or later than `now`) | `Limited { until: resets_at, scope: Account }` |
| A6 | `limit.scope == "models"` and `limit.models[model]` later than `now` | `Limited { until, scope: Model }` |
| A7 | `usage.accounts` non-empty and every account's effective state is `limited` (effective state: `unknown` when its `resets_at` has passed, or when it says `ready` with no windows, H20) | `Limited { until: the earliest known future resets_at among the accounts (None only when no account has one), scope: Account }` |
| A8 | `usage.accounts` absent or empty, and some `windows` entry with `scope == "account"`, `used_percent >= 100` and (`resets_at` null or later than `now`) | `Limited { until: latest such resets_at (None when any is null), scope: Account }` |
| A9 | the tightest live window (after dropping windows whose `resets_at` has passed) has 20 percent or less remaining (`100 - used_percent`) | `NearLimit { remaining_percent, window }` (H19) |
| A10 | otherwise | `Ready` |

Account limits with a past `resets_at` are ignored, as Desktop does (H18). A model-scope window at 100 percent is not a limit (H15), only a `NearLimit` candidate. A8 keeps the latest time because every exhausted account-scope window must reset before the login works again (H15). ISO times are parsed with `chrono::DateTime::parse_from_rfc3339`; Python's `isoformat()` output with `+00:00` and optional microseconds parses; a string without an offset is unparseable (so an account limit with it stays in force, A5).

### 4.5 Snapshot

`Roster::snapshot_with(&StaffingTable, &RunBudget)` is the value `P5-06` (and `staffed_run`) passes to `P5-02` as `NewManifest.roster`:

```json

 "current":{"model":"minimax-m3.1-flash","provider":"ollama-cloud"},
 "providers":[{"slug":"ollama-cloud","name":"Ollama Cloud","authenticated":true,
   "models":12,"availability":"ready","limit":null}],
 "tiers":{"survey":{"model":"minimax-m3.1-flash","provider":"ollama-cloud","effort":null,
   "price":{"input":"","output":""}}},

```

`prices` holds every model of every provider row of the run profile whose input or output price parses to `Free` or `Usd`, as Hermes's strings. It never contains `api_url`, `key_env`, `warning`, account ids or account labels (they can name private hosts or people).

### 4.6 The price book

`PriceBook::from_snapshot(&Value)` reads `profile` and `prices` from a snapshot. `price(profile, provider, model)` returns the frozen price for the snapshot's profile and `None` for any other profile. Accounting (section 8.2) uses only the price book, so folding the same journal always gives the same money: a new run builds the book from the snapshot it just wrote, a resume from the stored manifest's `roster` (the manifest key `roster` of `P5-02` section 3.2; use the field name `P5-02` merged for it). Live prices serve only the check, the estimate and the report.

## 5. Route resolution

`StaffingResolver::new(table: Arc<StaffingTable>, run_roster: Arc<Roster>)` freezes both for the execution. `route(&AgentRequest) -> Result<Route, RouteError>` is synchronous and pure: it reads nothing live, so `P5-02`'s replay check gets the same answer every time (S1). Profile `p` is `request.profile`, else the roster's profile.

| # | Request has | Route | Notes |
|---|---|---|---|
| R1 | `model` and `provider` | that model and provider; effort = `request.effort`; `source: Explicit` | if `tier` is also set, `Route.ignored_tier` = that tier |
| R2 | `model` only | provider = the single authenticated provider of profile `p` whose `models` contains it; `source: Explicit` | none: `model '<m>' is not offered by any signed-in provider of profile '<p>'`; several: `model '<m>' is offered by <a>, <b>; name a provider` |
| R3 | `provider` without `model` | error | `provider '<p>' needs a model; to move a tier to another provider, edit staffing.toml` |
| R4 | `tier` (no `model`) | the tier's model and provider; effort = `request.effort` if set, else the tier's; `source: Tier(<tier>)` | unknown tier: `tier '<t>' is not in staffing.toml (<path>); defined tiers: a, b`; no table: `tier '<t>' needs a staffing table; create <path>` |
| R5 | nothing | `defaults.tier` if set, as R4 with `source: Tier(<that tier>)`; else the profile's current model and provider (H2) with `source: ProfileDefault` | neither: `no tier, no model, and profile '<p>' has no default model` |

R2 and the second half of R5 need profile `p`'s roster. When `p` is not the roster's profile they fail with `profile '<p>' was not read at run start; name a model and provider, or a tier`. R1 and R4 work for any profile.

After choosing, when `p` is the roster's profile, the route is checked against the frozen roster (section 4.4): `Missing`, `Unauthenticated`, `NotOffered`, `Unavailable` are errors (`model '<m>' on '<prov>' is not usable: <reason>`); `Limited` and `NearLimit` are not (the scheduler waits). Routes never depend on limits, so the journal key (which hashes the resolved launch) is the same on resume unless the staffing table or the provider's model list changed.

## 6. The start-of-run tier check and the estimate

### 6.1 Tier check

`check_tiers(&StaffingTable, &Roster, &RunBudget, now) -> RosterCheck`. For every tier, its availability (section 4.4):

| Availability | Kind | Message |
|---|---|---|
| `Missing` | problem | `tier '<t>': provider '<p>' is not configured in profile '<profile>'` |
| `Unauthenticated` | problem | `tier '<t>': provider '<p>' is not signed in; sign in with Talaria's provider screen or 'hermes model'` |

| `Unavailable` | problem | `tier '<t>': model '<m>' is not available to this account on '<p>'` |
| `Limited` | warning | `tier '<t>': '<p>' is rate-limited until <HH:MM UTC, or 'an unknown time'>; its agents will wait` |
| `NearLimit` | warning | `tier '<t>': '<p>' has <n>% of '<window>' left` |

### 6.2 Pre-run estimate

`estimate_run_cost(&StaffingTable, &Roster, tokens: Option<u64>) -> CostEstimate`. Prices are dollars per million tokens, so every formula divides by 1,000,000:

- Without a token budget: `NeedsTokenBudget { tier_prices }`, rendered `no estimate without a token budget; tier prices: survey unknown, builder $3.00/$15.00 per million tokens`.
- With a token budget `T`, over the tiers whose input and output prices are both known (`Free` counts as 0): `low_usd = T × min over those tiers of min(input, output) / 1,000,000`, `high_usd = T × max over those tiers of max(input, output) / 1,000,000`. Example: `T` = 2,000,000 and one tier at $3.00/$15.00 gives `$6.00 to $30.00`. Rendered with two decimals. If any tier is unpriced, append `, plus <n> unpriced tiers (unknown)`; if every tier is unpriced, the estimate is `unknown`. `$0.00 to $0.00` appears only when every tier is free; an unpriced tier never counts as zero.

## 7. The scheduler

### 7.1 Lanes and widths

A lane is a `(profile, provider)` pair: Hermes reports limits, usage and credentials per profile (H34; `model.options` is profile-scoped, H3), so the same slug in two profiles may be two different accounts.

- Global width `G`: starts at `limits.max_in_flight`.
- Lane width `W[l]`: starts at `providers.<provider>.max_in_flight` of the lane's provider, else `G`'s starting value. The configured cap applies to each lane separately; two profiles on one shared account can therefore use twice the cap, still bounded by `G`.
- `in_flight` and `in_flight[l]` count held permits.

### 7.2 `acquire(request, launch, reason)`

`launch` is `P5-02`'s `ResolvedLaunch`; lane `l = (launch.profile, launch.provider)` (a launch without a provider cannot come from `StaffedLaunch`; if one arrives, the provider is `""`), model `m`, key `k = journal_key(&request.call_id, launch)`.

- `Reattach`: answer `Proceed` at once, count the permit (even above the widths), emit `Admitted { reattached: true }`. Never waits, never skips (the work is already in Hermes).
- `Fresh`: enqueue `(arrival_seq, k, l, m)`. For a lane whose profile has no cached roster, the scheduler first calls `get_or_load(profile)`; a failure emits `RosterReadFailed { profile, .. }` and the lane is treated as `Ready` (Hermes's own refusal then fails the call visibly). A queued call is granted when all hold:
  1. no earlier queued call for the same lane is still waiting (per-lane first in, first out);
  2. `in_flight < G` and `in_flight[l] < W[l]`;
  3. `availability(provider, m, now)` in the lane profile's roster is not `Limited`, the lane is not paused, and no forced refresh for the lane is pending (section 7.4);
  4. the budget is not reached (section 8.3).
  Among grantable calls of different lanes, the lowest `arrival_seq` goes first. Whenever a condition changes (a permit drops, a pause ends, a roster refresh), the queue is re-evaluated.
  If condition 4 fails, the call is answered `Skip` (not left waiting) and `BudgetReached` is emitted once per budget kind. A billing-paused lane answers `Skip` (section 7.5).
  While a call waits, `Queued { reason }` is emitted once per change of reason: `GlobalCap`, `LaneCap`, `ProviderLimited { until }`, `ModelLimited { until }`, `LanePaused { until, cause }`.

The permit is `P5-02`'s `GatePermit::new(release)`. Dropping it: decrement counters, fold new journal records (section 8.1), emit `Released`, re-evaluate the queue.

### 7.3 Order and fairness

Per-lane first in, first out keeps a slow provider from starving its own later calls and keeps the order deterministic under paused time. A limited lane never blocks other lanes. Width changes never revoke held permits; they only stop new grants until `in_flight` falls below the new width.

### 7.4 Rate limits

A rate-limit record is a `turn_settled` whose `result_meta.failure_reason` (section 8.4) is `rate_limit`, `upstream_rate_limit` or `overloaded` (H23). The rules apply exactly once per record, identified by `(key, attempt, turn)`, whether the record reaches the scheduler through the retry hook (7.6) or the journal fold (8.1):

1. If no earlier rate-limit record exists anywhere in the journal (all executions): `G = max(1, G / 2)` (integer division), emit `CapHalved { scope: Global, from, to }`.
2. Always: `W[l] = max(1, W[l] / 2)`, emit `CapHalved { scope: Lane { profile, provider }, from, to }`.
3. Mark the lane for a forced refresh; its next grant waits for `refresh(profile, force: true)`. If the refreshed roster shows the provider (or model) limited, calls wait for that; otherwise the lane is paused for `cooldown` (60 s) and `LanePaused { until: now + 60 s, cause: RateLimited }` is emitted.

### 7.5 Credit walls

A `turn_settled` with `failure_reason` `billing` pauses the lane for the rest of this execution and emits `LanePaused { until: None, cause: OutOfCredit }`. Queued and later calls for that lane are answered `Skip` with `Skipped { cause: OutOfCredit }`; other lanes continue. Billing is never retried. A resume starts without the pause (the operator may have added credit).

### 7.6 One retry of a rate-limited call

The handoff's staffing table says "halve on the first rate-limit error, retry the failed unit once" ([../06-workflows.md](../06-workflows.md#the-staffing-table)). Hermes's own retries happen before the scheduler sees the failure, so they do not replace this one. The scheduler implements the amended gate method (section 8.4):

```rust
fn retry_after_failure(&self, request: &AgentRequest, launch: &ResolvedLaunch, last: &SettledTurn, attempt: u32) -> bool
```

It returns true when `last.result_meta.failure_reason` is a rate-limit value (7.4), the lane is not billing-paused, and the budget is not reached; it applies the 7.4 rules for that record before returning, so the retry's `acquire(.., Fresh)` waits under the halved widths and any pause. It returns false for every other reason. `P5-02`'s backend allows at most one such retry per key per execution; a second failure is final and the script receives `null`. A crash between the failed attempt and the retry resumes as any failed attempt does (`P5-02` runs it again).

### 7.7 Roster refreshes

Triggers: a wait on a limit whose `until` has passed; a wait on an unknown-time limit, every `cooldown` (60 s); a rate-limit record (forced). Never more often than `roster_min_interval` (30 s) per profile except the forced one. A failed refresh keeps the previous roster and emits `RosterReadFailed { profile, message, persistent }`, with `persistent: true` from the third failure in a row while calls wait.

### 7.8 Events

Every event is delivered as `TimedEvent { at, event }`, serialised flat: `{"at":"2026-10-22T16:00:05Z","event":"admitted",...}`, where `at` is `clock.now()` in RFC 3339 UTC when the event happened. `subscribe()` returns an unbounded receiver that gets every event from that moment on, in order; a subscriber never loses events (an unbounded `tokio::sync::mpsc` per subscriber, not a broadcast channel). `Scheduler::start` returns the first subscriber.

## 8. Accounting and budgets

### 8.1 Folding the journal

The scheduler reads `<run folder>/journal.jsonl` with `P5-02`'s `JournalReader::read_from(path, offset)` (no lock), from offset 0 at `start`, then from the last offset on every permit drop and every `budget()` call at least 250 ms after the previous read.

| Record | Fields used | Effect |
|---|---|---|
| `call_intent` | `key`, `attempt`, `launch.profile`, `launch.provider`, `launch.model` | remember `(key, attempt) → (profile, provider, model)` |
| `turn_settled` | `key`, `attempt`, `turn`, `usage`, `result_meta` | tokens and money (8.2); rate limits (7.4) and credit walls (7.5) |
| `run_resumed` | none | marks the start of a later execution |

At `start`, the whole existing journal is folded silently: spend is restored, and the 7.4 width rules are replayed (so a run that halved starts halved, and a second execution never halves the global width again), but no event is emitted, no pause is applied, no forced refresh is marked, and no billing pause is restored. Records read after `start` apply every rule normally. Unknown record types are left to `P5-02`'s reader; this unit never writes to the journal.

### 8.2 One settled turn

Tokens: `usage.total_tokens` if it is a non-negative integer, else `usage.input_tokens + usage.output_tokens` when both are, else 0 and the turn counts in `tokens_unknown_turns`. These are per-turn amounts (H27).

Money: the cost in the journal is a running total per Hermes session (H28, S4), and an attempt is one session. Keep `last_known[(key, attempt)]`, starting at 0. For each `turn_settled` in journal order, read `usage.session_cost`:

1. Known: `cost_status` is `actual`, `estimated` or `included` and `estimated_cost_usd` is a finite number ≥ 0. Let `a` be the amount. The increment is `a - last_known` when `a ≥ last_known`, else `a` (a reset: Hermes rebuilt the session's agent, H28). Set `last_known = a`, add the increment, source `Hermes`.
2. Otherwise (status `unknown` or absent, or no `session_cost`), even when `estimated_cost_usd` is `0.0` (H29): this turn's own cost is not known. Price the turn's tokens with the price book (4.6) for the attempt's `(profile, provider, model)`: `input_tokens × input / 1,000,000 + output_tokens × output / 1,000,000`, source `Pricing`. Without a book price for both, add nothing and count the turn in `money_unknown_turns`. `last_known` is unchanged.

Examples: two known turns reading $0.01 then $0.02 total $0.02 (not $0.03); readings $0.03 then $0.01 (a reset) total $0.04; a known $0.01 turn then an unknown turn with no book price total $0.01 plus one unknown turn; `{0.0, unknown}` with a book price of $3.00/$15.00 and 1,000 in, 500 out gives $0.0105, and without one gives one unknown turn, never a known zero.

`Spend.money_source` is `Hermes`, `Pricing`, `Mixed` (both) or `None`. Display text (`Spend::money_text()`): `$<x.xx>` when no turn is unknown; `$<x.xx> plus <n> unpriced turns` when some are and the known total is above zero; `unknown (<n> unpriced turns)` when the known total is zero and some are unknown.

### 8.3 Budgets

`RunBudget { tokens: Option<u64>, money_usd: Option<f64> }`, from `RunBudget::resolve(cli_tokens, cli_money, &table)`: a command-line value wins over `[budget]`; none means unlimited.

`budget()` returns `P5-01`'s `BudgetSnapshot { tokens_total, tokens_spent, money_total, money_spent }`, where `money_spent` is the known total (never negative or non-finite). The budget is reached when `tokens_spent >= tokens_total` or `money_spent >= money_total`. The engine refuses new live calls once it is reached (`P5-01` section 6.1), reading the budget through `P5-02`'s backend, which answers with `gate.budget()`; this unit additionally answers `Skip` to queued calls and refuses retries. Calls already admitted keep running: the overshoot is bounded by the work in flight, as with Claude Code's `--max-budget-usd`. A resumed run whose folded spend already reaches a budget answers `Skip` to its first `Fresh` call.

### 8.4 The amendment to `P5-02`

This unit makes three bounded changes in `P5-02`'s modules, in its first commit, with every `P5-02` test still passing. The operator approves them, or folds them into `P5-02`'s own repair first, in which case this unit only uses them.

1. **Allow-list.** `turn_settled.result_meta` also copies `failure_reason` (a string, cut to 1,024 characters like the others). Cost needs no change: it already reaches `turn_settled.usage.session_cost` (S4).
2. **Gate hook.** `AdmissionGate` gains a provided method `fn retry_after_failure(&self, request: &AgentRequest, launch: &ResolvedLaunch, last: &SettledTurn, attempt: u32) -> bool { false }`. Every existing implementor (`NoGate`, test gates) keeps working unchanged.
3. **Backend.** When the turn policy returns `Finish(Failed(reason))` after a settled turn, and this key has not been retried in this execution, the backend drops the attempt's permit and asks `gate.retry_after_failure`. On `true` it writes `call_finished { outcome: failed, reason, retry: true }` (a new optional field; absent means false), does not deliver the outcome to the engine, and starts attempt `a + 1` with `acquire(.., Fresh)` and the `:a<n>` identifiers. On `false` it behaves as today. The record grammar already allows the next attempt after `call_finished(failed)`; the forwarder skips `retry: true` finishes; the attempt rule in `P5-02` section 5.3 gains a fourth way ("the gate authorises one retry of a failed attempt in this execution").

The journal version stays 1: readers ignore unknown fields, and older journals simply lack them.

### 9.3 How the pieces are composed

```rust

    cache.clone(), run_dir.journal_path(), clock.clone()).await?;
```

### 9.4 Roster report text

```text
Roster for profile fixture at 2026-10-22 16:00 UTC

Providers (signed in)
  ollama-cloud   12 models   ready
  example-cloud   8 models   limited until 16:30 UTC

Tiers
  survey   minimax-m3.1-flash on ollama-cloud            unknown       ok
```

Columns: price is `free`, `$<in>/$<out>` or `unknown`. Status is exactly one of `ok`; `warning: rate-limited until <HH:MM UTC or an unknown time>`; `warning: <n>% of '<window>' left`; `warning: no price` (unpriced under a money budget); `problem: <the section 6.1 message after the tier name>`. Provider availability: `ready`, `near limit (<n>% of '<window>' left)`, `limited until <HH:MM UTC or an unknown time>`, `not signed in`. `Budget:` is `none`, or `<n> tokens`, `$<x.xx>`, or both joined by `, `. A provider `warning` prints on the line below its provider, indented four spaces.

`display_safe` renders every roster-supplied string (provider names, model names, window labels, warnings) literally, replacing each Unicode control character (general category `Cc`, which covers ESC and the C1 range) and each bidirectional formatting character (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069) with `?` (architecture: untrusted text is rendered literally, control and bidirectional-override characters replaced by visible stand-ins). Columns are padded with spaces to the longest value. The JSON form (`--json`) is `serde_json::to_string_pretty(&report)`, with the same `display_safe` strings.

## 12. Design reasoning and rejected alternatives

- **This unit owns `StaffedLaunch`.** `P5-03`'s `ExplicitLaunch` refuses tiers and `src/hermes/` is not this unit's, so the composition of route and completion lives here. Rejected: a `RouteResolver` trait in `P5-03` (its own repair removed it), and an async route for sibling profiles (`LaunchResolver` is synchronous and must be pure).
- **One connection per profile for the roster.** A profile-bound ticket naming another profile is refused (H34). Rejected: sending `profile` on the run profile's connection.
- **Lanes per profile and provider.** Limits, credentials and prices are per profile; a slug alone would let one profile's quota wall stop another's work.
- **Accounting from the journal, with a frozen price book.** The journal is durable and is what resume trusts; freezing the run-start prices makes the fold give the same money on every resume. Rejected: live prices for history (a price change would move a past total); per-session `session.usage` calls (a legacy method).
- **Cost as a running total.** Hermes reports the session's running total (H28); adding each reading would double count a corrected turn.
- **`cost_status` decides what is known.** `0.0` with `unknown` is not zero (H29).
- **Reset times from `model.options`.** `failure_resets_at` does not reach the receipt (H30), and the roster is what Desktop shows.
- **One retry after halving.** The handoff asks for it; Hermes's retries happen before the halving. The retry needs a gate hook and a backend path in `P5-02`, kept small (section 8.4). Rejected: leaving the retry to `talaria workflow resume` (the draft's choice), which contradicts the handoff.
- **Halving once globally (per run, across executions), every time per lane.** One rate limit says the run as a whole was too wide; a lane that keeps failing needs its own width cut further.
- **`Skip` for calls queued when the budget is reached.** The engine already throws `BudgetExhaustedError` for new calls; a queued call has passed that check, so it must end without starting work.
- **Unpriced models are a warning, not a refusal, under a money budget.** Refusing would block subscription providers whose catalogue has no prices (H32). The warning and the unknown-turn count keep the gap visible.
- **Strict tier check at run start.** The roadmap says the runner refuses to start when a tier's model is not usable; a limited provider is only a warning because the scheduler waits for it.
