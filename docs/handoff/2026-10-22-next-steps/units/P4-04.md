## 1. What this unit adds, in one paragraph

A `/mcp` overlay over the connected Hermes profile's Model Context Protocol (MCP) servers. The
Servers tab joins the configured list with the gateway's cached runtime status and lets the user
test, enable or disable, set a key, sign in with OAuth (the browser-based authorisation standard),
remove, and add a custom server. The Catalogue tab lists Hermes's curated entries and installs
one. An explicit apply step calls `reload.mcp` so the running session picks the change up, after
showing Hermes's own warning that a reload refreshes every chat of the profile. Every step uses a
typed gateway method except enable and disable, which only the dashboard REST route offers.

## 4. Design

### 4.1 Settled decisions (with reasons)

- **D1. Socket first, one REST route.** Architecture decision draft 0007 keeps dashboard REST for
  what has no gateway method. Every MCP step has one except enable and disable (H40), so that one
  call goes through `P4-01`'s `RestClient::put_json`.
- **D2. Catalogue install through `mcp.servers.add {preset}`** (the default of operator question
  Q1). It is the typed path the roadmap names and Desktop's bot setup uses. Its gap: `requires` is
  always empty at v0.22.4 (H11), so `asana` and `n8n-official` install without the values they
  need (H12). Talaria still honours a non-empty `requires` (a later Hermes may fix it) by refusing
  to install and showing the `hermes mcp install` command.
- **D3. Secrets never in `config`.** `mcp.servers.add`'s `config` is written to `config.yaml`
  verbatim (H17); `bearer_token` and `set_api_key` put values in `.env` and only `${VAR}`
  references in `config.yaml` (H17, H19). The recorder withholds `mcp.servers.add` `config` as a
  free object anyway, but the file on disk is what matters. A URL is part of `config`, so the add
  form refuses credentials in the address and warns about query strings (section 4.13).
- **D4. No silent reload.** A reload refreshes every chat of the profile and can cost a re-sent
  prompt (H41, H42). Talaria asks Hermes first without `confirm`, shows Hermes's own message, and
  confirms only on `y`. It never sends `always` (refused, H41; the generated type would send it,
  H45) and never reloads in the background (H43 is out of scope).
- **D5. Gateway-hosted listener; link on a key press.** Talaria and the gateway are on the same
  machine (the native socket and REST are loopback only), so the gateway's own receiver (H32)
  works for a local browser. A client-hosted receiver (`client_redirect_uri`) adds nothing here.
  `o` opens only `https://` links, like `P4-02`.
- **D6. The SSH paste path.** A remote user's browser cannot reach `127.0.0.1` on the gateway's
  machine. Hermes's own answer is "paste the address" (H37). Talaria offers it through
  `mcp.servers.oauth.callback`, which by code reading feeds the same flow object the gateway's
  receiver feeds (H35, H39); the contract describes it more narrowly, so UAT-6 must observe it.
- **D7. Device code is shown, not run** (the default of operator question Q3). No gateway method
  starts it (H38). Talaria shows and copies `hermes -p <profile> mcp login <name> --flow device`,
  like `P4-02`'s rule for external sign-ins.
- **D8. Plugin servers are read-only here.** Writes are refused by Hermes (H17, H19, H21, H30,
  H40); refusing locally gives a clearer message and avoids a round trip. Tests stay allowed.
- **D9. Name rule.** Hermes accepts any non-empty name (H22); `:` would collide with the
  `server:tool` form `tools.configure` uses, and spaces make the `MCP_<NAME>_API_KEY` mapping
  lossy. Desktop's install-link rule `^[A-Za-z0-9._-]{1,64}$` is adopted.
- **D10. Neutral `configured` wording.** `mcp.servers.status` hides runtime state outside the
  launch profile unless a multiplexer runs (H15), so `configured` may describe a running server.
  The label says `configured · not reported running`, never "stopped".
- **D11. Secrets follow `P4-02`'s pattern.** `P4-02` (and `P1-09` before it) keeps typed secrets out
  of `talaria-core` and the application event channel: the value lives in a `talaria-tui`
  `SecretField` (a `P1-09` `MaskedValue`, 65,536 bytes reserved so it never reallocates and leaves
  no copy behind), and core sees only text-free events. This unit uses the same field, the same
  wiring shape (`P4-02`'s `ProvidersWiring` becomes `McpWiring`) and the same `execute(effect,
  secret)` signature, so `P4-09` and reviewers meet one pattern, not two. The cost: this unit has up
  to eleven secret fields at once (token, eight environment values, a key value, a paste), so the
  wiring keys them by `SecretSlot`.
- **D12. One reload override, not a hand-built frame.** The generated `reload_mcp::Params` cannot
  omit `always` (H45). `P0-03`'s rule is that protocol-level contract errors are corrected only in
  `crates/hermes-contract/src/overrides.rs`, each with a comment and a test; a typed override keeps
  `call_raw` out of product code, as `P1-02` requires.

**Key routing (as `P4-02`).** While `view.secret_focus` is `Some(slot)`, keys and paste go to that
slot's `SecretField` first: `Edited` becomes `SecretEdited { slot, empty: len == 0 }`, `Submit`
becomes `SecretSubmitted { slot }`, `Clear` (Ctrl+U) becomes `SecretEdited { slot, empty: true }`,
`NotHandled` (Tab, Esc, Ctrl+S, arrows) goes to core as `Key`. When core emits an effect whose
`secret_slot()` is `Some`, the wiring calls `service.execute(effect, wiring.secret_for(&effect))`
(a `Zeroizing` copy, dropped after the call); otherwise it passes `None`. `ForgetSecrets` clears
every field.

**`McpService::execute`.** One effect becomes one call, except `RelayCallback`, which first runs
`parse_redirect` on the secret; a bad address returns `CallbackRelayed { Err(BadPaste(e)) }` and
sends nothing. `AddServer { token: true }` puts the secret in `bearer_token`; `SetKey` puts it in
`value`. `OpenUrl`, `CopyText`, `ForgetSecrets` and `Close` never reach `execute` (it returns an
empty `Vec` if they do): the wiring handles them as `P4-02` does (section 4.14, item 5). The service keeps the
flow ids of started sign-ins; a final poll, a sent cancel or `close()` removes an id, so each flow
is cancelled at most once. `close()` sets a flag: a start answer that arrives later is cancelled at
once and returns nothing; the flag clears on the next `Open`.

**Error mapping** (copied from `P4-02`): `CallError::Rpc` → `Failure::Rpc { code, message,
reason: data.reason, detail: data.detail }` (`-32601` included); `NotConnected`, `Encode`,
`InvalidTimeout` → `NotSent`; `TimedOut`, `Unknown`, `BadResult` → `Unknown`. `RestError::
{NotLoopback, TlsNotSupported, Ticket, Connect}`, `Timeout { sent: false }`, `Dropped { sent:
false }` → `NotSent`; anything with `outcome_unknown()` → `Unknown`; `Unauthorized` → `Http { 401 }`;
`Forbidden { detail }` → `Http { 403, Some(detail) }`; `NotFound` → `Http { 404, None }`; `Refused`
→ `Http { status, detail }`; `Server { status }` → `Http { status, None }`; `BodyTooLarge`,
`BadBody` → `BadReply`. A `BadReply` to a write is shown like `Unknown`.

Row: name (up to 24), kind (8, from `transport_kind`), `installed · on`, `installed · off` or

### 4.5 The sign-in state machine

```text
Idle --ctrl+o--> Starting --start ok--> Waiting --poll approved--> Done(approved)
                    |                      |--poll error--------> Done(error | timed out)
                    |                      |--3 failed polls----> Done(lost) + Cancel
                    |                      |--360 s-------------> Done(timeout) + Cancel
                    |--start error--> Done(start failed)
   Esc/close/quit in Starting: remember "cancel when id arrives"; in Waiting: Cancel once
   p in Waiting: Paste field --submit--> RelayCallback (stay Waiting) --Err--> show text, ForgetSecrets
```

- The card is modal: list keys, Tab and Shift+Tab do nothing while it is open (as for the form,
  section 4.8), so only one sign-in exists at a time and a tab switch cannot happen during one.
- The countdown starts at 300 s (Hermes's callback wait, H36) from the start reply's arrival and
  repaints once per second; at 0 it reads `Waiting for Hermes to give up…` until the end arrives.
- The first poll goes 2 s after the start reply; each next poll 2 s after the previous answer;
  never two in flight. A poll answered `Unknown` counts as a failed poll; a cancel answered with
  any failure shows nothing. A failed poll is a `Failure` or a reply
  with `ok: false` (Hermes never sends one at v0.22.4, H33); three in a row end the card.
- A poll `error` is shown as `The sign-in timed out.` when it arrives with 10 s or less left on the
  countdown or later (Hermes's own timeout text may be reworded by its worker, H36); otherwise
  `Sign-in failed: <error_message>`.
- 360 s after the start reply with no end, Talaria ends the card as timed out and cancels.
- `Done(*)` shows its text until a key is pressed; Esc returns to the list.
- `CancelSignIn` is emitted at most once per flow id; a late `SignInStarted` after the user left
  emits it immediately and shows nothing.
- `RelayCallback` sends only the parts present; `iss` only when the pasted URL carries it.

SSH hint: shown when `over_ssh` was true at open. `over_ssh` is true when any of `SSH_CLIENT`,
`SSH_CONNECTION`, `SSH_TTY` is set and non-empty (Hermes checks `SSH_CLIENT` and `SSH_TTY`, H37);
`talaria-app` reads the environment once at start and passes the flag in. The port is the `port` of
the `redirect_uri` query parameter of `auth_url`; without it, the hint shows
`http://127.0.0.1/callback`. The `p` key works with or without SSH; the footer shows it always.

### 4.6 The apply state machine

```text
Clean --successful write--> Pending
Pending|Clean --ctrl+y or /mcp apply--> Asking (Reload{session_id, confirm:false})
Asking --confirm_required--> Confirming (shows message) --y--> Applying (Reload{same session_id, confirm:true})
                                                      --n/Esc--> previous state
Asking --reloaded (an older Hermes that skips the gate)--> handle as Applying's result
Applying --reloaded--> Clean (+ outcome text)
Applying --error or Unknown--> previous state (+ text)
```

Frames: `{"session_id": "<id>"}` then `{"session_id": "<id>", "confirm": true}`; with no foreground
session, `{}` then `{"confirm": true}`. The session id is captured when Asking starts; a foreground
change during the exchange does not change it. Successful writes: add, set key, enable or disable,
remove, sign-in approved, install. A test is not a write.

### 4.8 Keys and contexts

`KeyContext::Mcp` as listed in REQ-15; the app maps each `mcp_*` action to `McpAction`. Arrows,
Page Up, Page Down, Home, End, Enter, Esc, Backspace and printable keys reach core as `McpKey`.
While a card or the form is open, printable keys go to its focused field (a secret field takes them
in the wiring first, section 4.2); on a list they go to the filter. Letter actions: `KeyMap` always
maps `o`, `c`, `p` to `OpenLink`, `Copy`, `PasteRedirect`. Core acts on `OpenLink` and
`PasteRedirect` only on a waiting sign-in card, and on `Copy` only on a card that shows a link or a
command; anywhere else core treats the action as the typed letter (`Char('o')` and so on) and puts
it in the focused text field or the filter. `y` and `n` arrive as `Char` and act only on a
confirmation card. So `KeyMap` and `McpWiring::route_key` need no state of their own. In the form, Tab, Down and Enter move to the next field and Shift+Tab and Up to the previous one
(the tab switch keys are inactive while the form or any card is open); `SecretSubmitted` from a
secret field also moves to the next field. Text fields edit at the end only (Backspace removes the
last character); Left and Right act only on a choice field, where they change the choice, Ctrl+S saves, Esc asks `Discard this server? y · n` when anything was typed. Esc on a list
clears a non-empty filter; a second Esc closes the overlay.

### 4.9 Budgets and idle

The overlay draws `Loading…` on the first frame and issues its reads in parallel. No timer runs
unless a test is running (1 Hz elapsed counter) or a sign-in card is waiting (1 Hz countdown and
the poll due time). The filter is recomputed on each key; with 66 catalogue rows that is trivial.

### 4.10 Secrecy

1. Token, environment values, key values and the pasted address live only in `McpWiring`'s
   `SecretField`s (`P4-02`'s type, a `P1-09` `MaskedValue`: `Zeroizing<String>` with 65,536 bytes
   reserved, no `Debug`, `Clone`, `Display`, `Serialize`).
2. Core never holds them: it sees `SecretEdited { slot, empty }` and `SecretSubmitted { slot }`.
   `McpKey::Paste` is never sent while a secret field has focus.
3. They appear in exactly one request frame each: `mcp.servers.add.bearer_token`,
   `mcp.servers.set_api_key.value`, `mcp.servers.oauth.callback.code` and `.state`. The service
   receives a `Zeroizing` copy per call and drops it after.
4. The recorder deny-set withholds `set_api_key` `value`, `oauth.callback` `code` and `state`, and
   `mcp.servers.add` `config`. `bearer_token` relies on the recorder's key-name rule; test 34
   proves it is withheld, and a failure is a stop condition (report to the recorder's owner).
5. Tracing in the code this unit adds never logs the params of these four methods, `auth_url`, or
   the catalogue's raw `transport`. `P1-02`'s client logging is its owner's rule.
6. The clipboard receives only `auth_url` or a command.
7. Secret fields draw one `•` per character up to 40, then `…`, from `secret_len`.
8. All fields are cleared on completion of the effect that used them, on cancel, tab switch and
   close (`ForgetSecrets`).

### 4.14 Rules settled after the second builder review

1. **Refresh, not reload.** Where the issue says *refresh the lists*, core emits `LoadList` and
   `LoadStatus`. Only Apply sends `reload.mcp`; no add, install, remove, toggle, key or sign-in
   ever does (decision 4).
2. **Filter per tab.** Each tab keeps no filter across a switch: any tab switch, including the
   switch to Servers after an install, clears the filter.
3. **Lifetime.** `talaria-app` keeps one `McpState` per `P1-12` `OpenConnection`, beside the
   `McpService`. Closing and reopening keeps the rows, the pending flag and the install-hint
   marks; `Open` resets the tab, filter and card and refreshes the lists. A reply that arrives
   after a close or a tab switch updates state silently (rows, suffixes, pending flag); its notice
   is dropped while the overlay is closed. A late `SignInStarted` is cancelled (section 4.5).
4. **Partial add failure.** The `Added <name>, but saving <NAME> failed…` notice stays; the test
   that follows reports only through the row suffix (no notice).
5. **Open and copy (as `P4-02`).** The wiring in `talaria-cli` handles `OpenUrl` with `P4-02`'s
   `opener_argv` (in `talaria-app`'s `providers` module): it spawns the argv with no shell, null
   streams, not awaited. `None` or a spawn error → the wiring sends `McpInput::OpenFailed`, and
   core shows `Could not open a browser. Copy the link with c.`. `CopyText` goes through
   `P1-06`'s `InlineTerminal::copy_to_clipboard` (which writes `P4-02`'s `osc52`, in `talaria-tui`);
   core itself shows `Copied to the clipboard if your terminal allows it.` when it emits
   `CopyText`. `SecretField` is at `crates/talaria-tui/src/providers/secret_field.rs`.
6. **Foreground session.** `foreground` and `Foreground(..)` carry the foreground session id
   that `P1-05`'s reducer exposes (the value `P4-05` also reads); `app.rs` sends `Foreground`
   when it changes. This unit names no `P1-05` type beyond `Option<String>`.
7. **Dependencies.** Use workspace pins where present (`zeroize`, `proptest`; `proptest` as a
   dev-dependency of `talaria-tui` and `talaria-cli`). `talaria-core` takes `shell-words` (reuse
   the workspace pin if `P2-13` added one). The URL rules, `parse_redirect` and percent-encoding
   are hand-written with tests, as in `P4-02`. Test 34 captures tracing with a small hand-written
   `tracing::Subscriber` in the test file, so no new crate. Name every manifest line in the pull
   request.

```json
→ {"ok":false,"error":"<text>","tools":[],"oauth_needed":true,"oauth_tokens_present":false}

{"method":"mcp.servers.remove","params":{"name":"my-local"}}
→ {"ok":true,"removed":true}

{"method":"mcp.servers.oauth.start","params":{"name":"my-oauth"}}
→ {"ok":true,"session_id":"<flow id>","auth_url":"https://.../authorize?...&redirect_uri=http%3A%2F%2F127.0.0.1%3A<port>%2Fcallback&state=...","flow":"pkce"}
{"method":"mcp.servers.oauth.poll","params":{"name":"my-oauth","session_id":"<flow id>"}}
→ {"ok":true,"status":"pending","session_id":"<flow id>","error_message":null,"auth_url":"https://...","tools":null}
→ {"ok":true,"status":"approved","session_id":"<flow id>","error_message":null,"auth_url":"https://...","tools":[{"name":"...","description":"..."}]}
→ {"ok":true,"status":"error","error_message":"OAuth session not found or expired"}
{"method":"mcp.servers.oauth.cancel","params":{"name":"my-oauth","session_id":"<flow id>"}}
→ {"ok":true,"status":"error"}
{"method":"mcp.servers.oauth.callback","params":{"name":"my-oauth","session_id":"<flow id>","code":"<secret>","state":"<secret>"}}
→ {"ok":true,"session_id":"<flow id>"}   or   {"ok":false,"error_message":"OAuth callback state mismatch"}

{"method":"reload.mcp","params":{"session_id":"<session>"}}
→ {"status":"confirm_required","message":"Reloading MCP refreshes every chat of this profile."}
{"method":"reload.mcp","params":{"session_id":"<session>","confirm":true}}
→ {"status":"reloaded","message":"MCP servers reconciled (added: deepwiki); this chat's tools changed for its next turn","session":"applied","session_servers":["deepwiki"]}
{"method":"reload.mcp","params":{}}
{"method":"reload.mcp","params":{"confirm":true}}
```

The cancel reply's `status` is whatever the flow snapshot says after `mark_error(...,
cancelled=True)`; Talaria ignores it. Error frames: legacy `{"code":4064,"message":"server 'x' not
found"}`; canonical
`{"code":4001,"message":"mcp_servers_unavailable","data":{"reason":"mcp_servers_unavailable","field":"mcp_servers","detail":"did not connect: x"}}`.
The catalogue `transport` sample is the v0.22.4 behaviour (H10); a fixed Hermes would send `"http"`,
and both must decode and map to `remote`. The `message` of a `reloaded` result is free text; only
`status` and `session` drive behaviour.

Serialisation rule: options that are `None` are left out of the JSON object. For the legacy
`mcp.*` methods every optional param has a null default, so typify skips it when `None` (checked
against the contract: `McpServersAddParams`, `McpOauthStartParams`, `McpOauthCallbackParams`,
`ProfileParams`). For `reload.mcp` the generated type would always write `"always": false` and
`"confirm": false` (H45), so the override of section 4.2 is used. Test 32 asserts the exact objects
above.

### 5.2 REST

```text
PUT /api/mcp/servers/<percent-encoded name>/enabled
x-hermes-gateway-ticket: <fresh native-http ticket>        (no Origin header, no ?profile)
{"enabled": false}
→ 200 {"ok": true, "name": "<name>", "enabled": false}
→ 404 {"detail": "Server '<name>' not found"}     (P4-01's RestError::NotFound keeps no detail)
→ 409 {"detail": "Server '<name>' is provided by plugin '<p>' and cannot be modified"}
→ 400 {"detail": "Malformed server config"}
```

Percent-encode every byte outside unreserved characters (`A-Za-z0-9-._~`); names that pass D9
never need it, but plugin names are not checked by Talaria. A gateway without this route answers
404 too (FastAPI's `{"detail":"Not Found"}`), which is why REQ-5 reloads the list to tell the two
apart.

## 6. Mock-server rules

The mock gateway (`P1-12`'s `crates/talaria-app/tests/support/mock_gateway.rs`) gains twelve
handlers, built only from section 5 and the contract schemas:

1. It keeps an in-memory map of servers (name to summary-shaped config), a catalogue list (with the
   v0.22.4 `TransportSpec(...)` transport text), a map of flows, and a `reload_count`.
2. `mcp.*` handlers reproduce the error order of H17, H19, H20, H21, H30 exactly (plugin check
   before existence check on writes; `name required` before anything).
3. The `reload.mcp` handler refuses any key outside `session_id`, `confirm`, `rev`, `profile` with
   the canonical `invalid_params` frame, answers `confirm_required` unless `confirm` is `true`, and
   increments `reload_count` only when confirmed. Tests read `reload_count` to prove no silent
   reload.
4. Flows: `oauth.start` returns a fixed flow id and an `https://` URL whose `redirect_uri` names
   `127.0.0.1:43123`; `oauth.poll` returns a scripted sequence; `oauth.cancel` records each call.
5. Every handler records the exact params object it received, so tests assert on it.
6. No handler accepts a param the contract does not declare (the legacy models forbid extras).
7. A drop-after-method hook: `drop_after(method)` closes the socket right after receiving the next
   frame for `method`, without replying. If `P1-12` already merged an equivalent hook, use it.

The REST route of section 5.2 is registered inside `crates/hermes-client/tests/mcp_api.rs` with
`P4-01`'s `MockRest::with_route(method, path, handler)`, with scripted status codes, recording the
headers it received; `mock_rest.rs` itself is not edited. `talaria-app` tests reach the mock REST
server with the `#[path = "../../hermes-client/tests/support/mock_rest.rs"]` include, as `P4-02`
does. The REST drop case is tested through `failure_from_rest(&RestError::Dropped { sent: true })`.

## 7. Edge cases

| Case | Behaviour |
|---|---|
| A server listed by `mcp.servers.list` but missing from status | `status unknown` |
| A status row with no list row (should not happen) | ignored |
| `enabled: false` with runtime `connected` (not yet reloaded) | `off`; the pending line explains apply |
| `enabled` absent or `null` in `config.yaml` | Hermes sends `true` (H14); core never sees null |
| `auth` is `oauth` but the transport is `stdio` (hand-edited config) | Ctrl+O shows the local text; Hermes would refuse with 4001 |
| A server whose `tools` value is not a mapping | `Tool filter: all tools` |
| A test reply with 500 tools | first 20 in the card, `… and 480 more` |
| Tool descriptions with escape sequences or bidirectional controls | sanitised (test 28) |
| Two Ctrl+T on the same row | the second is ignored while the first runs; one test at a time overall (a test is slow and holds a gateway worker) |
| A catalogue `transport` that is neither `http`, `stdio` nor the `TransportSpec(type=...` text of one of them | kind column blank; install still allowed |
| A catalogue entry with a `connector_slug` | installs like any other; the label only says it is also a connector |
| An installed catalogue entry not yet in the server list | `<name> is installed but not listed yet. ctrl+r reloads.` |
| Catalogue entry already installed under the same name but by hand | Enter selects it on Servers |
| Install of `asana` or `n8n-official` at v0.22.4 | installs; the sign-in offered next (or a test) fails; the notice adds the `hermes mcp install` hint (section 4.4) |
| The pasted address has a fragment or extra parameters | ignored; only `code`, `state`, `error`, `iss` are read |
| The pasted address has `error=access_denied` | relayed; the next poll returns `error` |
| A poll reply with `ok: false` | counts as a failed poll (Hermes never sends one at v0.22.4) |
| Hermes's 300 s callback wait ends | the next poll is `error`; shown as timed out (section 4.5) |
| A flow left over from an earlier run (`already in progress`) | the 5024 text; Hermes keeps abandoned flows 900 s (H31) |
| `reload.mcp` returns `reloaded` to the first call (no gate) | treated as applied (older gateway) |
| `reload.mcp` with no foreground session | `{}` then `{"confirm": true}`; outcome text without session |
| The user changes the foreground session while a reload runs | the outcome refers to the session id that was sent |
| Enable toggle answers 404 but the server is still listed after reload | the route-missing text (section 4.7) |
| Clipboard copy in a terminal without OSC 52 | `Copied to the clipboard if your terminal allows it.`; the link or command is also on screen |
| Terminal narrower than 60 columns | cards take the full width and wrap; the link wraps at any character |
